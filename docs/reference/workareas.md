# Workareas (runtime cache, gitignored)

`workareas/` holds per-ticket state generated by the skills as they
run. It is **gitignored** — never checked into the repo. **Exception:**
`workareas/shared/` IS tracked (via a `.gitignore` negation) so the
review skill's handoff helper can publish artifacts on a workspace
branch for the PR owner to pick up.

```
workareas/reviews/EUDPA-X/                         → ticket.md, repos/, review-index.md, review.{repo}.md
workareas/reviews/EUDPA-X/file-reviews/{repo}/     → {file}.review.md, _consistency-check.md
workareas/code-style-reviews/EUDPA-X/              → .style-meta.json, items.{repo}.json, style-review.{repo}.md, style-rules.{repo}.md
workareas/code-style-reviews/EUDPA-X/file-reviews/{repo}/ → {file}.style.json
workareas/ticket-creation/.prereqs/                → epics.txt, capabilities.txt, meta.json (refreshed by prepare-ticket-creation.sh)
workareas/ticket-creation/<slug>/                  → draft.md
workareas/ticket-planning/EUDPA-X/                 → ticket.md, plan.md, .plan-meta.json, .implement-meta.json, best-practices/{repo}.md, .diffs/{repo}.diff
workareas/ticket-refinement/EUDPA-X/               → ticket.md, review.md, .refinement-meta.json
workareas/npm-upgrades/EUDPA-X/{repo}/             → packages.{repo}.json, .upgrades-meta.json, best-practices.md, .context/{pkg}/
workareas/govuk-upgrades/EUDPA-X/                  → .run-meta.json
workareas/govuk-upgrades/EUDPA-X/{repo}/           → versions.{repo}.json, CHANGELOG.md, version__{v}.changelog.md, best-practices.md
workareas/shared/EUDPA-X/                          → review handoff artifacts (tracked; committed to chore/EUDPA-X-review-handoff)
workareas/skill-creator/<name>/                    → decisions.json (CREATE-mode interview state)
workareas/skills-audit/<name>.md                   → AUDIT-mode plan document (per skill)
workareas/understanding-checks/EUDPA-X/            → .interview-meta.json, ticket.md, analysis.{repo}.json, questions.json, transcript.json, report.md, .diffs/{repo}.diff, best-practices/{repo}.md
workareas/journey-builder/EUDPA-X/                 → backlog.json + deferred.json (tracked; canonical build-loop state)

```

## What is tracked under `workareas/`, and why

Eight things, each because it outlives the run that made it:

- `journey-builder/*/backlog.json` — the executable definition of a body of
  work. Judgement, not cache.
- `journey-builder/*/deferred.json` — leads found but not yet verified to
  backlog standard.
- `journey-builder/*/.corpus-meta.json` — which commit each side is pinned at
  and which commit the pictures are actually of. A report that cannot say what
  it is a report of is worthless.
- `journey-builder/*/evidence.json` — every citation resolved to a permalink, a
  blob id and a snippet. Regenerable, but `git diff` on it after a re-pin is the
  record of which citations moved and which changed content.
- `shared/*/findings/*.json` — one file per finding, written by the authoring
  agents and assembled into `backlog.json` by `tim parity ingest`. The prose a
  ruling is made against, and the increment id comes from the file name, so a
  rename orphans every ruling and citation attached to the old id.
- `shared/*/evidence/anchors.<side>.json` — which controls the capture specs
  crop, derived by `tim parity anchors` from the `controls` each finding names,
  resolved against that side's captured DOM, plus an insertion point wherever
  the other side has a control this one does not. Data rather than code is what
  stops a spec edit ever being needed to add element evidence to a finding.
- `shared/*/compare/` — the scripts of the mechanical comparison the DR2.1
  findings were first derived from. Nothing reads them now: the `deltas/*.json`
  they wrote went with the crawler in e36c4b6, findings come from the finding
  files under `shared/*/findings/` through `tim parity ingest`, and anchors and
  insertion points from each finding's `controls`. Kept as the record of that
  run.
- `shared/*/evidence/<side>@<sha>/manifest.json` — the index of one capture:
  every page shot and element crop, with its hash and size, plus every anchor
  that matched nothing and why. The report reads this rather than the
  filesystem, so a missing frame is a stated gap and not a broken image.

The `journey-builder/*` files each need their own `!` negation in `.gitignore`,
because the patterns above them ignore a run directory's contents twice over.
The `shared/*` entries need none — `!workareas/shared/` re-includes the whole
tree, and the only rules below it keep the pictures and page models out. Never
use `git add -f`.

Pixels stay out. 70 prototype screenshots are 16 MB at 1x and they regenerate
from a pinned commit in about three minutes.
