# EUDPA-130:  Animals Notification Validation

## Metadata
- **Type:** Story
- **Status:** In Dev
- **Priority:** Medium
- **Labels:** CAP-06.3
- **Parent:** EUDPA-125
- **Assignee:** Paul Hodgson

## Description

<p><b>As a</b> Trader<br/>
<b>I want</b> to review all the details of my notification before I submit it<br/>
<b>So that</b> I can check everything is correct and complete any missing sections</p>

<div class="panel" style="background-color: #deebff;border-width: 1px;"><div class="panelContent" style="background-color: #deebff;">
<p>Description</p>

<p>The "Review your notification" page displays the notification's details grouped into the same sections as the notification tasklist, each with a Change link, and blocks the trader from continuing until every mandatory field is complete.</p>
</div></div>

<p><b>Acceptance Criteria</b></p>

<p><b>AC1 –</b> <ins><b>Display review of my notification</b></ins></p>

<p><b>Given</b> I have navigated from the "Contact address for consignment" page<br/>
<b>When</b> I arrive on the "Review your notification" page<br/>
<b>Then</b> I should see my notification organised into the same sections as the notification tasklist: About the consignment, Description of the goods, Transport and arrival, Documents, Consignment parties, and Contact address<br/>
<b>And</b> each section should show a "Change" link taking me to the relevant page to edit it</p>

<p><b>AC2 –</b> <ins><b>Display entered values or missing fields</b></ins></p>

<p><b>Given</b> I am on the "Review your notification" page<br/>
<b>Then</b> each field should show the value I have entered<br/>
<b>And</b> any field I have not completed should show "Missing"</p>

<p><b>AC3 –</b> <ins><b>Inline error for an incomplete or invalid section</b></ins></p>

<p><b>Given</b> a section has one or more missing mandatory fields, or answers that are not valid (for example because the notification was created using old reference data or an old version of our service).<br/>
<b>Then</b> I should see an inline error message against that section, indicating what I need to do to complete the section</p>

<p><b>AC4 –</b> <ins><b>Error summary blocks continuing</b></ins></p>

<p><b>Given</b> one or more sections are incomplete or invalid<br/>
<b>When</b> I select "Continue"<br/>
<b>Then</b> I should see an error summary "There is a problem" listing each incomplete section<br/>
<b>And</b> selecting a link in the error summary takes me to the relevant page<br/>
<b>And</b> I should not be able to proceed to the declaration page</p>

<p><b>AC5 –</b> <ins><b>Continue to declaration when complete</b></ins></p>

<p><b>Given</b> all sections are complete<br/>
<b>When</b> I select "Continue"<br/>
<b>Then</b> I should be taken to the declaration page</p>

<p><b>AC6 –</b> <ins><b>Re-validate on Continue</b></ins></p>

<p><b>Given</b> every section was complete when I loaded the "Review your notification" page<br/>
<b>When</b> I select "Continue"<br/>
<b>Then</b> the service should re-run every section's validation against today's rules<br/>
<b>And</b> if any section now fails (for example a saved reference value is no longer offered, a saved date now falls outside the allowed range, or a saved commodity code no longer resolves)<br/>
<b>Then</b> I should be returned to the review page with an inline error against each affected section and an error summary "There is a problem" listing them<br/>
<b>And</b> I should not be able to proceed to the declaration page</p>

<p><b>AC7 –</b> <ins><b>Re-validate on submitting the declaration</b></ins></p>

<p><b>Given</b> I have progressed to the declaration page<br/>
<b>When</b> I confirm the declaration and select "Submit"<br/>
<b>Then</b> the service should re-run every section's validation against today's rules<br/>
<b>And</b> if any section now fails I should be returned to the "Review your notification" page with the same inline errors and summary as AC6<br/>
<b>And</b> the notification should not be finalised</p>

## Comments (1)

### Syed Islam (2026-09-22)
*Behaviour spec cross-check*

Checked against {{openspec/specs/live-animals/journey-pages/check-your-answers/spec.md}} and {{openspec/specs/live-animals/journey-pages/declaration/spec.md}}.


AC1 (sections + Change links) — covered by *REQ-CYA-001* and *REQ-CYA-004*.

AC2 (entered values / "Missing") — covered by *REQ-CYA-002*.

AC3 (inline error per section) — covered by *REQ-CYA-007*.

AC4 (error summary "There is a problem" blocking continue) — covered by *REQ-CYA-007*.

AC5 (continue to declaration when complete) — covered by *REQ-CYA-006*.


AC6 and AC7 (re-running every section's validation against today's rules on Continue / on submitting the declaration, catching stale reference data, expired date ranges, or a commodity code that no longer resolves) are *not* covered anywhere in the live-animals spec tree. Neither {{check-your-answers/spec.md}} nor {{declaration/spec.md}} (REQ-DECLARATION-002 only covers the unconfirmed-declaration-checkbox case) describes this re-validation trigger. If this behaviour is confirmed, it needs its own requirement added to the spec — it isn't drift from an existing one.
