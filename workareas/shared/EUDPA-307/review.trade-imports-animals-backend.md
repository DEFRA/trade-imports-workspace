## Summary
This is the source-of-truth PR for EUDPA-307: it adds the five missing `OutboxEventType` constants, corrects the two mis-mapped transitions (`SUBMITTED → AMEND` now emits `NotificationAmendmentRequested`; `AMEND → SUBMITTED` re-submission now emits `NotificationSubmissionAmended`), routes `createNotification`, `cancelAmendNotification`, `softDeleteNotification` and `copyNotification` through the locked `writeWithOutbox` path instead of bypassing the outbox, and moves `versionId` computation into `OutboxService` (counted from stored submission events, not persisted on `Notification`). Test coverage (unit + integration) was extended in lockstep for almost every new transition.

## Positive Observations
- Every one of the seven transitions in the ticket's table is correctly wired to its schema-specified event type, cross-checked against `OutboxEventType`, `NotificationService`, and `OutboxService` line by line.
- `versionId` is computed before the outbox row is written (not at publish time), satisfying the ticket's "count before the write" requirement, and correctly omitted (`@JsonInclude(NON_NULL)`) rather than serialized as `null`/`0` for non-submission events in the cases the implementation does handle.
- `NotificationServiceTest`, `OutboxServiceTest`, `NotificationIT`, `OutboxPollerIT` and `ReplayIT` were all extended for the new event catalogue, not just patched to compile.
- Prior mis-mapping fixes are internally consistent — no stray reference to the old `NOTIFICATION_SUBMISSION_AMENDED`-on-amend or `NOTIFICATION_SUBMITTED`-on-resubmit mapping remains anywhere in the diff.

## Test Coverage
- **Unit Tests:** Present — extensive additions in `NotificationServiceTest`, `OutboxServiceTest`, `OutboxEventTypeTest`, `GbnAgMapperTest`.
- **Integration Tests:** Present — `NotificationIT`, `OutboxPollerIT`, `ReplayIT` all updated for the new event counts/types, though `NotificationIT` misses an assertion on the AMEND→SUBMITTED resubmit event type (item 6 below) — the second of the ticket's two named mis-mappings.

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** The transition-mapping logic itself is correct and well-tested, but one correctness bug (`versionId: 0` leaking out on a never-submitted `NotificationEdited` save, item 5) and one performance gap (missing compound index for a query now on the hot path of every lifecycle transition, item 4) are real, ticket-relevant risks that should be fixed before merge.
