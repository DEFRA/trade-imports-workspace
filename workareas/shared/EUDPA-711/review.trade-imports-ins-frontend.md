## Summary
Adding an address now starts on a new "Choose an address type" page. The add form asks which roles the address can be used for. Destination, Consignee or Importer, and Branch addresses get a fixed United Kingdom country. The list becomes three MoJ sub-navigation tabs, with a Type column, a Type (role) filter and search by role. Edit keeps the stored roles. The stub mirrors the API's two new refusal rules, the tests answer OIDC discovery with nock instead of `vi.mock`, and Welsh drafts cover every new string.

## Positive Observations
- One function owns each type rule: `addressTypeRequiresUnitedKingdom` and `ROLES_BY_ADDRESS_TYPE`/`addressTypeOfRole`, which match the API's groups exactly.
- An unknown tab or Type in the request falls back safely and is logged with the organisation id.
- The stub's refusals mirror the API's validation word for word.
- Mocking moved to the network boundary (`answerOidcDiscovery`) in nine test files, as the house testing rules ask.
- `copy-parity.test.js` keeps the Welsh keys in step with the English ones.

## Test Coverage
- Unit tests: extensive. Gaps: the handshake session path with an unlisted fulfilment id (#86), the new list log lines (#95), and the lighthouse helpers in `auth-setup.cjs` (#78).
- Integration (fit) tests: cover the type page, tabs, filter, add and edit. Several local copies of shared helpers remain (#92, #93).

## Risk Assessment
**Overall Risk:** Medium
