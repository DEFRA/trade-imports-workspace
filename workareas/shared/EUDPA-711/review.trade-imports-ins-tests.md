## Positive Observations
- `InsJourney` owns the route through the type page, and every spec that adds an address goes through it.
- Every API seed now carries a role that matches its journey use, and the drift check compares roles.
- The isolated-organisation fixture removes cross-worker interference for the specs that count rows.
- The validation messages and labels match the frontend copy word for word.

## Test Coverage
- E2E: covers every acceptance criterion in the ticket. One real flake risk: the list pager reads rows before the next page loads (#51).
- Security: the new `role` list parameter is never sent through ZAP (#44).
- A11y: scans added for the type page at narrow and default viewports.

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** The pager race (#51) can let an absence check pass on a skipped page. The rest is duplication and readability.
