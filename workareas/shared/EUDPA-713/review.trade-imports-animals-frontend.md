## Summary
The PR makes three changes:
- Every records and document-upload call now sends `Trade-Imports-Organisation-Id`, taken from the verified session.
- The organisation is set for each request with `withOrganisationId`, in `set-context.js` and around the entry guard.
- A 403 on the fulfilments read is treated as not found.

The production wiring is correct. Most of the new tests cannot fail, because `headers.js` falls back to `'5900001'` when `NODE_ENV` is `test`.

## Positive Observations
- The organisation comes only from the verified session, through `organisationIdOf` and `sessionOrganisationId`, never from a request body.
- `headers()` refuses to call the backend when no organisation is set, so a missing organisation fails fast in production.
- The 403 is treated as not found, so the page does not reveal that another organisation's notification exists.

## Test Coverage
- **Unit tests: partial.** There are tests for the header, the 403 and which claim wins, but two problems undercut them:
  - Because of the test fallback in production code, removing any of the organisation-setting code leaves every test green.
  - The claim-order test makes `organisationId` win over `currentRelationshipId`. The ticket says the owner is `currentRelationshipId`.
- **Integration tests: missing.** No route-level test proves the session's organisation reaches the backend.

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** Production behaves correctly. But a test-only branch in production code hides regressions, and the frontend does not log the 403.
