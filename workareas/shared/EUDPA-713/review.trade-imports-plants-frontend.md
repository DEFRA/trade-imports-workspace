**PR:** #139
**Commit reviewed:** baffe546d79377675924fcd7d6d492dc9dcdd4f2

## Summary
The PR mirrors the animals frontend:
- Every records call sends the organisation header.
- The organisation is set for each request in `set-context.js` and around the entry guard.
- A 403 is treated as not found.

It has the same `NODE_ENV=test` fallback, so its tests cannot fail either. It also writes the claim rule out twice instead of using the animals `sessionOrganisationId` helper.

## Positive Observations
- The organisation comes only from the verified session.
- If no organisation is set, the call throws in production instead of reaching the backend unscoped.

## Test Coverage
- **Unit tests: partial.** The organisation tests depend on the test fallback, and nothing tests which claim wins.
- **Integration tests: missing.** No route-level test proves the session's organisation reaches the backend.

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** The same problems as animals-frontend. It has also drifted from its twin, and it has no delegation, which the ticket says plants needs.
