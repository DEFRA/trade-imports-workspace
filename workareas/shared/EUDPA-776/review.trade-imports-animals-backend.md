## Summary
Removes the `consignment` party from `NotificationBase` and stops `NotificationService` copying it. Also removes `issuer` from the GBN-AG `ExchangedDocument` record, so a submitted notification's event no longer carries the consignment contact. The production change is small and correct. What is left behind is a dead test fixture, its unused imports, and stale docs and Javadoc. The AC "a new notification saves no consignment party" has no test proving it.

## Positive Observations
- `TradeParty.from(ConsignmentParty)` is kept, rightly: other parties and the permanent address still use it, even though the ticket's tech notes said to remove it.
- Spring Boot's default Jackson ignores unknown properties, so an older frontend that still sends `consignment` is accepted. No migration is needed, as the ticket says.
- Every consignment assertion in the four test classes was removed in step with the field.

## Test Coverage
- Unit tests: adequate for the mapping. `GbnAgMapperTest` proves issuer is absent only on an empty draft, and its title names a condition that no longer exists.
- Integration tests: none proves the backend accepts a save that still carries `consignment` and stores no `consignment` key (#4).
