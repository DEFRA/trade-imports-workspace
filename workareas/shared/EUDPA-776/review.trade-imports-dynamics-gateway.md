## Summary
- **v0.4.0 stream:** adds a fourth PIMS stream with no `issuer`: the `gbnagv4` records, the V4 mappers, `PimsEventV4` and `mapToV4`, all wired into the SQS listener.
- **v0.3.0 change:** v0.3.0 now always leaves `issuer` empty.
- **Inbound record:** the inbound `ExchangedDocument` drops `issuer`.

The new stream is correct against the v0.4.0 schema. But it is a near-verbatim copy of v0.3.0 (#35), and its output is barely tested: `mapToV4` is never called directly, and the IT checks only metadata. The PR also deletes tests for listener behaviour it keeps, and three docs still describe three versions.

## Positive Observations
- Every v4 record field matches `gbn-ag-pims-v0.4.0.schema.json`; the only data change from v3 is `issuer` dropped from `PimsExchangedDocument`.
- Names follow the v2/v3 pattern exactly (`-v4` message id suffix, `0.4.0` schema tag), and `sonar.cpd.exclusions` already covers `gbnag*`.
- **Deploy order:** a not-yet-updated backend still sends `issuer`, and production ignores it. Production uses Spring Boot's auto-configured `ObjectMapper`, which ignores unknown fields, so `ignoreUnknown = false` does not reject the event.

## Test Coverage
- Unit tests: partial. V4 mapper tests are copies of V3. `PimsPayloadMapperTest` never calls `mapToV4` (#28). Listener tests lost the v0.1.0 failed-counter and mapper-throws coverage (#12).
- Integration tests: partial. Only v0.4.0 metadata is checked. Nothing proves on the wire that v0.3.0 and v0.4.0 carry no `issuer` (#9), or that an event still carrying `issuer` is accepted (#33).

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** A new outbound message to PIMS whose payload is not tested end to end, with deleted coverage for retained behaviour.
