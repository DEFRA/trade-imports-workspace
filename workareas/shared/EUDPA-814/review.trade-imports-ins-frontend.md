## Summary
Adds a hidden sign-in through the real Defra ID (IDM) beside the stub sign-in: an `idm` config group, an `idm` Bell strategy, and start, callback, signed-in and signed-out routes that are served only when `IDM_OIDC_CONFIGURATION_URL` is set. To support it, discovery, token verification and metrics now take an identity provider. `verifyToken` now picks the signing key by `kid` and checks audience and issuer for IDM tokens.

## Positive Observations
- The stub sign-in is untouched. The IDM routes do not clash with the stub or real routes, and a test proves they return 404 when no IDM discovery URL is set.
- Choosing the JWKS key by `kid` fixes a latent bug: the old code took the first key served. Audience and issuer are now really checked for IDM tokens; before this PR they were passed where `@hapi/jwt` ignores them.
- What IDM returns is kept under its own session key. No service session cookie is set.
- The signed-in page matches the routing proxy's page row for row.
- The RS256 signing helper is shared by both test files, with no local copies.

## Test Coverage
- Unit tests: partial. verifyToken's kid, audience and issuer paths are well covered. Discovery and the metrics for the IDM provider are not proven (#7, #49), and the claims tests check names, not values (#51).
- Integration tests: partial. Every callback test injects credentials and skips Bell, so the token exchange and `profile()` mapping never run (#49). The "service session left alone" test cannot fail on its cache half (#50). The AC's error logging is not asserted (trade-imports-workspace #11 / #33).

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** The happy path works and the stub is untouched. However, a refusal sent to `/auth/signed-out` is shown as "Signed out" (#52), an unreachable IDM at startup stops the whole frontend in CDP (#19), and CDP dev and test have no IDM settings yet (#1).
