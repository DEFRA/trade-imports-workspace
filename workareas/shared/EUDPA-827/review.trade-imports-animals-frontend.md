## Summary
The live animals party pickers now show eight addresses a page with GOV.UK pagination below the results, a "Selected address: <name>" inset above them, and paging links that carry the search term, the page, the chosen address and the trail. A small client component (`PickerPagingSelection`) copies a newly ticked radio into the paging links, and a page past the last serves the last page and logs it once.

## Positive Observations
- Of the two frontends, this is the more complete. Paging links carry the trail. Page parsing, the ellipsis, a search going back to page 1 and a refused save keeping its page each have a unit test.
- The past-the-last-page fallback logs once at info with `journeyId`, `partyId`, `requestedPage` and `servedPage`.
- The English and Welsh copy is added and tested exactly, and the page-design doc is updated alongside the code.

## Test Coverage
- Unit tests: broad, but several titles claim more than they prove (page-numbers, pagination index, controller, address-picker template), and some rules have no test: the radio-only guard, the page-1 link with no page parameter, the row id page offset, and a failed save keeping its page.
- Integration tests: the fit spec covers 8 a page and the chosen address across pages. It has no browser test that searches and then changes page (AC 2), and the role filter is only checked on the last page.

## Risk Assessment
**Overall Risk:** Medium
**Rationale:** The behaviour meets the acceptance criteria, but a newly ticked address only survives a page change with JavaScript on, and several tests cannot fail for what their titles claim.
