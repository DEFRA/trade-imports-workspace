## Summary
The three high-risk plants address-book pickers (consignor, place of destination, consignment contact) page at eight with GOV.UK pagination, name the chosen address above the results, and read the page from the query or the posted form. The rules mirror the animals twin in one `pagination.js`, but the paging links leave out the trail, and several POST and pagination rules have no tests.

## Positive Observations
- The paging rules (8 a page, none at 8 or fewer, last page served and logged when a page past the end is asked for) match animals, and `describePaging` runs them for all three pickers.
- `results.test.js` proves the pagination renders straight after the results and is absent when one page holds everything.
- The README and architecture doc now say the pickers page.

## Test Coverage
- Unit tests: GET paging is covered. The POST page rules have no tests (a refused or failed save keeps its page, a search goes back to page 1, a bad page value reads as page 1), and neither do the ellipsis window, the search term in paging links or the row id offset. Some tests branch on `wholeCount`, and the role-filter listing test does not compare against the role's ids.
- Integration tests: the fit journey proves paging only for consignment contact (14 addresses). Consignor (8) and place of destination (6) never page. `openLastPageOfPicker` clicks nothing when there are no page links, and still passes.

## Risk Assessment
**Overall Risk:** High
**Rationale:** Paging links drop the `from` trail, so a trader who opens a picker from check your answers and changes page loses the way back. On top of that, several new POST rules have no tests.
