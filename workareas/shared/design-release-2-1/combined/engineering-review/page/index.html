Questions the handover asked

Is the backend fetch timeout and retry needed in CDP?

No. Every connect timeout in the build's logs is to Docker Desktop's host-gateway address for host.docker.internal, on ports 8085 (animals backend) and 8091 (plants backend). There is no CDP evidence. No log exists from after the fix either, so whether it fixed anything locally is unproven.

Does it behave behind CDP's HTTP_PROXY?

It does not bypass the proxy. With HTTP_PROXY set, backend calls use built-in fetch and the global proxy agent, as before. That also means the 2 second bound never applies in CDP, and the retry fires only if the socket to the proxy itself fails. A backend the proxy cannot reach comes back as a 5xx or a tunnelling error, and neither is retried.

In CDP the change is effectively dead code. It also puts CDP on a different fetch and FormData path from every test environment (finding rank 5).

Retry safety. Connect timeout and connection refused happen before any bytes are sent, so a create, submit or upload cannot be duplicated. ETIMEDOUT is the exception (finding rank 25).

Should it exist?

Verdict: remove it from production code in both frontends.

  • Revert backendFetch to plain fetch. Delete test/setup-backend-fetch.js, backend-fetch.real.test.js and the retry unit tests.
  • Keep stackWithCauses error logging. It is a real diagnostic gain on its own.
  • If you want a local bound, put it on the global dispatcher behind a stack-only flag. Retry only on connect-refused and connect-timeout, ideally only for idempotent methods, and test it against real sockets.

Verifier's correction. The retry decision is unit-tested: backend-fetch.test.js:73-108 fails if the retry branch is removed. What no test covers is the 2 second bound and the agent.

FIT global timeout raised from 900s to 1500s: is it hiding flakes?

No. The suite grew from 455 to 529 tests and from 12.7 to 18.0 minutes, with 0 flaky and 0 retries. The raise absorbs set-up cost: one-page assertions about submitted or amending notifications each drive a full journey in beforeEach. Main was already using 85% of the 900s budget. See finding rank 6.

Did the flake fixes weaken any assertion?

  • test.slow() additions: each is a one-line addition with no step or assertion removed. Each task now saves back to the Overview, which adds two page loads per task.
  • Dashboard pagination seeded: 26 creates now go through the frontend form client instead of 26 button clicks. Every assertion is unchanged, and this is set-up for a one-page assertion, which the rule allows.
  • Address-book beforeEach reorder: skip first, walk after. Steps and all four assertions per test are identical to main.
  • Date checks widened to accept yesterday: these do hide a real product bug. The plants frontend runs with TZ=Europe/London and parses the backend's zone-less date-time as London time. The confirmation, Date submitted and Date created pages show the previous calendar day between 00:00 and 01:00 BST. See finding rank 3.

Leaked commit 65b6afc on backup/inc-107-leaked-commit

Superseded by 02dd6bc, which landed the same document-card test with alphanumeric references and an existing JPG fixture. Nothing in it is needed. The branch is safe to delete (finding rank 24).

Side note: the backend rejects non-alphanumeric document references, but the animals frontend has no matching format rule. A trader typing UK-123 would get a backend 400 rather than a page error. Not yet verified beyond the file-type check running first.
