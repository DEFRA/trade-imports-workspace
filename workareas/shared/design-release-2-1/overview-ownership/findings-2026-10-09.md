# Who owns the overview, review, declaration and confirmation pages

Agent research, 9 October 2026, read from trade-imports-animals-frontend `origin/main` at 4c2119da. Paths are under
`src/server/app/`.

## Answer

- **Owned by the live-animals set:** the overview, check answers and review, the declaration and the confirmation. Each
  has its own feature folder in `sets/live-animals/journeys/linear/features/` (`hub/`, `check-answers/`,
  `declaration/`, `confirmation/`).
- **Shared across every set in the animals frontend:**
  - the status strip above the heading (`shared/layout.njk:95-100`, `shared/kit.js:33-58`, `journeyStrip` copy)
  - the "Copy as new" and "Delete" wording (`shared/copy.en.js` `notificationActions`), which the dashboard also uses
  - the notification statuses (`engine/persistence/records.js:3-6`; `real/status.js:8-20` throws on an unknown status)
  - submit (`engine/write/submit.js`)
  - the 404 path (`engine/journey.js:104-108`)
- **Plants:** has its own platform copy, so it's unaffected.
- **INS frontend:** renders none of these pages. Its dashboard links to the overview, or to the review when the status is
  SUBMITTED (`features/dashboard/view-model/list.js:89-95`).
- **Rules:** `docs/architecture.md` says a journey owns its pages, copy and task rows, and `shared/` doesn't depend on
  any set. `.dependency-cruiser.cjs` has the `set-isolation` rule at :60-69 and `no-l2-to-sets` at :13-22. So the
  germinal set copies these pages and shares only the layout, kit, copy, engine and statuses.

## The theme's rows

**Stay inside the set, no shared risk:**
- overview regions and the reason rename (inc-098)
- the transit task only when required (inc-100)
- review headings (inc-101)
- review rows (inc-102)
- arrival and transit statuses (inc-103)
- the commodity card (inc-104)
- identification (inc-106)
- documents (inc-107)
- addresses (inc-108, inc-109)
- the confirmation page (inc-115)
- tests (inc-117)

**Need care:**
- **Review end buttons (inc-110) and view header actions (inc-112):** "Copy as new" and "Delete" are shared wording.
  Reuse it, or add new keys to the feature's own copy. Rewording the shared keys changes the dashboard too.
- **Submitted view header (inc-111) and draft view header (inc-187):** don't change the shared strip in place. Turn it
  off with `journeyStrip: null` and build the header in the set's template.
  - Not-found is caught in the controller, not in the engine.
- **Declaration with no status strip (inc-114):** override locally with `{ ...kit.base(...), journeyStrip: null }`,
  which keeps the concurrency token. Don't change `layout.njk` or `kit.js`.
- **Submission date, outstanding items, "Submitted action required" (inc-113), and later "Completed" (inc-116,
  blocked):** this is the one real shared change.
  - New statuses go into the platform (`records.js`, `real/status.js`, the stub, STRIP_STATUS, shared copy) and the INS
    dashboard (`list.js:92` sends only SUBMITTED to the review).
  - Make the change add-only, and map each status in the frontend before the backend sends it, because the frontend
    throws on an unknown status.
  - The backend, animals frontend and INS land on one branch name.

## Ways to change shared parts safely

- **The strip:** it's a view variable, so a page can switch it off and draw its own header.
- **Statuses:** add-only, with the frontend mapping first and the INS dashboard in the same branch.
- **Set-specific wording:** goes in the feature's own copy, not `shared/copy.en.js`.
- **A per-set layout:** would mean editing every template's `extends` line. The journey config's `LAYOUT` key isn't a
  switch.
