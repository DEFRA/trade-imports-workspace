# Accessible autocomplete: rollout state and the DR2.1 rows it touches

Agent research, 9 October 2026. Read from each repo's `origin/main`. Full detail as the agent returned it.

## Answer

The rollout has not landed consistently.
- EUDPA-635, "Add HMRC accessible-autocomplete wrapper", is In Dev. Its PR, animals-frontend #395 (`d79f0cf0`, 8 Oct), is open and unmerged, with FIT and E2E failing.
- On animals main, three pages use the component: origin, port of entry and transit countries. The three import-reason exit fields are still plain selects.
- #395 leaves out the transhipment Destination country and the address-country selects.
- trade-imports-ins-frontend doesn't use the component at all. Plants is consistent.

## The component

- **Package:** alphagov `accessible-autocomplete` 3.0.2 (animals `package.json:77`, plants `:75`), with a wrapper adapted from HMRC Frontend.
- **Client JS:** `src/client/javascripts/components/accessible-autocomplete.js`, which calls `enhanceSelectElement`.
- **Macro:** `appAccessibleAutocomplete` (`src/server/common/components/accessible-autocomplete/macro.njk:29`). It wraps a native `govukSelect`, which is the no-JavaScript fallback.
- **No ADR.**
  - House guidance: `.claude/skills/prototype/references/match-the-design/nearest-equivalent.md:14-19` says use `govukSelect` for up to about 20 options and the autocomplete above that.
  - DR2.1's c-006 keeps "an accessible-autocomplete over a native select" and overrules the prototype's custom search.
  - `components-we-have.md:69` gives the version as 3.0.1, which is stale.

## DR2.1 rows, split into component mechanics and content

- **inc-009 (Country of origin search box).**
  - Mechanics:
    - no list on focus (`showAllValues:false`), which reverses today's openspec REQ-ORIGIN and EUDPA-635 AC4/AC12
    - contains-matching with the match in bold
    - a search icon button named "Search"
    - live-region wording
  - Content: placeholder "Search for a country", no hint, Welsh strings, results label.
- **inc-027 (port and transit searches).**
  - Mechanics: a "Search" button and the typed text in bold.
  - Content: options labelled "name - code".
- **inc-030 (transit countries).**
  - Mechanics: add on pick and remove in place, through a new client script; the no-JavaScript fallback stays.
  - Content: the added and removed announcements.
- **Content only:**
  - inc-026: arrival hint and placeholder
  - inc-174: transit list with subdivisions
  - inc-175: subdivision labels
  - inc-007: port order and exit labels
  - inc-173: stub lists
  - inc-006: destination subdivisions
  - inc-008 and inc-040: private transporter country, which stays a select
  - inc-078 and inc-082: INS add-address Country, a select with no type-ahead asked for
- **inc-020 (reason page copy).**
  - "Select one" with no divider conflicts with #395's "Select a country" and "Select port of exit".
  - The prototype shows these fields as plain selects, so EUDPA-635 goes beyond DR2.1 here.
- **inc-089 (place of origin picker).** A country search that filters a table. It is a possible second use of the component.
- **inc-014 (commodity as-you-type).** Not a select, so the component doesn't apply.

## Gaps and risks

1. #395 is unmerged and its FIT and E2E checks are red.
2. The transhipment Destination country is outside EUDPA-635.
3. The animals party add/edit Country (~250) is plain, with no ticket.
4. The INS address book Country (~250) is plain, the package isn't installed there, and there is no ticket.
5. The private transporter country (~33) is borderline.
6. #395's AC15 swaps the arrow for a decorative CSS magnifying glass on every instance. That conflicts with inc-009 and inc-027, which want a real "Search" button.
7. Whole list on focus: EUDPA-635 and the spec say yes, but inc-009 (c-009) says no.
8. No ADR or best-practices page records the component as the house choice.
