## 0. Decisions

1. **Scope of the format change: option text only; the check-answers summary keeps `'<name> (<code>)'`.** The ruling (ruling-sam-2026-10-09-pm claims 2/3/45) is about how a *search list* reads; the AC names the options and the search box only. The port of exit increment already set this precedent (its options read `- `, its check-answers row still reads `(GB DVR)` — `check-answers.test.js:932`, `check-answers.fit.spec.js:243`, tests repo `hub-groups-and-cya-rows.spec.ts:104`). So `ports.label()` stays as it is in both frontends. Rejected: changing `label()` too — it changes the review/check-answers pages, which no AC asks for and which nothing in DR2.1 cited here governs.
2. **Animals port of entry reuses `ports.portOptions()`** and adds `selected` on top, instead of keeping its own template string. One place owns the option label for both animals port questions. Rejected: just editing the template string in the controller (keeps two copies of the format).
3. **Plants splits its single `displayName` into two**: `summaryLabel` (`'<name> (<code>)'`, used by `label()`) and `optionText` (`'<name> - <code>'`, used by `portOptions()`), mirroring animals. Rejected: changing `displayName` (would change the plants check-answers row, see decision 1).
4. **Tests repo `portLabel()` becomes `'<name> - <code>'` and `portOfExitLabel()` is removed** — both port lists now read the same, so one helper serves port of entry, port of exit and place of landing; `port-of-exit-list.spec.ts` switches to `portLabel`. Rejected: keeping two identical helpers.
5. **The animals E2E integration proof uses Port of Dover** (the AC's own example) instead of Aberdeen Harbour; the plants E2E proof is a new test that also uses Port of Dover. Journey helpers and other specs that merely need *a* port keep their port and only follow the new label.
6. **No-JS proof (AC5) lives in the frontends' FIT suites, not the tests repo.** Animals already has `port of entry without JavaScript`; it gains an option-text assertion. Plants has no no-JS place-of-landing test; one is added following the plants exemplar that opens a no-JS browser context with the signed-in storage state (`cancel-amend.fit.spec.js` "without JavaScript"). The tests repo journeys to these pages pass through JS-only type-aheads (origin), so a tests-repo no-JS run would need a new no-JS journey path — out of proportion; the E2E specs instead assert the native select's option text under JS, which is the very element a no-JS user gets. Rejected: a new tests-repo no-JS journey.
7. **`point-of-entries.ts` display strings follow the new format** although nothing reads `display` today, so the constant does not document a label the service no longer shows.
8. **Client component comment** (`accessible-autocomplete.js` lines 27-28 animals / 26-27 plants, both repos): the second sentence, which states the old `"{name} ({code})"` format, is deleted, leaving `// Case-insensitive substring match over the option labels.` Settled by attempt 1's review (explanatory comments that restate data formats go stale). Rejected: rewording it to the new format.
9. **FIT checks run `test:fit:ci`** (ports 3050/3053), never `test:fit` — the leased stack holds 3000/3003. This was attempt 1's only failure.
10. **No new doc comment on plants `portOptions`** (review removed it in attempt 1); the function name and `optionText` helper say it.
