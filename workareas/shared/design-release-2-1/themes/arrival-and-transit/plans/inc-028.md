## 0. Decisions

1. **Error wording: "Select a means of transport to the port of entry"** (the row's AC, quoting prototype p6-039/p6-040 and specs p2-081). The sibling branch's inc-018 shipped "Select the means of transport to the port of entry", and the workspace spec (REQ-ARRIVAL-006) records that wording, but this branch has neither. The row cites the prototype verbatim, so it wins. Rejected: keeping "the" to make the eventual EUDPA-693 merge clean. Welsh: "Dewiswch gyfrwng cludo i’r porthladd mynediad" (indefinite, so `cyfrwng` takes the soft mutation after `Dewiswch`). Rejected: inc-018's "Dewiswch y cyfrwng cludo…", which is the definite form.
2. **Same shape as inc-018, so the two branches merge with a one-line conflict.** The copy key is `portOfEntry.errors.meansOfTransportRequired`. In `validate.js` the helper is named `meansRule(stored)`. The stored reading keeps `oneOf` with no required check, so a page never answered opens with no error and the overview and review still judge completeness from the obligation (`meansOfTransport` is already `status: 'mandatory'`). The submit reading uses `requiredOneOf`. Test names are inc-018's, word for word, because the workspace coverage.json already links SCN-ARRIVAL-006-A and SCN-ARRIVAL-011-A to those names (they currently dangle on this branch).
3. **A tampered means of transport now shows the required message, not "Select a valid option".** `requiredOneOf` uses one message for blank, absent and unknown values. Inc-018 accepted the same thing. The existing unit test and FIT test for an out-of-list means change their expected message to match.
4. **Save and return to overview needs no new code.** `lib/validate/run.js` already drops blank-or-absent errors when `allowMissing` is set, including `string.empty` from `requiredOneOf`. Both controllers already pass `allowMissing: kit.isHubExit(request)` (inc-003). An impossible date is still refused (`any.invalid` is kept). This row adds tests for those behaviours only.
5. **Navigation needs no new code.** `kit.nextTarget` already handles every case. `exit=hub` goes to the overview. `?change=1` goes to the review (`notification-view`). Inside the opening run it goes to the run's next step: transit countries for RAILWAY/ROAD_VEHICLE, otherwise the transporter list, because the transit step's gate fails. Outside the run, `nextInTaskRow` goes to the hub, since "Arrival details" and "Transit countries" are separate task rows. Inc-002 built this, and `opening-run.test.js` and `overview-task-return.spec.ts` already pin it. The claim holds. This row adds the missing proofs: the in-run sea case, a Change link from the review on arrival details, and transit with countries on Save and return.
6. **"Arrival details is not Complete" after Save and return with no means** needs no obligation change. The obligation is already mandatory. The E2E test proves it.
7. **E2E for "means required" goes in `tests/animals/e2e/pages/arrival-details.spec.ts`. E2E for "Save and return" goes in `tests/animals/e2e/features/soft-save.spec.ts`**, beside the existing arrival test there. The review Change-link leg is added to `tests/animals/e2e/features/change-from-cya.spec.ts` as a third leg, not a new spec.
8. **The obsolete E2E test "saves a draft and returns to the overview when submitted empty" is deleted**, not re-pointed. Its behaviour (an empty Save and continue succeeds) is now false. Its replacement is the new refusal test.
9. **The walk helper `walkOpeningRunToRolesAndAddressesWithoutCph` picks "Air"** before Save and continue on arrival details. With Air, the run skips transit countries and lands on the transporter list, as the helper already expects. Rejected: Road, which would put the transit page into the walk.
