## 0. Decisions

1. **The browser title gets its own copy key. The H1 stays the question.** The row's AC changes only the browser title ("Transit countries - Import notification service - GOV.UK"). No other row on this backlog changes the H1. inc-174 is the only other open transit row, and it is about the search list. Today `kit.base(copy.title, …)` makes the browser title equal the H1, "Which countries will the consignment travel through?". Add `transitCountries.pageTitle: 'Transit countries'` (Welsh `'Gwledydd tramwy'`, the phrase the Welsh copy already uses in `errors.someNoLongerAvailable`). Pass `copy.pageTitle` to `kit.base`. The template keeps `copy.title` for the H1. The layout already adds the `Error: ` prefix whenever `errorSummary` is set (`shared/layout.njk` line 23), so the error title needs no code. Rejected: changing `title` to "Transit countries", which would also change the H1 and the page-object heading, and which the AC does not ask for.
2. **The Back link follows the opening-run state that inc-002 uses. No marker is added to the address** (ruling `sam-2026-10-09` p1-198). Inside the opening run, transit countries is reached only by Save and continue on arrival details: `RUN_STEPS` puts arrival details directly before it. Outside the run, arrival details returns to the overview (inc-002, inc-028), so the trader can reach the page only from its overview task. So: `inOpeningRun` true → Back goes to arrival details (`port-of-entry`). Otherwise Back goes to the overview. Rendering the overview completes the run (`hub/controller.js` → `completeOpeningRun`), so a trader who leaves the run for the overview and then opens the task gets the overview, as AC3 requires.
   - It is built as one generic helper in `shared/kit.js`, `runBackLink(request, previousSlug)`, beside `runTarget`. It takes the slug, so `shared/` gains no live-animals knowledge.
   - Rejected: deriving "the previous run step" from the journey's `RUN_STEPS`. That would need a new export shape on `configureJourneyFlow`, which is a flow-machinery change for a single caller.
   - Rejected: reading the `Referer` header. Browsers can strip it, and the ruling forbids address markers.
3. **What "does not apply" means is read from scope, not from the raw answer.** `scope.has('transitedCountries')` is true exactly when the obligation's `includesGate` admits RAILWAY or ROAD_VEHICLE (`obligations/sections/transport.js`). Air, Sea and no saved means all leave it out of scope, so the page follows the model and does not copy its list. The redirect target is `hubPath(journeyId)`. Rejected: a local `['RAILWAY','ROAD_VEHICLE']` list, which would be a second copy of the gate.
4. **Every POST is guarded, not only Save and continue.** AC5 says "submitting the transit countries form … saves no countries and goes to the overview". The form has four submit routes: Add, Remove, Save and continue, and Save and return to overview. All four go to the overview without rendering or committing when the page does not apply. The guard runs first in `post`, before `validation.fromPayload`. Only one route can save, so this is the simplest rule that holds for all four.
5. **The guard wins over `?change=1`.** A Change link from the review cannot reach a page that is out of scope, because the review shows no transit row then. The AC says "goes to the overview", so the redirect target is the overview in every context. Rejected: `kit.exitTarget`, which would send a `?change=1` request to the review.
6. **The empty-list sentence is deleted, not hidden.** Remove the `{% else %}` branch from `transit-countries.njk`. Remove the `transitCountries.empty` key from `copy.en.js` and `copy.cy.js` together, so copy-parity stays green and no dead copy is left. `hasCountries` stays in the view model, because the template still uses it to decide whether to draw the table.
7. **The Back link in a Change context is unchanged.** It stays the overview (`hubPath`), as it is today. No AC covers it, and inc-028 changed only where the save goes.
8. **AC5 proof lives in unit and FIT. The tests-repo E2E covers AC1–AC4 and AC6.** To reach AC5 through a real browser, the means has to change in a second tab while the transit form is open. That is done in the self-hosted FIT spec (raw locators, `page.context().newPage()`). The unit test asserts the exact "nothing saved" (`after` equals `before`). An E2E copy would add a second-tab page-object pattern the tests repo does not use anywhere else. AC1–AC4 and AC6, which are the parts a trader meets in a normal session, each get an E2E proof against the real stack.
9. **A new journey helper `walkOpeningRunToArrivalDetails()` in the tests repo.** It is the first part of `walkOpeningRunToRolesAndAddressesWithoutCph` (create the notification, then origin through additional details), extracted so the in-run Back-link test can stop on arrival details and choose Road. The existing walk then calls it. The walk's behaviour does not change.
10. **Claims checked against the live tree.**
    - Page address: it stays `transit-countries` (`page.js`), as the notes say.
    - Today's Back link: `hubPath` always (`transit-countries.controller.js` line 60). AC2 is therefore new behaviour.
    - Today's empty state: the sentence is rendered (`transit-countries.njk` line 56). AC6 is new.
    - Today's browser title: the H1 question. AC1 is new.
    - Today, opening the page with Air, Sea or no means saved renders the page. Nothing in `flow/dispatch.js` or `entry-guard.js` gates it. AC4 and AC5 are new.
    - inc-002 (`journey-foundation`) is `done`, and its mechanism is `kit.runTarget` → `inOpeningRun`.
    - Every claim holds. No contradiction was found.
