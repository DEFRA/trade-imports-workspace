## 0. Decisions

1. **Route.** The redirect is a page that decides for itself what to show when it has nothing to ask. `docs/flow-and-gates.md` ("That page decides for itself what to show someone who has answered nothing else") and `sets/live-animals/docs/journey-flow-and-gates.md` (the consignment-details page redirects when it holds no line) both name this as the house pattern. So it is a controller change, not a change to `flow/entry-guard.js`. That guard is the journey-wide deep-link policy, which answers "has this journey started?", not "does this page apply?". Rejected: a new per-page clause in `entryGuardTarget`, which would put one page's obligation knowledge into the journey-wide guard. The row is a page change through frontend-change's general route ("change the frontend", L4 feature), read against the flow-maintenance guard rails. No recipe for adding a field, page, section or collection applies.
2. **The applicability rule's owner.** Whether transit countries apply is decided once, by the `transitedCountries` obligation's `includesGate` on `meansOfTransport` over RAILWAY and ROAD_VEHICLE (`obligations/sections/transport.js:96-111`). An unset means fails `values.includes(undefined)`, so "none saved" is out of scope as well. The controller reads that decision through `scope.has(...)` on the obligation the page already declares in `meta.collects`. `docs/scope-and-wipe.md` "Consumers" gives this as the stated design: "Controllers use `scope.has()` to avoid rendering, validating or committing hidden fields". The controller never re-derives the rule from the means codes. Rejected: importing `transitedCountriesApplies` from `check-answers/view-model/applicability.js`, which would tie a transport controller to the review's view-model. Also rejected: checking `meansOfTransport` values in the controller, which would make a second owner of the rule.
3. **The browser title is a new copy key beside the heading.** The page's H1 stays `copy.transitCountries.title` ("Which countries will the consignment travel through?"). The browser title is a separate key in the transit-countries copy namespace: "Transit countries" in English, "Gwledydd tramwy" in Welsh, matching the Welsh hub row title already in `hub/copy/copy.cy.js:49`. The controller passes it to `kit.base()` in place of the heading. `shared/layout.njk:18` already adds the "Error: " prefix when `errorSummary` is set, so the error-state title needs no new code. Rejected: reusing the hub row's copy key, which belongs to another feature (the invariant says a set-specific string goes in the feature's own copy). Also rejected: renaming the heading key, which is out of scope and would change vocabulary across the feature. Design source: the prototype spec `prototype-specs/e2e/transport-and-arrival.fit.spec.js:88` asserts `toHaveTitle('Transit countries - Import notification service - GOV.UK')`.
4. **The redirect covers every POST path, not only Save and continue.** The criterion is "submitting the transit countries form ... saves no countries and goes to the overview". Add country, Remove, Save and continue and Save and return to overview all submit the form, so each one goes to the overview and commits nothing. The check runs once, at the top of the GET and POST handlers, before the payload is read or dispatched. Rejected: guarding Save and continue alone, which would let Add and Remove re-render a page that does not apply.
5. **The redirect target** is the overview (`hubPath`) in every state, the opening run included. The prototype (`transport-and-arrival.fit.spec.js:76`) sends the user "to the hub". Rejected: `kit.nextTarget`, the run's next step, because the criteria name the overview.
6. **One read of the state on POST.** `post` now needs the current state for its scope check. It reads it once and passes it to the Add, Remove and Save and continue paths, so their own state re-reads before rendering are dropped. This is a bounded tidy-up inside the touched functions, which are all in this file. The save-failure fallback keeps its own read. Rejected: a second, extra read in `post`, which would leave three reads of the same state on one request.
7. **Logging.** The redirect changes an outcome (a state switch away from the page), so it logs once at info, from one place, with the ids support searches by. `consignment-details.controller.js:86-93` is the exemplar. Section 13 has the detail.
8. **What each POST test can observe, and how "saves no countries" is proved.** The write path purges out-of-scope fulfilment on every commit (`engine/write/pipeline/canonical.js:23`, `purgeFulfilments(...)`; `docs/scope-and-wipe.md`: a value that leaves scope is deleted). So with Air saved, a committed transit list is purged, and the stored answers after a submit equal those before it whether or not the controller checks scope. Comparing stored answers proves nothing, and no test may claim it does. Outside the opening run, `kit.nextTarget` for this page already gives the overview (the page's task row has one page, `flow/navigation.js:55-60` falls back to `hubPath`), so a plain Save and continue, or Save and return to overview, also lands on the overview without the check. Each POST test therefore uses a submit whose outcome changes when the POST check is removed:
   - **Add country** and **Remove**: without the check they re-render the transit page at 200 with the "added" or "removed" status. With it they redirect to the overview.
   - **Save and continue in an active opening run**: without the check it commits and goes to the run's next step, the transporters page (`flow/run.js` `RUN_STEPS`, where transporters has no gate). With it, it goes to the overview.
   - **Save and continue and Save and return to overview with saves refused**, through `driveHandler`'s `saveFailure` seam (`engine/test-support.js`, `recordsRejectingSaves`), which makes every `records.replaceFulfilment` throw. `state.commit` always reaches it for a non-empty canonical patch (`canonical.js:23-28`, `engine/journey.js:116`). Without the check the attempted commit fails and the page answers 500 with the recoverable error. With it the response is the overview redirect. This is the proof that **no save is attempted**: a redirect under refused saves can only come from a path that never commits.
   - "No countries are stored afterwards" is already guaranteed by the purge, so it is recorded as such and not asserted as this change's proof.
   The FIT and E2E two-tab tests reach the page from the overview, so they are not in an opening run. They use **Add country** as the submit from the stale tab, so that without the check the transit page re-renders with France listed instead of the overview. Rejected: Save and continue from the stale tab, which lands on the overview with no error summary with or without the check. E2E in the tests repo also covers the browser title (normal and Error) and opening the page by its address with no means, with Air and with Sea saved.
9. **Claims checked against the live tree.** The row says main has no title key and no redirect: confirmed (`transit-countries.controller.js:60` passes `copy.title`, and GET and POST have no scope check). The row also says SCN-TRANSIT-COUNTRIES-006 and -008 coverage already links tests. That no longer holds: the current spec and coverage have no REQ or SCN 006 or 008, so this row writes both. The salvage commit `49e22db9` cannot be applied: it targets an older controller signature `render(h, journey, …)` and a `kit.runBackLink(request, previousSlug)` that no longer exist. Only its intent is taken: the title key, the scope redirect on GET and POST, and the doc line. Its Back-link and empty-state hunks are left out. The tests salvage `29c74b5` targets an older page object and spec, so its intent is rewritten against the current ones. Its Back-link tests are already on the branch as REQ-007 coverage, and its empty-state assertions are already gone.
10. **Where the tests repo's means-saving step lives.** `transit-means-scope.spec.ts:17-23` holds a local `saveArrivalWithMeans` closure (open Arrival details from the overview, fill it with a chosen means, save, land on the overview). The new redirect tests need the same step, so it is promoted to the animals journey flow and the local closure is deleted. Rejected: a second local copy.

- GET out of scope: reachable through a bookmarked or typed address, a stale link, or the browser history after the means changes to Air or Sea, and for a notification with no means saved.
- POST out of scope: reachable through a transit page left open in one tab while another tab saves Air or Sea, or by Back to a cached page.
- Opening run with an out-of-scope means: reachable, because the run is active for a notification created in this session.
- Nothing unreachable is built.
