## 0. Decisions

1. **The row says the origin page already names subdivisions with their parent country. It does not.** The country of origin page uses `countries.originCountryOptions()`. That lists each subdivision under its bare name ("Canary Islands"): see `services/countries/index.js:103` and `run-mode.test.js:80-83`. Naming the origin page's subdivisions with their parent country is a separate todo row, inc-175 (origin-page theme). The labelling the row means already exists as `countries.destinationCountryOptions()`, from reference-lists inc-006 (`index.js:118`). It returns the same codes as `originCountryOptions()` (the destination-options test pins this), names each subdivision `<territory> (<parent country>)` and returns one list sorted with `localeCompare`. **Settled:** the transit page reuses `destinationCountryOptions()`. So AC1's "same countries and subdivisions as the country of origin search" holds on codes and order (both sort by the label shown). AC2's naming comes from the shared builder. The origin page's own labels stay as they are (inc-175's job). **Rejected:** (a) changing `originCountryOptions()` here, because that is inc-175's change in another theme; (b) a new transit-only builder, because it would duplicate the existing one.
2. **The transit page and its validation share one source.** `validate.js` gets `offeredCountries()` (calls `destinationCountryOptions()`) and `offeredLabel(code)` (the text of the offered option with that code, or `undefined`). `offeredCodes()` is then derived from `offeredCountries()`. Every place the controller names a country uses `offeredLabel`: the rows, the added and removed announcements, the "You have already added …" error and the refused value put back into the search box. So the list, the rows, the status messages and the errors always read the same name. **Rejected:** `countries.originDisplayLabel`. It also resolves `GB` to "United Kingdom" through the address-form fallback, and that fallback is not an offered entry.
3. **No rename of `destinationCountryOptions`.** inc-006 owns that name. It is called from import-reason's controller, validation and tests, and renaming it would collide with the other theme branches. The transit `validate.js` wraps it as `offeredCountries()`, so the transit code reads plainly. Its JSDoc gets one added clause saying the transit countries search uses it too. For the same reason, the tests repo reuses `destinationCountryNames()` from `domain/shared/fixtures/reference-data.ts`, adds a clause to its JSDoc and keeps its name. **Rejected:** renaming to a neutral name, because of the cross-theme churn.
4. **A refused `GB` is no longer echoed back into the search box as "United Kingdom".** Only a tampered form can send it, since the list never offers it. With `offeredLabel`, the box comes back empty, as for any other unknown code. No test pins the old echo.
5. **Change in scope: the review page's transit-countries card names a subdivision the same way.** Once subdivisions can be saved, `check-answers/view-model/cards/movement/transit-countries.js` would show "Canary Islands" through `countries.originLabel`, while the page shows "Canary Islands (Spain)". The card switches to `countries.originDisplayLabel(code)`, as the origin card (`cards/consignment/import-details.js`) already does. It is one line. **Rejected:** deferring it, because the obvious inconsistency would ship with this row.
6. **No count is asserted anywhere.** The notes say so: the count differs between the stub and real MDM. The list E2E compares option texts with the captured fixture and runs only on the compose stack, as the destination list spec does. The territory journey E2E reads its territory from the page, so it runs on any environment.
7. **No copy change.** Labels come from reference data. Every page string already exists in `copy.en.js` and `copy.cy.js`, so the Welsh-draft invariant has nothing to add.
