## 0. Decisions

1. **The gap is real.** `port-of-entry/validate.js:44` checks `meansOfTransport` with `oneOf(...)`, which allows `''`, so an empty means passes on both buttons. `requiredOneOf` exists at `lib/validate/validators.js:153` and refuses blank, absent and unknown values with one message. Claim confirmed.
2. **Both buttons refuse.** Main's `docs/validation.md:59-63` already says Save and return to overview runs the same checks as Save and continue, and the controller (`port-of-entry.controller.js:94-105`) runs `validation.onSubmit` before either exit. So putting the required rule in the page validation covers both buttons. The controller does not change. The programme header's invariant "'Save and return to overview' saves without the page's required-answer checks" (c-211, ruling 2026-10-07) is out of date: the 26 October ruling replaced it and the row says so. The row wins, and a follow-up records the stale header line (section 7).
3. **The requirement applies only to the submitted reading, not the stored one.** `pageValidation` runs the same `fields` against a submitted form (`stored: false`) and against stored answers (`stored: true`, the GET render and the task-list or stored-answer readings; `page-validation.js:53,59`). On GET the controller renders the errors from `onStored`. A required rule on the stored reading would open every fresh or draft Arrival details page with a "Select a means of transport" error, and would flag every draft without a means as an invalid stored answer. So the means rule is required on the submitted reading and keeps its current optional membership on the stored reading. The module already has this exact shape: `import-reason/validate.js:58-72`, where `countryRule` and `portRule` return `oneOf` when `stored` and `requiredOneOf` when submitted. The means rule follows that mechanism. (`portMessage` and `arrivalDateRangeMessage` in this file vary only the message by `stored`, so they are not the precedent for switching required to optional.) Rejected: `requiredOneOf` on both readings.
4. **A tampered or unknown means gets the required message on submit.** `requiredOneOf` has one message for blank, absent and unknown values, so an out-of-list means submitted from the form now shows "Select a means of transport to the port of entry" instead of the default "Select a valid option". This is the reused branch's shape (843821b8). Rejected: composing a second membership rule to keep the default message, which would add a second mechanism beside `requiredOneOf`.
5. **Copy.** One new error string in the feature's own copy, `transport/copy/copy.en.js` under `portOfEntry.errors`, with its Welsh twin in `copy.cy.js`: English 'Select a means of transport to the port of entry', Welsh 'Dewiswch gyfrwng cludo i’r porthladd mynediad' (taken from 843821b8). The shared copy is not touched (programme invariant on shared wording).
6. **Welsh criterion.** `shared/copy.js` `copyFor` always resolves English. No locale is chosen by request yet, so no running page is served in Welsh. The fourth criterion is proved where Welsh exists today: the Welsh copy bundle holds the exact string under the key the page reads, pinned by the per-locale wording test pattern in `transport/copy/copy.test.js`. Rejected: building a locale switch, which nothing in this row reaches.
7. **Only the means becomes required.** Arrival date, port, identification and document reference keep their current shape-only rules. That keeps REQ-ARRIVAL-011 ("only the means of transport is needed to continue") true, along with PR #200's open question 30: the page refuses only what it already refuses, plus the means.
8. **Journeys that saved arrival details without a means now choose one.** In the frontend FIT suite, `transporters.fit.spec.js:59-68` and `commercial-transporter-details.fit.spec.js:22-36` open arrival details and save it empty. In the tests repo, `flows/animals/journey.ts` `walkOpeningRunToRolesAndAddressesWithoutCph` (line 605) and `port-of-entry-select.spec.ts:27` do the same. Each must choose a means. Where the next page is the transporter list, choose a means that does not bring in transit countries (Air), as `walkOpeningRunCattleByAir` already does.
9. **The two FIT openers that save arrival details share set-up.** `transporters.fit.spec.js` and `commercial-transporter-details.fit.spec.js` each have a local opener with the same first steps: start, unlock, open arrival details, save, see Overview. Both now gain the same means step. Under the house rule that set-up used by two tests goes in the shared helper, that sequence moves into `fit/live-animals-journey.js` beside `openArrival` and `openTransit`, takes the means to choose, and `openTransit` is built on it. The two local openers keep only their own later steps.
10. **The required message has one home in the tests repo.** Two specs assert it (`pages/arrival-details.spec.ts`, `features/soft-save.spec.ts`), so it goes in `domain/animals/constants/means-of-transport.ts` beside `MEANS_OF_TRANSPORT_SELECT_TEXT`.
11. **Provenance only:** inc-028 (replaced), c-045 / c-006 (field checks kept, 'Error: ' title), ruling sam-2026-10-26 claim 1, req-315 and req-329. None of these appears in code, comments or test titles.
