## 0. Decisions

1. **The "Select a commodity" inline error sits where govukInput puts it: label, hint, error, input — not
   "between its label and hint".** AC4 and req-085 say "inline on the search field, between its label and
   hint". GOV.UK Frontend's `govukInput` renders the error message *after* the hint, and the programme
   invariants say pages are built from GOV.UK Frontend components (no custom blocks to copy the
   prototype). Reordering would mean hand-rolled input markup. Settled: the error is on the search field
   (`errors.commoditySearch`), rendered by `govukInput` in its standard place; tests assert the error is
   part of the search box's accessible description and the summary link focuses the search box. Rejected:
   custom markup putting the error above the hint. This is a claim in the row that does not hold against
   the toolbox; recorded here as the defect.
2. **Save and return to overview is already soft on the commodity page.** req-088's deltaNote says today's
   page shows "Select a commodity" with a 400 on Save and return; it does not —
   `search.controller.js` already skips the check on `kit.isHubExit(request)` and commits the (possibly
   empty) selection, and `search.controller.test.js` "Should go to the overview with nothing chosen on Save
   and return to overview" pins it. Settled: no controller change for AC5; the plan adds proof — the
   overview row reads exactly "To do", and a saved selection that is cleared then saved-and-returned is
   emptied.
3. **Clearing the unweaned answer is already the engine's purge, not new code.** `containsUnweanedAnimals`
   is in scope only while a line carries a commodity in `unweanedCommodities()` (today `['Cow']`), and
   `reconcileEntriesAt` purges out-of-scope answers (`engine/mutators.test.js` "deselecting the last
   triggering commodity destroys the dependent"). A selection of only 01061900 species (Cat, Dog) therefore
   already clears it. Settled: no obligation or controller change; add a controller-level unit test and an
   E2E integration proof. Rejected: a prototype-style explicit `unweaned = null` in the commodity
   controller — it would duplicate the evaluator's wipe authority. Note the live rule is wider than the
   prototype's: any selection with no cattle line clears it (Horse-only too). The spec states the
   01061900 case the row names, under the existing "only cattle" requirement, which already implies the rest.
4. **AC9 "missing both answers" does not produce packages errors on live animals.** Number of packages is
   optional on live animals (`integerInRange`, label "(when required)", REQ-OB-COMMODITY-003 "as an
   optional answer"; the prototype only requires it for germinal products). A blank packages box is never
   an error. Settled: the order rule is implemented as stated — every number-of-animals error first, then
   every number-of-packages error — and proved with two Cow species whose animal counts are blank and
   whose package counts are not whole numbers (`abc`), which yields 2 + 2 errors. Rejected: making packages
   required (would contradict the obligation spec and is not what DR2.1 does for live animals).
5. **Species cell separator.** The prototype renders each Latin name followed by `,<br>` except the last.
   Settled: same — `{{ name }}{% if not loop.last %},<br>{% endif %}` per name, escaped by Nunjucks
   autoescape. The Latin name is `commodities.speciesLabel(speciesSelection) ?? speciesSelection`, exactly
   as `consignment-details/view-model/groups.js` names the species heading today (exemplar). Rejected: a new
   service function — `speciesLabel` already returns the scientific name.
6. **Species cell on a 01061900 per-species row** lists that row's own species' Latin name (one name). A
   commodity row lists the Latin names of every line under that commodity, in line (canonical) order.
7. **Caption "Description of the goods"** is a new caption section `descriptionOfTheGoods` holding only
   `consignmentDetailsPage`. The identification and additional-details pages keep their captions
   ("About the consignment", "Commodity details") — moving them is not this row. Welsh:
   "Disgrifiad o’r nwyddau", matching the hub group's existing Welsh "2. Disgrifiad o’r nwyddau".
8. **Trade Tariff link.** The link text becomes `Trade Tariff tool<br>(opens in a new tab)` *inside* the
   `<a>`, followed by the full stop outside it, so "(opens in a new tab)" sits on its own line and stays in
   the accessible name ("Trade Tariff tool (opens in a new tab)"). The copy splits into `lookupLink`
   ("Trade Tariff tool") and a new `lookupNewTab` ("(opens in a new tab)"). Rejected: the prototype's
   placement of "(opens in a new tab)." outside the link — AC3 requires it in the accessible name.
9. **Hint and inset strings are feature copy** (`CMD/copy/copy.{en,cy}.js` → `search`), never shared copy.
   Welsh drafts:
   - inset: "Rhaid i chi gyflwyno hysbysiad ar wahân ar gyfer pob ITAHC unigol. Rhaid i chi hefyd gyflwyno hysbysiad ar gyfer nwyddau nad oes angen ITAHC arnynt."
   - searchHint: "Gallwch chwilio yn ôl enw cyffredin (er enghraifft, gwartheg), cod nwyddau (0102), neu enw Lladin (Bos taurus)."
   - lookupLink: "teclyn Tariff Masnach"; lookupNewTab: "(yn agor mewn tab newydd)"
   - table.species: "Rhywogaeth"
   The cy files already open with the `// MACHINE-DRAFT Welsh` marker; it stays.
10. **Plants mirroring** (programme invariant on shared behaviour) is not in this row's repos
    (`frontend`, `tests`); the ITAHC inset and the live-animals hint are animals-only. No plants change is
    planned here (see section 7 and risks).
