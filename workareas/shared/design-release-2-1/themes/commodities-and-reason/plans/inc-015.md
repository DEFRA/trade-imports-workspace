## 0. Decisions

1. **The two Back links are run-aware.** While the opening run is under way:
   - the commodity page's Back link goes to the origin page;
   - Commodity details' Back link goes to the commodity page.

   Outside the run (opened from its overview task, a Change link, an amendment), each keeps today's overview Back link. Grounds:
   - the prototype's `getJourneyBackLink` (routes.js:488) returns `/notification-hub` when opened from the hub, and the linear back link otherwise;
   - the sibling row inc-021 asks for exactly this pattern on the reason page;
   - REQ-FLOW-013 says a page "MUST keep its usual Back link and never link back to the review".

   Rejected: an unconditional origin/commodity Back link. That would send a trader who opened a task from the overview back into a page they never came from.
2. **The journey says which page each run step's Back link names, through a new optional journey-flow seam.**
   - `flow/run.js` exports `runBackTarget(pageId, journeyId)` from a `RUN_BACK_STEPS` map. This row fills only commodities → origin and consignmentDetails → commodities.
   - The platform exposes it as `journeyRunBackTarget`. It is optional, the same way as `sectionCaption`.
   - `kit.runBackLink(request, page)` is what controllers call.

   Rejected:
   - (a) Importing `originPage` into the commodities feature folder. Feature folders are independent by design; only the journey's flow data imports page identities across features.
   - (b) Deriving the Back link as "the previous run step". For Commodity details that is the main import reason, but AC4 and the prototype (source p3-005) name the commodity page, which skips the reason.
3. **No change to `flow.js` sections or `task-rows.js`.**
   - The run order already matches Design Release 2.1.
   - Moving Additional details out of the reason's section and changing the section order is inc-021's row ("Reason and additional details sit in Design Release 2.1's journey order").
   - Every task row here holds one page, so `nextInTaskRow` already returns to the overview.
4. **"Opened from check answers it returns to check answers" (AC2) is met through the existing change round trip, not by sending the commodity page straight to the review.** The review never links to the commodity page. Its species Change link (`species-card-actions.js`) opens Commodity details with `?change=1`. The commodity page is reached with the change flag only from Commodity details itself, by "add another commodity" or by the empty-details redirect. Today `commit-selection.js` then hands back to `Commodity details?change=1`, so the new species can be counted, and Commodity details' Save and continue returns to the review (`exitTarget`). The trader opened the change from check answers and lands back on check answers.

   Rejected: redirecting the commodity page to the review. A newly added species would land there with no count, and the trader would have to follow Change again (REQ-FLOW-010's collection rule points the same way). The row's own note leaves where Commodity details goes after a change to req-119.

   This plan pins the current hand-back with a unit test. **Flag for review.**
5. **AC5's "otherwise to the arrival details" needs no code.** Additional details collects `animalsCertifiedFor`, which `obligations/sections/misc.js` models as always mandatory, so the additional details step always applies today. If a later row (inc-023 unweaned, or an APHA gating) makes it conditional, `nextRunTarget` already skips a gated-out step (SCN-FLOW-007-B). Its own unit test pins the identification → additional-details branch.
6. **Plants is not changed.**
   - The invariant "plants mirrors … keeps its own … step order" applies.
   - Sam's ruling 2026-10-09-pm (claims 43/44) leaves plants its own step order. Back links that name the previous run step are step order.
   - `plantsfrontend` is not in the row's repos.
7. **k6 walk order.** Only the import reason moves: origin, commodities, **import-reason**, consignment-details, identification, additional-details, then the rest unchanged. The tail (documents/addresses/cph before arrival) is not this row's slice. The `STEP_ENDPOINTS['live-animals']` key order moves the same way, so the catalogue reads in walk order. The search term (`ANIMAL_COMMODITY_SEARCH`, 'Cow') stays: the row's note gives that to req-1919.
8. **Welsh.** No copy changes, so there is no Welsh draft to add.
