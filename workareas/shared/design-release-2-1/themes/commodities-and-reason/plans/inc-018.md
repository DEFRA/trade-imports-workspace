(`ls src/server/app/sets` → `live-animals`), so the germinal half named in the row's notes has nowhere to land
and belongs to inc-182, as the row says.

Routing: this is a routed "change the frontend" (page validation, controller-owned) plus one obligation status
change ("change an obligation" guard rails). No add-a-* recipe applies. The guides that govern it are
`src/server/app/docs/validation.md` (controllers own field validation; `allowMissing` on the hub exit; commodity
details stays strict) and the obligation-maintenance guard rails in `.claude/skills/frontend-change/SKILL.md`.

## What the live tree does today (claims checked)

- **Arrival details** (`features/transport/port-of-entry/`): every field is optional on Save and continue.
  `validate.js` uses `oneOf('meansOfTransport', …)`, which allows `''`. So an empty Save and continue goes to
  the overview. The tests repo pins that today (`arrival-details.spec.ts` "saves a draft and returns to the
  overview when submitted empty"). The row's note says transit-means-scope treats the page as "enforced as a whole
  page". It does not: that spec fills every field and its comment is wrong. The claim is wrong, but the fix is the same:
  the comment and helper change with this row.
- The spec already says `REQ-ARRIVAL-006` "Saving the page empty is rejected", and its coverage links a test
  ("shows an error summary when submitted empty") that no longer exists. This row makes the spec true and
  relinks it.
- **Commodity details** (`features/commodities/consignment-details/`): number of animals is already a hard stop
  (`requiredIntegerInRange`), on Save and continue **and** on Save and return to overview (the page does not opt
  into `allowMissing`; `validation.md` says "A page that must stay strict (commodity details) does not opt in";
  `SCN-FLOW-004-E` and the unit test "Should hold the page on a blank count when Save and return to overview is
  pressed" pin it). Number of packages is `integerInRange` (blank allowed) and only on lines whose commodity is in
  `packageCountCommodities()` (Cow, Cat, Dog, Horse, …; not Fish).
- The obligation `numberOfPackages` (`obligations/sections/commodities/lines.js`) is `status: 'optional'`;
  `numberOfAnimals` is `mandatory`. `meansOfTransport` (`obligations/sections/transport.js`) is already
  `mandatory`.
- **Plants** is a separate repo (`trade-imports-plants-frontend`) with its own arrival validation. Nothing here
  touches it, so the plants criterion holds without any change there. `tests/plants/e2e/features/arrival.spec.ts`
  ("the arrival date must be given before the notification moves on") already pins plants' own check on Continue.

## 0. Decisions

1. **Means of transport hard stop is page validation, not an `ENFORCED_AT_CONTINUE` prerequisite.** Use the
   import-reason exemplar (`features/import-reason/validate.js` `countryRule`/`portRule`):
   `stored ? oneOf(...) : requiredOneOf(...)`. The submit reading refuses a blank. The stored (GET) reading stays
   lenient, so a first load shows no error. *Rejected:* adding `meansOfTransport` to
   `bridge/obligation-source.js` `ENFORCED_AT_CONTINUE`. That is a shared L2 list that gates *later pages*, not this
   page's Save and continue. It would not put an error on the question, and EUDPA-667 owns that list.
2. **Save and return to overview on Arrival details stays lenient.** The controller already passes
   `allowMissing: kit.isHubExit(request)`, and `requiredOneOf` reports a blank as `any.required`/`string.empty`,
   which `allowMissing` drops. That keeps programme invariant c-211, and the existing unit test "Should save an
   empty page and go to the overview on Save and return to overview" keeps pinning it.
3. **One message for a blank or unknown means on submit**: `requiredOneOf` takes a single message. EN
   `'Select the means of transport to the port of entry'`, CY draft
   `'Dewiswch y cyfrwng cludo i’r porthladd mynediad'` (CY matches the existing Welsh label "Cyfrwng cludo i’r
   porthladd mynediad"). This replaces `validatorDefaults.oneOf` ("Select a valid option") for a tampered value on
   submit. The stored reading keeps `oneOf` with its default message. *Rejected:* composing `oneOf` +
   `requiredText`, because composing merges the `''` allowance (validators.js comments).
4. **Number of packages hard stop matches number of animals exactly**, including on Save and return to overview.
   The row says "alongside the number of animals", and `validation.md` and `SCN-FLOW-004-E` say this page stays
   strict. *Rejected:* relaxing packages alone on the hub exit. That splits one page's rules, and the documented
   exception for this page already covers it. Flagged under risks against invariant c-211.
5. **Packages messages**: blank → new key `packagesRequired`: EN `'Enter the number of packages'`, CY
   `'Rhowch nifer y pecynnau'` (mirrors `animalsRequired` / `'Rhowch nifer yr anifeiliaid'`). Not a whole number,
   or below 1, → the existing `packagesWholeNumber`. Same as today.
6. **The `numberOfPackages` obligation becomes `status: 'mandatory'`.** Without that, a line can reach the
   overview with packages blank and the "Commodity details" row still reads complete. For example, a line is added
   from "What are you importing?" after the details were saved, or a draft predates this change. The page refuses
   that state, so the row must agree, as it does for number of animals. The spec `REQ-OB-COMMODITY-003` ("as an
   optional answer") changes with it. *Rejected:* page-only change, which would leave the task row and submit
   readiness contradicting the page. Scope is unchanged: only package-count lines.
7. **Integration proof** is new E2E tests in the tests repo, run by the gate's `e2e` rung
   (`trade-imports-ins-tests` `test:docker-compose`). Every existing tests-repo helper or spec that saved Arrival
   details with no means, or Commodity details with a package line blank, gets the answer added, in this change
   (programme invariant). Assertions are never weakened.
8. **`walkOpeningRunToRolesAndAddressesWithoutCph` chooses `Airplane`** on Arrival details, not Road Vehicle. A
   non-overland means keeps the Transit countries page out of the opening run, so the walk still lands on the
   transporter page next, exactly as it does today.
9. **transit-means-scope.spec.ts chooses the means alone** in `saveArrivalWithMeans` (no `fillArrivalDetails`).
   That is the row's "tests that say arrival details is enforced as a whole page change with it", and it gives AC2 a
   second witness through the real stack.
