## 0. Decisions

1. **Defect: the second acceptance criterion (number of packages a hard stop on Commodity details) does not hold,
   and this plan does not build it.** Three sources, two of them outranking the claim it rests on, say the
   live-animals number of packages is optional:
   - **V4, the highest-ranked source on a field's Mandatory/Optional marking.** `confluence-6497338582-p1-099`
     (`workareas/shared/design-release-2-1/distil/extract/confluence-6497338582.part1.json:838-845`): "Number of
     packages is Optional: it can be left blank", quoting the Mandatory cell of the `number_of_packages` row verbatim
     as `Optional`. `sources.json` gives this source the role of deciding "whether it is mandatory to proceed or
     optional", says it "outranks the prototype on data … including where a prototype claim of kind 'data' says
     otherwise", and lists it above all three prototype sources in `precedence`.
   - **The prototype's own source.** `prototype-dr2-1-source-p3-028`
     (`distil/extract/prototype-dr2-1-source.part3.json:226-234`, verbatim from `app/routes.js:1125-1130`): "The
     live-animal 'Number of packages (when required)' field is optional: it is not validated for live-animal
     species." The required-packages rule it does have is the **germinal** one
     (`prototype-dr2-1-source-p3-035`, `app/routes.js:1132-1142`).
   - **The prototype's spec suite, read directly.**
     `workareas/shared/design-release-2-1/prototype-specs/e2e/description-of-the-goods.fit.spec.js:53-57`: an empty
     save on the live-animals commodity details page raises exactly one error, the number-of-animals one
     (`expectErrorSummary` asserts the whole summary list element-by-element — `e2e/support/journey.js:39-44`),
     with the packages box present and blank (`:47`); `:70-74` then saves and moves on with packages still blank.
     The packages hard stop in that file is on the germinal page (`:92-103`, cattle semen 05111000), beside the
     total gross weight and the storage temperature.

   How the claim went wrong: `prototype-specs/COVERAGE.md:161-162` lists the hard stops as one phrase — "number of
   animals/packages/weight/temperature" — merging the live-animals page's single hard stop with the germinal page's
   three. Claim `prototype-dr2-1-specs-p7-139` read that phrase as all four on one page; weight and storage
   temperature exist only on the germinal page, which is the tell.

   *Rejected: build the criterion anyway.* It would make the code differ from its design source and from the V4
   marking, which the house rules call a correctness finding, and it would raise the cost the row's own "Ordering
   risk" note already describes ("a trader importing chickens sees an optional … box they can leave blank; after
   this row they cannot continue"). *Rejected: return `ok:false` for the whole row.* The first criterion is
   confirmed twice over and absent from the code; blocking it would waste a correct, buildable slice. The packages
   half goes to section 7 as a follow-up.

2. **The means rule degrades on the stored reading.** The rule is save-blocking on the submit reading and stays
   exactly as it is today on the stored reading, following `features/import-reason/validate.js:58-97`
   (`countryRule`, `portRule`, `RULES[PURPOSE_FIELD]`), which is the mechanism `docs/validation.md:65-71` describes:
   "The reading that is running is passed to the rules as `stored`, so one broken rule can be worded for each."
   `port-of-entry/validate.js:31-34` already receives `stored` and already branches on it twice (`:20-26`).
   *Rejected: one save-blocking rule for both readings.* `port-of-entry.controller.js:87-92` renders
   `onStored`'s errors on every GET, so a trader opening Arrival details for the first time would meet an error
   summary for a question nobody has asked yet; and `journeys/linear/flow/stored-answers.js:9-35` would demote the
   task row and mark the review card on the same unasked answer.

3. **The primitive is the save-blocking membership rule the library already exports**
   (`lib/validate/validators.js:145-167`, re-exported at `lib/validate/index.js:16`), which four features already
   use. *Rejected: composing a required-text rule with today's membership rule.* The JSDoc at
   `validators.js:65-75` and `:202-216` records why that silently passes a blank — composing merges the
   empty-string allowance onto the required rule.

4. **One message covers blank, absent and out-of-list on the submit reading.** That primitive takes a single
   message, so the out-of-list means error moves off the shared default (`shared/copy.en.js:94-104`) and onto the
   page's own. Accepted: the design source's wording reads correctly for the trader's case, out-of-list is reachable
   only by tampering with the select, and the stored reading keeps today's default message unchanged.
   *Rejected: a second validator so the two cases keep separate messages.* That is a second mechanism beside one
   that exists, for a case no user can reach.

5. **The English wording comes from the design source, not from this plan.** `prototype-dr2-1-source-p6-040`
   (`distil/extract/prototype-dr2-1-source.part6.json:329-335`, verbatim from `app/routes.js:4378-4384`) sets
   "Select a means of transport to the port of entry", asserted in the prototype's own suite at
   `prototype-specs/e2e/transport-and-arrival.fit.spec.js:47` and `:49`. The implementor copies that string. The
   Welsh is a machine draft beside it, as `transport/copy/copy.cy.js:5` already marks the file. No `design`
   finding: the design source sets one label for one element and the GDS error pattern agrees with it.

6. **A refusal commits nothing and re-renders what was entered.** The prototype writes the page to its session even
   when it shows the means error (`prototype-dr2-1-source-p6-041`, `app/routes.js:12567-12573`); that is a
   prototype session artefact, and persistence is a real constraint the prototype cannot express
   (`sources.json`, the `ruling:sam-2026-10-07` role). The real page follows its own existing refusal path —
   `port-of-entry.controller.js:100-105` re-renders the submitted values with a 400 and commits nothing.

7. **Both save buttons are refused.** `ruling:sam-2026-10-26` claim 1 replaces c-211 and c-313, and
   `docs/validation.md:59-63` already states it. The theme backlog header still carries c-211's old wording
   ("'Save and return to overview' saves without the page's required-answer checks"); the ruling outranks it
   (`sources.json` gives `ruling:sam-2026-10-26` the role "outranks every other source on Save and return") and the
   code already behaves this way. Planned to the ruling.

8. **Neither plants nor germinal products is touched.** The row's detail and `ruling:sam-2026-10-09-pm` p3-063 make
   arrival details' own rules animals only, so the plants-mirror invariant has nothing to mirror here; and there is
   no germinal set on this tree.

9. **No obligation changes.** `obligations/sections/transport.js:69-73` already requires the means of transport, so
   the hub, review and submit-readiness half of this requirement is already true. The one-word obligation edit the
   row's salvage note names belongs to the packages half, which Decision 1 drops.

10. **A stale claim in the row's notes, recorded so the reviewer does not chase it.** The notes say "Existing tests
    that say arrival details is enforced as a whole page (transit-means-scope) change with it". They do not:
    `tests/animals/e2e/features/transit-means-scope.spec.ts:17-23` fills every arrival answer through the shared

    (`distil/extract/repo-tests.part2.json:240-246`), quotes a comment at `:14-15` that is no longer in the file.
    That spec needs no change — but the coverage note that cites it does; see Decision 15.

11. **The error-state accessibility check goes in the arrival fit spec.** The row adds a new error state to a page
    whose fit spec has an axe check for the page and for the date picker open (`arrival-transit.fit.spec.js:859-868`)
    but none for an error state. `consignment-details.fit.spec.js:373-382` is the exemplar for pairing a new error
    state with a scan. *Rejected: leaving it to the tests repo's a11y suite* — that suite reaches the arrival error
    state only through the out-of-window date (`tests/animals/a11y/notification-journey-error-state.spec.ts:147-158`).

12. **The tests repo's new error string gets a home rather than being retyped.** Two specs need it

    once copies spread. Its home is `domain/animals/constants/means-of-transport.ts`, which already holds this
    question's select text (`:10`). *Rejected: a new `arrival-details-page.ts` constants file* — it would split one
    question's vocabulary across two files.

13. **The rationale above the rule list this change edits moves to the repo's validation doc.** The house rules keep
    rationale, and any description of the caller, out of code, and the plan edits the function that comment sits on
    (`transport/port-of-entry/validate.js:28-34`), so it is this change's to fix. `src/server/app/docs/validation.md`
    already owns the arrival window's design (`:92-106`), so the fact lands there and the comment goes.
    *Rejected: leaving the comment where it is* — a breach in a function this change edits is a defect to fix in this
    change. *Rejected: deleting it without a home* — the fact is why the page passes a window in, which the doc does
    not state yet.

14. **The `journey-flow` capability states the behaviour this change inverts, so it is spec'd here too.**
    `openspec/specs/live-animals/journey-flow/spec.md:141-147` carries a scenario under `REQ-FLOW-004` stating that
    Arrival details with a port chosen and no means of transport returns to Overview with no error shown, "as saving

    `openspec/coverage/live-animals/journey-flow/coverage.json:206-207` links it to the two tests section 2 inverts —
    both notes already saying "red when the page requires a means of transport". Left alone, the increment would land
    a behaviour spec asserting the opposite of the code and two coverage links naming test names that exist in
    neither repo. The scenario is replaced in place, keeping its ID, and the two links are re-pointed — section 8.
    `REQ-FLOW-004`'s own statement needs no change: it already says saving and returning makes the same checks as
    saving and continuing, and its closing sentence about a blank optional answer stays true, because the other four
    arrival answers stay optional (test 3, test 7). *Rejected: inverting only the arrival-details capability.* The
    spec would then hold two capabilities contradicting each other on one page's save.

15. **The `transit-means-scope` coverage link under the leniency scenario goes.** Its note at
    `openspec/coverage/live-animals/journey-pages/arrival-details/coverage.json:273` claims "each save chooses the
    means alone", which is untrue: the spec saves through `fillArrivalDetails`, whose defaults fill the arrival date,
    port, identification and document reference as well (`flows/animals/journey.ts:313-325`), so it witnesses nothing
    about the means being the only answer the page needs — which is exactly what the scenario states. The plan edits
    that scenario's entry, and `openspec/config.yaml:66` ("Build coverage by reading test bodies, not titles") makes
    the note this change's to fix. *Rejected: rewording the note to describe what the spec does witness.* The link
    would still sit under a scenario it gives no evidence for, and three tests that do prove it arrive as `full`.
