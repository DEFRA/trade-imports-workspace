## 0. Decisions

1. **The Overview task row keeps "Main reason for import".** The row says "the page" and "the review". Renaming the third Overview task belongs to inc-098 in the parent backlog ("Hub regions for assistive technology and the 'Main import reason' row", overview-and-review theme). `hub/copy/copy.{en,cy}.js`, `hub/copy/copy.test.js` and every tests-repo `overview.task('Main reason for import')` / task-list literal stay as they are. Rejected: renaming the row here too. That would take over another row's acceptance criteria and break the many hub specs inc-098 owns. One consequence: the frontend's `SCN-FLOW-004-C` line about the *task* keeps "Main reason for import", and only its line about the *page* changes.
2. **The review heading's copy key is renamed** from `groups.mainReasonForImport` to `groups.mainImportReason` in `check-answers/copy/copy.{en,cy}.js`, and its two readers move with it (`view-model/sections/about-consignment.js` and `check-answers.fit.spec.js`). Rejected: keeping the old key name over the new text. The key would then name wording the page no longer shows ("explicit names"). This is the live-animals set's own check-answers feature copy, not the app-level `shared/copy`, so the "never reword shared copy in place" invariant does not apply.
3. **Each select keeps its own placeholder key.** `country.placeholder` and `port.placeholder` both become `'Select one'` (Welsh `'Dewiswch un'`, the Welsh the transport and documents features already use for "Select one"). Rejected: merging them into one `selectPlaceholder` key. Keeping the keys keeps the copy tree, its readers and the copy-parity shape unchanged.
4. **The divider goes, and nothing replaces it.** Delete `DIVIDER_OPTION` from `import-reason/controller.js`. Each list becomes `[{ value: '', text: placeholder }, ...options]`. With no other `selected` option, a native select shows its first option, so "Select one" is selected while nothing is chosen. The reason page's selects stay plain `govukSelect` (ruling sam-2026-10-09-pm p1-040).
5. **The type-ahead criterion has nothing to act on.** On this branch, every reason-page select (`transhipmentDestinationCountry`, `transitPortOfExit`, `transitDestinationCountry`, `temporaryAdmissionPortOfExit`) is a plain `govukSelect`, with no autocomplete module, no `data-module` and no webpack entry. The criterion "where a select already offers type-ahead" therefore applies to nothing. Its effect is that the placeholder of the underlying `<select>` reads "Select one", and this plan delivers that. The plan does not invent an autocomplete. Recorded so the reviewer does not look for one.
6. **Defect in the Welsh criterion (it does not hold as written).** The criterion says "with the language set to Welsh, the page shows Welsh text". The application has no way to set the language. `shared/copy.js` `copyFor(locales, locale = 'en')` is always called without a locale ("Only `en` exists until a second language is commissioned"), so no request ever renders `copy.cy.js`. Planned against reality: every new string gets its Welsh draft beside it in `copy.cy.js` (the programme invariant). The vitest copy tests pin each Welsh string, and the copy-parity test proves each one differs from the English. No E2E or FIT can switch to Welsh, so none is planned. The spec records no Welsh scenario, because nothing a user can do shows it.
7. **Welsh drafts** (machine draft, matching the files' existing MACHINE-DRAFT header):
   - "Main import reason" → `'Prif reswm mewnforio'` (page title, and the review group heading)
   - "Select one" → `'Dewiswch un'` (both placeholders)
   - "You can find this information on the ITAHC." → `"Gallwch ddod o hyd i'r wybodaeth hon ar yr ITAHC."`
8. **The review row labels already match.** `check-answers/copy/copy.en.js` already has `rows.purpose: 'Purpose in the market'`, `rows.exitDate: 'Exit date'`, `rows.portOfExit: 'Port of exit'`, `rows.certifiedFor: 'Certified for'` and `rows.unweaned: 'Includes unweaned animals'`, so only the group heading changes. The backlog notes say the same.
9. **The tests repo's `selectOption({ index: 2 })` on the reason-page port selects moves to `{ index: 1 }`.** Index 2 was the first port, after the placeholder and the divider. Without the divider, index 1 is the first port. Leaving 2 would still pass but would quietly pick the second port. The change keeps each test's intent.
10. **The tests repo's E2E for the browser title uses the literal string** `'Main import reason - Import notification service - GOV.UK'`. No tests-repo spec asserts a title yet, so there is no helper to reuse. Rejected: adding a title helper for one assertion.
