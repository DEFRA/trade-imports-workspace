## 0. Decisions

1. **Both Back links go through the run-aware seam inc-015 built, `runBackTarget` / `kit.runBackLink`, and are not hard-coded.**
   - Mid-run, the reason page goes back to What are you importing.
   - Mid-run, Additional details goes back to Identification details when any chosen commodity needs identifiers, otherwise to Commodity details.
   - Outside the run (opened from the overview, a Change link or an amendment), both keep the overview, as REQ-FLOW-013 requires.

   Rejected: an unconditional Back link. A trader who opened a task from the overview would be sent into a page they never came from. The prototype's `getJourneyBackLink` returns the hub when opened from it (ruling sam-2026-10-09 p1-196).
2. **The `RUN_BACK_STEPS` map values become functions of the answers, and `runBackTarget` takes the answers as a third argument.**
   - Additional details' Back target depends on what was chosen; the other three entries ignore it.
   - `kit.runBackLink(request, page, answers)` passes the answers through. `journeyRunBackTarget` already forwards `...args`, so `src/server/app/flow/journey-flow.js` does not change.

   Rejected:
   - (a) A second map or a special case in the controller. The rule belongs with the journey's flow data, as inc-015 placed it.
   - (b) Deriving "the previous run step whose gate passes". The identification step's page gate passes for a fish-only consignment, because the page redirects itself onwards, so it would name Identification details wrongly.
3. **"A chosen species needs identifiers" is decided by `identifiesAnAnimal`, the test `task-rows.js` already uses** to hide the identification row. It is exported from `task-rows.js` and imported by `run.js`.
   - It asks the same question the identification page asks before it redirects past itself. Its comment says so, and both read the commodities service's identifier lists.
   - So the Back link names Identification details exactly when that page shows itself.

   Rejected: copying the predicate into `run.js`. Two copies could drift apart.
4. **Flow sections move to Design Release 2.1's order and stay ten sections.**
   - `commodities` becomes `[commoditiesPage, importReasonPage, consignmentDetailsPage]`.
   - `animalIdentification` stays `[animalIdentificationPage]`.
   - The `consignment` section is replaced by `additionalDetails`, `[additionalDetailsPage]`, in the same position.
   - Grounds: the row's detail and note ("Moving Additional details out of the reason's section and after Identification"), and inc-015 decision 3, which left this here.
   - What it changes:
     - It changes no navigation a user sees. Outside the run, `nextInTaskRow` already stops at the end of each single-page task row.
     - Page prerequisites (`flow/prerequisites.js`) are unchanged: the reason and Commodity details both still come after origin and commodities.
     - Only `nextInSection` (used by the review section only), the section roll-ups in `status.test.js`, and the spec's section-order scenario see it.

   Rejected:
   - (a) Leaving `sections` alone. SCN-FLOW-001-A would go on saying "import reason and additional details" form one section after identification, which Design Release 2.1 no longer has.
   - (b) Merging everything into one commodity section (eight sections). That rewrites REQ-FLOW-001's "ten sections" and every section roll-up for no observable gain.
5. **`task-rows.js` rows and the hub groups are unchanged.** The hub already shows Design Release 2.1's order and grouping. Row order feeds `status.test.js`'s row arrays only.
6. **Tests-repo journey helpers are unchanged.** `answerReasonAndAdditionalDetails`, `toImportReason` and `toAdditionalDetails` reach both pages from the overview, which still works and returns to the overview. The opening-run walkers already follow the new order.
7. **Plants and perftests are not changed.**
   - Plants: the programme invariant lets plants keep "its own … step order", and Back links that name the previous step are step order (inc-015 decision 6). `plantsfrontend` is not in the row's repos.
   - Perftests: the k6 walk already visits the pages in this order (inc-015), and only reaches pages by URL, so Back links never affect it.
8. **Welsh.** No copy changes, so there is no Welsh draft.
9. **The fish-only branch's integration proof uses 'Salmo salar'.** The tests repo already selects it on the real stack (`consignment-details.spec.ts`, `animal-identifiers-conditional.spec.ts`). It is asked no number of packages, so only the number of animals is filled.
