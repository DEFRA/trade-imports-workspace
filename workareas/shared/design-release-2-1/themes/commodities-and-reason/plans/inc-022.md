Reachability note for AC5 and AC8: the questions are radios, which a browser cannot un-choose once one is
checked, so "nothing chosen with an earlier answer saved" reaches the server only from a form whose radios were
cleared (assistive tech, a stale form, a scripted post). The fix is still real: a blank radio post must not erase
the task. The E2E proofs clear the radios in the DOM before submitting (the FIT spec already uses `evaluate`
the same way to tamper a radio value).

## 0. Decisions

1. **AC1/AC2 are already true; this row pins them, it does not change status logic.** No edit to
   `task-rows.js`, `hub/controller.js` or the obligations. Rejected: re-deriving the row's parts or adding a row
   `applies` test — nothing is wrong there.
2. **A blank reason commits nothing (AC5).** `import-reason/validate.js` `toAnswers` returns `{}` when
   `values.reasonForImport === ''`. This applies to both Save and continue and Save and return to overview,
   because a blank reason radio can never be a trader's intent to clear (radios cannot be un-chosen) and the
   reason is already optional-to-proceed (`oneOf`). Rejected: making it Save-and-return-only (two readings of the
   same blank, no user benefit); rejected: keeping `reasonForImport: ''` but skipping the purge (the purge is
   the engine's authority and is right whenever the reason really changes).
3. **Follow-up blanks under a chosen reason are still committed.** Under Transit, a blank port is committed as
   `''`, so a trader who resets a select to "Select one" really clears it, and AC3's "Transit chosen with the
   destination country given" holds. Rejected: dropping every blank from the reason patch (would make a select
   impossible to clear).
4. **Additional details commits only the questions that carry an answer (AC8).** The controller drops `''`
   entries from its commit patch, so a blank certification or unweaned answer leaves the stored one alone. Same
   reasoning as decision 2 (both are radios). An all-blank submit commits an empty patch; `engine/write/commit.js`
   already returns the current view and scope for an empty patch (`hasKeys` guard in `canonical.js` and
   `flow-only.js`), so the redirect still has a `scope`. Applies to Continue and Save and return to overview
   alike. Rejected: special-casing the hub exit only.
5. **The amend "Save and return" skips required-answer checks (AC7) through a named kit helper.** Add
   `kit.skipsRequiredChecks(request, journey)` = `isHubExit(request) || amendReviewTarget(request, journey) !== null`
   in `shared/kit.js`, and use it **in the import reason controller only**. Rejected: widening every page that
   passes `isHubExit` today (origin, port-of-entry, transit-countries, transporters, additional-details) —
   AC7 names the reason page alone, and the other pages' amend behaviour is another row's decision. Additional
   details needs no change for amend: its rules have no required-answer check to skip.
6. **The integration proof is E2E in the tests repo through the real stack**, in the two existing feature
   specs that already own these behaviours: `tests/animals/e2e/features/soft-save.spec.ts` (AC3–AC8) and
   `tests/animals/e2e/features/reason-purpose-scope.spec.ts` (AC1, AC2, AC4's flip). No new spec file.
7. **AC5 and AC8 E2E set-up seeds through the frontend form client** (`animalsSeededJourney.createDraftNotification('readyToSubmit')`,
   which saves Internal market + Breeding and Slaughter + No) — a one-page assertion, which the house rule
   allows — then clears the radios in the DOM with a page-object action and presses Save and return to overview.
   Rejected: a raw POST from the test (skips the page the trader actually uses).
8. **AC1 in E2E proves two of the five reasons (Re-entry alone, and Transit with port and country);** the unit
   test in `task-rows.test.js` proves all five. Rejected: five near-identical E2E walks (a loop in a Playwright
   test is a house anti-pattern; the status roll-up is pure and fully reachable in unit).
9. **No copy changes.** Every message these behaviours show already exists ("Enter a real date", "Complete",
   "To do"). No Welsh work.
10. **No plants mirror.** The high-risk plants frontend has no import reason or additional details page
    (`find repos/trade-imports-plants-frontend/src/server/app -type d -name "*reason*"` finds none), so the
    plants-mirroring invariant does not apply.
