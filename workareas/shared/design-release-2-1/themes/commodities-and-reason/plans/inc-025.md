## 0. Decisions

**D1 — One owner for how a species reads.**
`features/commodities/species-label.js:1` is already the single seam every listing
goes through — nine production call sites, found by
`grep -rn "speciesLabel" repos/trade-imports-animals-frontend/src`:
`check-answers/view-model/cards/consignment/species/species-card-rows.js:13`,
`commodities/line-title.js:5`, `consignment-details/view-model/groups.js:8`,
`consignment-details/validation/count-drop.js:26`,
`animal-identification/card/view-model.js:96`,
`search/view-model/selected-summary.js:13`,
`view-model/selected-commodity-rows.js:13`, `search/view-model/labels.js:9` and
`search/view-model/result-order.js:10`.
The new reading lives there and nowhere else: a species reads as its scientific
name, then a space, then its common name in round brackets.
Rejected: a second label function used only by the five places criterion 1 names.
That is a second mechanism beside one that exists, and it would leave two readings
of one concept in the same feature.

**D2 — The format is not a copy key, so criterion 3 has nothing to do.**
The bracket is punctuation, and the common name comes from MDM in one language and
is never translated, so no English string is added or altered and there is no Welsh
counterpart to draft. The repo already keeps species-naming formats in code rather
than in copy: the dash form at `features/commodities/line-title.js:6` and the
bracket form at `features/check-answers/refusal.js:60`. Every copy sentence that
names a species keeps its wording and only receives a different substituted value:
`features/commodities/copy/copy.en.js:57-58` (the count-drop error), `:82-83` (the
progress heading), `:84-85` (the over-count message) and `:87` (the saved-animal
row label).
Rejected: a copy key per locale for the format, which would put identical
punctuation in two locale files and invite them to drift.
What goes inside the brackets is not a string this row owns either — see D15.

**D3 — The review keeps reading exactly as it does today.**
Criterion 1 names five places, and the review — Check your answers and the
read-only view of a submitted notification, which share one view model via
`features/check-answers/view-model/cards/consignment/species/species-card-rows.js:10-18`
— is not one of them. That card already shows the common name on a row of its own
(`:12`), added deliberately by the same change that introduced `speciesLabel`
(`git show c3183a8e -- .../species/species-card-rows.js`). So the card keeps its
Common name row, its Species row reads the stored scientific name, and its title
stays the code, a dash and the scientific name
(`check-answers.test.js:185` pins that title as `0102 — Bos taurus`). Two call
sites therefore stop asking the label owner and read the line's stored scientific
name instead: `species-card-rows.js:13` and `line-title.js:5`.
Rejected: letting the review pick the new reading up through the seam, which would
print the common name twice in one card — once on its own row and once inside the
Species value — and would change a page the row does not ask for.

**D4 — The identification card stops feeding the display label to the gates.**
