## 0. Decisions

1. **The applicability rule becomes an allow list of commodity codes, replacing
   the exemption list.** Today `cph.applyTo` is
   `anyNotInUnionOf(commodityCode, cphExemptCommodityCodes, …)`
   (`obligations/sections/commodities/aggregates.js:17-26`) over
   `CPH_EXEMPT_CODES = [HORSES_CODE, OTHER_LIVE_MAMMALS_CODE]`
   (`services/commodities/rules.js:113`), so every other code — rabbits, camels,
   ostriches, parrots, reptiles, bees, fish, and anything new in the catalogue —
   brings the question in. The data-fields page's "CPH required commodities"
   expand lists nineteen entries over seventeen distinct codes, and the
   11 November ruling says in so many words that V4 wins on shape, the allow
   list replacing the deny list, with how the list is held in code left to the
   frontend. So the rule becomes an allow list over `commodityCode`, through the
   `anyAllowListed` helper the unweaned rule already uses
   (`aggregates.js:34-43`). Rejected: keeping the deny list and lengthening it
   to name every code that is let off, which cannot express "and nothing new".
   Provenance: c-357, ruling:ian-2026-11-11, confluence:6497338582 p2-107.

2. **The allow list holds all seventeen codes, hatching eggs included, not only
   the fourteen today's catalogue can reach.** Today's catalogue (the capture
   fixture the commodity service serves,
   `src/server/app/services/_capture/fixtures/commodities.json`, 26 codes) holds
   `0102`, `0103`, `010410`, `010420` and the ten poultry codes, and holds no
   `0407…` code, so a line can never carry a hatching-egg code today. The list
   is rule data, not a code branch: naming all seventeen is what makes the same
   rule cover the rest the moment MDM's catalogue holds them, with no further
   change, which the requirement asks for in those words. Each listed code is
   still provable today, because the obligation evaluator is driven by commodity
   code directly, independent of the catalogue. Rejected: listing only the
   fourteen reachable codes, which would need a code change when the catalogue
   grows and would contradict the row's own detail. See also section 15.

3. **Back on this page gets one fixed owner; where the save goes stays with the
   journey's flow mechanism, so the missing-earlier-answer rule and its one log
   survive.** Criterion 6 makes Back answer the consignment addresses page
   however the page was reached, which no shared mechanism does — so one
   function in the page's controller owns that path (the addresses page's path
   carrying the request's trail unchanged), and the out-of-scope visit of
   criterion 1 and Back both land there. Criterion 7's save does **not** read
   that function. The journey's documented rule is that "when the next page that
   applies needs a required earlier answer that is missing, Save and continue
   goes to the page that asks for that answer instead ... so the page Save and
   continue opens is always one Overview offers"
   (`src/server/app/docs/flow-and-gates.md:74-77`, repeated at
   `sets/live-animals/docs/journey-flow-and-gates.md:15-16`), and that rule lives
   behind `kit.nextTarget` / `kit.nextTargetKeepingTrail` (`shared/kit.js:208-227`
   over `flow/navigation.js:51-71` and `flow/prerequisites.js:50-60`, enforcing
   `ENFORCED_AT_CONTINUE` — country of origin and commodity code —
   `bridge/obligation-source.js:29-32`), which logs that landing once at info.
   A fixed addresses target for the save would both land the trader on a page
   Overview may not be offering and silence that log, in a state that is
   reachable today: a draft carrying a commodity line with the country of origin
   still blank, which the characterisation corpus already holds
   (`sets/live-animals/journeys/linear/fixtures/characterisation-corpus.js`, its
   partly filled record). So the save keeps asking the flow mechanism; because
   this page is a sub-page of the consignment parties section and the next step
   after it that applies is the consignment addresses page
   (`flow/flow.js:66-68`, `flow/navigation.js:13`, `:51-71`, and
   `addresses/page.js` carries no gate), the answer is the consignment addresses
   page whenever nothing earlier is missing, which is what criterion 7 asks for.
   Rejected: making the save read the fixed owner, which is what this plan said
   before and which the plan review refused for exactly these reasons.

4. **The save and the out-of-scope skip carry the trail rather than pushing this
   page onto it, and both go through the one next-target export that does that.**
   `kit.nextTarget` pushes the page saved (`shared/kit.js:243-245`), which today
   leaves the consignment addresses page's own Back pointing at the page just
   left, because that page takes Back from the trail
   (`addresses/controller.js:190`). The repo doc states the rule for a page in
   this position — "a sub-page that returns to the page that opened it keeps that
   page as its Back and its save target, carrying the trail. A page that
   redirects onward without showing itself carries the trail, so Back on the
   page it lands on skips it" (`src/server/app/docs/flow-and-gates.md:148-152`) —
   so both this page's save and its out-of-scope skip use
   `kit.nextTargetKeepingTrail`, the export that carries the trail, which is also
   what the sibling sub-page in this section already uses for its own skip
   (`permanent-address/controller.js:99`, `:141`). Rejected: `kit.nextTarget`
   with the trail pushed, which departs from that doc and re-creates the Back
   step onto a page the trader has just left.

5. **This page never consults a posted save choice, so the one next-target
   export it uses gains the save-choice option its sibling already takes.** The
   page offers `Save and continue` alone, on a draft and while amending
   (`cph-number/template.njk:88` passes `showReturnControls: false`;
   `shared/save-actions.njk` renders the hub-exit button only when that is true),
   so a posted `exit=hub` can only be a forged payload; honouring it — which
   `kit.hubExitTarget` does today through `cph-number/controller.js:81`, and
   which `kit.nextTargetKeepingTrail` would do through `shared/kit.js:258-260` —
   is letting a control the page does not have decide where a save goes, against
   criterion 7's "always" and against the theme invariant that a page's save
   controls differ only in where they go once every answer passes. So
   `kit.nextTargetKeepingTrail` takes the same optional save choice
   `kit.nextTarget` already takes (`shared/kit.js:235-237`, `:243`) and already
   has a caller for (`documents/controller.js:304-305`), defaulting as now to
   the request's own choice so its three existing callers are untouched
   (`permanent-address/controller.js:99`, `:141`,
   `commodities/animal-identification/animal-identification.controller.js:113`).
   This is the one place the row reaches outside its own feature, and it is
   needed because the rule it serves (where one save control sends the trader)
   has one owner. Rejected: leaving the forged hub exit honoured and narrowing
   criterion 7 to the three ways the page is opened — which contradicts the
   criterion as written and leaves the `save-actions.test.js` case pinning the
   old rule. Provenance: c-110, c-115, ruling:sam-2026-10-26.

6. **The `?return=addresses` marker comes off the county parish holding link and
   out of the page's controller.** Once Back always answers the consignment
   addresses page and the save goes through the flow mechanism,
   `kit.hubEntryReturn(request, ['addresses'])` changes no outcome on either
   path. Keeping it would leave two mechanisms deciding one rule. The marker, the
   `withReturnMarker`/`readReturnMarker` pair and their refusal logging all stay
   in `shared/trail.js` for the party edit links
   (`addresses/party-edit/edit-href.js:6`), the permanent address link
   (`addresses/controller.js:130-136`) and the commodity question detour
   (`commodities/commodity-question-detour.js:18`). Rejected: keeping the marker
   on the link as harmless, which the house rule on one rule, one owner refuses.

7. **A blank save stores the answer as empty rather than leaving it unwritten.**
   The page's validation already joins the three parts to `''` for a blank
   submission (`cph-number/validate.js:42`, `:101`) and already blanks all three
   parts on a rejected stored value (`:102`), so empty string is the shape this
   page's answer already takes for "no number". Writing it clears a number saved
   before, which the requirement asks for, because the canonical write merges
   the patch over the stored answers
   (`engine/write/pipeline/canonical.js:47-55`). The empty value reads as
   unanswered everywhere that matters: `isBlankValue` (`model/obligations/is-blank-value.js`)
   makes the addresses page offer the add link again
   (`addresses/controller.js:98`), keeps the review row blank
   (`check-answers/view-model/rows/summary-row.js`), and keeps the addresses
   task row short of fulfilled, which is what holds the submit gate
   (`flow/gates.js`, `bridge/readiness-config.js:27`). Checked against the
   animals backend: `cphNumber` carries no validation annotation
   (`NotificationBase.java:38`) and the outbox already treats a blank as absent
   (`LogisticsLocation.java:22-26`), so an empty value on the wire is accepted.
   Rejected: mapping a blank to `undefined`, which the canonical merge would
   write as an undefined key rather than a clearance.

8. **The help's second paragraph is split in copy around its link, and the link
   opens in the same tab with no new-tab suffix.** The house pattern for a
   sentence carrying a link is a prefix, the link text and the href as separate
   copy leaves composed in the template
   (`commodities/search/search.njk:90` over
   `commodities/copy/copy.en.js:29`). The design source renders a plain
   `govuk-link` with no `target`, so no "(opens in a new tab)" wording is added —
   adding it would change the sentence the criterion quotes. Rejected: the
   new-tab treatment the confirmation page uses
   (`confirmation/template.njk:51`), which the design source does not show here.
   Provenance: c-117.

9. **Each rule in the commodity-rules module keeps its own list of codes.** The
   ten poultry codes the new list names also appear in the package-count list
   (`services/commodities/rules.js:65-89`). Every rule in that module lists its
   own codes and they overlap freely, so the new list follows suit rather than
   extracting a shared poultry group, which would mean editing the package-count
   list for no change in behaviour. Rejected: a shared poultry constant, as
   widening the row's footprint.

10. **The characterisation oracles are edited by hand to the decision the new
    rule makes, and only where the new rule accounts for the difference.**
    `bridge/fulfilments.characterisation.test.js:36-38` holds the evaluator's
    whole output against
    `sets/live-animals/journeys/linear/fixtures/characterisation-oracles.json`,
    deep-equal and JSON-equal, so both the rewritten reason and the ostriches
    case leaving scope land in that file; there is no regeneration script in the
    frontend's `package.json`, so it is edited as the hand-maintained golden it
    is. The implementor reads the failure as the statement of what changed and
    moves the oracle to it only for the entries section 2 names; any other
    difference is a defect in the change, not an oracle to update. Rejected:
    loosening the test to ignore the obligation's reasons, which would throw away
    the one place the rule's recorded decision is pinned end to end.

11. **The spec says where the page sits in the journey once, in the vocabulary
    the code defines.** The row's detail calls the page "a step of the
    consignment addresses section", but `page.js:4` marks it `subPage: true` and
    the code defines a step as a page that is not a sub-page and belongs to a
    task row (`flow/navigation.js:13`), which is why the save-and-continue order
    skips it as a destination. The page capability's Purpose already says "it is
    not a step in the journey's order" (`spec.md:9`), which is true. So the
    Purpose keeps that sentence and says the rest as the row means it: the page
    belongs to the consignment addresses section, is opened from that page, from
    Overview and from a review Change link, and always returns to that page.
    Rejected: adding "is a step of the consignment addresses section" beside the
    sentence that says it is not a step in the journey's order, which is what
    this plan said before and which leaves the contract with two answers.
