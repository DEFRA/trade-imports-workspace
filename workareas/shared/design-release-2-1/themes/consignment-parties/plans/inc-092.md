## 0. Decisions

**D1. Criterion 1 is already true at this HEAD. No code change for it.**
The consignment addresses page's county parish holding section already carries the
heading, the description sentence and the link named in the criterion, and it
already sits after the place of destination section and before the permanent
address section. Proven now by
`src/server/app/sets/live-animals/journeys/linear/features/addresses/controller.test.js:313-326`
(the empty section's title, hint and add link), `:440-452` (the ordered list of
section titles: the five parties, then the county parish holding section, then
the permanent address section) and
`src/server/app/sets/live-animals/journeys/linear/features/addresses/fit/hub-picker.fit.spec.js:422-430`
(the rendered heading, description and single link). The whole live-animals unit
suite is green at this HEAD (121 files, 2139 tests —
`workareas/shared/design-release-2-1/themes/consignment-parties/logs/inc-092-plan-baseline-unit.log`).
So criterion 1 contributes spec and coverage wording only (section 8), not code.
Rejected: re-asserting it in a new test, which would duplicate two existing
proofs.

**D2. Criterion 3's "with a 'Change' link to the county parish holding number
page" on the review page is a defect in the row. It is not built.**
The design source settles the review page's Change links against it:

- `trace:prototype-dr2-1` p11-074: "The review's 'Addresses' card lists 'Place of
  origin', 'Consignor', 'Consignee', 'Importer', 'Place of destination' and
  'County parish holding (CPH) number', **with a Change link to
  roles-and-addresses**."
- `trace:prototype-dr2-1` p13-151: "The review's Consignment addresses section
  shows **one 'Addresses' card with a single Change link** and the name and
  address of Place of origin, Consignor, Consignee, Importer and Place of
  destination."
- The criterion's own citations do not support the clause. `trace:prototype-dr2-1`
  p13-120 is about the **consignment addresses** page, not the review ("After
  saving the CPH number the Consignment addresses page shows it as '12/345/6789'
  with a Change link to the CPH page") — it is criterion 2's evidence, cited
  twice. `prototype:dr2-1-specs` p3-109 is a **gap** claim ("The suite does not
  assert where each 'Change' link on the completed roles page leads"), so it
  refutes nothing and supports nothing. `prototype:dr2-1-specs` p4-037 and
  `trace:prototype-dr2-1` p13-154 support the **display** half only.

Building it would also contradict two things the service already has and proves:
the design doc at
`src/server/app/sets/live-animals/docs/page-design.md:82-84`
("Each card has one Change link, in its heading. Rows carry none, except 'Edit
details' on an address copied onto this notification.") and the passing fit test
at
`src/server/app/sets/live-animals/journeys/linear/features/check-answers/check-answers.fit.spec.js:432-452`,
which asserts every Change link sits in a card heading and that the review
renders no summary-row actions at all.

So criterion 3 is built as its evidence states: the review's county parish
holding row reads the saved number in the slashed form. The card's one Change
link, already pointing at the consignment addresses page, stands, and the county
parish holding section on that page carries the Change link into the county
parish holding number page — the route the design source shows. Rejected: adding
a row-level action to the review's county parish holding row, which no source
asks for, which the design doc forbids and which an existing passing test
refutes. Carried to section 7 as a design question if anyone wants to revisit it.

**D3. One owner for the whole shape of a stored county parish holding number —
its digits, whether they make a whole number, how they divide, and how it reads
on screen — in the county parish holding number feature.**
Two render paths in two features need the display form, and the feature's own
`cph-number/validate.js` already needs three of the same four things. So one new
module inside
`src/server/app/sets/live-animals/journeys/linear/features/cph-number/` owns all
of them, and the display path, the review path and `validate.js` all take what
they need from it (D4). The feature folder is the repo's stated home for a
feature's own rules (`src/server/app/sets/live-animals/docs/features.md`: "Each
feature is a vertical slice").
Rejected: a formatter in each of the two render paths (two owners for one display
rule); a formatter exported from `validate.js` (a module named for validation
mispredicting a display helper, and the wrong way round — validation is one of
the three callers, not the home); two new modules, one for the number's shape and
one for its display form, when the display form is the divided parts written with
slashes and belongs beside the division it is built from; a copy-file function
(copy files hold wording, and the slash is a number format, the same in both
locales).

**D4. `validate.js` keeps only its field names, its payload reading, its entry
rule for separators and its checks. Everything about the number's digits comes
from the new owner.**
Today `validate.js` holds a second copy of three rules the display also needs:

- the three part lengths, `:16-18`, paired with the page's field names at
  `:20-24`;
- normalising a value to its digits, `:26`;
- whether a value is a whole county parish holding number, `:28`;
- dividing a value's digits into county, parish and holding in order, `:30-40`.

After this change the new module owns all four and `:16-18`, `:26`, `:28` and
`:30-40` hold none of them. `:20-24` keeps the page's three field names and takes
the lengths from the owner, so the per-field length checks at `:68-82` still
state each box's own length. `:86-91` asks the owner whether the parts it joined
make a whole number. `:97` reads a stored value's ordered parts from the owner
and pairs them with its own field names. The payload reading (`:46-49`, `:56-61`),
the joining back into one answer (`:42`), the blank test (`:44`) and the answer
mapping (`:98-99`) are unchanged.

One thing stays in `validate.js` on purpose: the page's entry rule at `:51-54`,
that a whole number typed into the county box may be written bare or with spaces
or slashes and nothing else. That is the page's rule about what a trader may
type, spec'd at SCN-CPH-008-B, not a rule about a stored number's digits, and it
keeps its own removal of those separators before it asks the owner the
whole-number question. Routing it through the owner's normalisation instead would
widen it — a county box holding letters among nine digits would start being split
into three parts — which is a behaviour change this row does not want and no test
covers.
Rejected: giving the new module only the part lengths, which leaves the
normalisation, the whole-number test and the ordered division with two
implementations inside one feature folder; leaving all four in `validate.js` and
importing them from there, which makes a module named for validation the owner of
a display rule (D3).

**D5. A stored value whose digits do not make a whole number shows as stored, not
as blank and not slashed.**
That state is reachable and both display paths meet it (section 15). Showing the
stored text unchanged lets the trader see what needs correcting, matching how the
review already shows an address that breaks the address-book rules under its
error (`check-answers/view-model/rows/party-row.js:45-53`). The branch turns on
the owner's whole-number rule (D4), the same rule the county parish holding
number page's stored-value check turns on, so the page and the two displays never
disagree about which stored values are whole. Rejected: showing nothing (hides a
value the record holds); slashing a partial value (invents a shape the record
does not have).

**D6. The flow fixtures keep the slashed value they hold today, and no fixture
changes.**
`src/server/app/sets/live-animals/journeys/linear/flow/fixtures/happy-path.json:83`,
`flow/reachability-fixtures/seeds.js:18` and
`fixtures/characterisation-oracles.json:761` store `12/345/6789`. Those are read
by the shared FIT helper (`fit/live-animals-journey.js:500`, whose
`answerCphNumber` splits the value on `/` to fill the three boxes) and asserted
onward by `services/persistence/records/mapper-a-contract.test.js:85`. Stripping
them to nine digits would drag in the mapper contract test and the
characterisation oracle for no behaviour this row needs. It also costs nothing:
the display reduces a value to its digits before it slashes, so a stored
`12/345/6789` and a stored `123456789` both read `12/345/6789`. Carried to
section 7 as a follow-up.

**D7. No new copy key, so no new Welsh draft.**
The change adds no user-facing words. The separator is a number format, not
wording: the county parish holding number page's hint already shows the same
digits and slashes verbatim in both locales (`cph-number/copy/copy.en.js:5`,
`copy.cy.js:6`). The programme's Welsh invariant is therefore met with no copy
edit, and `copy-parity.test.js` stays green.

**D8. The tests repo keeps its nine-digit constant and gains a second one for
the displayed form.**
`domain/animals/constants/journey-options.ts:32-35` builds the nine-digit
constant from the three parts. That constant is what the backend stores and
publishes, and four specs assert it as such (the persistence, outbox, Dynamics
and admin seed-context specs). A second constant, derived from the same three
parts so the parts keep one owner, carries what the two pages show. Rejected:
renaming the existing constant, which would edit five further spec files for
naming alone and widen the row past its own behaviour.

**D9. Criterion 3 gets no new FIT test.**
Its value is proven precisely by the review view-model unit test, and on the real
page by the tests-repo end-to-end spec that already asserts that row. The row's
rendering path (a summary-list row's text) is already proven by the review's
existing FIT tests, and a new FIT test would have to walk the whole journey to
reach the review with a saved number. Rejected: a FIT walk, for its cost against
nothing it would add.

**D10. The no-JavaScript proof of the display is a test of its own, not an
assertion added to a shared helper.**
`cph-number/cph-number.fit.spec.js` asserts the landing on the consignment
addresses page in a module-scope helper, `:42-47`, reached from `:60-69` and so
from four tests (`:148`, `:154`, `:246`, `:252`) and once directly (`:215`) —
across both the JavaScript-on and the JavaScript-off describes. Putting the
displayed-value assertion in either helper would change what all five tests
prove, including two whose titles are about keeping typed digits, not about the
next page. So the owner of the new assertion is one new test in the file's
JavaScript-off describe (`:235-273`), built from the module-scope helpers that
are already there for filling the boxes and saving, plus the shared section
locator; it covers itself and no other test. The five tests above keep exactly
the assertions they have today.
Rejected: extending `:42-47` (five tests change, two titles stop stating what
their assertions prove); extending `:60-69` (four tests change, same problem).

**D11. The two comments in files this row edits go, and the one fact worth
keeping goes to the tests repo's docs.**
`tests/animals/e2e/features/all-operators.spec.ts:4-6` explains the api seed and
the journey walk — other modules — above a test declaration, and
`domain/animals/constants/journey-options.ts:26-29` is rationale for a constant
that also explains an assertion on another page. Both breach the house rules on
comments, and the tests repo's own `docs/animals-journey.md:3` says the same
thing for itself: "The code carries no comments, so the reasons live here." The
constant's fact is already recorded there verbatim at `:18`, so that comment is
deleted outright; the spec's fact is not recorded, so it moves into that doc
beside the other walk reasons (section 2). Rejected: leaving them because they
predate the row — this row edits both files for its own behaviour, so both meet
the rules in full; rewording them in place, which keeps rationale in code.

## 3. New files

**`src/server/app/sets/live-animals/journeys/linear/features/cph-number/<module>.js`**
The one owner of the shape of a county parish holding number, and of nothing else
(D3, D4). It owns:

- the three part lengths, in order — county, parish, holding;
- reducing a value to the digits it holds;
- whether a value is a whole county parish holding number, which is the rule the
  page's stored-value check and the display's branch (D5) both turn on;
- dividing a value's digits into the three parts in that order;
- the form a stored number reads in: its parts written with a slash between
  them when it is whole, the stored text unchanged when it is not, and nothing
  when nothing is stored.

It is not part of `validate.js` because that module is named for, and owns, the
page's validation, and validation is one of the three callers rather than the
home; it is not part of either render path because two render paths need the
display form and a display rule has one owner. Follow the structure of its
sibling `cph-number/validate.js`: a small module in the feature folder,
module-private helpers, named exports only for what another module needs.

**`src/server/app/sets/live-animals/journeys/linear/features/cph-number/<module>.test.js`**
Beside it, as `validate.test.js` sits beside `validate.js`.
