## 0. Decisions

1. **Reuse the shared `saveAndContinue` locator, don't invent a second one.** `fit/live-animals-journey.js:1458-1462` already exports `saveAndContinue(page)` as a GOV.UK "Save and continue" button locator, consumed by many other FIT specs as `saveAndContinue(page).click()` (e.g. `fit/live-animals-journey.js:890`). `hub-picker.fit.spec.js:121-127` and `party-edit.fit.spec.js:22-28` each define a same-selector local copy that already calls `.click()` itself. Fix: import the shared locator and append `.click()` at each call site; delete both local copies. Rejected: changing the shared export to click itself — it has many existing callers built on it returning a bare locator (`fit/live-animals-journey.js:1505` composes it into `.or()` chains), so changing its contract is out of scope and would break them.

2. **CPH number's own "press the only button" step is the same shared step, not a separate one.** `cph-number.fit.spec.js` presses its one button nine times via a local `SUBMIT_BUTTON` CSS selector (`form button[type="submit"]`), never through an accessible-name lookup at all. `expectPageEndsWithPrimaryAlone` (already asserted in this file, at the "ends with the primary alone" test) proves that button is the page's one "Save and continue" control, so it is the journey's shared save step under a different name. Fix: drop `SUBMIT_BUTTON` and press via the shared `saveAndContinue(page).click()` at every call site.

3. **CPH widths: extend the mechanism the error-styling check already uses, not a new one.** The notes' claimed line numbers (`cph-number.fit.spec.js:105-107`, `:121`) describing `toHaveClass(/govuk-input--width-\d/)` are stale — a prior commit on this branch (`5507d0cb`, "Design release 2.1 test hygiene") already replaced those and the `govuk-input--error` class checks with, respectively, a relative `boundingBox().width` ordering check and `govukColourOf(page, 'error')` + `toHaveCSS('border-top-color', …)`. The error-styling half of the AC is therefore already met. The widths half is not: relative ordering (`widths[0] < widths[1] < widths[2]`) proves an ordering, not the "two, three and four character widths" the AC asks for. Fix: read GOV.UK's own rendered width for `govuk-input--width-2/3/4` through the existing `measureReferenceElement` helper (`fit/live-animals-journey.js:142-165`) and assert each box's computed `width` against it with the existing `expectStyle` helper (`fit/live-animals-journey.js:128-132`) — the same pattern already used inline, file-local, by `additional-details.fit.spec.js:130-141`, `identification.fit.spec.js:1326`, `hub.fit.spec.js:364` and `transporters.fit.spec.js:82-87` (that last one names its own local wrapper, `govukTagStyleOf`). Rejected: promoting a new shared `govukInputWidthOf` beside `govukColourOf` — nothing else needs it yet, so a module-level export would be unused outside this one test ("build only what this change makes reachable"). The relative-ordering assertion becomes redundant once each box's exact width is proven against values that are themselves ordered 2.75em < 3.75em < 4.5em, so it is deleted rather than kept alongside the exact check.

4. **Part labels: locate by what Playwright calls them, not by their `for` attribute.** The current loop (`cph-number.fit.spec.js:118-131`) finds each label with `page.locator('label[for="${id}"]')` — a DOM-attribute selector, not an accessible-name lookup — then checks visibility and a clipped-width floor (`boundingBox().width > 1`). Fix: locate each label by its own text, scoped to the CPH fieldset group already found elsewhere in this test (`page.getByRole('group', { name: copy.cph.legend })`, as at line 95), i.e. `…getByText(text, { exact: true })`, and keep the `toBeVisible()` and clipped-width assertions unchanged. Rejected: dropping the clipped-width check in favour of `toBeVisible()` alone — GOV.UK's visually-hidden technique (`width:1px;height:1px;overflow:hidden`) keeps an element's bounding box non-empty and `visibility` not `hidden`, so Playwright's own `toBeVisible()` would still pass for a label hidden that way; the width floor is the one check that would actually catch it, and it is not a class-list check, so the AC does not ask for it to change.

5. **The error-styling note in `openspec/coverage/live-animals/journey-pages/cph-number/coverage.json` (SCN-CPH-001-A) says the test "asserts width classes"** — stale from decision 3 above, in a test this increment directly edits, so it is corrected in the same change (see §8). The sibling note on SCN-CPH-004-E ("all three boxes carry `govuk-input--error`") is equally stale but describes a test this increment does not touch (the error-styling test body is unchanged, already fixed by the prior test-hygiene commit) — left alone and listed as a follow-up (§7), since fixing it would widen this row's footprint into a file and function it has no other reason to edit.

6. **Tests repo needs no change.** The E2E equivalents already go through one shared step: `page-objects/shared/base-page.ts:271`'s `saveAndContinue` getter, consumed by `animalsPages.*.saveAndContinue.click()` throughout `tests/animals/e2e/pages/cph-number.spec.ts`, `tests/animals/e2e/features/address-book/addresses-picker.spec.ts` and the party-edit equivalent. None of them assert width or error styling by class. The row's `repos: ["frontend", "tests"]` is kept as given, but §1/§2/§3/§4 touch only `frontend`.
