# inc-216 plan: an unanswered row in an unfinished review card is left blank, with no red bar

Set: `sets/live-animals` (spec namespace `live-animals/`). The change is styling plus the markup of one value cell; frontend-change routes no recipe for it (no field, page, section, collection, obligation or flow change), so it is planned directly, with section 8 still applying.

## 0. Decisions

- **Claims checked against the live tree, all hold.** The bar is drawn by `.app-summary-list__value--missing` (`src/client/stylesheets/components/_summary-list-missing.scss:8-13`, a `border-bottom` in the error colour) on the wrapper span inside the answer cell, imported at `components/_index.scss:8`, and emitted only by `missingCell()` in `check-answers/view-model/rows/value-text.js:42-47`, whose single consumer is `blankEmptyRows` in `view-model/incomplete-cards.js:89-94`. The card-level marking (`app-summary-card--error` from `_summary-card-error.scss`, the "Complete <card>" error message and the error summary) is separate and stays. No other file in the animals repo, the germinal set or the tests repo references the class (repo-wide grep, section 12). Plants has no such class: animals only, as the row says.
- **Delete the stylesheet rather than neutralise it.** Once the cell stops emitting the class, the rule is dead; keeping it would be a second, unreachable mechanism. Rejected: keeping the wrapper span with no styling (a class with no rule is noise and leaves the test locating by a dead class).
- **The missing cell emits only the visually hidden "Missing"** (GOV.UK `govuk-visually-hidden`, escaped through the existing `escapeHtml`). No wrapper element. `missingCell` keeps its name and its export: it still returns the cell for a missing answer, and its doc comment ("no visible text, and a visually hidden missing for a screen reader") stays true, so it is neither reworded nor deleted. Rejected: renaming it — the name already predicts the return value.
- **No copy change**, so no Welsh draft: `copy.missing` / `Ar goll` are unchanged and still read by the screen reader. `copy.en.js:4` carries no "missing style" wording beside it, so nothing to edit there (the row's note anticipated one; there is none).
- **What proves AC2 (no red line beside or under an answer cell, desktop and phone).** The line was only ever drawn by the wrapper span inside the cell; the hidden child carries `govuk-visually-hidden`, whose mixin forces `border: 0 !important`, and the answer cell (`govuk-summary-list__value`) draws no bottom border of its own at either width — so a computed-border check on either reads `0px` with or without the change and proves nothing. Rejected: any computed-style assertion. Decided: AC2 is proved by an exact assertion of the answer cell's whole content — the cell holds the visually hidden "Missing" and no other element — at desktop and at phone width. With that true, no element exists in the cell that could draw the line; without the `value-text.js` edit the cell's content is the wrapper span and the assertion goes red.
- **One vocabulary: a blank cell with "Missing" announced for a screen reader, not a mark.** The spec's "marked missing" / "missing style" becomes "left blank" (section 8), so the same rename runs through every test title, helper and coverage entry this plan touches: the unit titles at `check-answers.test.js:785, 791, 797, 806, 869, 988, 1161`, the FIT titles at `check-answers.fit.spec.js:89` and `:427`, the FIT helper `missingMarker` (`:34`), and coverage.json's names, test-title links and notes. "Missing" as the word for an unanswered answer stays — it is what the screen reader announces and what `copy.missing` and the unit constant `MISSING_HTML` name — so titles such as "renders entered and missing answers in their summary rows" keep it. Card-level wording ("marks the card it names", "a marked card" meaning the card's red border and message) names marking that still exists and stays. Rejected: renaming only the spec and leaving the old titles (two vocabularies for one concept).
- **Stale coverage link repointed.** coverage.json:260 links SCN-CYA-002-A to a unit title ("Should anchor and name only the first document card while documents are unfinished, and mark the blank rows of every document card missing") that no test in the repo carries. Its successor is the unit test at `check-answers.test.js:869` (blank rows inside an unfinished documents card); the link is repointed at that test's renamed title, strength kept `partial`.
- **The "every blank row" FIT test asserts every blank cell.** On a just-started notification the arrival-details card's five answers (port of entry, arrival date, means of transport, transport identification, transport document reference — `view-model/cards/movement/arrival-details.js:27-41`) are all unanswered, so the edited test asserts the whole-content rule on every answer cell of that card, and its title states that. Rejected: keeping a first-cell assertion under an "every" title.
- **Bounded tidy-up in the edited test file.** `check-answers.fit.spec.js` is edited for the row's behaviour, so every house-rule breach in it goes: the doc comments on internal helpers (lines 32-33, 37-38), the history comment at 59 ("the old whole-code cap"), and the rationale/test-describing comments at 116-118, 144-145, 180-182, 209-211, 254-256, 402-403 and 424-426. All are deleted, not reworded; the rationale they carry is already in the spec or `docs/page-design.md`. `check-answers.test.js` has no comments, ids or history to fix beyond the title rename. `value-text.js`: the remaining doc comments sit on exported functions and state their contract, so they stay.
- **Phone and desktop proof lives in FIT, not E2E.** Gate phases are not restricted for this row, but the tests repo has no selector on the bar and no assertion of review-cell styling; FIT already drives the real rendered page with the compiled stylesheet, and the row's notes say no tests-repo change. The integration proof is the gate's tests-repo E2E rung, which must stay green (it exercises the review page through the stack); no new E2E spec is planned because nothing in the tests repo can observe the difference that FIT does not already observe in a real browser.
- **Spec wording.** The row's provenance (ruling 7a, designer review S34/S35) becomes behaviour: REQ-CYA-002's "drawing it in the missing style" becomes "leaving it visibly blank, with 'Missing' announced in its place for a screen reader". The requirement name and the scenarios' "marked missing" become "left blank" wording to match; IDs are kept and coverage links follow the renamed titles.
