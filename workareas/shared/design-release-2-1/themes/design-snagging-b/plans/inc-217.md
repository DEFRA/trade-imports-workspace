## 0. Decisions

1. **Port by hand, not by cherry-pick.** The stale commits (animals dc9c1e4f, 9fef3175; plants 4072036; tests 4ef38d0, d4d2ccc) were read in full as hints. They do not apply as written: the animals declaration on this tree renders only from the review's `step=review` POST (GET redirects to the review), its `render` carries the reviewed concurrency token, and its tests drive it through `declaration/test-support.js`'s stand-in GET. 9fef3175's controller guard, `outstanding.js` rewrite and their tests rest on submission records (`state.OUTSTANDING_HEALTH_CERTIFICATE`, `journey.outstandingItems`) that do not exist here; the row's notes keep them on the stale branch. So this row takes only: the confirmation copy (three strings, a new-tab hint), the confirmation template's two links, the declaration legend/small-checkbox/no-strip from dc9c1e4f and 4072036, and the wording and new-tab E2E from d4d2ccc. Rejected: `git cherry-pick` then revert hunks — it would bring the guard and the ITAHC rule and their stale-titled tests.
2. **How the strip is withheld on both declarations: through the mechanism `kit.base` already has.** `kit.base` draws the strip only when it is given the journey (`journeyStrip(journey, …)` returns null without one; animals `shared/kit.js:170,186`, plants `shared/kit.js:201,217`), and takes the journey id on its own through its `journeyId` option. The animals confirmation already uses exactly this (`confirmation/controller.js:26`, `base(copy.title, { journeyId: journey.journeyId })`), and plants `spec/decisions.json` (d-061) records it as how a page carries no strip. So each declaration's `render` passes `kit.base` the journey id, not the journey. What else that changes, checked against the tree: `hubHref` is kept (it comes from the id); `amend` is already null (neither declaration passes `request`); `amending` is read by no template in either repo (grep over `*.njk`); `concurrencyToken` from `kit.base` becomes null — animals already sets its own (the reviewed token, `declaration/controller.js` render), and plants now sets its own to the journey's concurrency token in the same place, which its template posts (`template.njk:19`). Rejected: (a) setting the strip to none in the view model after the `kit.base` spread — a second way of hiding the strip beside the one `kit.base` has; (b) a new `kit.base` option — a third switch for the same thing.
3. **The confirmation guard and the outstanding rule stay as they are** (unsubmitted → overview/hub; bullet shown only when no document was uploaded). The row's notes say so. The behaviour spec, however, already states the stale branch's guard (REQ-CONFIRM-002: to the declaration) and ITAHC rule (REQ-CONFIRM-006-B/C), with coverage links to tests that do not exist on this tree. That is a claim that does not hold: section 8 brings both requirements back to what the code does, and the follow-up names the row (overview-and-review inc-115, still `todo`) that will move them again.
4. **Page title.** The row calls the animals page "Notification submitted"; its H1 and browser title stay "Import notification submitted" (copy `title`/`panel.title`). The criteria change only body wording and links, not the title. Plants' confirmation page has none of the changed strings (no outstanding section, no HMRC links, no view-or-amend body), so it is untouched; plants takes only the declaration half, as the row's detail says.
5. **The new-tab hint is a new rendering the row asks for: visually hidden inside each HMRC link.** No existing feature hides the hint. The three existing renderings all show it: commodities search puts `lookupNewTab` visibly inside the link after a `<br>` (`commodities/search/search.njk:84`), and documents (`documents/copy/copy.en.js:30`) and transport (`transport/copy/copy.en.js:102`) write "(opens in a new tab)" into the visible link text. The row asks the HMRC links to keep their visible text and say so to screen readers, so the confirmation adds a hidden-span rendering, with the hint string in the confirmation feature's own copy (en and cy; Welsh draft beside it, following the machine-draft header already on the file). Shared copy has no new-tab string and the programme invariant forbids rewording shared copy; one shared string and one pattern across all four renderings is a follow-up (section 7).
6. **The legend is feature copy** in each declaration's `copy.en.js`/`copy.cy.js`, value "Declaration confirmation" with a Welsh machine draft. No copy-literal unit test: the rendered group name is asserted in FIT through the copy key and in E2E through the literal, so the literal is proven where it is seen.
7. **Bold date.** The date value (not the "Date of declaration:" label) is wrapped in `<strong>` inside the existing `govuk-body` paragraph, in both templates. No copy change. Rejected: `govuk-!-font-weight-bold` on a span — `<strong>` is semantic and already the house idiom (`confirmation/template.njk:5`).
8. **Where the "no strip" tests live in animals.** In `journey-strip.test.js`, the home of "which page draws the strip", rendering the declaration through the review's stand-in GET. Rejected: `declaration/controller.test.js` — editing it would pull in a rewrite of its `kit.base` mock (`currentConcurrencyTokenDiffers`, which mocks an own module) that is wider than this row (follow-up).
9. **Animals `render` positional boolean.** `declaration/controller.js`'s `render` is touched (strip), and it takes `recoverableError` as a trailing positional boolean after a positional `errors`. Per the house rules, it takes them as an options object, matching plants' `render` (`plants declaration/controller.js:30-36`). All callers are in the same file.
10. **"No strip" proven positively.** Every new assertion proves what shows instead: the first element inside the page's content column is the "Declaration" H1 (animals) / the H1 (plants, whose section caption renders nothing on this page). The view-model unit tests assert the strip's exact value (`null`).
11. **E2E homes.** Animals declaration: `tests/animals/e2e/pages/declaration.spec.ts` (draft and amendment). Animals confirmation: a new page spec and page object, following `declaration.spec.ts` and `declaration-page.ts`. Plants: `tests/plants/e2e/features/review.spec.ts`, where the plants declaration tests already live (no seeded plants flow exists; it walks the UI). Rejected: extending `amend-resubmit.spec.ts` — it owns the amend-and-resubmit journey across pages, not one page's layout; a seeded amendment (`createAmendNotification`) in the declaration page spec proves the amendment declaration's layout with less set-up and keeps each spec to one concern.
12. **The route from a seeded notification's review to its declaration is a `to*` method on the animals journey flow** (`flows/animals/journey.ts`), per `docs/best-practices/playwright/BEST_PRACTICES.md` ("A spec reaches its page through a `to*` method on its domain's journey flow"; "A sequence of steps used by two specs becomes a `to*` method on the journey flow"). It opens the current notification's review (the seeded journey records the reference in the `JourneyContext` both fixtures share, as `toAdditionalDetailsOfCurrentNotification` relies on) and reuses the journey's existing review-to-declaration steps, which `fromOverviewToDeclaration` and `submitFromReview` repeat today: that shared part is extracted as one private step they all call, ending on the declaration heading. Rejected: a step on `AnimalsNotificationActions` — not the journey flow the guide names.
13. **Plants declaration copy's provisional status goes to the doc that records provisional copy.** This row adds new provisional plants copy (the legend, with a Welsh machine draft), and `high-risk-plants/docs/copy-status.md` ("Every page's copy below is provisional until a content designer reviews it") has no declaration row. So the doc gains a declaration row covering the statements and the legend, and the "Provisional plants statements pending content review." comment leaves both plants declaration copy files. The `MACHINE-DRAFT Welsh` header on `copy.cy.js` stays: the doc names that header as the mark of a machine-draft file.
