## 0. Decisions

1. **Where the split lives: the page's `fromPayload` in `cph-number/validate.js`, not `normalise` and not the controller.** `pageValidation` (lib/validate/page-validation.js:24) documents `fromPayload` as "Reading a submitted form"; `toAnswers` is applied to the values `fromPayload` returns (page-validation.js:51-54), while `normalise` only changes what the rules read (page-validation.js:23, 39) and would leave `toAnswers` joining `'12/345/6789' + '' + ''` into a slashed stored value. Rejected: `normalise` (wrong value saved), a controller pre-step (a second mechanism beside `pageValidation`, and the "Save and return to overview" reading would miss it). Because the split lives in `fromPayload`, every submit path that goes through `validation.onSubmit` gets it.
2. **What counts as a whole number in County:** Parish and Holding are both empty after trimming, and County with every space and slash removed is exactly nine digits. Anything else (e.g. `1234`, `12a456789`, nine digits in County with Parish filled) is read exactly as today, so today's per-part errors and echoed values are unchanged. Rejected: stripping every non-digit (would silently accept `12a3456789`-style typos, and contradicts the row's note "spaces and slashes").
3. **Slicing reuses the existing 2/3/4 split** (`splitStored`, validate.js:28-38, which already owns "nine digits → three parts"); the new whole-number recognition is one named helper beside it, called from `fromPayload`. One rule, one owner: the 2/3/4 slicing is not written twice. The implementor may rename `splitStored` so its name no longer says "stored" now that it serves both readings — a rename covers every use in the file.
4. **No client script.** Removing `maxlength` and splitting on the server meets "nothing typed or pasted is lost" with JavaScript on or off; the repo has no client script touching the CPH page today (`grep -rn -i "cph\|\.focus()" src/client` hits only the autocomplete's own button), so "no automatic focus move" is already true and is pinned by tests, not built. The prototype's digit filter and paste-spreading stay with waiting-on-design inc-093 (provenance).
5. **Row claim that does not hold — AC4's "and the consignment addresses page shows it as 12/345/6789".** The clause is not backed by its cited source: req-2122 is about how the number is entered and saved and says nothing about display. It is contradicted by the spec, SCN-CPH-007-A ("the CPH section shows the nine digits"), by the code (the addresses hub renders the stored value raw, `features/addresses/controller.js:60-66`) and by the e2e `cph-scope.spec.ts:31`, which asserts `123456789`. No backlog row delivers a slashed display on the addresses hub: overview-and-review inc-108's criterion covers the review page's Addresses card only. This plan therefore narrows AC4 to what holds and what this row changes — the number is saved as `123456789`, and the addresses page's CPH section shows the nine digits `123456789` — and records the slashed addresses-hub display as its own follow-up backlog item (section 7), recorded as a departure from the row in section 14. Rejected: adding a CPH display formatter here (a display change with no source behind it, outside the row's entry-and-save behaviour, and it would make SCN-CPH-007-A untrue on a claim the spec does not hold).
6. **AC1 (three labelled boxes as drawn) already holds** apart from the `maxlength` cut-off: the page already renders three visibly labelled boxes in one `govuk-date-input` row with `govuk-input--width-2/3/4` and `inputmode="numeric"` (template.njk:50-89), which is the GOV.UK rendering of the prototype's partial (p9-011). No layout or class change. The prototype's `pattern`/`autocomplete` attributes and the hint wording belong to consignment-parties inc-091 (row notes) and are left alone.
7. **AC8 (Welsh):** this row adds or changes no string — labels, hint and errors stay as they are in copy.en.js / copy.cy.js — so no copy file changes and no machine-draft Welsh is needed. Rejected: adding a hint about pasting (not asked for, and the hint wording belongs to inc-091).
8. **"Paste" in tests** is driven as a single text insertion into County (one input event carrying the whole string, as a paste delivers), with JavaScript on and off; Playwright's clipboard paste needs browser permissions the FIT/e2e projects do not grant. Typing "straight through" is driven key by key, so the old `maxlength` would have dropped keystrokes 3–9.
9. **Not routed through frontend-change recipes:** no field, page, section, collection, obligation or journey-flow change. `sets/live-animals/docs/add-a-field.md:26-28` already names this page as the exemplar for "a field that normalises input before it saves", which this change keeps true. Section 8 still syncs the spec.
10. **Rationale leaves the template and validate.js; history leaves the test titles.** The files this row edits carry rationale comments (template.njk:16-17, 32-36 — now stale, it names "the maxlengths" — and 43-45; validate.js:46-48, 73, 77, 93-94; controller.test.js:82-85, 140-141). House rules: rationale goes in the repo's docs, a stale comment is deleted. Each is deleted; where its rationale is not already in `sets/live-animals/docs/page-design.md` "## CPH number", that section states it (group-level single error, date-input row used for layout only, no character limit and server split, focus never moved). Two test titles in the edited test files narrate history ("legacy" at validate.test.js:50, "still carries" at controller.test.js:142); both are retitled to state what they prove now — a stored value with slashes is read as its parts — with no history word (section 4).
11. **The FIT hint test keeps only its positive assertion.** cph-number.fit.spec.js:109 proves the old grouping's absence with a `toHaveCount(0)`; the accessible-description assertion at line 108 already proves the hint exactly. The absence line is deleted and the title states what remains proved: the group is described by the hint. Rejected: keeping it (a removal proved by absence breaks the house rule).
