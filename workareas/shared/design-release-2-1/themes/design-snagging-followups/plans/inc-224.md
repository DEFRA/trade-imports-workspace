## 0. Decisions

- **What Enter does (from Sam's ruling of 26 Oct, recorded on the row).** Enter in a field of a card for several animals saves that card as its own in-card button does, and the trader stays on Identification details with the entry kept. Implemented as: Enter presses the page's hidden default button; that post reads and validates every card form, species of several animals included, saves every form holding a value, and returns to Identification details when any form saved was for a species of several animals.
- **Every typed card, not only the focused one.** Without JavaScript, an implicit submission cannot tell the server which field held focus: the browser presses the form's first submit button. Saving every card holding a value is the only server-side reading that meets "nothing typed is ever dropped" with and without JavaScript. Rejected: a client script that routes Enter to the focused card's own button. It would be a second mechanism beside the form post, and fails the no-JavaScript invariant.
- **Errors block the whole post.** An invalid value in any card read by Enter re-renders the page with every typed value kept and nothing saved, through the existing refusal render. Rejected: saving the valid cards and refusing the rest, which would need a partial-save path the controller does not have.
- **Enter with only one-animal cards typed** goes onwards as Save and continue does (hub, next run step or check your answers under change context). The ruling covers cards for several animals; one-animal cards keep their current Enter behaviour.
- **Enter with nothing typed** goes onwards as before. The empty-form guard applies to a card's own button only, and stays so.
- **The hidden button's action value names what it is, not "finish".** The value was "finish", which no longer describes a post that may stay on the page. The WIP uses a value naming the implicit submission; keep it. The hidden button keeps its existing copy text: it is aria-hidden, visually hidden and out of the tab order, so no user reads it.
- **The action literal stays inline** in the template and in the tests, as the card's add and remove action values already are (`_identification-card.njk:64`, `card/view-model.js:54`). Rejected: a shared constant for this action alone, which would be a second convention beside the existing one.
- **One owner for "this line holds one animal".** forms.js now asks it in two functions (which lines the page's save buttons read, and whether Enter stays). Extract one helper in forms.js that both call, so the rule has one owner. Rejected: leaving the composed expression repeated.
- **Not routed through frontend-change.** No field, page, section, collection, obligation or journey-flow change: the page order and the pages offered are unchanged, only what one submit does. Section 8 still applies.
- **The unit test that pinned the drop as a safe default is replaced**, not kept beside the new one (row AC 3).
- **The row's claims hold** against the tree at the parent of the WIP: the hidden button posted "finish", forms.js read only one-animal lines for it, and the controller test pinned the drop.
