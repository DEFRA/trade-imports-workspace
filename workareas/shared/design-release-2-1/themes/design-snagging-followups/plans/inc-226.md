## 0. Decisions

1. **"Four places, both domains" are these four declaration tests.** The animals FIT (`declaration.fit.spec.js:95-116`), the plants FIT (`declaration.fit.spec.js:41-66`), the animals e2e (`tests/animals/e2e/pages/declaration.spec.ts:24-37`) and the plants e2e (`tests/plants/e2e/features/review.spec.ts:120-133`). Each has the legend class, the small-checkbox class and the 700 font weight. Checked against the live tree: the claim holds.
2. **The declaration screenshots mask the date; the bold date is proved by the date's semantic element.** The tests repo already has a mechanism for date-dependent screenshots, `freezeDatePickersAt` (`utils/frozen-date-picker.ts:33-45`, README Visual Regression Tests, the calendar paragraph at :367-370). It is not used here, for this reason: its contract (its doc comment) is that date *pickers* behave as though today were a fixed day. It stops the browser clock and moves each picker's served `data-min-date` / `data-max-date` attributes before the picker script reads them. It never changes text the server has written into the page. The declaration date is that kind of text: the server renders today's date inside a `<strong>`, and the browser clock does not reach it. Showing a frozen date there would mean rewriting the visible text of the element being photographed, a second purpose the helper's name would mispredict, so in effect a second mechanism. The AC allows a mask, and the README's existing rule (mask what a run makes different, `README.md:362-365`) already covers it. What masking gives up: no screenshot shows the date's weight. That is carried instead by the FIT and e2e "date in bold" tests, which keep proving the date is the line's strong-emphasis text (Playwright's `strong` role, carried by the `<strong>` element) with the date pattern, and drop only the computed `font-weight`. That keeps SCN-DECLARATION-001-B and SCN-PLANTS-DECLARATION-001-B full (red with the `<strong>` removed). Rejected: extending `freezeDatePickersAt` to rewrite page text (above); freezing the server clock (no mechanism, and production work this row does not need). If the installed Playwright has no `strong` role, the fallback is the `strong` element locator scoped to the date line, still element semantics, not class or CSS.
3. **"Not shown on screen" and "small" for the declaration confirmation are proved by the new declaration screenshots.** The FIT and e2e tests keep the group found by its accessible name ("Declaration confirmation") and the checkbox by its label. Playwright's `toBeVisible` passes a visually hidden element (1px clipped box), so no non-visual assertion can prove the legend is off screen; the screenshot does, and decision 14's probe proves it would go red.
4. **Screenshots are full page with the status strip masked, following `origin-of-import.visual.spec.ts`.** The declaration page has no status strip (REQ-DECLARATION-007), so its screenshots mask the date of declaration instead (the page object's existing `dateValue`). Rejected: element screenshots of the hub totals and the identification card. The hub totals have no wrapper element of their own (`hub/template.njk:8-24` is a heading plus a grid row), and a full page also covers the hub's button pair and the card's place in the page.
5. **Refused review at phone width uses a phone viewport literal in the review visual spec.** Only that spec needs one. It matches the FIT's `PHONE_VIEWPORT` width (360px) so the two suites look at the same layout. Rejected: importing `scanViewports` from `fixtures/a11y.ts` (an accessibility-fixture concern) or promoting a constant to `fixtures/visual.ts` before a second visual spec needs it.
6. **Reaching each screenshot state.**
   - Declaration (animals): seeded draft then `toDeclarationOfCurrentNotification`, as the animals declaration e2e spec does.
   - Declaration (plants): `completeNotification` then `toDeclarationFromReview`, as the plants review e2e spec does.
   - Hub totals: the new Overview-with-saved-counts journey step (section 2, tests `flows/animals/journey.ts`).
   - Identification card: a **Felis catus** line declared as two animals with one saved, through `toAnimalIdentificationWithCounts([{ species: 'Felis catus', animalCount: 2 }])` (`flows/animals/journey.ts:408`), then the first cat saved with the canned values `animal-identifiers-conditional.spec.ts:21-31` already uses (passport, owner name, permanent address, phone, email). The card then shows the second animal's entry form, whose labels are the Microchip, Passport and Tattoo identifier labels whose 400-weight assertion is dropped (`identification.fit.spec.js:1018-1037`, a Cat line), above the saved-animals table. Rejected: a cattle line (the exemplar FIT at :985-1007), which shows an ear tag field and none of those labels.
   - Refused review: seeded `'unlocked'` draft, opened on the review, Continue pressed (as `notification-view-states.spec.ts:44-51` does).
7. **The arrival-transit hint check goes back to a relative comparison**, as `9c344032` had it: the lead-in and every list item are compared with the document reference hint's colour read in the browser at run time. The `computedStyle` helper that test used no longer exists (`fit/live-animals-journey.js` has none). With one caller, the read lives in the test, not in the shared helper (house rule: build only what is reachable; a value used by one function lives there).
8. **`GOVUK_BLUE` and `GOVUK_SECONDARY_TEXT` are deleted from `fit/live-animals-journey.js`.** After this change nothing imports them (checked: hub and arrival-transit are their only users). `expectStyle` stays: `type-ahead.fit.spec.js` still uses it and `docs/testing.md:45` documents it.
9. **The identification card's green-button test is deleted, not rewritten.** It proves only appearance (the GOV.UK primary green); the identification screenshot now shows the card button, and no spec scenario links to it. The label test keeps its label text and empty-description assertions and drops only the 400 weight; the identification screenshot shows those same labels (decision 6).
10. **The review page's refused-card class (`app-summary-card--error`, check-answers FIT :439-441 and :469-471) is deleted.** The card is still proved marked by its own error message text inside it. The red left border (SCN-CYA-002-C) moves to the refused-review screenshots at desktop and phone width, probed by decision 14.
11. **The save-controls helpers change in both twins, and so does the one caller title that names the old proof.** Animals `expectThreeSaveControls` / `expectPageEndsWithPrimaryAlone` and plants `expectThreeSaveControls` find the controls by role inside the journey form and prove their order, with no `govuk-button-group` class and no sibling XPath. The plants twin is not named by the AC but carries the identical rule (programme invariant: plants changes with animals). The private `buttonGroupOf` in animals is deleted with it. The animals caller `consignment-details.fit.spec.js:375` is titled "…in the button group, then Cancel and return to overview": it is retitled to the role-and-order behaviour the helper now proves, and its two coverage links carry the new title (section 8). The other callers' titles ("ends with the primary alone…", "offers the three save controls") stay true and are unchanged. The side-by-side / own-line layout of SCN-FLOW-014-A stays proved by the unit test `save-actions.test.js` ("Should put Cancel and return to overview on its own line below the two buttons"), so the FIT link for that scenario becomes partial and the scenario stays full.
12. **Scope stays the row's named assertions.** Other class and CSS assertions in files this row edits (arrival label `govuk-label--m` at `arrival-transit.fit.spec.js:211`, transit remove-cell `text-align` at :835, the hub's `govuk-button--secondary` check at `hub.fit.spec.js:355`, the caption wrap measurement at `hub.fit.spec.js:447-463`, `expectOnlyHiddenMissing`'s class check at `check-answers.fit.spec.js:47`, `identification.fit.spec.js:394`'s class locator) are not in the row; each would need its own screenshot or rewrite. They go to follow-ups (section 7). Rejected: widening into them, which would add screenshots the AC does not ask for.
13. **Baselines are written against the leased stack with the tests repo's own scripts:** `test:visual:update:macos` (darwin) and `test:visual:update:linux` (linux, via `bin/update-visual-baselines-linux.sh`, a `docker run` against the running stack, not a compose project), each narrowed to the new spec files. Neither starts, stops or rebuilds the stack.
14. **The screenshot invert probe is required work, with a recorded red and green result.** For each of these screenshots: animals declaration, plants declaration, refused review at desktop and refused review at phone. Method: temporarily alter the page in the test just before the screenshot (declarations: strip the small-checkbox modifier, then separately the legend's visually-hidden class; refused review: strip the card's error modifier), run the spec with `test:docker-compose:visual -- <spec>` to a log file and see it go red; restore the test and run again to see it green. Each red and green run is written to `logs/inc-226-probe-<screenshot>-<red|green>.txt` under this theme's workarea. The probe edit is never committed. If a probe stays green, the screenshot is fixed (its framing, mask or threshold) until the probe goes red; the plan has no branch where these links stay partial. Their coverage links are written full (section 8). The Overview totals and identification screenshots are added as partial links to scenarios other tests already keep full, so they need no probe.
