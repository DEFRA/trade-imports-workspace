## 0. Decisions

1. **Mirror, not share.** Plants gains its own copies of animals' two client helpers (the fold-for-search module and the escape-and-bold module, `repos/trade-imports-animals-frontend/src/client/common/helpers/search-fold.js` and `bold-matches.js`), with the same exported names, contracts and behaviour. The twin repos have no shared package. "One rule, one owner, mirrored in each twin repo" is what the house rules ask for. Rejected: a shared npm package, which is new infrastructure no row asks for.
2. **The plants autocomplete stops owning matching and bolding.** Its local escape, regex-escape, normalise and bold-pieces functions, and the `MATCH_CLASS` and `HTML_ESCAPES` constants, are deleted. It filters and bolds through the two helpers, exactly as animals' `accessible-autocomplete.js:23-33` does. Rejected: adding folding inside the plants autocomplete. That would make a second owner of the matching rule beside animals' helper, and leave a regex bolder that cannot map folded positions back.
3. **The row's data claim is wrong, so the proof uses real data.** The row says typing "Cote" finds "Côte d'Ivoire". On the live tree:
   - the captured reference data names that country "Cote d'Ivoire", with no accent (`plants-frontend …/_capture/fixtures/countries.json:279`, stub `countriesResponse.json:6758`);
   - it is not in the SPS origin list that the plants (and animals) origin page offers (`countries-origin.json`, and the tests repo's copy, have no "Ivoire");
   - no captured country, subdivision or port name holds an accented letter.

   So "Côte d'Ivoire with 'Côte' in bold" holds only for an option that carries the accent. The plan proves it in the plants unit test, with a jsdom select holding that option (mirroring animals' `accessible-autocomplete.test.js:26,84-94`). On the real stack and in FIT, the observable form of "matching ignores case and accents" is the other direction: an accented query finds a plain name. The plan's integration proof types "Réunion" and expects the origin list's own "Reunion" (subdivision FR-LRE, `countries-origin.json:65` in both repos) to be offered, with "Reunion" in bold. Plants today lowercases "réunion" and finds nothing, so this test is red without folding.
4. **"Party country" is not a type-ahead.** The AC lists "place of landing, genus, party country". Plants has exactly three `appAccessibleAutocomplete` uses: origin country (`origin/template.njk:21`), place of landing (`arrival-details/template.njk:31`) and genus (`commodities/details/details.njk:37`). The party-edit country is a plain `govukSelect` (`party-edit/party-edit.njk:78`), with no enhancement and no client-side matching, so it has nothing to fold. The invariant is met by the three real type-aheads. Rejected: turning the party country into a type-ahead, which is a design change no source asks for.
5. **One FIT case per type-ahead covers "every plants type-ahead".** The FIT spec's per-type-ahead table gains an accented-query case. It runs the same assertion shape as the existing bold test, so all three type-aheads are proved through the one mechanism. Data, all from the captured fixtures or copy:
   - country: typed "Réunion", suggestion "Reunion", bold "Reunion";
   - place of landing: typed "Dóv", suggestion "Port of Dover - GB DVR", bold "Dov";
   - genus: typed "Cást", suggestion the English Castanea genus label, bold "Cast".

   Rejected: unit-only coverage, which would not prove the three pages load the enhancement with folding.
6. **Spec placement.** The accent scenario goes under the existing origin requirement for the searchable country field (REQ-PLANTS-ORIGIN-002), and that requirement's text gains "ignoring case and accents" and the bold letters. The AC names the origin spec. Arrival-details and commodity-details state only "searchable field", with no matching rule. Adding the rule there is listed as a follow-up, not done here.
7. **The two fixed-appearance FIT assertions in the edited file are fixed here, through one reader.** Both sit in the file this row edits and break the programme invariant ("Appearance is proved by screenshot tests in the tests repo, accessible names, or GOV.UK values read at run time, never by fixed colour, size or class assertions"):
   - the focus-indicator test asserts a fixed `outline-width` of `3px` and a `box-shadow` pattern (`type-ahead.fit.spec.js:292-304`);
   - the no-JavaScript test asserts the label's `govuk-label--{m,s}` class (`:196-198`).

   **One home for every GOV.UK reference measurement:** the existing reader `govukInputStyleOf` (`type-ahead.fit.spec.js:332-346`), which already builds a reference element with GOV.UK classes and reads its computed style. It is extended with two options: focus the reference before reading, and build a reference of a given element type (an input by default, a label for the label-size case). Colours are still read through the fit helper's `govukColourOf` (`fit/high-risk-plants-journey.js:76`), which the spec already imports.
   - Rejected: copying animals' `measureReferenceElement` (`animals type-ahead.fit.spec.js:420-443`). Animals has it because it also defines `govukColourOf` locally. Plants already has a reference-element reader in the fit helper, so a copy would put a second one beside it.
   - Because the extended reader then measures labels too, "Input" in its name no longer predicts what it reads. The implementor renames it so the name covers any GOV.UK reference element, under the house naming rule, and every caller in the file follows.
   - The focus test compares the enhanced input's outline width and inset shadow with a focused reference GOV.UK input's. Where the reference shadow's colour (its own text colour) differs from the enhanced input's, the test compares with the enhanced input's own text colour, read at run time, swapped in. That swap lives inside the focus test, its one user, not at module scope.
   - The no-JavaScript test compares the label's computed font size and weight with a reference GOV.UK label of the row's size (`govuk-label govuk-label--{labelSize}`), read at run time. The reference is measured in the JavaScript-enabled `page` the test already has open on the same page, so the measurement never depends on script running in the no-JavaScript context. GOV.UK label sizes do not depend on JavaScript.
   - Only the animals twin's copy of the label-class assertion (`:251-253`) stays a follow-up: animals is not branched for this row.
8. **The empty placeholder file goes.** `src/client/common/helpers/.gitkeep` is deleted, because the directory now holds real files.
9. **Plants `bold-matches.js` departs from animals' layout on single-use literals.** Animals' file keeps `HTML_ESCAPES` at module scope though only `escapeHtml` uses it, and `MATCH_CLASS` at module scope though only `strongMatch` uses it. The plants file keeps the escape map inside the escaping function and the bold class inside the function that wraps a match, per the house rule "A literal value used by one function lives in that function." Exports, contracts and behaviour still match animals. Rejected: a byte-for-byte mirror, which would bring the breach into a file this change creates. The animals copy is a follow-up.
10. **The E2E test's expected name is a constant copied from the canned data, beside the test.** It is copied from `resources/reference-data/countries-origin.json:65` ("Reunion") and sits with the existing copied constants in `origin.spec.ts:11-15` (`FRANCE`, `NORWAY` and the rest). Rejected: a new by-code bare-name reader in `reference-data.ts`. Its `subdivisionByCode` (`:39-47`) returns the "<subdivision> (<country>)" display and `countryAndSubdivisionNames` (`:56`) returns every name, so a new reader would be a function for one test, and the file's own neighbours use copied constants.
11. **The plants testing doc is brought up to date, not departed from.** `testing.md:99-101` and `:106-107` forbid `box-shadow` and pixel sizes in a fit spec and allow only colours read from a token. The rewritten tests compare a shadow, a width and a font size with a GOV.UK reference read at run time, which is what the programme invariant allows and what the typography and error-border tests already do. The doc is corrected to state that rule (section 12). Rejected: recording a departure, which would leave the doc forbidding what three tests in the file already do.
