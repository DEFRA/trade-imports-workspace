## 0. Decisions

1. **The open question is settled.** Sam ruled (26 and 27 Oct) that Notification submitted lists the ITAHC as owed whenever no ITAHC was uploaded, whatever other documents were. The row's "if no, close the row" branch does not apply.
2. **Only a document whose type is the ITAHC counts.** A veterinary health certificate, or any other type, does not clear the reminder. An earlier spec version (workspace commit `0e7e5fed`, parent) counted "an ITAHC or health certificate"; the ruling names the ITAHC alone, so that wider reading is rejected.
3. **A recorded document entry of type ITAHC counts as uploaded.** Its completeness flag from `collectionView` is not consulted: a notification only reaches Notification submitted once its documents passed submission. Rejected: requiring `complete`, which adds a second condition no criterion asks for.
4. **The ITAHC type code is a literal inside the one function that owns the rule** (`outstandingItems`, `confirmation/outstanding.js`). The document-type list in `services/document-types/stub.js` is option data for the select, not a shared constant for business rules; importing from a stub into a feature rule is rejected. If a second rule ever needs the code, that change extracts it.
5. **Integration proof covers the new case only.** One tests-repo E2E walks the UI journey uploading a veterinary health certificate (the only way to get a non-ITAHC document onto a submitted notification: the seeded journey's form client cannot upload files) and reads the reminder on Notification submitted. The ITAHC case (no section) is proved by the controller unit test and the existing template test, not by a second full UI walk with upload and virus scan. Rejected: a second E2E walk, for suite cost, when the template's guard already has an exact-heading-list test.
6. **The commodity selection criterion is a FIT test on the search page reached through the opening sequence** (origin answered with Save and continue, landing on What are you importing?), using the shared `expectThreeSaveControls` helper, which finds the three controls by role and order inside the journey form. The existing search FIT specs open the page from Overview, which is not the scenario's GIVEN. Rejected: adding it to the existing `commodity search` describe, whose `beforeEach` opens from Overview.
7. **The journey-flow criterion is a spec-wording reconciliation plus proving tests, not a code change.** The written basis for this reading is the repo's own validation doc, `src/server/app/docs/validation.md:41-44` ("A required Joi rule can block a malformed or blank page save … saving an optional blank is allowed, while submit readiness still reflects every in-scope mandatory obligation"), and the page recipe, `sets/live-animals/docs/add-a-page.md:124-127` ("A page with no required rule accepts a blank on both buttons"). Checked against the live tree (identical to `origin/main`): Arrival details' page checks (`transport/port-of-entry/validate.js:36-55`) require no answer — `oneOf` allows a blank means of transport (`lib/validate/validators.js:169-176`) — so Save and continue and Save and return to overview both accept a blank means, and Save and return lands on Overview with no error (`port-of-entry.controller.test.js:225` already proves the empty-page case). The row's claim that SCN-FLOW-004-G is "against the same-checks rule" holds only on a reading where "a missing answer" means any answer the task needs; REQ-FLOW-004's own scenarios (C, E) show it means an answer the page itself requires. So REQ-FLOW-004's text is tightened to say that, and SCN-FLOW-004-G keeps Overview with no error, now stated as the same outcome Save and continue gives. Rejected: making means of transport required on the page, which changes behaviour no ruling asks for and breaks the soft-save design the other arrival scenarios rely on.
8. **SCN-FLOW-004-G gets two proofs:** a frontend unit test on the arrival page's post (fast, proves the save and redirect) and a tests-repo E2E beside the other arrival details soft-save test (proves Overview, the task status "To do" and the port shown on re-opening through the real stack). Only the E2E proves the task status, so it is the full link.
9. **No plants change.** The plants frontend's submitted page has no "Before the consignment is imported" section (grep for its copy finds nothing under `sets/`), and criteria 2 and 3 change no behaviour. The programme invariant on plants parity is kept by there being nothing to mirror.
10. **No Welsh change.** No English string is added or changed; the existing `copy.outstanding.documents` line ("upload the ITAHC and any other required documents") and its Welsh draft stay as they are.
11. **Every class locator in `search.fit.spec.js` goes, because the change edits that file.** Lines 22 (used at 181 and 234), 42, 125 and 207 locate by GOV.UK class; each becomes a role, label or visible-copy locator. The id locator `#commodity-selection` (line 46) stays, with its reason in section 2. Rejected: changing only the back link, which leaves the file breaching the testing rule it is edited under.
12. **The arrival unit test's home is the existing means-of-transport describe** (`port-of-entry.controller.test.js:42`, with its `useStubbedJourney` set-up), because the test is about what that page does with the means of transport. Rejected: the arrival-date window describe (line 148), which is about the date bounds and fakes the clock; and a new describe, which would be a second group for the same concern beside line 42.
13. **The E2E arrival test re-opens through the shared `overview.openTaskAfterReopening`, and the two inline copies of that helper's body in `soft-save.spec.ts` go in the same change** (lines 85-86 and 120-121), as the test-support rule asks once a helper exists.
14. **`validation.md:46-48` is brought into line with the tightened REQ-FLOW-004.** Its "A missing or invalid answer keeps the user on the page" is the same loose wording; lines 41-44 above it say an optional blank saves, so the two paragraphs read as contradicting each other. Rejected: leaving it on the strength of 41-44 alone, because a reader of 46-48 on its own gets the wrong rule.
