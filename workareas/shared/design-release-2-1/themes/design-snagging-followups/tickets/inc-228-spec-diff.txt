h3. What the specification now says

On the plants origin of the import page, the country type-ahead now ignores case and accents and shows the matched letters in bold, as the animals service does. This summary is generated from the specification as merged to main.

h4. [Plants journey pages / Origin of the import|https://github.com/DEFRA/trade-imports-workspace/blob/main/openspec/specs/plants/journey-pages/origin/spec.md]

h5. Changed: The country field is a searchable list that filters as the user types

The requirement now says matching ignores case and accents, and the matched letters show in bold. Its full text reads: The system MUST offer the country of origin as a searchable field that filters to matching countries as the user types (matching ignores case and accents, and the matched letters show in bold), MUST offer the whole list as soon as the field is opened before anything is typed, and MUST show the chosen country's name in that field when the user returns to the page.

h5. Added: An accented search finds a country listed without the accent

* *GIVEN* the user is on the origin of the import page with JavaScript
* *WHEN* they type "Réunion" into the country field
* *THEN* "Reunion" is offered, with "Reunion" in bold
