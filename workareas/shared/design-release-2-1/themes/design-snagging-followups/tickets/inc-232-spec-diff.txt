h3. What the specification now says

In animals and plants, "Save and return to overview" now makes the same checks as "Save and continue": a missing or invalid answer keeps the user on the page with an error for each, what they entered kept and nothing saved. Upload documents now adds a complete document from every save button and refuses a part-filled one.

This is generated from the Behaviour Spec as merged to main.

h4. [Live animals: journey flow|https://github.com/DEFRA/trade-imports-workspace/blob/main/openspec/specs/live-animals/journey-flow/spec.md]

The rule for pages the hub links to now says Save and return makes the same checks as Save and continue, instead of saving a page with a required answer left blank.

h5. Changed: Save and return to overview refuses a page with a required answer missing

This used to return to Overview with no error and the answer saved; it now keeps the user on the page with both errors.

* *GIVEN* the Main import reason page with "Transit" chosen and its port of exit and destination country left blank
* *WHEN* the user selects "Save and return to overview"
* *THEN* they stay on the page, which shows "Select a port of exit" and "Select a destination country"
* *AND* "Transit" is still chosen
* *AND* nothing is saved

h5. Changed: Commodity details with the number of animals blank is refused on save and return

Only the name changed (it was "Commodity details keeps its checks on save and return"), as Commodity details is no longer the one exception.

* *GIVEN* the Commodity details page with the number of animals left blank
* *WHEN* the user selects "Save and return to overview"
* *THEN* they stay on the page, which shows "Enter the number of animals"
* *AND* nothing is saved

h4. [Live animals: what are you importing (commodity selection)|https://github.com/DEFRA/trade-imports-workspace/blob/main/openspec/specs/live-animals/journey-pages/commodity-selection/spec.md]

The rule now refuses an empty selection on both save buttons, and a selection already saved stays as it was.

h5. Changed: Save and return to overview with nothing chosen shows the same error

This used to return to Overview with no error; it now stays on the page with "Select a commodity".

* *GIVEN* the user is on the commodity selection page with nothing chosen
* *WHEN* they save and return to overview
* *THEN* they stay on the page, which shows "Select a commodity" in the error summary and inline on the search field
* *AND* the commodity selection task reads "To do"

h5. Changed: Save and return to overview after clearing a saved selection is refused and keeps the saved selection

This used to empty the saved selection; it now refuses the save and keeps the selection.

* *GIVEN* the user has a saved selection and clears it on the commodity selection page
* *WHEN* they save and return to overview
* *THEN* they stay on the page, which shows "Select a commodity"
* *AND* reopening the page shows the saved selection still chosen

h4. [Live animals: main reason for import|https://github.com/DEFRA/trade-imports-workspace/blob/main/openspec/specs/live-animals/journey-pages/import-reason/spec.md]

Two rules changed: a partly answered reveal is now refused on either save button, and Save and return now makes the checks of Save and continue, clearing a reason no longer chosen only once the new one is saved.

h5. Changed: Save and return to overview refuses a partly answered reveal, keeping the reveal open

This used to save and return to Overview; it now stays on the page with both errors and the reveal open.

* *GIVEN* the user has chosen "Transit" and left the port of exit and the destination country blank
* *WHEN* they save and return to overview
* *THEN* they stay on the page, which shows "Select a port of exit" and "Select a destination country"
* *AND* "Transit" is still chosen, with the reveal open
* *AND* nothing is saved

h5. Changed: Transit without a port of exit is refused and keeps the country

This used to save and show Overview; it now stays on the page asking for the port of exit.

* *GIVEN* the user has chosen "Transit" and given a destination country but no port of exit
* *WHEN* they save and return to overview
* *THEN* they stay on the page, which shows "Select a port of exit"
* *AND* the destination country they gave is still held
* *AND* nothing is saved

h5. Changed: Changing the reason clears the saved purpose

The user now also gives a port of exit and a destination country, so the save goes through.

* *GIVEN* the user has saved "Internal market" with a purpose
* *WHEN* they change the reason to "Transit", give a port of exit and a destination country, and save and return to overview
* *THEN* choosing "Internal market" again shows no purpose chosen

h4. [Live animals: origin of the import|https://github.com/DEFRA/trade-imports-workspace/blob/main/openspec/specs/live-animals/journey-pages/origin-of-import/spec.md]

h4. [Live animals: upload documents|https://github.com/DEFRA/trade-imports-workspace/blob/main/openspec/specs/live-animals/journey-pages/upload-documents/spec.md]

The rule now says every save button keeps a started document: a part-filled one is refused with an error for each missing detail, and a complete one is added. The virus-scan rule was reworded with no change in meaning.

h5. Changed: Save and return to overview with every detail filled in adds the document and shows Overview

This used to refuse a filled-in form and ask the user to choose the file again and use the add action; a complete document is now added.

* *GIVEN* the user has filled in the reference, document type, date of issue and chosen a file
* *WHEN* they save and return to overview
* *THEN* Overview is shown
* *AND* reopening Upload documents lists the document, its row showing the type chosen

h5. Changed: Save and continue with only the document type says what is missing

The file error now reads "Upload a document" instead of asking the user to choose a file and use the add action.

* *GIVEN* the user has chosen a document type and filled in nothing else
* *WHEN* they save and continue
* *THEN* errors say the reference and the date of issue are required
* *AND* an error on the file says "Upload a document"
* *AND* the user stays on the upload documents page

h5. Changed: Save and continue with an untouched form leaves the page

Only the wording changed: "continue" now names the "Save and continue" button.

* *GIVEN* the user has added nothing and filled in nothing
* *WHEN* they save and continue
* *THEN* Overview is shown

h5. Added: Save and return to overview with a part-filled document is refused

* *GIVEN* the user has filled in only the reference
* *WHEN* they save and return to overview
* *THEN* they stay on the upload documents page, with an error for each of the document type, the date of issue and the file
* *AND* the reference they typed is still on the form
* *AND* no document is added

h5. Added: A reference, date of issue and attachment with no document type is refused on save and continue

* *GIVEN* the user has filled in the reference and the date of issue, chosen a file and left the document type unchosen
* *WHEN* they save and continue
* *THEN* the page shows "Select a document type"
* *AND* no document is added

h5. Added: The same rules hold without JavaScript

* *GIVEN* the user has no JavaScript
* *WHEN* they save and return to overview with every detail filled in
* *THEN* Overview is shown and reopening Upload documents lists the document
* *WHEN* they save and return to overview with only the reference filled in
* *THEN* they stay on the upload documents page with an error for each detail not given, and no document is added

h5. Added: A complete document saved with Save and continue is added and held while it is scanned

* *GIVEN* the user has filled in the reference, document type, date of issue and chosen a file
* *WHEN* they save and continue
* *THEN* the document is added and listed as "Scanning for virus"
* *AND* they stay on the upload documents page, which shows "You cannot continue until all documents have been scanned or removed"
* *AND* the same holds while amending for "Save and return" and "Save and continue"

h5. Added: While amending, an untouched form leaves by the button chosen

* *GIVEN* a notification being amended, with the upload documents page opened from a Change link and nothing filled in
* *WHEN* the user selects "Save and return"
* *THEN* the review is shown
* *WHEN* they instead select "Save and continue"
* *THEN* the page after upload documents is shown, not the review

h5. Added: Save and add another with a part-filled document is refused

* *GIVEN* the user has filled in some but not all of the reference, document type, date of issue and file
* *WHEN* they select "Save and add another"
* *THEN* they stay on the upload documents page, with an error for each detail not given
* *AND* the values they typed are still on the form
* *AND* no document is added
