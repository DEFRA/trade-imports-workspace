## 0. Decisions

1. **Keep the origin-page version of the placeholder option.** The row asks for this. The wrapper passes a placeholder to the library only when the page gave non-empty text, so the library's default stays in place otherwise. The macro always writes the data attribute, empty when no text was given. Rejected: the arrival-and-transit version, which always passes a placeholder and sets it to empty when none is given. The notes say the origin-page commit carried "its unit test", but neither origin-page commit has a unit test of the wrapper, only page copy tests. The unit test is new work in this row (section 4).
2. **Match the typed text against the raw suggestion, then escape each piece.** The row's "How" note says to escape the suggestion first and then wrap matches. Read literally, that breaks:
   - a query with `&` or `<` would never match the escaped text;
   - a query such as `amp` would match inside `&amp;` and split the entity into broken markup.

   So the template splits the raw text at each case-insensitive match of the query, escapes every piece, and wraps only the matched pieces in `<strong>`. What the criteria ask for still holds: the text shows exactly as written, no markup from the list data runs, and the bold comes from `templates.suggestion`. Characters such as `(` or `.` in the query match literally. Rejected: escape first and then match, as the note literally says.
3. **One query normaliser for filtering and bolding.** The filter in `accessible-autocomplete.js:28-31` lower-cases and trims the query. The bold must use the same normalised query, so what is bold is always what matched. With an empty query (the whole list on focus) nothing is bold. Rejected: a second, separate normaliser inside the template.
4. **The joined button is a decorative element the wrapper adds once after enhancement.** It sits in the container the library inserts before the select, outside the `autocomplete__wrapper` markup that the library re-renders on every keystroke, so typing never removes it.
   - It sits at the right end of the box, inside the width the page gives the field. Box and button together keep the field's width, and the suggestion list (100% of the wrapper) is as wide as the joined control at every width, phone included.
   - It is hidden from assistive technology, not focusable, not a form control, so it cannot submit the page.
   - A click on it puts focus in the enhanced input.
   - The painted `::after` icon and the hidden dropdown arrow go.

   Rejected: the library's `dropdownArrow` option. It renders only when `showAllValues` is set, and it renders inside the re-rendered tree behind the transparent input, so it cannot be a joined square.
5. **The change event fires only when the select's value actually changed.** `onConfirm` runs on a click, on Enter, and on blur (with no option on blur). After it has settled the select, the wrapper dispatches one bubbling `change` on the select if, and only if, the select's value now differs from before the confirm. That includes a blur that clears the select. A blur that leaves the value as it was fires nothing, as a native select would. Rejected: firing on every confirm, which would report a change on every blur.
6. **The Main import reason panel width is not built here.** The backlog's Main import reason row owns the two-thirds width of those four boxes (its criterion 4 and its note "wrap each in a two-thirds width GOV.UK override"). This row makes the joined control fill whatever width its form group has, so that override works unchanged. Here we prove the panel case at the width the panel gives today, at desktop and phone width. Criterion 8's "narrower width drawn inside the panel" appears once that row lands. Rejected: adding width classes to `import-reason/template.njk` here, which would duplicate that row.
7. **Claim correction: two of the "four Main import reason country boxes" are port boxes.** Criterion 5 calls all four country boxes. The template (`import-reason/template.njk:33-77`) has two country boxes (transhipment destination, transit destination) and two port boxes (transit port of exit, temporary admission port of exit). All four get the same bold and button, because one component draws them.
8. **Plants Commodity details gets bold too.** Criterion 5 lists only Country of origin and Proposed place of landing for plants. The genus box on Commodity details uses the same wrapper, so it bolds matches too. Building a second, plain template only for it would add a second mechanism.
9. **Component tests per repo.**
   - Unit: a jsdom test beside the wrapper, in each frontend. It mirrors `plants .../address-book-picker.test.js`.
   - FIT: one new cross-page spec per frontend for the look and behaviour on every type-ahead page. It sits beside the existing cross-page `section-caption.fit.spec.js`, so the large page specs stay page-owned.

   Rejected: assertions scattered into every page spec, which would widen the tidy-up into every one of those files.
10. **Stub the library, not our modules, in the unit test.** The criterion asks for a stubbed `enhanceSelectElement`. The stub only captures the configuration the wrapper hands over. The tests then exercise that configuration's own functions (`source`, `templates.suggestion`, `onConfirm`) through inputs and outputs. There are no call-record assertions. Rejected: `toHaveBeenCalledWith` on the stub.
11. **Animals gains `jsdom` as an exact-pinned devDependency (30.1.2, as plants pins it).** Animals has no DOM test environment declared. A copy of jsdom sits in its `node_modules`, but it is not in `package-lock.json`. Rejected: relying on that stray copy.
12. **The e2e bold assertion looks up the suggestion named France, not position one.** Today France is the first suggestion for `fra` in both lists. The origin page row will add labels such as "Clipperton (France)" to animals, which sort before France. Asserting on the option whose accessible name is France meets the criterion now and survives that row. Rejected: asserting on the first suggestion, which that row would break.
13. **The wrapper's licence header stays; its rationale list goes.** The file is adapted from HMRC's Apache-2.0 component. The source attribution, copyright, licence and NOTICE lines stay, plus a plain statement that the file is modified (the licence requires it, §4(b)). The "Adaptations" rationale list is deleted rather than extended, because rationale does not belong in code. A docs page for it is a follow-up, since this row may not add a file for clean-up alone.
