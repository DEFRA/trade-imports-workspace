## 0. Decisions

1. **Built from scratch, not cherry-picked.** The row's notes say to cherry-pick the origin-page branch commits (animals f69647ac, b03938b9, 7b24d265; plants 831e13a, cd55531; tests c988fd4, f2c4e00a, 7613607, 4f9cec8). Sam's request for this run is to build it fresh on the new workflow, and that wins. Those commits are read as references only. They also break house rules this plan must keep (a `REMOVED_COUNTRY_HINT` constant and `toHaveCount(0)` removal proofs, comments that describe other modules, two thin aliases of one list function), and their FIT edits predate the shared helpers the previous row added. The Welsh machine drafts in them (region hint, internal reference hint, "Chwiliwch am wlad") may be reused as copy text.
2. **The type-ahead placeholder mechanism already exists.** The macro already takes `autocomplete.placeholder` and the wrapper already passes it to the library (previous row). This row only passes text from each origin page. No component change.
3. **Two copy strings, two keys.** The native select's first option stays "Select a country" under the existing `country.placeholder` key. The search box text "Search for a country" gets a second key in `country`. The new key has the same name in both frontends (one concept, one name across twins), and its name must say it is the search box's text, not the select's. Rejected: reusing `placeholder` for the search text, which would change the no-JavaScript first option.
4. **Subdivision labels: one list function, not two aliases.** Today animals has `originCountryOptions` (plain subdivision names) and `destinationCountryOptions` (subdivisions named with their country), both built by one private helper that takes the naming as a parameter (`services/countries/index.js:103-124`). Once origin names subdivisions with their country, the two lists are identical. One exported function owns "every origin country and subdivision, each subdivision named '<subdivision> (<country>)', sorted by the label shown". The naming parameter goes. The origin and Main import reason pages both call it. The same collapse applies to the FIT fixture helpers in `services/_capture/fixtures.js:20-40`. Rejected: keeping two exported names over one body (two names for one concept).
5. **Plants keeps plain territory names** (row note, answered 20 October). In the tests repo the fixture keeps two list helpers, each named for what it holds rather than the page that uses it: plain names (plants origin) and subdivisions named with their country (animals origin and animals destination). `subdivisionByCode`, used only by animals, returns the labelled display, so `countryCodes.subdivisions.canaryIslands.display` reads "Canary Islands (Spain)" for every animals spec, including the animals-admin outbox spec that picks it. **One formatter owns the "<subdivision> (<country>)" string in the tests repo:** a single module-private helper in `reference-data.ts` takes a subdivision and its country and returns that label. `subdivisionByCode` (which must now find the parent country, not only the subdivision) and the labelled list helper both call it. Neither builds the string itself. Rejected: the format written twice, once in `subdivisionByCode` and once in the list helper's callback.
6. **The region code is stored only under Yes with a country.** `regionCodeFrom` in `validate.js` returns an empty code when the answer is not Yes or when no country gives a prefix. The raw typed suffix stays in `values`, so a refused page still shows what was typed. `fromAnswers` then reads an empty code back, so choosing Yes again shows an empty box. This makes the obligations spec (REQ-OB-ORIGIN-002) and REQ-ORIGIN-017 true; neither is true in the tree today (`validate.js:67-74` stores a bare code with no country and keeps the code under No).
7. **The 5-character cap has one owner.** The template's `maxlength` reads the suffix limit that `validate.js:19` owns, passed through the controller's render context. Rejected: a literal "5" in the template, which would be a second owner of the rule.
8. **Look and feel, inside the GOV.UK toolbox.** The revealed region code label takes `govuk-label--s`. The internal reference input drops `govuk-!-width-three-quarters`, so it fills the column. No custom CSS.
9. **Claim that does not hold: "With Welsh chosen".** Neither frontend has a way to choose Welsh at run time: `shared/copy.js` `copyFor` always resolves English unless a caller passes a locale, and no route does. The Welsh criteria are therefore proved at copy level: the Welsh module carries the drafts, carries no country hint key and no 58-character sentence, and `copy-parity.test.js` keeps the key trees equal. No FIT or E2E test switches language.
10. **"No prefix without JavaScript" belongs to the region code prefix row.** Criterion 23 cites that row and its ruling. Today the prefix is server-rendered with or without JavaScript. This row proves the stored code (ES-CN), the reopened label "Canary Islands (Spain)" and the prefix ES with JavaScript on. The no-JavaScript prefix rule is built by the region code prefix row, which depends on this one.
11. **The Overview origin task rule already holds.** The task reads Complete only with a country and an answered region question (with a code under Yes), through the obligations in `obligations/sections/origin.js`. No production change. The coverage file already names tests for it that do not exist, so the existing origin assertion in `flow/task-rows.test.js:50-61` gains the missing states (country only; Yes with no code; Yes with a code) and coverage points at it. No new E2E for it.
12. **Every rationale comment leaves the files this row edits.** Bounded tidy-up covers the whole of each file edited for the row's own behaviour, not only the touched functions. So every comment carrying rationale, history, an id, or a description of another module, caller, the UI or a test is deleted from: origin `validate.js`, origin `controller.js`, origin `controller.test.js`, `services/countries/index.js`, `services/_capture/fixtures.js`, the tests repo's `reference-data.ts` and `tests/animals/e2e/pages/origin.spec.ts`. Import-reason `controller.js` 38-40 also goes (it sits in the function this row touches). Three more files edited for the row's own behaviour lose every rationale comment, description of another test or module, and count: animals `journeys/linear/flow/task-rows.test.js` (the comments at 149-151, 415-416, 437-438, 449-450, 457-459 and 493-495), animals `services/run-mode.test.js` (310-312) and plants `origin/copy/copy.test.js` (89-90). Nothing in them needs to move to `page-design.md`. Doc comments on exported functions are cut to the function's contract. Any present-tense reason worth keeping goes into a new "Origin of the import" section of `sets/live-animals/docs/page-design.md`:
    - the country is checked only against the list, not required, so a trader can save what they know and return;
    - the trader types only the part of the region code after the country's prefix, and the stored answer is the whole joined code;
    - a typed prefix is accepted and not doubled;
    - the region code is required under Yes and stored only with a country's prefix, and is cleared under No;
    - the rules measure the storable code, while the page shows back what was typed;
    - clearing the country clears the region code too;
    - the internal reference is checked for length only;
    - the back link goes to the dashboard until something is saved, then to the overview;
    - the status strip shows from the first request;
    - stored answers are re-checked against the page's rules when the page opens, so a country the reference data no longer offers is named on the page.
   A reason that only a test needs (a seeded code outside the captured list stands in for a country no longer offered; the internal reference keeps the trader's punctuation) is said by the test's title or by a constant whose name says it, never by a comment. Rejected: deferring the untouched functions' comments to a follow-up.
13. **Proving the look.** The bold label and the full-width box are proved by exact class assertions in FIT, following the existing label-size test (`origin.fit.spec.js:94-108`), and by the regenerated visual baseline. No measured geometry (`docs/best-practices/playwright/BEST_PRACTICES.md` "No measured geometry").
