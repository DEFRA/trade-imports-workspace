   - Rejected: rebuild from scratch. The work was reviewed and green twice.
   - Rejected: restore the stash unchanged. It puts assertions in a flow (decision 3) and adds a page-object accessor and a flow wrapper beside existing mechanisms (decisions 4 and 5).
2. **The prefix is hidden without JavaScript by CSS keyed on GOV.UK's own class.** Sam's 20 October ruling, in the row's notes. The server always draws the prefix. GOV.UK's page template adds `govuk-frontend-supported` to `body` with an inline script before content paints (`node_modules/govuk-frontend/dist/govuk/template.njk:35`). One rule hides the prefix while `body` lacks that class. So the shown-again and error cases show the right code at once with nothing to compute or flash in, and without JavaScript nothing shows. The CSS only hides; it never states a shown `display` value, so GOV.UK's prefix layout stays in charge.
   - Rejected: the `hidden` attribute removed by the script. The prefix would pop in after the bundle loads.
   - Rejected: a prefix created by the script. Same flash, and the saved code would be computed on the client.
3. **Drop the opening-run extraction, and every edit to `opening-run.spec.ts`, `horse-temporary-admission.spec.ts` and `hub-groups-and-cya-rows.spec.ts`.** None of it serves the prefix. The extraction put `expect` calls in `flows/animals/journey.ts`, which `docs/best-practices/playwright/BEST_PRACTICES.md:79` and `:270` forbid ("Assertions stay in specs"; "Assertions in page objects or flows"). With those three specs unchanged against `origin/main`, the existing shared block touches no changed file and the duplication rung does not report it. The extraction, done with the assertions left in the specs, is a section 7 follow-up. This answers the row's "re-plan allowing the shared test-step extraction, or restore the stash" by taking neither: the extraction is not needed once its cause is gone.
   - Rejected: keep the extraction. It breaches the flow rule above, widens the footprint to three specs and a flow for clean-up alone, and the plan would then also owe the third copy of the certificate in `overview-task-return.spec.ts` and the fourth in `tests/animals-admin/e2e/features/outbox-event-notification.spec.ts`.
4. **No new notification-view accessor.** The E2E reads the "Region of origin code" summary value through the existing `summaryValue(summaryCard('Import details'), 'Region of origin code')` (`page-objects/animals/notification-view-page.ts:36-42`), as `origin.spec.ts:111` already does. `notification-view-page.ts` is not edited, so its three doc comments are not this row's to fix: a follow-up.
   - Rejected: the preserved accessor. A second way to reach a value the page object already reaches, and it pulls `opening-run.spec.ts` and `hub-groups-and-cya-rows.spec.ts` into the row.
5. **The E2E answers the origin page through the existing flow pair, extended with the code to type.** `fillOriginOfImport` (`flows/animals/journey.ts:93-103`) types a fixed `'75'` under Yes. It gains the region code to type as a `JourneyOptions` field (`domain/animals/constants/journey-options.ts:20-39`, default in `defaultJourneyOptions`), falling back to today's value. Specs then call `fillOriginOfImport` and `saveOriginOfImport` (`:105-107`), as the territory test in the preserved spec already does.

   - Rejected: the preserved spec-local "choose France and require a region code" helper in `origin.spec.ts`. It is set-up used by two tests that the extended `fillOriginOfImport` already does (France is the default country; an empty code is a value it can type), so the local copy goes.
6. **The prefix always renders an inner element, empty before a pick.** GOV.UK's input omits the prefix when its `text` and `html` are both empty (`govuk/components/input/template.njk:22`). The prefix goes through `html`, holding an inner element whose text is the saved country's code. The script writes that inner element's text.
7. **The client module is a `data-module` component in the existing application bundle, not a new webpack entry.** It follows `src/client/javascripts/components/status-announcer.js` for shape and is registered with `createAll` in `src/client/javascripts/application.js`, after the type-ahead. `createAll` only initialises when `body` has `govuk-frontend-supported`, the same condition the CSS keys on, so the prefix shows exactly when the script runs.
   - Rejected: a per-feature bundle like `documents/client/index.js`. That route is for a page that orchestrates its own behaviour.
8. **The country-to-prefix rule keeps one owner: `prefixFor`, `origin/validate.js:53`.** It already maps a subdivision to its parent's code and builds the stored code. The controller builds a map from every offered option's value to `prefixFor(value)`, from the same option list it already fetches for `countryItems` (no second fetch). The template puts the map on the module's element as a data attribute. The client only looks the chosen value up.
   - Rejected: data attributes on each `<option>`. They would change the `countryItems` contract the shared type-ahead macro reads.
   - Rejected: the client splitting the value at the hyphen. A second owner of the prefix rule.
9. **The module finds the country field by its form control name, not its id**, because the type-ahead renames the select's id. It reacts to the `change` event the type-ahead dispatches on the select. That covers a country, a subdivision, and clearing the box (confirmed empty on blur). A value with no map entry, the placeholder included, empties the prefix.
10. **No update on load.** The server-rendered code is authoritative when the page opens. The module only reacts to changes, so no "does nothing on load" unit test is written: no line's removal would turn it red. The shown-again and error cases are proved in the browser.
11. **A code typed with the country's letters but no hyphen (`FR75`) stays as typed and is stored `FR-FR75`.** The row asks the build to decide. Stripping bare letters would also strip a real region code that begins with them, and no criterion asks for it. Tested at handler level, stated in the spec (REQ-ORIGIN-020's third scenario, section 8) and in `page-design.md`.
12. **`maxlength` stays at 5.** Without a visible prefix, a trader who types `FR-ABCDE` has it cut to `FR-AB` by the browser. Raising the cap would weaken the box for everyone with JavaScript and needs new copy and a Welsh draft. The length boundary after a typed prefix is proved as a submission made without the box's cap, matching how the spec's existing length scenario phrases it. A follow-up takes the cap and hint to design.
13. **The prefix value stays HTML-escaped inside the `html`.** On a refused POST the prefix is `prefixFor` of the submitted value, and an out-of-list value is echoed. The inner element is built in an autoescaped Nunjucks `set` block, never by concatenation and never marked `safe`. The map goes through GOV.UK's `attributes` param, which escapes every value. A FIT test proves a submitted value carrying markup shows as text.
14. **The visual baseline does not change.** The only origin baseline (`tests/animals/e2e/visual/origin-of-import.visual.spec.ts`) is the first load with nothing revealed, so the prefix is not in it. The gate's tests-repo `e2e` rung runs `test:docker-compose`, which runs `@visual`. 15. **The integration proof is the gate's tests-repo `e2e` rung.** No section 5 or 6 check calls a `test:docker-compose` script.

Landing on the next page stays an assertion in the spec after the shared call, never inside the helper. `answerOriginEntry` (`:256-260`, the No path) is the exemplar for shape and is unchanged. Tests that do not read the internal reference take its fixture default.
   - Kept local, with reason: the check-Yes step (used by tests that check Yes with no country, so no shared step fits them; one action, one spec), the prefix locator and the two prefix assertions (only this spec reads the prefix; assertions stay in specs). None copies a shared helper's body.

   - Rejected: the second attempt's local fill, submit and save-and-land helpers. A local copy of `answerOriginDetails`'s body, breaching `docs/best-practices/node/testing/frontend.md:95`.
