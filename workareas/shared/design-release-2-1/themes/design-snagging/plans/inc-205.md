## 0. Decisions

1. **Port, don't cherry-pick blind.** The source is the commodities-and-reason commits (animals `cadd4794`, tests `c8cdcd3`). Previewed against HEAD: animals conflicts only in `flow/section-captions/copy/copy.test.js` (HEAD renamed that test). Tests conflicts in `additional-details-scope.spec.ts` (HEAD uses `referenceNumber` and a single tag) and `soft-save.spec.ts` (HEAD already asserts "To do" for the commodity task, so that hunk is dropped). The implementor brings the behaviour over and applies the house rules to it. inc-011's comments, `not.toContain` absence checks, its `@integration` tag and its doc comments on page objects are not carried over.
2. **Error position (AC "between its label and hint") does not hold.** GOV.UK Frontend's input renders label, then hint, then error message, then the input. The programme invariant says pages are built from GOV.UK components. Decision: keep the component's own order. The error sits inline on the search field. The spec (SCN-COMMODITY-SELECT-009-A/C) says "inline on the search field" and states no order, so no spec text changes. Rejected: hand-building the input to move the error above the hint. Listed under Departures.
3. **Error order AC ("two species each missing both answers") does not hold on HEAD.** On this branch a blank number of packages is not an error: `fields.js:31` validates packages with `integerInRange`, which is optional. "Missing both" therefore gives two animals errors and no packages errors. Decision: plan against the spec's own scenario (SCN-COMMODITY-DETAILS-010-A), which is blank animal counts plus package counts that are not whole numbers. inc-011's tests used that shape too. Rejected: making packages required. That belongs to another row (the spec's REQ-COMMODITY-DETAILS-012 records it, but nothing on this branch builds it; see the follow-ups). Listed under Departures.
4. **Species cell format.** One Latin name per line, with a comma at the end of each line except the last. This is how the prototype draws it (`consignment-details.html` at `56371e2`: `{{ speciesName }}{% if not loop.last %},<br>{% endif %}`). For a row under code 01061900 the cell holds that row's one species.
5. **One owner for "a line's species is named by its Latin name, falling back to the stored value": a new export of the set's commodities service.** `sets/live-animals/services/commodities/index.js` already owns species naming: `speciesLabel` (`:43-44`) and the sibling rule `speciesCommonName` with its own fallback (`:50-51`). The new rule goes beside them, built on `speciesLabel`. A new export changes no existing caller.
   - `groups.js` (`groupLine`, today `:11-12`) and `selected-rows.js` both call it. Neither view model keeps a copy.
   - Every other copy can reach it. The set copies (`consignment-details/validation/count-drop.js:22-23`, `animal-identification/card/view-model.js:18-19`, `check-answers/view-model/cards/consignment/species/species-text.js:6-7`) import the service already. The platform copy (`services/persistence/records/notification-mapper/shared/lines/species-entry.js:34`) reaches the service through `commodity-reference.js`, which `routes-live-animals.js:72` configures with this whole service module, so one delegate there reaches it without the platform importing the set (`src/server/app/docs/architecture.md:49`). Converting those four copies is a follow-up (section 7).
   - Rejected: an export of `groups.js`. A page view model cannot be reached from platform code, so it could never be the single owner.
   - Because this row edits the service file for its own behaviour, bounded tidy-up applies there: every house-rule-breaking comment in it goes, with any still-true reason moved to `services.md` or `page-design.md` (section 2).
6. **Error order owner.** `consignment-details/fields.js` `fieldsFor` owns the order of the page's validators, and `compose` keeps that order in the error summary. It builds every number-of-animals validator first, then every number-of-packages validator for the lines that ask for one. It keeps its exported name and signature, its one caller is unchanged, and it carries no comment. Named helpers are the implementor's call.
7. **Caption owner.** `flow/section-captions/index.js` `captionSections` gets a new section holding only the commodity details page, named "Description of the goods" (Welsh machine draft beside it). That page leaves the "About the consignment" section. Rejected: a per-page caption string, which the design rule "one entry per section, never a string per page" forbids. That rule moves from the doc comment to `journey-flow-and-gates.md` "Section captions" in this row (decision 16).
8. **Spacing (S14) uses GOV.UK spacing only.** The "Add another commodity" paragraph gets the scale-7 bottom-margin override: 40px on desktop, 25px on mobile. The commodity heading has no top margin, so the gap is 40px. The rule between commodities is a visible GOV.UK section break with scale-7 top and bottom overrides. The break carries no `--l` size modifier, because `--l` gives 30px. The page template (`consignment-details.njk`) emits the rule before every group except the first. The group macro (`_species-quantities.njk`) stops emitting a rule after each group, so no rule sits above the Save buttons. Rejected: a boolean argument on the macro (house rule: no positional boolean flags), and custom CSS (programme invariant).
9. **No pixel test for 40px.** The row's notes say no layout-tolerance test. The rule's placement is behaviour and is pinned by FIT: one separator between two commodities, none for one commodity, none after the last. The 40px values are proved by the rendered re-shoots the run's rendered-proof step takes.
10. **Search minimum stays.** A query under 3 characters still lists nothing (`search/matching.js`, spec REQ-COMMODITY-SELECT-002). Only the hint sentence goes, and no extra line is shown after a short search (Sam, 20 Oct).
11. **Unweaned answer clearing is existing behaviour.** The engine's scope-and-wipe already drops `containsUnweanedAnimals` when no cattle line is left (`engine/mutators.test.js` covers it at engine level). inc-011 added only tests for it. The plan ports those tests as the commodity-save and end-to-end proof of SCN-OB-COMMODITY-002-C. They do not change production code, so they are not regression tests for a change in this row. Recorded under Departures.
12. **Soft Save and return on the commodity page is existing behaviour.** `search.controller.js:77` already skips the check on a hub exit, and HEAD's `soft-save.spec.ts:113-127` already asserts "To do". The plan adds only the cleared-selection case (SCN-COMMODITY-SELECT-009-D).
13. **Shared E2E set-up extends the journey's existing steps.** `AnimalsJourney` already has the bodies the scope tests repeat:
    - `answerCommodity` (`journey.ts:151-158`): commodity task, choose species, save, Commodity details, fill, save.
    - `toConsignmentDetails` (`:322-325`): choose Bos taurus, save, open Commodity details.
    - `toAdditionalDetails` (`:350-357`) and `answerReasonAndAdditionalDetails` (`:167-178`): open Additional details from Overview.
    The shared part of the first two ("choose these species, save, open Commodity details") is extracted once and used by `answerCommodity`, `toConsignmentDetails` and the new add-a-commodity step. `toConsignmentDetails` takes the species to choose, defaulting to today's cattle, so the two-species `beforeEach` calls it rather than repeating it. The "open Additional details from Overview" part is extracted once and used by `toAdditionalDetails`, `answerReasonAndAdditionalDetails` and the new open step. Every local copy is deleted: the closures in `additional-details-scope.spec.ts:25-43` and in `cph-scope.spec.ts:18-29`. Rejected: inc-011's module-level functions in the spec, and a parallel step beside `answerCommodity` with its own body.
14. **Spec text is already true.** The workspace `openspec/` was written on the combined branch, where this behaviour existed. Every requirement and scenario this row needs is already there (see section 8). The spec sync is confirming coverage links against the test titles that land, with no new spec text.
15. **ITAHC wording kept as drawn** (Sam, 20 Oct). Not spelled out.
16. **Every reason cut from code gets a doc home before it is cut.** Captions reasons go to `journey-flow-and-gates.md` "Section captions". Commodity page reasons go to a new "Commodity pages" section of `page-design.md` (the doc that says it holds "the reasons that would otherwise sit in code comments"). Commodity service reasons go to `services.md` "The commodity rules". The Welsh pluralisation reason and translator note go to `copy-status.md`. Section 12 lists each.
17. **Removals are proved positively.** The tick-box error's removal is proved by the whole error summary (one link, to the search field) and the search field's exact accessible description. The emptied selection is proved by reopening the page and pressing Save and continue: the page refuses with "Select a commodity" on the search field, which happens only when nothing is saved.
