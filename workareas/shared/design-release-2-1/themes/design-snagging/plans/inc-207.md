## 0. Decisions

1. **Port by rebuilding the two source commits against the live tree, not by cherry-picking.** The commodities-and-reason commit (animals 77762214, tests ad920c1) and the overview-and-review commit (animals 56a0aeb8, tests 36c7865) are both stale. Since they were written:
   - the divider option is already gone from both reveal lists (controller.js:38-46);
   - the country list service was renamed (`countryAndSubdivisionOptionsNamedWithCountry`);
   - the import-reason FIT spec was restructured round shared helpers;
   - the tests repo's import reason page object reads the type-ahead's hidden select.
   So the implementor re-applies only what is still missing:
   - the copy changes, in en and cy: page title, both placeholders, the certification hint, the review group heading, the hub task title;
   - the review group copy key rename;
   - the tests.
   From 56a0aeb8/36c7865 take only the hub task title: hub copy en/cy, the hub copy test and the tests-repo task name references. Never the hub regions or the plants overview spec. Rejected: `git cherry-pick`, which would conflict in every test file and re-add a removed helper.
2. **The four reveal search boxes follow the 20 October ruling's shared look: a bold label and full width. Acceptance criteria 2 (regular-weight labels) and 4 (two-thirds width) are not built (section 14).**
   - **The ruling.** The snags register records in full: "Settled 20 Oct: keep the type-ahead, with the same styling as the origin and port searches" (snagging/snags.json:96, snag S10). The backlog's open question says "Build as written unless the designers choose otherwise". The ruling is the designers' choice, made after the row was written. It settles the open question: the boxes stay type-ahead (rejected: plain selects).
   - **What origin and port of entry share.**
     - Both use the one shared search control (accessible-autocomplete macro.njk, accessible-autocomplete.scss, client accessible-autocomplete.js): the search box with its joined blue button, the suggestion list, bold matched letters and the error border.
     - Both labels are bold.
     - Neither sets a width class, so both boxes are full width.
   - **Where they differ.**
     - Label size: origin uses `govuk-label--m` (origin/template.njk:21); port of entry uses `govuk-label--s` (port-of-entry.njk:24).
     - Empty-box text: origin shows "Search for a country" (origin/template.njk:28); port of entry shows none (port-of-entry.njk:29).
     - Port of entry also has a hint, which is that question's own copy, not styling.
   - **The call.** Where the two agree, the ruling decides. Where they differ, this page decides.
     - Label: bold, at port of entry's small size, which is also what the four fields have today (template.njk:36, 48, 58, 72). The four are follow-up questions inside a reveal, as port of entry is one of several questions on its page. Origin's medium label is that page's main question. So criterion 2's regular weight is not built.
     - Width: full width, the same as both. No width override. So criterion 4's two-thirds is not built.
     - Empty box: "Select one". The ruling cannot settle it, because the two searches differ. Criterion 3 and the earlier ruling on type-ahead placeholders (sam 2026-10-09, claim 4) both ask for it.
   - **What is lost.** The four labels stay bold and the boxes stay full width, unlike the prototype's regular labels and its 396px cap. Inside the temporary admission reveal, "Exit date" becomes regular weight (Decision 6) above a bold "Port of exit". That follows two rulings literally: S11 asks for the prototype's date picker styling, and S10 asks for the origin and port look. This is listed under risks, and the visual baselines (section 4) put it in front of a person.
   - Rejected: building criteria 2 and 4 against the ruling. The ruling is later and names the look outright, and the backlog's own open question defers to it.
   - The comparison and the call go into page-design.md and the reason page's prototype-differences note (section 2), so the designers can see them.
3. **The type-ahead's empty search box reads the same copy as the select's first option.** The `country.placeholder` and `port.placeholder` keys become 'Select one' / 'Dewiswch un', and the template passes the same key as the type-ahead's placeholder. One concept, one key. Rejected: a separate search-placeholder key like origin's `searchPlaceholder`. Origin's search box and its select say different things; here they say the same.
4. **Width stays as it is.** No form-group or select width override is added (Decision 2). Without JavaScript the select keeps the GOV.UK select's own width, as port of entry's does.
5. **The four reveal type-aheads share one look, so the template states it once.** The small bold label, `showAllValues`, `noResults` and the placeholder are the same for all four. They live in one template-local owner (for example a small macro in `template.njk` that wraps `appAccessibleAutocomplete`). Each reveal passes only its id, label text, items and copy group. Rejected: four copies of the same option set. That is the drift the snag reported.
6. **The exit date's look goes through `kit.dateField`'s existing options.** The S11 ruling asks for the prototype's date picker styling, so criteria 5 and 6 are built.
   - The controller passes an empty `labelClasses` (regular weight) and `formGroupClasses` with the GOV.UK scale-6 bottom-margin override (kit.js:302-305, 317-318, 325, 332).
   - The override is needed because GOV.UK Frontend removes the bottom margin of the last form group nested inside another form group. The date's form group is the only one inside the MoJ date picker's wrapper, so it meets that rule, and the date box ends up touching "Port of exit". The `!important` spacing override beats that rule.
   - Scale 6 is 30px from tablet width up (the criterion says desktop) and 20px on a phone.
   - Rejected: a rule in `_date-picker.scss`. That would be custom CSS and would change every date picker.
7. **The spacing is proved by a `@visual` baseline, not by measurement.** The Playwright guide bans measured geometry and says appearance belongs in a `@visual` baseline (BEST_PRACTICES.md:168-176). The tests repo already has that mechanism (`tests/animals/e2e/visual/origin-of-import.visual.spec.ts`, `test:docker-compose:animals:visual`). A new visual spec beside it takes baselines of the reason page with each reveal open, with and without JavaScript, and in the exit date error state. Those baselines also record the ruling's look (bold labels, full width) and the "Select one" boxes. Label weight is checked in FIT through computed style, which is a value, not a measurement. Rejected: width-ratio and gap helpers in the shared FIT helper, which would be a second, tolerance-based mechanism.
