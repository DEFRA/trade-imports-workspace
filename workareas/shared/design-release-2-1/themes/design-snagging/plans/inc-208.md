## 0. Decisions

1. **Ported by hand, not cherry-picked.** The row's notes say cherry-pick the arrival-and-transit commits (animals bb6fb2e0, plants b2f3bdc, tests 7f87ba3) without the shared-component and date-field hunks. Both of those hunks are already on this branch: the autocomplete `placeholder` option (macro + client module, from the type-ahead row) and `kit.dateField`'s `labelClasses` option (from the date picker row). The rest of those commits carries house-rule breaches (release names in test titles, rationale comments, "AC" ids) and keeps two means decks. So the implementor writes the same behaviour against the live tree. Rejected: a literal cherry-pick, which would conflict on the landed hunks and bring the breaches with it.
2. **One copy key for the port's empty text.** The animals port's existing `placeholder` copy leaf becomes "Select a port". It feeds both the no-JavaScript select's first option (already does, via `portItems`) and the type-ahead's empty search box (new: passed as the autocomplete `placeholder`). This matches how Main import reason uses one key for both. Rejected: a separate `searchPlaceholder` key as origin has. Origin's two texts differ by design; here the prototype shows one text.
3. **Plants empty search box shows its placeholder too.** The row asks that plants take "inc-026's plants hint and placeholder". The plants half of that commit changed only the hint, so "placeholder" can only mean twin parity with animals. Plants passes its existing `placeOfLanding.placeholder` copy ("Select a place of landing" / "Dewiswch fan glanio") as the autocomplete placeholder, so the empty box reads the same as the select's first option. Rejected: leaving the plants box blank while animals shows text, which breaks the twin invariant.
4. **The means of transport label has one owner, read by the arrival page and the review card.** The row's own criterion says "the review page reads the chosen one back with the same label", so the review read-back is this row's behaviour, not clean-up.
   - Owner: one exported function in the transport feature returns the label for a stored means code, reading `transport/copy` `portOfEntry.means.options` in the request's copy bundle. It lives in a new module under `features/transport/` (section 3), the way `addresses/parties.js` exposes the addresses feature's party copy to check-answers.
   - Readers: `port-of-entry.controller.js` `meansItems` (lines 42-49) takes each option's text from it, and the review card `check-answers/view-model/cards/movement/arrival-details.js:32` takes the row value from it.
   - `check-answers/copy` `means` is deleted in both locales. Nothing else reads it (grep `\.means\b\|means\[` over `src/server`: only `arrival-details.js:32`).
   - Checked against the code: `.dependency-cruiser.cjs` has no rule against one feature importing another in the same journey. `arrival-details.js` already imports `../../../../transport/page.js`, and `check-answers/refusal.js` already imports `documents/copy`.
   - This departs from the live-animals recipes (add-a-field §5, add-a-section §7), which put displayed value labels in the check-answers copy. The house rule wins (section 14), and both recipes are restated so they no longer lead a later change into a second owner (section 2).
   - Rejected: keeping two decks pinned by a test. That is two owners of one display rule (`.claude/rules/code-quality.md:50`), and a test deriving its expectation from the transport deck passes on HEAD.
5. **The arrival date hint becomes a fixed string.** In both locales `portOfEntry.arrivalDate.hint` becomes a plain string ending "For example, 27/3/2026", as plants already does. `exampleText` leaves `arrivalWindow`. Three tests go because the behaviour they prove no longer exists: two `arrival-window.test.js` tests (the example is today, and lies inside the window), and the FIT test "the worked example in the arrival date hint is itself accepted" (27/3/2026 falls outside the window now). Rejected: keeping a dynamic example beside a fixed one.
6. **Hint grey goes only where it is needed.** GOV.UK's `govuk-list` sets its own text colour, so the bullet list renders black inside the hint. The lead-in `<p>` may already inherit the hint grey. The implementor adds the GOV.UK hint class (keeping each element's spacing override) to whichever of the lead-in and the list renders outside the hint colour. The FIT test (section 4) is the proof, and its removal probe decides. An element whose class removal turns nothing red does not get the class. Rejected: adding the class to both blind, which may build an untested change.
7. **The grey is spec'd.** The row explicitly asks for the scenario "the identification lead-in and list are shown as hint text", and this capability already records label size (REQ-ARRIVAL-015). So the grey is added to REQ-ARRIVAL-014 as observable wording ("in the same grey as the page's other hints"). Rejected: leaving it out as pure styling.
8. **Arrival date label size** goes through the existing `kit.dateField` `labelClasses` option (animals `shared/kit.js:304-325`, plants `shared/kit.js:317-338`), set by each page's controller. Rejected: a new option or a template override.
9. **One question-label locator for E2E, on the shared `NotificationPage`** (`page-objects/shared/base-page.ts:160`), which every animals and plants page object extends (plants through `PlantsNotificationPage`). A field-hint locator goes there too. Promoting the label locator deletes all four local copies, which are the same `label[for="<id>"]` shape:

The two page objects outside arrival details are edited only to delete their copy, which the house rule's "promoting a helper deletes the local copies" requires of this promotion. Rejected: deleting only the two arrival copies, which leaves two locals beside the shared helper.
10. **Tests-repo means labels come from the `meansOfTransport` constant.** `domain/animals/constants/means-of-transport.ts` already names the vocabulary. Every touched line that chooses or reads back a means takes its label from the constant's `display`, not a literal. `fillArrivalDetails` keeps its `means` label parameter (a string), so no signature changes across callers. Its default and the callers pass the constant's `display`. Rejected: changing `fillArrivalDetails` to take a `MeansOfTransport`, a signature change across callers that this row does not need.
11. **The E2E suite gains an assertion on the arrival date hint.** The row's notes say no tests-repo spec asserts it today. That is true, and asserting it gives the fixed example its integration proof.
