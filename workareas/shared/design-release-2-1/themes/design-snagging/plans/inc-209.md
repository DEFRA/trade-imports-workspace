## 0. Decisions

1. **The tests repo merge is already in.** The row asks for `origin/main` to be merged into the tests repo. `git merge-tree --write-tree --name-only --no-messages HEAD origin/main` printed only a tree id (`95a649c…`), with no conflicted paths. `git log HEAD..origin/main` is empty. No resolutions file sits beside the backlog. So there is nothing to resolve or plan. The loop's `git merge --no-ff --no-commit origin/main` will report "Already up to date" and leave no `MERGE_HEAD`. Its commit step must treat that as a no-op, not as a failure (see Risks). Rejected: returning ok:false. The row's code change does not depend on the merge, and the merge's goal (main's shared answers on this branch, gate green) already holds.
2. **Copy split: reuse the origin page's two key names.** The transit select's empty first option becomes "Select a country" ("Dewiswch wlad"), and the search box gets its own placeholder, "Search for a country" ("Chwiliwch am wlad"). The transit copy takes the same two key names the origin copy already uses for this concept (`origin/copy/copy.en.js:5-6`), and its single `placeholder` key goes. One concept, one name across the two country searches. Rejected: keeping `placeholder` for the select text and adding a third name beside it. The port-of-entry and import-reason searches still use `placeholder` for select text. Aligning them is outside this row's footprint, so it goes in section 7 as a follow-up.
3. **Empty state: no line at all.** With no countries added, the page renders neither the table nor any sentence in its place, and the `empty` copy key goes from both locales. This is the template part of the old arrival-and-transit commit `49e22db9` and nothing else from it. That commit's FIT assertions proved the removal by absence (`getByText(EMPTY_LIST_SENTENCE).toHaveCount(0)`), which breaches the house rule, so they are not ported. The tests here prove the empty page with exact whole-list assertions of what it does show.
4. **Remove at the right goes through the mechanism the set's other tables already use for their action column:** the GOV.UK text-align-right override class on the row cell, passed in the govukTable cell's `classes`. It is used at `commodities/consignment-details/_selected-commodities-table.njk:21`, `commodities/animal-identification/_saved-animals-table.njk:19` and `commodities/animal-identification/_selected-commodities-summary.njk:13`. None of those three aligns its action header cell (its text is visually hidden), so the transit header cell stays as it is too. That keeps one mechanism for one rule. It is still GOV.UK's own utility class, so no custom CSS. Rejected: the row note's hint, the govukTable `format: "numeric"`. It would add a second alignment mechanism beside the existing one (house rule: "Extend the mechanism that exists. Do not add a second one beside it."), and would give a non-numeric action cell the numeric-column styling. The note is a hint, not the script.
5. **The label goes medium through the label `classes` the template already passes**, matching the origin page (`origin/template.njk:21`).
6. **The placeholder goes through the macro's existing `autocomplete.placeholder` option** (`accessible-autocomplete/macro.njk:12,44`), as the origin page passes it (`origin/template.njk:28`). No new mechanism.
7. **The row's note says to update "the ins-tests transit visual baseline", but no transit baseline exists.** The tests repo has visual specs only for origin-of-import and import-reason. The workspace Playwright guide says appearance belongs in a `@visual` baseline, not in measured geometry (`docs/best-practices/playwright/BEST_PRACTICES.md` "No measured geometry"). So this row adds a transit-countries visual spec with darwin and linux baselines, modelled on `origin-of-import.visual.spec.ts`. Rejected: an E2E position or width assertion, which the guide forbids.
8. **FIT proves Remove at the right as a yes-or-no computed style:** the Remove cell's text alignment is right. This follows the colour check already in `arrival-transit.fit.spec.js:198-214`. Rejected: comparing bounding boxes.
9. **Tidy-up inside the edited files.** Every comment in `transit-countries.njk`, `_added-countries-table.njk`, `transit-countries.controller.js`, `transit-countries.controller.test.js` and `tests/animals/e2e/pages/transited-countries.spec.ts` breaches the comment rules: each is rationale, or describes other code or the UI. Each is deleted. Where a reason is still worth keeping, it moves to the set's `docs/page-design.md` "Transport" section, the repo's stated home for "the reasons that would otherwise sit in code comments" (page-design.md:3-5). Where a deleted test comment held the reason a test exists, the test's title must say it; the implementor checks each such title.
10. **Page object, tests repo: locators only, expected lists as shared data.** The workspace Playwright guide says "Locators live on page objects under `page-objects/<domain>/`. Assertions stay in specs." (`BEST_PRACTICES.md:79`). So the transit page object gains only locators: the page's body paragraphs, its form buttons, the status region and the listed country names, plus the type-ahead as a public field, as the origin page object exposes it (`page-objects/animals/origin-of-import-page.ts:7`). The exact expected empty-page paragraph and button lists live as shared data in a new module under `domain/animals/constants/` (section 3), beside the other animals constants the specs import. `transited-countries.spec.ts` and `transit-means-scope.spec.ts` each make the whole-list assertions themselves against that data. Its `countryControl` getter duplicates the type-ahead's locator (`#transitedCountry`) and goes. Its `emptyListLine` getter locates a line that no longer exists and goes. Rejected: an assertion method on the page object with a section 14 departure. The guide is clear and the locator split costs only one data module.
11. **Adding on pick stays out.** "Add country" stays the confirm step, by Sam's ruling of 20 Oct (the add-on-pick spike).
12. **Rendered proof:** re-shooting `screens/main/S24--empty.png`, `S24--one-country-added--nojs.png` and `S25--one-country-added.png` is workarea evidence, not repo code. It belongs to the run's evidence step. The implementor builds no tooling for it.
13. **Removals are proved by what remains.** The removal tests in `arrival-transit.fit.spec.js` and `tests/animals/e2e/pages/transited-countries.spec.ts` are in files this row edits, so their absence-only checks of the removed row are replaced with exact whole-list assertions of the countries still listed.
14. **The new visual spec takes the exemplar's structure and nothing else.** Its reason for existing is decision 7, and the reason for masking the journey strip is recorded in section 3. Both live in this plan, not in the file. The exemplar's own comments are an existing breach outside this row's footprint (section 7 follow-up).
15. **The transit controller's refusal branches log, under bounded tidy-up.** The plan edits `transit-countries.controller.js` for the row (`countryItems`), and three of its outcome-changing branches log nothing: the Add refusal (a 400 from the add refusals: nothing chosen, not on the list, already added, at the cap), the Continue refusal (a 400 when the page's validation refuses on submit) and the GET banner (the stored list holds codes the page no longer offers, or is over the cap). Nothing upstream logs them: not `kit.js`, the engine, nor `server.js`'s catch-all, which logs only 500 and above. House rule, Logging and errors: "Every branch that changes an outcome (refusal, redirect, retry, fallback, state switch) logs once, with the ids support searches by." `pino-logging.md` §4a: "`info` for an expected refusal, such as a validation error". So each of the three logs once, at info, at the branch that decides, through `request.logger`, with `journeyId`, the refusal reason by a stable name (as the declaration refusal does, `declaration/controller.js:79-86`), and the country codes the refusal turned on. No payload or body. The recoverable-save fallback in `postContinue` is decided inside `kit.recoverableSave` (`shared/kit.js:212-224`), outside this footprint, so it goes to section 7 as a follow-up. This departs from `architecture.md:168-170` ("A validation 400 that re-renders the page does not log"); the house rules win, so section 14 records the departure and section 12 has the doc line changed. Rejected: logging in `kit.js` or the engine for every page. That widens the footprint across every caller, so it is a follow-up too.
16. **E4's expected list is the shared reference-data resource, and it runs where that list is served.** The no-JavaScript whole-list test expects "Select a country" followed by `countryAndSubdivisionNamesWithCountry()` from `@resources/reference-data/reference-data`, the same list `tests/animals/e2e/features/reference-lists/country-of-origin-list.spec.ts` uses (the transit list is the origin list: `countryItems` reads `countries.originCountries()`). It skips with `skipUnlessComposeEnvironment` as that spec does, because only the compose stack is sure to serve the stub's fixture. The no-JavaScript Add test beside it runs on every environment. Rejected: narrowing E4 to the first option only. The guide says "Assert the whole rendered list", and the compose-only pattern already exists for exactly this list.
17. **Two multi-step callbacks in the controller become named helpers.** `render`'s `countryRows` label callback looks up the index, then reads the label. The recoverable-failure callback passed to `kit.recoverableSave` in `postContinue` reads the journey, renders, then sets the status code. House rule, Structure: "A pipeline whose callbacks branch or take several steps gets named helpers, so the top function reads as a few named steps." Each becomes a named helper in the controller, or a single-step expression, with no behaviour change. The implementor names them.
18. **One spec owner for the list's first entry.** REQ-TRANSIT-COUNTRIES-009 and SCN-009-A stop naming the first entry and speak only of the countries and territories the search offers. The new REQ-TRANSIT-COUNTRIES-011 owns the wording: the label, the empty search box text, and the no-JavaScript list's first entry. Rejected: keeping "Select a country" in REQ-009 too, which gives one rule two owners that can drift.
