**Vocabulary.** `page-design.md:127-129` already calls the type-ahead autocomplete macro "the shared search control". The new component in this plan is a different control: a text box whose search is submitted by a joined icon button. In this plan it is called the **submitted search box**. The new macro, its stylesheet, its FIT look helpers and the new `page-design.md` lines take a name built on "submitted search", never "search control", so the two cannot be read as one.

## 0. Decisions

1. **One submitted search box per frontend, as a shared component.** Today the search block (label, hint, input, secondary text button) is copied into five templates: the animals party picker and the transporter list, and the plants consignor, place of destination and consignment contact pickers. It becomes one macro and its stylesheet in each frontend under `src/server/common/components/<name>/`, following `accessible-autocomplete/macro.njk` and `accessible-autocomplete.scss`. Each page calls it. Rejected: editing the five copies in place, which would give one look five owners.
2. **MoJ classes on GOV.UK macros, not `mojSearch`.** `mojSearch` emits its own `<form>`, and each page here is one POST form. The shared macro calls `govukInput` with MoJ's input-wrapper class and puts a `govukButton` in the input's after-input slot. The button carries MoJ's icon-button classes, MoJ's `aria-hidden`, unfocusable search svg and visually hidden button text from the page's existing `search.button` copy ('Search' / 'Chwilio'). The button keeps `name="action" value="search"` and stays the first submit in its form, so Enter in the box runs the search. MoJ Frontend 11.1.0 is already installed in both frontends, so `@ministryofjustice/frontend/moj/components/search/search` is imported in each `application.scss`, beside the date picker import. Neither the prototype's `type="button"` nor its clear 'x' is copied.
3. **Blue, joined, with the GOV.UK focus state.** The component stylesheet extends the existing `%blue-icon-button` placeholder (`src/client/stylesheets/helpers/_icon-button.scss`), as the date picker toggle and the autocomplete button already do. It also removes MoJ's gap between box and button so the two are joined. MoJ's default is green. The open question's default (blue) is taken, and the designers can switch it to green in one place.
4. **Label medium on every submitted search box the row names.** The macro always gives the label GOV.UK's medium label class. The row's detail says the prototype draws one control everywhere, so the transporter list gets the medium label too. Rejected: leaving the transporter label small, which would give the macro a label-size option nobody needs.
5. **Half width is passed by the picker callers; the macro applies no width of its own.** The macro takes one wrapper-classes parameter, applied to MoJ's input wrapper (box and joined button together). Each picker caller passes GOV.UK's one-half width override through it: the animals `_address-picker.njk` and the three plants picker templates. The transporter list passes no width class: its submitted search box sits in the left half of the GOV.UK grid row of decision 12, so it fills that half, which is half the content column. Rejected: a half-width default in the macro, which inside the transporter's grid half would make the box a quarter of the column; and a width option with a value nobody passes.
6. **Claim corrected: the transporter filter does not match type or status today.** Criterion 6 says the filter matches "by name, address, approval number, type or status … as today's server filter matches". It does not: `rows.js:23-30` matches name, address summary and approval number only. req-390 asks for type and status too. Built as the criterion states, by widening the one owner. The searchable text adds the type word and status word from the copy `rows.js` already resolves (`rows.js:10`, `copy.types` and `copy.statuses`). `copyFor` (`shared/copy.js:15-16`) is called with no locale there, so these are the English words (Commercial/Private, Approved/New) and nothing else. No Welsh word is matched, and no test or spec line claims it. The hint 'Name, address or approval number' stays as it is: no criterion changes it, and the prototype uses the same hint.
7. **One folding rule owns matching and bolding, on the server and in the page.** Case and accent folding (`foldForSearch`, `rows.js:17-21`) moves out of `rows.js` into one dependency-free module under `src/server/common/helpers/`. That module owns two things built on the one fold: whether a text contains a term, and where a term's folded matches sit in a text's original characters (so 'garcia' marks all six letters of 'García'). `rows.js`, the transporter filter, the shared bold helper and the type-ahead all go through it. `src/server/common` is already the shared space the client build reaches (`components/_index.scss` imports `src/server/common/components/accessible-autocomplete`). Rejected: a second fold in the client, or a case-only regex for bolding (`accessible-autocomplete.js:42`), either of which would give the rule two owners and leave rows matched by folding with nothing bold.
8. **The in-page filter reads text the server renders and has no rule of its own.** `rows.js` owns which fields a transporter is searched on. Each row it builds also carries its folded searchable text, and the template puts that on the row's first cell as a data attribute. `govukTable` has no row attributes, so the client hides the cell's parent row. The filter folds the typed term with the fold module and shows the rows whose searchable text contains it, so, over the whole list, every row the filter shows is a row `matchingTransporters` returns for the same term, and the reverse. With JavaScript on, the filter keeps the page holding the whole list: pressing the search button or Enter is handled by the component, which runs the filter and cancels the submit, so the server never narrows the list under a script-enabled trader and a new term can still find any row. Without JavaScript the submit reaches the server, which narrows the list as it does today. A FIT test types a term, presses Enter, then types another term that finds a row the first left out. A term that runs across two fields (address into approval number, `rows.test.js:81-85`) still matches, as the server matches it today.
9. **Bolding is per cell.** In each shown row, the filter bolds, inside each of the name, address, approval number and type cells and the status tag's text, every place where the whole folded term matches that cell's own text, through the shared bold helper. A row matched only by a term that runs across two cells is shown with nothing bold, because no single cell holds the whole term. An emptied box restores every cell's text unbolded. This is criterion 7 as built: "the letters that match in each shown cell". Rejected: making a term that runs across two cells stop matching, which would change the server search a no-JavaScript trader uses today.
10. **The escape-then-bold helper is shared, and takes the match class from its caller.** `escapeHtml`, `escapeRegExp` and `boldMatchedPieces` (`src/client/javascripts/components/accessible-autocomplete.js:22-51`) move to one client helper module under `src/client/common/helpers/`, the directory the CDP template keeps for client helpers. The helper escapes the text, finds the matches through the fold module (decision 7), and wraps each match in `<strong>` carrying a class its caller passes. The type-ahead passes its own match class (`accessible-autocomplete.js:18`), styled at `accessible-autocomplete.scss:55`, so its markup and its exact-string tests stay as they are. The transporter filter passes GOV.UK's bold font-weight override class, so it needs no stylesheet of its own. The class name is owned by each caller, never by the helper. Rejected: the helper keeping the type-ahead's class, which would put the autocomplete's name on the transporter table; and a neutral marker class both style, which adds a CSS rule.
11. **The type-ahead's suggestion matching goes through the same fold.** Today the type-ahead keeps suggestions with a case-only comparison (`accessible-autocomplete.js:57-60`). With the shared helper bolding by the fold, that would leave the type-ahead with two rules: one to show, one to bold. Its suggestion filter now asks the fold module whether a suggestion contains the term. Effect a user sees: on the origin, port of entry, transit countries and import reason type-aheads, plain letters also find accented options ('cote' finds "Côte d'Ivoire"). The exact output for unaccented options is unchanged, so `accessible-autocomplete.test.js` stays green. Rejected: a folded bold over a case-only filter, which bolds letters the filter did not match on.
12. **'Add a transporter' joins the search on one GOV.UK grid row.** The row has two halves: the submitted search box on the left, and the existing secondary 'Add a transporter' link-button on the right, right-aligned with the GOV.UK text-align override. It comes after the live region and before the fieldset, so the order reads search box, search button, 'Add a transporter', then the radios. The grid stacks on a phone, so the button sits below the search there. No flex CSS of our own.
13. **Live region copy: one function in the copy file; the template renders every count the page can show.** The filter writes into a polite, visually hidden live region that the server renders empty inside the form.
    - The shown-count message is one new copy entry under `transporters` in `transport/copy/copy.en.js` and `copy.cy.js`, a function of the count, in the shape of the addresses `resultsCaption` (`addresses/copy/copy.en.js:53`). It owns the wording and the singular or plural choice, in English and the Welsh machine draft.
    - A function cannot cross a data attribute, so the transporter template calls it once per count from one to the number of rows it renders, inside the row loop it already has, and writes the resulting list of messages as JSON (the Nunjucks `dump` filter) into a data attribute on the filter's module element. The filter reads the message for the number of rows it shows by position. It builds no sentence and decides no plural.
    - When nothing matches it reads the existing `noMatches` ('No transporters match your search.'), passed the same way as a plain string data attribute, as `accessible-autocomplete/macro.njk:43` passes `data-no-results`.
    - Rejected: placeholder strings with the plural chosen in client JavaScript, which would give the plural rule a second owner.
14. **The empty state works in the page.** The server renders the table and the `noMatches` paragraph every time, and hides whichever does not apply with the `hidden` attribute. With JavaScript off that renders as it does today. With JavaScript on, the filter shows the paragraph and hides the table when no row matches. This keeps the spec rule that a search matching nothing shows a message, not an empty table.
15. **A filtered-out pick stays picked.** The filter hides rows and never removes or unchecks a radio. A checked radio in a hidden row still posts with the form. The hidden `selected` field keeps covering the server search.
16. **Spec homes: extend the requirements that already own the picker search.** The button named 'Search' and the no-JavaScript Enter search go into `REQ-ADDR-006` (live-animals/addresses) and `REQ-PLANTS-ADDR-002` (plants/addresses), each with one new scenario. The transporter's search is `REQ-TRANSPORTER-002`, changed in place. No new picker-search requirement is added, so each capability keeps one home for its search. The plants `journey-pages/*` specs defer the picker to `plants/addresses` and gain nothing.
17. **Comment and title clean-up in the files this row edits.** Every rationale comment, comment about another module, library or page, restating comment, and history in a test title in a file this row edits is fixed in this change (sections 2 and 12). Rationale worth keeping moves to `page-design.md`. The `saveActions` call in `_address-picker.njk` passes `showReturnControls` by keyword, as `add-a-page.md:161` documents it.
18. **Fit run time.** The fit suite hit its 900-second global timeout on another laptop. New FIT tests are few and combine assertions per page state. Each picker spec gets its look and no-JavaScript checks from one shared helper. The five animals pickers share one template, so the animals checks run once, on the picker `hub-picker.fit.spec.js` already opens.
19. **Visual baselines.** The tests repo has no visual spec for these pages (`tests/animals/e2e/visual` holds only import-reason and origin), so there is no baseline to refresh. The re-shoots in the row's notes are workarea evidence that the orchestrator takes, not code.

## 14. Departures from written rules

1. "Do not add a SCSS partial or a CSS rule." (`docs/best-practices/gds/components.md`, "Stay in the GOV.UK toolbox".) Each frontend adds one component stylesheet. It extends the existing `%blue-icon-button` and removes MoJ's gap between box and button. Reason: the designers' snags and the 9 October ruling (claims 24-25) ask for the joined blue icon button, which MoJ draws green with a gap. The row's open question settles on one override beside the date picker's. The transporter filter's bold uses a GOV.UK override class, so it adds no rule.
2. "Never copy a prototype's JavaScript behaviour as it is", the JavaScript triage in the same section, and the programme invariant "no custom JavaScript is written to copy the prototype" (backlog header). The transporter list gets a small custom filter. Reason: Sam's 20 October ruling asks for filtering as you type on this list. No GOV.UK or other government component filters a table of radios. The accessible autocomplete would drop the columns traders compare (row notes, "Control call"). It is progressive enhancement over a page that already searches without JavaScript, built from the server's data, and does not copy the prototype's script.

3. "One rule, one owner: each display or business rule lives in one function, mirrored in each twin repo." (`.claude/rules/code-quality.md`.) The animals type-ahead matches suggestions through the new fold module, so plain letters find accented options. Reason: no plants criterion needs folded matching, and the footprint of this row stays bounded to the animals frontend's type-ahead. The follow-up in section 7 ("Move the plants type-ahead's escape-then-bold helper into a shared client helper with a fold module") closes the divergence.
