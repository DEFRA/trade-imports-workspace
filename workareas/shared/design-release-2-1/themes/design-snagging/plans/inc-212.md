## 0. Decisions

1. **Claim corrected: the address-lines part of the plants contact criterion is superseded.** The contact criterion asks for "each address read back on separate lines, with the country no longer in a column of its own". The row's notes of 20 October record Sam's later ruling: the address-cell snag (each line on its own line, full width) left this row for the address-book row that also swaps "View details" for "View". "Do not change the picker's address cells or width here." The later ruling wins. The contact page takes the heading, count and fieldset layout and keeps its five-a-page paging and "Selected address" inset (the open question's default). Its address cells, its Country column and its "View details" expander stay as they are. Rejected: building the separate-lines cells on the contact page only, which would make the three plants pickers differ and break the shared partial the row's notes ask for.
2. **Claim checked: the animals place of origin picker already searches like the other four.** All five animals parties share one picker (`parties.js:17-58`, `party-picker.controller.js:181`), and no "Enter a country" search exists in either frontend (`grep -rn "Enter a country"` finds only the transit-countries, address-edit and layout-test strings). That criterion needs no code. It gets proof only: the existing per-role FIT test checks the search label and hint for all five parties, place of origin included.
3. **Claim checked: plants offers no add-address control.** None of the three plants picker templates renders one, and no plants controller builds an INS link. That criterion needs no code. Its proof is a positive assertion of what the plants pickers do show above the search (section 4).
4. **'Add a new address' becomes a secondary GOV.UK button beside the heading on the five animals pickers.** It moves out of the shared `addressPicker` macro (the link under the intro, `_address-picker.njk:65-69`) into the page template `party-picker.njk`. There, caption and H1 sit in the two-thirds half of a GOV.UK grid row, and the button sits in the one-third half, right-aligned with the GOV.UK text-align override. It is a `govukButton` with `href` and the secondary modifier, so it renders as a link with role button. The grid stacks on a phone, so the button falls below the heading there. No custom CSS. The caption stays the H1's previous sibling, so the existing FIT locator still finds them. `addressPicker` loses its add-link parameter. The href rule is unchanged (`addAddressLinkFor`, `party-picker.controller.js:83-84`), so stub mode still offers no control. Rejected: keeping the button in the macro and passing it the heading, which would move the H1 into a partial that also renders the form.
5. **One results block, the same shape in both frontends.** Under the search box, each picker shows:
   - an H2 'Select an address' (GOV.UK medium heading);
   - when there are rows, the count paragraph 'Showing <shown> out of <total> results';
   - one GOV.UK fieldset whose legend 'Select an address' is visually hidden. It holds the picker's error message, then the table or, when nothing matched, the existing no-matches message.

   Pagination stays after the fieldset. The fieldset is described by the error message when there is one, following the GOV.UK error pattern, so every radio is announced with the error. That replaces the plants contact page's per-radio `aria-describedby` (`consignment-contact-select/template.njk:60`). The table caption goes. The heading and the legend are one copy string: one concept, said twice. With no matches the heading stays, and the no-matches message replaces the count and the table, keeping today's empty state (rule: a search matching nothing shows a message, not an empty table). Rejected: printing "Showing 0 out of 0 results", which the prototype draws but which says less than the existing message.
6. **The count's wording has one owner per frontend.**
   - Animals: the `picker.resultsCaption` copy function (`addresses/copy/copy.en.js:53`, `copy.cy.js:54`) is replaced by a count function under `picker` with the new wording.
   - Plants: the three page copies each hold their own `resultsCaption` today (consignor, place of destination and consignment contact `copy.en.js` and `copy.cy.js`). They are deleted, and the one count function lives in the shared picker copy `address-book-picker/copy/copy.en.js` and `copy.cy.js`.

   The rename covers the concept's whole vocabulary: the copy key, the view-model field (`resultsCaption` in both view models), the template reads, the unit and FIT tests, and the tests repo's `resultsCaption` page-object locators. Each Welsh entry is a machine draft.
7. **Plants: the three pickers' results block becomes one shared partial.** This follows the row's notes. The block runs from the error message through the table and pagination. Today it is copied into the consignor, place of destination and consignment contact templates (`template.njk:41-104` in each). It becomes one macro in `address-book-picker/`, mirroring the animals `addressPickerResults` macro. It takes the field name (radio name, error id, first-row id), the picker view model and the shared picker copy. The address cells, the Country column and the "View details" expander are moved as they stand (decision 1).
   - The strings that block renders move from the three page copies into the shared picker copy: `errorPrefix`, `noMatches`, `table.*`, `selectRowPrefix`, `viewDetails`, `viewDetailsFor`, `pagination.previous` and `pagination.next`, plus the new heading/legend and count. The pagination labels move because the block renders the pagination: the shared view model (`address-book-picker/view-model.js:63`) reads them from the shared picker copy, as it reads the count.
   - Each page copy keeps its title, description(s), `search`, `selectedAddressPrefix` and `errors`. The search box and the "Selected address" inset are rendered by each page template above the block (`template.njk:27-39`), lines this row does not change. Their identical strings are left three times over and listed as a follow-up (section 7), so the row's footprint does not widen to the search box the previous row built.
   - `renderPicker` passes the shared picker copy to the view beside the page copy. The module-level name `cardCopy` in `render.js:13` no longer describes what it holds (card strings and results strings), so it is renamed.
   - Every FIT helper and spec that reads a moved key reads it from the shared picker copy (sections 2 and 11): `addressRowRadio`, `expectSelectedAddressCarriedToSecondPage` and `describeAddressPicker` in `fit/high-risk-plants-journey.js`, `party-edit.fit.spec.js:44`, `consignor-select.fit.spec.js:34` and `consignment-contact-select.fit.spec.js:135-184` and its `addressRowRadio` calls. This is a signature change across callers that the move forces: `addressRowRadio` no longer takes a copy, because the row prefix has one home.

   Rejected: passing each page's own copy into the partial, which would keep the count and table wording three times over. Rejected: moving `search` and `selectedAddressPrefix` too, which would edit the search box markup the previous row landed.
8. **A save with nothing chosen is never refused, on any picker in either frontend. A chosen id the book does not hold, or no longer holds, is still refused.**
   - Animals (`party-picker.controller.js:153-159`): with no id posted (no radio, no carried `selected`), the save commits nothing and redirects where a save goes (`savedTarget`): the consignment addresses page, the amend review, or the addresses page still changing. The role stays empty or keeps its copy. The not-in-book refusal (`:161-173`) stays as it is.
   - Plants: the consignor and place of destination controllers drop `leavesUnchanged` (`consignor-select/controller.js:51-52`, `place-of-destination/controller.js:73-75`). A blank save goes to `kit.nextTarget` with nothing committed, as the contact controller does (`consignment-contact-select/controller.js:86-88`).
   - The overview exit needs no special case, because every blank save now leaves.
9. **Plants: the save rule gets one owner.** The decision from a posted selection is the same on all three plants pickers: nothing chosen means leave unchanged, an id not in the book means refuse, otherwise use the chosen record. It moves into one function in a new module under `address-book-picker/`, beside `chosenFor`, and that function logs the two branches that do not commit (section 13). The three controllers' `post` calls it. Each keeps its own field name, error copy and commit. Rejected: editing the rule in three controllers, which would give one rule three owners. The rest of the controllers' copied plumbing (page parsing, the search action, `committedId`) is a follow-up (section 7), because only the save rule is this row's behaviour.
10. **Animals keeps its one owner.** The five parties already share `party-picker.controller.js`. The blank-save and refusal branches log there.
11. **Escape the name in the animals radio label.** `_address-picker.njk:18` concatenates `row.name` into the radio item's `html` string unescaped, so a name holding `&` or `<` goes into the page as raw HTML. The label is built the way the plants pickers build it (a `{% set %}` block, which autoescapes), so the name is escaped. A unit test renders a name holding both characters (section 4).
12. **Comment clean-up in the files this row edits.** These files hold comments that give rationale, describe other modules or restate the code:
    - animals `party-picker.controller.js:41, 44-45, 47-49, 103, 153`;
    - plants `consignor-select/controller.js:19-28, 47-50, 54-55, 90`, `place-of-destination/controller.js:23-32, 49-57, 69-72, 77-78, 108-109` and `consignment-contact-select/controller.js:18-30, 49-50, 78`;
    - plants `render.js:15-18, 54-58, 89-90`;

    - the tests repo page objects `place-of-destination-page.ts`, `consignment-contact-select-page.ts` and `party-picker-page.ts` (every doc comment that describes the page, a library or rationale).

    Each is deleted. A doc comment on an exported function keeps only its contract (`renderPicker` keeps its parameter block). Rationale worth keeping moves to the repo docs (section 12). The animals view model has no comments.
13. **Plants page objects share one picker base.** The three plants picker page objects repeat the same locators (address radio, search box and button, selected inset, page link, Save and continue, error summary, current address card) and each would gain the new heading and count. They extend one new shared base under `page-objects/plants/`, which owns those locators and the search step. The three keep only what is their own: slug, heading, description, region name. Rejected: adding the new locators three times.
14. **FIT run time.** All five animals pickers share one template and one controller, so the animals FIT proves the layout and the blank save once, on the consignor picker. The five-party loop of refusal tests (`hub-picker.fit.spec.js:182-193`) becomes a single not-in-book refusal test. The controller unit test proves all five parties' blank save in one loop.
