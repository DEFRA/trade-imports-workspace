## 0. Decisions

1. **Headed sections, not a summary list.** Follows the row's ruling: conflict c-087's summary-list outcome is set aside, because DR1 did not judge the component. `distil/conflicts.json` c-087 already carries the "set aside on 19 October" note (checked live), so there is no workspace edit for it. Rejected: keeping the summary list.
2. **The template owns all markup.** The controller passes structured sections (heading, hint, add link or chosen lines, Change and Edit details hrefs). Today `hubRow` builds HTML strings in JS for the summary-list key. Nunjucks autoescapes the lines, and the hard-coded HTML goes away. Rejected: building inset HTML in the controller.
3. **One section shape for the five parties and the CPH number.** The CPH section uses the same loop and shape: its chosen state is one line, the stored CPH value, with Change and no Edit details. Rejected: a second CPH block in the template. CPH display stays as stored (`123456789`). Showing it as `12/345/6789` belongs to consignment-parties inc-092.
4. **The inset address lines.** Name (bold), then `addressLine1`, `addressLine2` and `addressLine3`, each on its own line. Then one final line that joins `townOrCity`, `county`, `postcode` and the country name with ", ", skipping blanks. This reproduces the prototype (`Hull, HU9 5PX, United Kingdom`; routes.js appends the country to the last address line) on this repo's address shape. A party with no address parts shows only its name, plus the country line if there is a country. The country name is the one held on the party copy (`address.country`), as check your answers reads it; no lookup. Rejected: county on its own line. The prototype data has no county, and the criterion's example puts the locality, postcode and country on one line.
5. **Add links name the party and carry no hidden suffix.** As the row's notes say (c-089), the add link names the party. Change and Edit details keep a visually hidden suffix naming the party, the lower-cased section heading, as today.
6. **Accessible structure.** Each section is a `<section>` labelled by its own `govuk-heading-m` h2 (`aria-labelledby`), so it is a named region. The hint uses the `govuk-hint` style in a paragraph. The chosen party sits in `govukInsetText`. Links are plain `govuk-link`s in `govuk-body` paragraphs. No prototype `app-dr2-*` classes.
7. **The 'Consignor' rename in animals is one copy change.** `copy.parties.consignor.title` (en and cy) feeds the section heading, the picker H1 and browser title (`party.title` in party-picker.controller.js:47,56), the party-edit caption and the hidden link suffixes. Welsh becomes 'Anfonwr', the word animals check your answers already uses. The animals overview task hint 'Consignor or Exporter, ...' stays (c-103), and so do the consignor's id, routes and address-book role.
8. **The plants rename covers the consignor picker and check your answers, not the task list.**
   - Changing: the picker H1 and page title (`consignor-select/copy`), its held-copy card title ('Current consignor' / 'Anfonwr presennol', in `address-book-picker/copy` `parties.consignor.current`) and the party-edit caption (`address-book-picker/copy` `parties.consignor.title`), so plants mirrors the animals edit caption.
   - Check your answers: the card label (`check-answers/copy` `cards.consignor`) and that page's two consignor error lines (`errors.parties.consignor`, `errors.cards.consignor`), so the page names the party one way. The wording mirrors animals check your answers ('Correct the address details for the consignor').
   - Staying: the plants overview task row 'Consignor or exporter' (`hub/copy` `rows.consignor`). The ruling names only the picker and check your answers, and it mirrors the animals overview hint staying.
   - Rejected: renaming the task row. Its tests and spec (`plants/journey-flow`, `consignor-select` REQ-002) would move with it.
9. **Removed copy keys.** `hub.notAddedYet` and `hub.add` go from both locales, because nothing renders them now. New keys per party carry the add-link text (in `copy.parties.<id>`, so `PARTIES` picks them up by its existing spread), and `hub.cph` gets its own. New `hub` keys hold the intro paragraph. The warning loses its full stop in en and cy.
10. **Fit helper promotion.** `rowFor` is copied in hub-picker.fit.spec.js:27-30 and party-edit.fit.spec.js:19-22, and inlined twice more in fit/live-animals-journey.js:740 and :771. All four become one section locator in `fit/live-animals-journey.js`, and the local copies are deleted.
11. **Tests repo page object owns the section vocabulary.** `AnimalsAddressesPage.partyRow` becomes a section (region) locator, and `addParty` uses each role's named add link. `PartyRole` 'Consignor or exporter' becomes 'Consignor'. Specs keep calling the page object.
12. **Rationale home.** The reasons go in `sets/live-animals/docs/page-design.md` "Consignment addresses pages", never in code: why headed sections, why the add link needs no hidden suffix, why the country joins the last line, and why every party link carries the change context (a change started from check your answers returns there after the picker).
13. **Row and 'not added yet' vocabulary becomes section and add-link vocabulary everywhere this change touches.** The page has no rows and no 'Not added yet' text once this lands, so every name, title and comment that says so becomes untrue. The rename covers, in the frontend: the FIT helpers `openCphNumberFromRow` and `answerCphNumberFromRow` (fit/live-animals-journey.js:769, :778, and their import and call in cph-number.fit.spec.js:7, :44 and fit/live-animals-journey.js:748); `expectConsignorNotAddedYet` (hub-picker.fit.spec.js:38, :300, :309); the controller.test.js locals `rowsFor`, `cphRowOf`, `rowTitled` and `CONSIGNOR_TITLE`. In the tests repo: the page-object members `partyRow` and `cphRow` (addresses-page.ts:15, :35) and their callers, and the spec variables `consignorRow` (addresses-copied.spec.ts:29, :130; addresses-picker.spec.ts:58, :119) and `cphRow` (cph-scope.spec.ts:12). Every test title listed in section 4 item 19 moves the same way. The new names are the implementor's: each says "section" or names the add link, never "row" or "not added yet". The check-your-answers locators (`notificationView.partyRow`, `consignorCyaRow`) stay: that page still has summary rows. The picker's table rows (`detailedRow`, "the row selected on a later page") stay: the picker still has rows. Rejected: renaming only the identifiers the code change forces.
14. **The address-book spy test is replaced at the network boundary.** controller.test.js:140-147 spies on the repo's own `services/address-book` module. It becomes a behaviour test: with the address book on the network boundary refusing every address request (`addressBookCountriesServing` with `restoreAddressBookAfterTests`, engine/test-support.js:310, :320, as party-edit.controller.test.js uses them), the page still renders the held party in its section's inset exactly. Rejected: deleting it, because the page naming a party from the copy alone, never the book, is a behaviour the spec records (copy held on the notification). Rejected: asserting the request list is empty, which proves by absence.
15. **Absence assertions the role rename touches become exact positive assertions.** addresses-copied.spec.ts:146-147 and addresses-edit.spec.ts:171, :188-189 each prove a removal by absence (`not.toContainText`, `toHaveCount(0)`). The page object gains one locator for the links a section offers, and each spec asserts that exact list: a chosen section offers exactly Change and Edit details, and an empty section offers exactly its named add link. Rejected: keeping `toHaveCount(0)` beside a positive check.
