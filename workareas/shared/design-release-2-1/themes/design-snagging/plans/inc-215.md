## 0. Decisions

1. **Layout goes through `kit.base()`, which gains a surface option.**
   - The precedent, as it is: `kit.base()` hard-codes `contentColumnClass: SURFACES.form` (`src/server/app/shared/kit.js:195`), and so does `setlessBase()` (`:209`). The dashboard never calls `base()`: it builds its own view model and sets `contentColumnClass: surfaceClass('display')` directly (`features/dashboard/controller.js:73-76`). No `base()` caller replaces its `contentColumnClass` today, so documents would be the first.
   - Weighed on that basis:
     - Overriding the key after the `base()` spread in documents `render.js` leaves two owners of one page's column: `base()` sets form, the feature silently replaces it. That is a second route beside the mechanism that owns page chrome.
     - A surface option on `base()`, defaulting to the form surface and resolved through `surfaceClass` (`kit.js:25-32`), extends the existing mechanism. `base()` stays the one place a `base()` page's column is decided, and an unknown surface still throws. No caller changes: every other caller keeps the default.
   - Chosen: the `base()` option. Documents `render.js` passes the display surface to `base()`. `base()`'s doc comment (`kit.js:151-164`, exported API) gains the option.
   - The dashboard's direct `surfaceClass('display')` stays as it is: it does not use `base()`, so it is not a second route through it.
   - Rejected: overriding the key after the spread (two owners, above) and custom CSS (programme invariant: govuk-* only).
2. **Two-thirds reading width inside the page uses GOV.UK grid classes in the template**, not a new surface value: the error-summary container, caption, H1, guidance and the details expander sit in a nested `govuk-grid-row` / two-thirds column; inside the card, the four fields and "Save and add another" sit in a nested two-thirds column; the added-documents table, the refresh link and the still-checking message stay outside that column, full card width. Rejected: a new `SURFACES` entry (the surface map is the page column, not inner layout).
3. **The layout's own banners and status strip go full width.** `shared/layout.njk:79-99` renders the recoverable-error and stale-action banners and the journey strip inside the content column, so on this page they span the full width. Accepted: the prototype draws its notification status in the full-width column too (`upload-documents.html:29-31`), and the dashboard already lives with this. Rejected: moving those blocks out of the layout for one page.
4. **A long document reference wraps instead of spilling.** The reference cell takes GOV.UK's `govuk-!-text-break-word` override (present in govuk-frontend 6.5.1, `dist/govuk/overrides/_typography.mixin.scss:39`). Without it a 58-character unbroken reference can push the table past the card. Rejected: custom CSS or truncation.
5. **Actions right-align with the GOV.UK table's numeric format** on the Action header (template) and the actions cell (`view-model/rows.js` `actionsCell`), as the prototype does (`upload-documents.html:211, 230`). The View file link stays beside Remove.
6. **The sixteenth-document refusal becomes an Attachment field error.** The limit message moves from a summary-only entry linked to the documents list (`form/errors.js:70-75`, `controller.js:108-112`) to a field error on the file field passed through the render's existing `errors` option, so `kit.errorSummary` links it to `#file` and the template shows it inline on the Attachment field. Provenance: conflict c-075 and the prototype route `app/routes.js:10949-10957`. `contracts/documents-added-anchor.js` stays: `scan/summary-errors.js:18, 24` still links to the list, and the tests repo reads `#documents-added`.
7. **The empty-state text goes, in both locales.** The `else` branch of the template and the `empty` copy key are removed from `copy.en.js` and `copy.cy.js` together. The review page's own empty line (`check-answers/copy` `documentsEmpty`) is a different key and stays (row note).
8. **"In Welsh" is proven by the copy, not a rendered Welsh page.** `shared/copy.js:15-16` always serves the default locale today, so a Welsh render cannot be driven. Removing the key from both locales, with `copy-parity.test.js` holding the trees equal, is the proof.
9. **Date of issue hint stays feature copy.** The hint is the documents feature's own `dateOfIssue.hint`, as import-reason keeps its own (`import-reason/copy/copy.en.js:52`). Programme invariant: shared copy is never reworded in place. Welsh: "Er enghraifft, 27/3/2026" (AC; machine draft). Rejected: a new shared date-example key (wider clean-up, see follow-ups).
10. **Both constraint bullets become per-locale copy functions, so each locale owns its own sentence shape.**
    - The size bullet is a function of the size label, shaped like `file.upToMaximum(max)` (`copy.en.js:53`). English gives "files that are smaller than 10MB". The Welsh draft keeps its copula ("yn llai na") inside its own function.

    - Rejected: deleting `file.a` and printing the hint bare in the template. That drops the Welsh copula while the Welsh size bullet keeps one (`.claude/rules/copy.md`: change en and cy together, GDS rules in both).

## 14. Departures from written rules

1. **The capacity refusal logs although it re-renders with 400.**
   - Rule: `repos/trade-imports-animals-frontend/src/server/app/docs/architecture.md:169-170` — "A validation 400 that re-renders the page does not log".
   - Reason: the cap is a business refusal, not field validation: the trader's entries can all be valid and the save is still refused because the notification already holds fifteen documents, the same kind of refusal as the declaration refusal the doc logs as its canonical example. And `.claude/rules/code-quality.md` — "Every branch that changes an outcome (refusal, redirect, retry, fallback, state switch) logs once, with the ids support searches by" — wins over a repo doc. The doc's wording is a follow-up (section 7).
2. **The reference cell carries a custom CSS class, `app-table__cell--break-anywhere` (`src/client/stylesheets/components/_table.scss`, used at `documents/view-model/rows.js`).**
   - Rule: `.claude/rules/gds.md` — "no custom CSS".
   - Reason: `govuk-!-text-break-word` sets only `overflow-wrap: break-word`, which leaves a table cell's minimum width at the unbroken reference, so a `REFERENCE_MAX_LENGTH` reference pushes the table past the card. `overflow-wrap: anywhere` lowers the minimum width, so the table stays inside the card. The exception is recorded in `src/server/app/sets/live-animals/docs/page-design.md` under Documents.
   - Mutation probe: removing the class from `rows.js` turned both long-reference fit tests (JavaScript on and off) red, `expectNoHorizontalOverflow` reporting the File upload card overflowing by 315px at 1280px with the table and the reference cell named; restoring it turned them green (logs `inc-215-fix-css-probe-red.log` and `inc-215-fix-css-probe-green.log`).
