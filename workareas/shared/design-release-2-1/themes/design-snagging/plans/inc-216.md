## 0. Decisions

- **The claims hold.** On the live tree the bar is `.app-summary-list__value--missing` in `src/client/stylesheets/components/_summary-list-missing.scss:8-13` (an inline-block with a red `border-bottom`), imported at `components/_index.scss:8`, emitted only by `missingCell()` in `check-answers/view-model/rows/value-text.js:42-47`, which `view-model/incomplete-cards.js:92` calls for each empty row of an errored card. No germinal-products set exists in this repo today, and plants has no such class, so the row stays animals-only, as it says.
- **The missing cell keeps the visually hidden "Missing" and loses its wrapper.** The cell's html becomes only the GOV.UK visually hidden element carrying `copy.missing`. Rejected: keeping the wrapper span with no class or no style — markup that carries nothing.
- **The stylesheet is deleted, not emptied**, and its `@use` removed from the components index. Rejected: keeping an empty partial.
- **`value-text.js` loses all three doc comments** (`dateText` :22, `notApplicableCell` :35-36, `missingCell` :39-41). The module is an internal helper of the check-answers view-model (only files under `check-answers/view-model` import it), so by `docs/best-practices/doc-comments/jsdoc.md:9-13` and the house rule none of its functions may carry one, and `missingCell`'s also describes its callers. Nothing in the file describes its callers afterwards. The functions keep their names: renaming `dateText` (whose comment explained that it returns null for a blank) would edit its callers in four card files only for clean-up, so it is a follow-up (section 7). The unit suite already pins the null-for-blank behaviour through the rendered rows.
- **No copy change**, so no Welsh draft is needed: `copy.missing` (`'Missing'` / `'Ar goll'`) is unchanged.
- **The card-level marking is untouched.** The red left border (`app-summary-card--error`, `_summary-card-error.scss`) and the "Complete <card>" error message stay, as ruling 7a (sam-2026-10-09-pm) requires.
- **The phone viewport gets one owner: the shared FIT helper.** The new FIT test needs a phone width. Two local copies exist today: `type-ahead.fit.spec.js:25` (375 × 800) and the literal in `hub.fit.spec.js:530` (360 × 740). This change promotes one phone viewport to `fit/live-animals-journey.js` and, in the same change, replaces both local copies with it, so the house rules "Set-up used by two tests goes in the shared test helper. Promoting a helper deletes the local copies" and "Extend the mechanism that exists" both hold once it lands. This changes two callers outside the row's own files; the bounded tidy-up allows it because the row's own test genuinely needs the viewport and a third copy would be a second mechanism. Each of those two files gets only the touched function fixed (the type-ahead phone-width `beforeEach`, the hub small-screen test). The shared value is 360 × 740, the narrower of the two: the hub overflow test keeps the width it has today (no loosening) and the type-ahead phone checks run at a width at least as strict. Rejected: a third local copy in the check-answers spec; promoting without replacing the copies.
- **`fit/live-animals-journey.js` is edited for this row's own test, so its breaches are in the footprint.** Every doc comment in it is on a test helper, not an exported public API (`jsdoc.md:9-13`: "Do not ... internal helpers, even when exported for a test"): lines 35-40, 53-58, 107, 137-142, 148, 207, 365-369, 379-387, 426-430, 434-438, 445-449, 458-463, 540-545, 731-736, 748-752, 785-791, 842-847 are deleted. `childTagsAndClassesOf`'s parameter is named for a form group but the new test passes it an answer cell, so the parameter gets a name for any element (body only; no caller changes). No exported name changes.
