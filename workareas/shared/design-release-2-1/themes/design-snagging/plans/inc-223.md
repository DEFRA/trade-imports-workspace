## 0. Decisions

1. **Save fallback logging lives at its one owner, `kit.recoverableSave`, in each frontend.** It is the branch that decides "recoverable backend failure, fall back" (`isRecoverableBackendError`), and the pino guide says to log at the branch that decides, once. It gains the request so it can log once at warn with `journeyId` (from the request's route params) and the caught error as `err`, plus any extra ids its caller passes. Every caller changes to pass the request (the row needs this structural change; it is the "logging a rule at its one owner" case). Rejected: adding the same warn line to each of ~16 animals and 14 plants fallback callbacks, which would be thirty copies of one rule. The provenance note asked each caller to log `{ err }`; the owner logging it satisfies the criterion with one owner.
2. **The fallback callback no longer receives the error.** Once the owner logs it, nothing in a callback needs it, so the callback stops taking it (build only what is reachable). The callers that log their own fallback line today — the documents add-save, the documents removal (two calls through its file-local removal-retry logger) and the transit countries save — drop their own line, and pass their extra ids (`uploadId`, and `index` for a removal) to the owner, so each fallback still logs exactly once with the ids support searches by. The file-local removal-retry logger and the transit countries save-unavailable helper's log line go; the transit helper keeps only its render.
3. **Refusal logging gets one owner too: a new kit helper in each frontend's `shared/kit.js`.** It logs a page's refusal once at info with `journeyId` and the error codes, and any named reason or ids the branch passes. "Error codes" are the field keys of the errors the page shows (never the messages, which can carry what the trader typed). It names no feature, so it meets the kit rule in architecture.md ("only when every journey page could use it and it names no feature, set or page"). Every branch that refuses an answer and shows the page again with errors calls it once, whatever status code it answers with. Rejected: a Hapi `onPreResponse` extension that sniffs 400 views (it cannot see pages that refuse with 200, and it hides the decision from the branch that makes it); rejected: an inline `request.logger.info` per branch (one rule, many owners).
4. **Branches that already log a named refusal while re-rendering with errors move onto the helper** and pass their reason and ids, so one function owns the line shape and each branch still logs once: transit countries Add refusal and Continue refusal, the documents 15-document limit, the documents oversize payload, and the documents "Continue refused: not cleared by the virus scan" re-render. Branches that refuse by redirecting (the declaration's `logRefusalAndRedirect`, kit's stale-action redirect, the party picker's no-address save) or with a bare 400 and no page are not "shown again with errors" and keep their own lines. The transit countries GET banner log is a stored-answer display, not a refusal of a submitted answer, and stays.
5. **The refusal inventory** (from `grep` for `hasErrors(`, `if (errors`, `Object.keys(...).length > 0` and `HTTP_STATUS_BAD_REQUEST` re-renders, read against each file). Animals: contact, transporters, transporter details save (private and commercial), transporters select, transporter add, transit countries (Add, Continue), port of entry, additional details, consignment details, animal identification, commodity search, party picker (the not-in-address-book refusal), party edit, import reason, documents (field errors, limit, oversize, not-cleared Continue), origin, cph number, declaration (the required tick). Plants: arrival status, commodity details (each refusing branch in `details.controller.js`), commodity list (each 400), commodity type, the three address-book pickers through `address-book-picker/save-selection.js`, place of destination/consignor/consignment contact where they re-render with errors, identification numbers, origin (each refusing branch), arrival details, party edit, declaration (the required tick), check answers (its 400 re-render). The implementor re-runs the inventory grep before finishing; any further branch found joins it.
6. **Status codes are left as they are.** Some animals pages refuse with 200 (transporters, transporter details save, transporters select, transporter add, consignment details, animal identification) while architecture.md says a refused POST answers 400. Changing a status is a behaviour change this row says it does not make; it goes to follow-ups.
7. **The date example "For example, 27/3/2026" moves to a new entry in each locale of the animals shared copy (`shared/copy.en.js`, `shared/copy.cy.js`).** It is cross-feature wording about the platform's date text format (`kit.readDate` reads d/m/yyyy), and the copy rule says shared copy holds cross-feature strings. A new key is not a rewording of shared wording, so the shared-copy invariant holds. The documents and import reason hints point at it, as the addresses copy already points its add-address leaves at shared copy; the transport arrival date hint keeps its own leading sentence and joins the shared example after it. Rejected: a journey-level copy module (none exists; it would be a second mechanism). Plants is left alone: its date hints are the journey spec's own wording held per arrival state on its arrival details page, not the same three pages.
8. **The Welsh file type list joins with the copy's own word for "or".** Each documents copy locale gains its word for "or" ("or", "neu"); one function in `documents/upload-config.js`, which owns the allowed types, joins the upper-cased extension labels with commas and that word before the last. The view model builds the hint from the page's own copy. The English error message that quotes the list stays built from English copy through the same function. Rejected: `Intl.ListFormat` per locale, because it keeps a language word outside the copy files reviewers and translators work in, and the app has no locale tag to pass (`copyFor` selects by module, not tag). The English list reads exactly as now ("PDF, DOC, DOCX, JPEG, JPG, PNG, XLS or XLSX").
9. **The scan status refresh choice becomes a named option** on both `withScanStatus` and `scanStatusOf` in `documents/scan/status.js` (the latter is exported and also takes the bare boolean), keeping the concept name the document uploads service already uses for the same flag. All three callers (documents controller status route, `handlers/load-page.js`, `check-answers/refusal.js`) and the status unit test pass it by name.
9a. **The scan status fallback in the touched `scanStatusOf` logs through the request.** Its catch branch (shows the document as pending) logs today through a module-level `createLogger()` with only `uploadId`, so the line has no trace id and no `journeyId`. Because every caller already changes to pass the named refresh option, the same options object also carries the request: `scanStatusOf` logs that fallback once at warn through `request.logger` with `journeyId` (from the request's route params), `uploadId` and `err`, and the module-level logger and its import go. Two of the three callers hold the request already. The third, `check-answers/refusal.js`, reaches `withScanStatus` from the exported `documentScanCardErrors(answers, { includePending })`, which has no request: it gains the request in its existing options object, and its two callers, `isReviewRefused` in the same file and `renderNotificationView` in `check-answers/controller.js:155`, pass the request they already hold. This crosses one file more than decision 9 did; it is the "log a rule at its one owner" case, and the files touched only to pass the request get only their touched lines and function fixed (decision 11). Rejected: keeping the module logger and leaving the fallback without `journeyId` (breaks architecture.md's Logging rule in a function this row touches); rejected: logging in each caller (three owners of one fallback).
10. **The action column moves from `format: numeric` to the `govuk-!-text-align-right` class** on both its header and its cells, following the transit countries added-countries table, which already does this.
11. **Bounded tidy-up in touched code.** Each `kit.recoverableSave` call this row edits is fixed inside that call: a positional boolean passed to a file-local `render` from its fallback becomes a named option on that file-local `render` (animals and plants delete-notification and cancel-amend `render(h, journey, true)`; animals declaration `render(..., {}, true)`), and the rationale comment inside the additional-details save is deleted. Every one of these `render` helpers is file-local, so no signature change crosses files. In `documents/upload-config.js` the two rationale comments are deleted: the ingress body cap is already stated in `sets/live-animals/docs/page-design.md` ("The file size limit is held at 10 MB so the request stays inside the CDP ingress body cap"), and every accepted extension is already listed in the behaviour spec's accepted-types scenario. In the functions touched only to pass the request on (decision 9a): `documentScanCardErrors`'s doc comment is cut to its contract (what it returns and when a pending scan counts), dropping the reasoning; `renderNotificationView`'s rationale comment on card error precedence (`check-answers/controller.js:164-167`) is deleted, and the merge order it explains is said by an extracted, named function in that file instead.
12. **No tests-repo change.** Nothing a user sees changes in English, the Welsh copy is not served (`copyFor` always resolves English today), and the action column already renders right-aligned. The gate's E2E phase over both frontends is the no-regression proof (the animals arrival details spec already asserts the composed transport hint; the documents limit, reject, refresh and scan lifecycle specs exercise the documents page and its refusals).
13. **Claims checked.** The animals architecture doc's logging paragraph was already reworded (lines 165-173 now say a named-reason validation refusal logs) but still only covers controllers that decide a "named refusal reason", not every refusal shown with errors; it is reworded to the general rule. `kit.recoverableSave` in animals already hands its fallback the error; in plants it does not. `scanStatusOf`'s fallback logs through a module-level logger with no `journeyId` (decision 9a). Every other claim in the row holds.
