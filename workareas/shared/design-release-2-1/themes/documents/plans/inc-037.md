## 0. Decisions

- **The narrowing lives in the documents feature's own contract module, not in the service module.** Two lists are conflated in the tree today and this row separates them. `services/document-types/index.js:3` answers the vocabulary this service may send to the backend; `features/documents/contracts/document-type-options.js:3` answers what the Upload documents page offers, and today it is a pass-through of the first. The offered list is a live-animals journey decision, and the service layer is set-agnostic by construction — "Never imports `sets/**`, never contains live-animals copy or vocabulary" (`.claude/skills/frontend-change/SKILL.md`, L2; `src/server/app/docs/architecture.md`). So the page's list is narrowed where the page's list already has an owner, and the service module keeps all fourteen. Rejected: editing `services/document-types/stub.js`, which would take a journey decision into the platform layer, break the emitted-vocabulary contract test at `src/server/app/services/mapper-a-enum-contract.test.js:50-52`, and — through `features/documents/validate.js:19` — make every document already saved as the withheld type read back as no longer valid, which the third criterion forbids. Rejected: a second exported list beside the catalogue in the service module, which is a second mechanism for one concept and duplicates thirteen codes that would then have to be kept in step by hand.
- **The row's note about why the third criterion exists does not hold, and the plan is built on what the code does.** The note says `form/payload.js` validates the submitted type against the same list "so an older saved value is refused as a type the page never offered". `form/payload.js:37-41` and `:56-59` only ever see the add form's own payload — one new document — so no already-saved type passes through them. The check that would refuse an older saved value is the stored-list check at `features/documents/validate.js:18-26`, which reads the service module directly and not the feature's contract. That is exactly why narrowing at the contract satisfies the third criterion for free, with no compensating code, and it is the strongest reason to put the narrowing there. The criterion is kept as a proof obligation all the same, because nothing else pins the separation.
- **The withheld type's label stays in both locales' copy decks.** `view-model/rows.js:57` labels a saved row's type from `copy.types`, and `features/check-answers/view-model/cards/documents.js:21` does the same on the review. Dropping the label would blank the Document type cell for a document already recorded as that type, which the third criterion forbids. Rejected: moving the label somewhere separate from the other twelve — one map, one owner.
- **No new or changed English string, so the Welsh invariant needs nothing.** The change removes an option from a list; every label on the page, the withheld one included, keeps the wording and the Welsh draft it already has.
- **The design source was read at the location the workarea's `sources.json` gives, and one of its two halves is unavailable on this machine.** `prototype:dr2-1-source` points at `~/git/defra/defra-design/GB-notification-service` at commit `04a073b`; there is no such checkout here, so `app/routes.js:10843-10861` could not be opened. `prototype:dr2-1-specs` is local and pins the same list: `workareas/shared/design-release-2-1/prototype-specs/e2e/documents.fit.spec.js:11-26` lists the placeholder and exactly the thirteen labels, in exactly the order the first criterion gives, with no Health certificate. The DR1 judgement agrees, in its own words — the frontend's fourteenth type is one "DR1 offers only to its internal testing release and not to a design-release user" (`workareas/shared/design-release-2-1/sources/dr1-parity-union/backlog.json`, row inc-136). Two independent design sources, same list: no `design` finding, and no need for the third.
- **The thirteen are the catalogue minus one, so this is a deletion and not a reordering.** Checked against `services/document-types/stub.js:1-16`: the first eleven codes, then the withheld one, then the last two. Removing the twelfth leaves the design's thirteen in the design's order. Nothing is re-sequenced.
- **The option-list tests keep naming the labels in order themselves.** `controller.test.js:1461-1486` asserts the item values against the service module's list and the item labels against literals; `fit/upload.fit.spec.js:201-221` lists the labels through the copy deck in a hand-written order. The values assertion becomes thirteen literal codes rather than a read of either list, because reading the production list would make the test assert the production list against itself. The labels keep coming from the copy deck, which is what makes a rewording fail a test, and the order stays hand-written, which is what makes a reordering fail one.
- **The conflict's own account of the test work is half wrong, and the tests-repo work is additive.** The ruling says the change is to "the frontend's options (and the fit and E2E specs that assert fourteen)". No end-to-end spec asserts the option list: the only document-type touch in the tests repo is the page object's default choice (`page-objects/animals/accompanying-documents-page.ts:84-89`) and the all-answers fixture (`domain/animals/constants/journey-options.ts:148`), both of which choose types that are still offered. So nothing in the tests repo breaks, and the integration proof below is new coverage rather than a repair.
- **The integration proof is written here and run by the branch pull requests, not locally.** The row's `gatePhases` is empty, so the loop runs no gate rung for it, and the row's own note records that the local docker-compose rung on this machine timed out nearly every spec and died without writing a result while the lease holds a twenty-container stack. A timed-out run is not a pass (workspace `CLAUDE.md` rule 6), so no local end-to-end command is named as a check: naming one that cannot resolve would stop the increment with nothing broken. Both repos' pull requests run `tests/animals/` against the branch-tagged tests image and the branch service images, and that is where the new spec is proved.
- **Every coverage strength this row writes is decided here, from which red probe this run can actually make red.** The unit and FIT probes are local runs named as checks in section 5, so the links they witness are `full`. The new end-to-end link is `partial`: no end-to-end rung runs for this row, and its probe would need the leased stack's frontend image rebuilt, which this run does not do, so the test is never seen failing — at most partial by `openspec/config.yaml:59-61`. Rejected: writing `full` on the end-to-end link because the branch pull requests run the spec green, which proves it passes and never proves it would fail.
- **The spec gains a scenario for the saved-type read-back.** The third criterion is observable page behaviour on a reachable state, so it is recorded rather than left to the unit suite alone. It is worded as what the page shows now, never as what it no longer offers, per the authoring conventions in `openspec/config.yaml`. Rejected: leaving the existing saved-row scenario to carry it, which states only that the chosen type is reported and so says nothing about a recorded type the select does not offer.
- **The review page and the backend are untouched.** The review's own label map (`features/check-answers/copy/copy.en.js:19`, `copy.cy.js:20`) already holds the withheld type, and the claim hands the stored type straight to the backend with no check of its own (`features/documents/handlers/claim-upload.js:116`). The backend's enum keeps all fourteen (`accompanyingdocument/DocumentType.java:44-45`), read and confirmed; it is not one of this row's repos and needs no change.
- **Plants takes nothing.** The programme's mirror invariant applies only where plants has the same page or behaviour. The plants frontend has no documents page, no document-type list and no document-type copy — the only match for either name is a doc comment in the shared platform's reachability module (`repos/trade-imports-plants-frontend/src/server/app/model/analysis/reachability/index.js:40`). Confirmed by grep over its whole `src`.
- **This change is not routed through a frontend-change recipe.** It adds no field, page, section or collection, and changes no obligation and no journey flow: the type obligation declares status and scope only and names no allowed values (`sets/live-animals/obligations/sections/documents.js:30-35`).
