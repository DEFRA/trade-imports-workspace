## 0. Decisions

1. **The increment's claims all hold against the live tree; one needed
   re-reading.** `COMMODITY_IDENTIFIERS` in
   `src/server/app/sets/live-animals/services/commodities/rules.js:8-20` gives
   `0103`, `010410` and `010420` no identifiers, so `IDENTIFIED_CODES` excludes
   them, `needsIdentifying` is false for them and those lines skip Identification
   details today — exactly as the row's 11 November note records. The row's older
   note that "no two species share a code in today's five-commodity catalogue" is
   **no longer true**: the captured MDM catalogue
   (`src/server/app/services/_capture/fixtures/commodities.json`) serves five
   species under `0101` — Horse (`Equus cabalus`), Donkey (`Equus asinus`),
   Mountain Zebra (`Equus zebra`) and two hybrid entries — and the stack's MDM
   stub serves three (`Equus asinus`, `Equus cabalus`, `Equus cabalus*asinus`).
   So the fourth criterion is not only buildable, it fixes a live defect: a
   donkey line on `0101` is asked for a horse name today, because
   `scopedFields` gates every identifier on the commodity code alone
   (`.../animal-identification/identifier/fields.js:13-17`). Planned against
   that reality.

2. **Ear tag is added at the commodity code, not narrowed to the domestic
   species.** V4's ear-tag list writes `0103 - Pig (Domestic)` and
   `010410 - Sheep (Domestic)`, and the extract itself records that the page
   does not settle whether that label narrows the rule. The row's own criteria
   say "a selected pig species (0103)" and "a selected sheep (010410) or goat
   (010420) species", and the requirements they carry state the rule by code.
   Rejected: deriving a code-and-species pair list for the ear tag from the
   domestic species' Latin names — that would pin the rule to MDM's spelling of
   three species for no stated reason and would ask nothing of a wild boar line
   the catalogue serves.

3. **The horse name becomes a code-and-species rule, through the pair-gate
   mechanism that already exists.** V4 names exactly one commodity for the horse
   name, `0101 Horse`, while it names all five `0101` species for the passport.
   `allowListedPairs` (`src/server/app/model/obligations/helpers/allow-listed-pairs.js`)
   is the model's existing helper for "this obligation's code and Latin name must
   be listed together", already used by the permanent address
   (`.../obligations/sections/commodities/identifiers.js:125-145`), and the
   witness synthesiser and `dependsOn` derivation already handle it
   (`model/analysis/reachability/witness/synthesise.js:89`,
   `model/obligations/helpers/introspection/obligation-metadata.js:36-37`). The
   other four identifiers stay code-gated. Rejected: making every identifier a
   pair gate, which would need the full species list per code enumerated in code
   — MDM's content, which the programme forbids editing in code.

4. **Which gate value shape to pass is the bridge's to decide, not the page's.**
   `appliesForGateValue` (`src/server/app/bridge/applicability.js:13-14`) is
   extended so a caller hands it the line's commodity code and the line's
   species Latin name, and it forms the `[code, species]` pair only for a gate
   that declares a paired obligation (`metadata.pairedObligationId`, stamped at
   `model/obligations/helpers/internals/build-gate.js:79`). `admitsValue` and
   `listsGateValue` need no change: they already branch on the shape of the value
   handed in. Rejected: having `identifier/fields.js` read gate metadata itself
   and build a pair for the identifiers it knows are pair-gated — that puts the
   gate's shape in a second place, and the next identifier V4 narrows by species
   would have to be added to both.

5. **`scopedFields` takes the line's species as well as its code, and every
   caller passes it.** This is the signature change the row genuinely needs: the
   rule "which identifiers is this animal asked for" has one owner, and once the
   horse name is pair-gated a caller that still passes only the code gets a
   **wrong answer for a horse line, not for a donkey one**. The reason is the
   gate's value shape: `listsGateValue` matches a bare string by identity
   against the gate's list (`model/obligations/helper-internals.js:12-15`), so
   `appliesForGateValue('horseName', '0101')` tested against a list of
   `[code, species]` pairs is false for every species, horses included. A
   code-only caller therefore drops the Horse name field from a horse card, the
   Horse name column from its saved-animals table and the Horse name column from
   its review table. The reverse — a donkey keeping a horse name it was never
   offered — cannot happen and is not the risk being guarded: an out-of-scope
   `horseName` is invisible to scope and destroyed on the next entry write
   (`engine/entry-write-purge.test.js:41-67`), and the review's columns are
   filtered to the identifiers some unit actually holds
   (`.../check-answers/view-model/cards/consignment/species/identifier-columns.js:13-20`),
   so a donkey can never hold a horse name to head a column with. Six call sites
   thread the species through; `identifierColumns` and `permanentAddressApplies`
   already take it, so the shape is the one the feature already uses. Each
   touched file gets only its touched lines and functions brought up to the house
   rules. Rejected: leaving the review-page and saved-animals-table builders
   code-only and pair-gating the horse name anyway — that is precisely the
   regression above, and section 4 names the two tests that now catch it.

6. **Pigs, sheep and goats cannot be reached end to end on the local stack, and
   that is a test-double limit, not a gap in this slice.** The stack runs the
   frontend with `LIVE_ANIMALS_MODE=real`
   (`docker/stack/frontend.compose.yml:74`), so commodity search and the species
   check go through reference-data to the MDM stub, whose fixtures hold search
   terms for cattle, horses, donkeys, cats, dogs, ferrets, ostriches and fish
   only, and species pages for eight codes that do not include `0103`, `010410`
   or `010420` (`trade-imports-stub/src/main/resources/responses/mdmProductSearchResponses.json`,
   `mdmProductSpeciesResponses.json`); an unsaved term answers an empty page
   (`ProductController.java:79-81`). So the first three criteria are proved at
   the FIT rung, which drives a real browser against the real frontend over the
   captured MDM catalogue that does hold all three codes. The integration proof
   in the tests repo covers the fourth criterion, the new mechanism and the one
   that fixes a live defect: the stub serves `donkey` → `Equus asinus` under
   `0101` and lists it under `0101`'s species, so a donkey line is selectable and
   passes the species check. Widening the stub's fixtures is a follow-up
   (section 7); the stub is not one of this row's repos and is not even in the
   theme's `build-args.json`.

7. **No new copy, so the Welsh invariant is met without a copy change.** Every
   label and length-error message this row needs already exists in both
   languages (`.../commodities/copy/copy.en.js:76-82,98-105` and
   `copy.cy.js:80-86,104-110`), and `copy.test.js:49-70` already pins that every
   identifier any identified code asks for carries both in English and Welsh —
   so adding three codes to the ear-tag list is covered by a test that already
   exists.

8. **No plants change.** The plants mirror invariant binds a row that changes a
   page or behaviour the high-risk plants frontend also has. Plants has no animal
   identification page and no animal identifiers, and the row's `repos` list
   excludes it.

9. **"And no other identifier" is true as this row lands and is extended by
   inc-268, not contradicted by it.** `ruling:ian-2026-11-11` adopts V4's tattoo
   list, under which a pig panel also asks for a tattoo; inc-268 carries that
   and records that it depends on this row because it extends the same pig entry.
   Nothing in this plan builds a tattoo for pigs.

10. **No backend change.** The notification mapper writes the ear tag from the
    unit for any code (`.../notification-mapper/shared/lines/species-entry.js:13-21,35`),
    and the animal count already caps the records generically
    (`engine/evaluate/cardinality.js:21-33` keyed off `numberOfAnimalsQuantity`),
    so the three new codes need no mapping or cardinality work.

11. **One card's identifier fields are read card-scoped in the tests repo, and
    the page object owns that.** The two-species-on-one-code proof puts a horse
    card and a donkey card on one page, and every identifier getter the page
    object has today is page-wide
    (`page-objects/animals/animal-identification-page.ts:17-31`), as is the
    journey's save helper (`flows/animals/journey.ts:580-584` driving
    `animal-identification-page.ts:62-64`), so each resolves to two elements and
    Playwright strict mode fails. The card-scoped mechanism the page object
    already has is `speciesCard(species)` (`:44-46`), and
    `AnimalsPermanentAddressPage` already shows the shape a card-scoped reader
    takes (`page-objects/animals/permanent-address-page.ts:18-48`: a card
    locator, a locator for all of a species' cards, and field helpers that take
    the card). Rejected: hand-built card-scoped locators inside the spec — set-up
    two tests use goes in the shared helper, and the existing single-card specs
    (`animal-identifiers-conditional.spec.ts:15-18,44`) would then read one way
    while the new one reads another.

## 2. Edits

### frontend — the rule and its allowlists

**`src/server/app/sets/live-animals/services/commodities/rules.js`**
- `COMMODITY_IDENTIFIERS` gains an entry for each of the swine, sheep and goat
  codes, each asking for the ear tag and nothing else. The existing constants
  for those three codes (`SWINE_CODE`, `SHEEP_CODE`, `GOAT_CODE`, lines 3-5) are
  the keys; no new code literal is introduced.
- The declaration gains the ability for one identifier on a code to name the
  species on that code it applies to; where it names none, it applies to every
  species the catalogue serves under the code. The horse name uses it, naming
  the horse species alone. Nothing else names a species.
- The per-identifier derivation (`codesCarrying`, lines 22-25) keeps producing a
  list of codes for an identifier that names no species, and produces a list of
  `[code, species]` pairs for one that does — the same shape
  `PERMANENT_ADDRESS_CODE_SPECIES` (lines 73-77) already has, so the pair list
  and the pair derivation beside it read as one mechanism.
- **Every name in that derivation chain must predict the pairs, not only the
  accessor downstream of it.** Today `codesCarrying` (22-25) and the module
  constant it fills for the horse name, `HORSE_NAME_CODES` (line 35), both say
  *codes*; after this change the horse name's value is code-and-species pairs,
  so a name whose value word says codes mispredicts what the code returns. The
  derivation and the module constant are renamed for the values they now carry,
  consistent with how the permanent address's pair list already reads
  (`PERMANENT_ADDRESS_CODE_SPECIES` at 73-77, read through
  `permanentAddressCodeSpecies` at `index.js:43`). Where one derivation can
  return either shape, its name must cover both. The rename follows the concept
  word through every place it appears — the four code-only constants (27-33)
  that keep their shape and keep their names, the importers in
  `services/commodities/index.js:1-16`, the obligation section's import
  (`obligations/sections/commodities/identifiers.js:1-9`), and the unit tests'
  tables and titles — not only the one identifier whose shape changed.
- `IDENTIFIED_CODES` (line 37) stays the codes the map carries, so the three new
  codes join it and their lines start reaching Identification details.
- A mixed identifier — species-scoped on one code and code-wide on another — is
  not reachable from this declaration and must not be built for (section 15).

**`src/server/app/sets/live-animals/services/commodities/index.js`**
- The horse-name accessor (line 36) now reads the code-and-species pair list, so
  its name must say pairs, the way `permanentAddressCodeSpecies` (line 43) does.
  The other four identifier accessors are unchanged.

(`.../animal-identification.controller.js:110-122`), and it keeps doing so for a

refusal, redirect, retry or fallback is added: the cap refusal
(`controller.js:98-108`) and the at-least-one-identifier refusal
(`form/forms.js:100-111`) are a user's own input error shown back on the form,
which the house rules say not to log, and both already behave as they do.

  under `0101` and the stack's MDM stub serves three, so both the matching and

- The page object's card-scoped readers are reachable now: the new E2E test puts

  the one that adopts a future V4 identifier list of that shape; there is none in

- **Not built:** pair-gating the passport, the microchip or the tattoo. V4 names

  list for either would narrow nothing. inc-268 reaches the tattoo's commodity
  list, and it reaches it as a code list.
- **Not built:** a species test row for a `0101` pony, zebra, mule or hinny
  beyond what the catalogue serves. The rule names the one species that takes the
  horse name, so every other species under the code is covered without being
  named, served now or served later.
