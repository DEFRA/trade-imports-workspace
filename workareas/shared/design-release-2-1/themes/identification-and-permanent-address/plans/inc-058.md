## 0. Decisions

**D1 — The new journey is a `walk*By*` method, not a generic `answer*` composition.**
`flows/animals/journey.ts` already holds three full-notification walks —
`walkCattleByAir` (840-883), `walkHorseBySea` (885-921) and `walkPoultryByRail`
(923-956) — each a self-contained, literal, step-by-step script for one E2E journey
spec, sharing only `walkToImportReason` (768-778) and the private
`walkFromTransporterToReview` (811-838). The new journey follows that same shape and
is added beside them, rather than composing the generic `answerOrigin`/`answerCommodity`/
`answerAnimalIdentification`/… methods `completeAnswerSections` (525-535) uses, which
exist for a different purpose (letting many different specs build a notification from a
shared `NotificationAnswers` object) that this one-off journey does not need.

**D2 — The two permanent-address choices are written inline, not through
`answerPermanentAddresses` or a widened `CommodityLineAnswer`.**
`answerPermanentAddresses` (592-615) applies one line's single `permanentAddress` answer
to every animal on that line — by design, since `CommodityLineAnswer.permanentAddress`
(`domain/animals/constants/journey-commodity-line-answers.ts`) is one answer per line, not
per animal. Acceptance criterion 2 needs two *different* answers for the two animals of
one line (one "Same as the place of destination (POD)", one "Enter a new address"), which
that shared type cannot express without widening it to carry a list — a change no other
caller needs today. The literal-value house rule ("a literal value used by one function
lives in that function") settles it: the new walk method answers the permanent address
page directly, through the same page-object calls (`selectPlaceOfDestination`,
`selectNewAddress`, `fillNewAddress` — `page-objects/animals/permanent-address-page.ts:26-48`)
that `answerPermanentAddresses` itself uses, scoped to each of the two cards in turn.
Alternative rejected: adding a `PermanentAddressAnswer[]` variant to
`CommodityLineAnswer.permanentAddress` and teaching `answerPermanentAddresses` to zip it
against the saved cards — reachable only by this one test today (see section 7's
follow-up) and a wider footprint than the row needs.

**D3 — Which cat gets which choice, and the new address's data.** The first cat
(card 1) is saved as "Same as the place of destination (POD)" (needs the destination
party already added by `addFiveParties`, which the new step runs after). The second cat
(card 2) is saved as "Enter a new address", filled from the already-canned
`MANDATORY_COMMODITY_LINES.domesticCat.permanentAddress`
(`domain/animals/constants/journey-commodity-line-answers.ts:31-40`: name "Pet Owner",
address line 1 "1 Farm Lane", Skipton, postcode, phone, email) — reused, not retyped, per
"test data is copied, never invented". This gives criterion 3's "new address's first
line" directly.

**D4 — `walkFromTransporterToReview` gains one optional named step.** The method's
options object (`{ addCph }: { addCph: boolean }`, line 814) already lets a caller choose
one branch after `addFiveParties()` (826-832). It gains a second, optional, named
field — a step the caller may supply, run immediately after `addFiveParties()` and
before the CPH/continue branch — so a species that needs permanent addresses can answer
that page before the method leaves the consignment addresses page. `walkCattleByAir`,
`walkHorseBySea` and `walkPoultryByRail` pass nothing for it and are unaffected: none of
cattle, horse or chicken needs a permanent address
(`services/commodities/rules.js:91-96`'s `PERMANENT_ADDRESS_SPECIES` lists only Felis
catus, Canis familiaris and Mustela putorius furo). This extends the one existing
mechanism every walk method already funnels through, rather than duplicating its tail
(parties → CPH/continue → contact address → notification view) in a new method.

**D5 — CPH: `addCph: false`, no new CPH handling.** The commodity code domestic cats
share (`01061900`, "other live mammals") is in `CPH_EXEMPT_CODES`
(`services/commodities/rules.js:97`), so the consignment addresses page offers no CPH
section for a cats-only consignment — the same branch `walkHorseBySea` already exercises
with `addCph: false` (919).

**D6 — No unweaned-animals selection.** `UNWEANED_CODES`
(`services/commodities/rules.js:72-78`) does not list `01061900`, and
`allowlists.test.js:154-158` in the frontend already proves
`containsUnweanedAnimals` stays out of scope "for a cats-dogs-ferrets-only
consignment" — so the additional-details step for this journey makes no unweaned
selection at all (unlike `walkCattleByAir`/`walkHorseBySea`, which always do, because
cattle and horses are both in that list).

**D7 — A new `internalMarketPurposes` entry for "Companion animal not for resale or
rehoming".** `domain/animals/constants/internal-market-purposes.ts` models only
`breeding` today, but the frontend's own purpose list
(`sets/live-animals/journeys/linear/features/import-reason/copy/copy.en.js:19-34`,
`PURPOSE_IN_INTERNAL_MARKET_LABEL`) already offers eleven further options including
`'companion-animal-not-for-resale-or-rehoming': 'Companion animal not for resale or
rehoming'`. Criterion 1 names this purpose, so the constant is added — matching the
existing convention (every other reason/purpose/means-of-transport value is referenced
through its own domain constant, never typed as a raw string in a spec or a journey
method) — rather than typing the string inline. `InternalMarketPurpose`
(`journey-options.ts`) is used nowhere that enumerates its members exhaustively (checked:
only `journey-options.ts` and `internal-market-purposes.ts` itself reference the type), so
adding a member is a safe, additive change.

**D8 — `certifiedFor` uses the existing `certificationPurposes.furtherKeeping`.** No
acceptance criterion names a certification purpose for this journey; the additional-details
page's purpose list (`certification-purposes/stub.js`) is not species-gated
(`additional-details/controller.js:46` calls `certification.certificationPurposes()`
unconditionally), so any valid value satisfies "every task reads Complete". Reusing the
constant `walkCattleByAir` already imports keeps this increment's footprint to behaviour
the criteria actually need, rather than adding a new certification-purposes constant.

**D9 — Number of packages is left blank for both cats.** `noOfPackages` is optional on
`CommodityLineAnswer`, and `walkPoultryByRail` (923-956) already leaves it blank for
chicken even though `01051111` is also in `PACKAGE_COUNT_CODES`
(`services/commodities/rules.js:63-71`) — proving the field is optional on the page
regardless of commodity-code membership in that list. The new journey follows that same
precedent rather than `walkCattleByAir`/`walkHorseBySea`'s choice to fill it.

**D10 — Identification details is filled through the page's top-level fields, matching
`walkCattleByAir`'s convention.** With one species (domestic cat) on the page,
`AnimalsAnimalIdentificationPage`'s unscoped `microchip`, `passportNumber` and `tattoo`
getters (`page-objects/animals/animal-identification-page.ts:29-43`) and its unscoped
`saveAndAddAnother`/`saveAndFinish` getters (78-84) each resolve to the one visible
instance, exactly as `walkCattleByAir` already relies on for `earTag`/`passportNumber`.
This is the same page the `cardXxx`-scoped accessors in
`tests/animals/e2e/pages/permanent-address.spec.ts` also use for cats (scoped because
that spec's tests build and rebuild state across several visits); for a single
linear walk with one species on the page, following the existing walk-method
convention keeps this file's `walk*By*` family consistent rather than mixing two
locator styles inside it.

**D11 — Spec-sync target: strengthens `SCN-CONSIGN-ADDR-008-D`, no spec.md change.**
`openspec/specs/live-animals/journey-pages/consignment-addresses/spec.md`'s
`REQ-CONSIGN-ADDR-008` already states that the permanent-address section shows a count
line "when ... not all saved against the place of destination", and
`SCN-CONSIGN-ADDR-008-D` already has full unit+fit coverage for one instance of that
(two animals both hand-entered with different addresses —
`openspec/coverage/live-animals/journey-pages/consignment-addresses/coverage.json:160-167`).
Criterion 2's mix (one POD, one hand-entered) is a different instance of the same
general condition, proved here for the first time through a full submitted journey. The
new test is linked to that existing scenario as a stronger (e2e) witness; no requirement
or scenario text needs to change, and no new capability or `AREAS.md` row is needed.

     `MANDATORY_COMMODITY_LINES.domesticCat.permanentAddress` (D2, D3), then Save and
     continue, waiting for the consignment addresses page's heading again before the step
     returns.
  8. Returns the reference number.
