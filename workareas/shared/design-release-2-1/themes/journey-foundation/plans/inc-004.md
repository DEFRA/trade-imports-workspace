## How it works today (pinned against the tree)

- Every journey page ends through `shared/save-actions.njk` → `saveActions(hubHref, primary, copy, showReturnControls = true)`:
  primary (default "Save and continue"), secondary `govukButton` "Save and return to overview" (`name="exit" value="hub"`),
  and a `<a class="govuk-link">` "Cancel and return to overview". `showReturnControls = false` leaves the primary alone
  (DR1 rule (b), REQ-FLOW-012). Identical macro in both frontends.
- "Return to the review" is the real service's `?change=1`: the review's Change links append it (`check-answers/view-model/rows/change-link.js`),
  and `kit.exitTarget(request, fallback)` sends any save to `notification-view` when `request.query.change` is set (hub exit wins).
  Forms are `<form method="post" novalidate>` with no `action`, so they post to the current URL, query included.
- Nothing about the page endings depends on the notification's status. `kit.base()` knows `journey.status` (it draws the
  strip) but exposes no amend flag.
- Animals amend review = `check-answers` (`notification-view`) with `journey.status === AMEND`. GET and POST both compute
  card/party/scan errors whenever the notification is not SUBMITTED, so an amend review shows a "There is a problem"
  summary on open and a refused Continue re-renders it with focus (400). Plants `check-answers/controller.js` does the
  same (`continueErrors` unless SUBMITTED; refused POST → 400 with the summary).
- Redirects on a `change=1` save (animals): origin, consignment-details, import-reason, additional-details,
  animal-identification, port-of-entry, transit-countries, transporters, addresses, contact and documents all reach
  `notification-view` through `kit.nextTarget`/`exitTarget`. Three do not:
  - `commodities/search/actions/commit-selection.js` → `consignment-details?change=1` (the new line still needs its count; kept, D9);
  - `cph-number/controller.js` → `hubExitTarget ?? hubEntryReturn ?? nextTarget`, so `?return=addresses&change=1`
    goes to the addresses page, not the review (fixed, edit 11);
  - `addresses/party-picker/party-picker.controller.js` → always `addresses` (with change context) (fixed, edit 12).
  Plants: every page in scope redirects through `kit.nextTarget` (consignor-select, place-of-destination,
  consignment-contact-select, origin, arrival-status, arrival-details, identification-numbers; commodity-type except when
  lines were dropped, which goes to the list first).
- Back links: every animals question page's Back link is the hub, except `addresses/controller.js`, which goes to
  `notification-view` under change context. Plants: every question page goes to the hub.
- `.app-link-button` (button drawn as a link) already exists in both repos' `src/client/stylesheets/core/_main.scss` and is
  used with `govuk-link` on submit buttons.

## 0. Decisions

- **D0 — Replay, then correct.** The first attempt's code passed review and the gate; its only failure was spec
  validation on requirements it did not edit, now fixed upstream. Rebuilding from scratch would buy nothing. Rejected:
  re-deriving the code (risk of drift from a reviewed, green change).
- **D1 — How "Save and return" reaches the review without a new field (c-267, AC4).** The button carries
  `formaction="<this page's path>?<its query, with change=1>"` — the real service's own `?change=1` return, put on the
  button instead of the form. "Save and continue" carries `formaction="<path>?<query without change>"`, so it always
  moves on, even on a page opened from a Change link. "Save and return to overview" keeps `name="exit" value="hub"` and no
  formaction. No button gains a `name="action"` it did not already have. Rejected: `exit=review` (a new value the ruling's
  "exit=hub and ?change=1 stay" does not admit); a JavaScript switch (no-JS invariant). `formaction` is plain HTML5.
- **D2 — Where the two URLs come from.** A new L2 module `src/server/app/shared/amend-form-actions.js` exports
  `amendFormActions(path, searchParams)` → `{ returnAction, continueAction }`: copy the query, drop the GET-only
  `staleAction` flag, then set / delete `change`. The nunjucks global context (`src/config/nunjucks/context/context.js`)
  adds `amendFormActions: amendFormActions(request.path ?? '', request.url?.searchParams)`, so it is right on the POST
  re-render too. `kit.base()` adds `amending: journey?.status === AMEND`. Templates pass
  `amend = amendFormActions if amending else none`. Rejected: threading `request` through every `kit.base` call.
- **D3 — The macro (both frontends, byte-identical).**
  `saveActions(hubHref, primary, copy, showReturnControls = true, amend = none, hubExitWhileAmending = true)`.
  With `amend` set it renders, in order, inside the same `govuk-button-group`: `govukButton` "Save and return" (primary
  styling, `name`/`value` copied from `primary` when the page names one, `attributes.formaction = amend.returnAction`);
  `govukButton` "Save and continue" (`govuk-button--secondary`, same `name`/`value`, `formaction = amend.continueAction`);
  and only when `showReturnControls and hubExitWhileAmending`, `<button type="submit" class="govuk-link app-link-button"
  name="exit" value="hub">` "Save and return to overview". No cancel link while amending (AC1). Without `amend` the macro
  renders exactly what it renders today.
- **D4 — Which pages get which ending.**
  - three controls (overview-linked, AC1/AC8): animals origin, commodity selection (search), commodity details,
    main reason for import, additional details, identification details, arrival details (port-of-entry), transit
    countries, transporter list, roles and addresses, upload documents; plants origin, commodity type, arrival status,
    arrival details, identification numbers.
  - two controls (AC5/AC8): animals CPH number (`showReturnControls = false`), the five role pickers
    (`_address-picker.njk`, already `false`), and the contact address page (`hubExitWhileAmending = false`); plants
    consignor-select, place-of-destination, consignment-contact-select (`hubExitWhileAmending = false`).
  - unchanged even while amending: animals transporter-add, transporters-select, commercial- and
    private-transporter-details (add-a-transporter detours that return to the transporter list, which carries the amend
    ending); plants commodities list and commodity details (reached from commodity type); both review pages.
- **D5 — "The permanent address page" (AC5, c-210) does not exist in animals or plants.** Animals collects a horse's
  permanent address as fields on the identification page, which is overview-linked and gets the three controls. Plants
  has none. Nothing to build; a claim that does not hold, recorded for the backlog owner.
- **D6 — "Outside an amendment they keep their single primary button" holds for CPH and the five role pickers only.**
  The animals contact page and the three plants pickers are overview-linked and end with three controls outside an
  amendment today (REQ-FLOW-004 / plants picker specs, ruled under DR1); this row does not change that.
- **D7 — Back links (AC6).** The AC's examples (origin back to "the notification type page") are the prototype's; the real
  animals service has no notification-type page, and origin's Back is already the hub. The rule that holds is "never a
  Back link to the amend review": the one page that breaks it is animals roles-and-addresses under change context. While
  amending it goes to the hub; on a draft it keeps going to the review. Plants needs no change. Party-edit spokes are
  not question pages and are left alone.
- **D8 — Redirects that must honour "Save and return".** CPH: `kit.hubExitTarget(request) ?? kit.amendReviewTarget(request, journey) ?? hubEntryReturn(request) ?? (await kit.nextTarget(...))`
  — a draft carrying `return=addresses&change=1` still goes to the addresses page. Party pickers: new
  `kit.amendReviewTarget(request, journey)` (review path when `journey.status === AMEND` and the request carries change
  context, else `null`), used through a named `savedTarget` helper ahead of the existing addresses redirect in both the
  "keep the address already chosen" branch and `commitSelection`; a draft keeps going back to `addresses?change=1`.
- **D9 — Commodity selection keeps its detour.** "Save and return" on "What are you importing?" goes to commodity details
  (`?change=1`), whose own "Save and return" then reaches the review — a new commodity line needs its count first.
- **D10 — "Save and continue" goes where it goes outside an amendment** (`kit.nextTarget` without change context): the next
  page of the same task row, or Overview at the end of the row. In plants the arrival row shows it (arrival status →
  arrival details); in animals most task rows are one page, so it is Overview.
- **D11 — The held Continue (AC7, AC9, c-201).** While `journey.status === AMEND`, both review pages render with no error
  summary and no card/role/row error text, on open and after Continue, and a refused Continue redirects back to the review
  (post/redirect/get, 302) instead of re-rendering a 400. The refusal predicates are unchanged, so the declaration still
  refuses an incomplete amendment. The "Missing" styling of blank rows stays: it is not an error message.
- **D12 — The AC7 example (arrival date more than 6 months ahead) cannot be saved through the real arrival page**: it
  refuses it on either save control (`date.range`). The E2E proves the held state the way the real service allows (clear
  the arrival date, "Save and return to overview" per inc-003's soft save); the 6-months case is proved at unit level by
  seeding the stored answer (check-answers GET and POST cases), and specified as SCN-CYA-010-C.
- **D13 — Copy.** New shared key `saveActions.saveAndReturn`: en "Save and return", cy "Cadw a dychwelyd" (Welsh draft,
  invariant 1). Added, not a rewording of shared copy (invariant 7).
