## How it works today (pinned against the tree)

- Every journey page ends through `shared/save-actions.njk` → `saveActions(hubHref, primary, copy, showReturnControls = true)`:
  primary (default "Save and continue"), secondary `govukButton` "Save and return to overview" (`name="exit" value="hub"`),
  and a `<a class="govuk-link">` "Cancel and return to overview". `showReturnControls = false` leaves the primary alone
  (DR1 rule (b), REQ-FLOW-012). Identical macro in both frontends.
- "Return to the review" is the real service's `?change=1`: the review's Change links append it (`check-answers/view-model/rows/change-link.js`),
  and `kit.exitTarget(request, fallback)` sends any save to `notification-view` when `request.query.change` is set (hub exit wins).
  Forms are `<form method="post" novalidate>` with no `action`, so they post to the current URL, query included.
- Nothing about the page endings depends on the notification's status. `kit.base()` knows `journey.status` (it draws the
  strip) but exposes no amend flag.
- Animals amend review = `check-answers` (`notification-view`) with `journey.status === AMEND`. GET and POST both compute
  card/party/scan errors whenever the notification is not SUBMITTED, so an amend review shows a "There is a problem"
  summary on open and a refused Continue re-renders it with focus (400). Plants `check-answers/controller.js` does the
  same (`continueErrors` unless SUBMITTED; refused POST → 400 with the summary).
- Redirects on a `change=1` save, page by page (animals): origin, consignment-details, import-reason, additional-details,
  animal-identification, port-of-entry, transit-countries, transporters, addresses, contact and documents all reach
  `notification-view` through `kit.nextTarget`/`exitTarget`. Three do not:
  - `commodities/search/actions/commit-selection.js` → `consignment-details?change=1` (the new line still needs its count; kept, D9);
  - `cph-number/controller.js:89-93` → `hubExitTarget ?? hubEntryReturn ?? nextTarget`, so `?return=addresses&change=1`
    goes to the addresses page, not the review (fixed, edit 11);
  - `addresses/party-picker/party-picker.controller.js:125-130, 152-158` → always `addresses` (with change context) (fixed, edit 12).
  Plants: every page in scope redirects through `kit.nextTarget` (consignor-select, place-of-destination,
  consignment-contact-select, origin, arrival-status, arrival-details, identification-numbers; commodity-type except when
  lines were dropped, which goes to the list first).
- Back links: every animals question page's Back link is the hub (origin: hub, or dashboard before anything is saved),
  except `addresses/controller.js:89-91`, which goes to `notification-view` under change context. Plants: every question
  page goes to the hub. The amend review's own Back is the hub in both.
- `.app-link-button` (button drawn as a link) already exists in both repos' `src/client/stylesheets/core/_main.scss` and is
  used with `govuk-link` on submit buttons (animals dashboard, confirmation, remove buttons).

## 0. Decisions

- **D1 — How "Save and return" reaches the review without a new field (c-267, AC4).** The button carries
  `formaction="<this page's path>?<its query, with change=1>"` — the real service's own `?change=1` return, put on the
  button instead of the form. "Save and continue" carries `formaction="<path>?<query without change>"`, so it always
  moves on, even on a page opened from a Change link. "Save and return to overview" keeps `name="exit" value="hub"` and no
  formaction. No button gains a `name="action"` it did not already have. Rejected: `exit=review` (a new value the ruling's
  "exit=hub and ?change=1 stay" does not admit, and a Change-opened page's Save and continue would still go to the review
  because `change=1` rides on the form URL); a JavaScript switch (no-JS invariant). `formaction` is plain HTML5.
- **D2 — Where the two URLs come from.** A new L2 module `src/server/app/shared/amend-form-actions.js` exports
  `amendFormActions(path, searchParams)` → `{ returnAction, continueAction }`, built the way `redirectOnStaleAction`
  builds its URL (`${request.path}?${query}`): copy the query, drop the GET-only `staleAction` flag, then set / delete
  `change`. The nunjucks global context (`src/config/nunjucks/context/context.js`, which already imports `shared/paths.js`)
  adds `amendFormActions: amendFormActions(request.path ?? '', request.url?.searchParams)`, so it is right on the POST
  re-render too. `kit.base()` adds `amending: journey?.status === AMEND`. Templates pass
  `amend = amendFormActions if amending else none` to the macro. Rejected: threading `request` through ~20 `kit.base` calls;
  importing the macro `with context` (implicit, and the repo's macros take everything as arguments).
- **D3 — The macro (both frontends, byte-identical).**
  `saveActions(hubHref, primary, copy, showReturnControls = true, amend = none, hubExitWhileAmending = true)`.
  With `amend` set it renders, in order, inside the same `govuk-button-group`:
  1. `govukButton` "Save and return" (`copy.saveAndReturn`), primary styling, `name`/`value` copied from `primary` when the
     page names one (documents `action=continue`, transporters and the address pickers `action=save`), `attributes.formaction = amend.returnAction`;
  2. `govukButton` "Save and continue" (`copy.saveAndContinue`), `govuk-button--secondary`, same `name`/`value`,
     `attributes.formaction = amend.continueAction`;
  3. only when `showReturnControls and hubExitWhileAmending`: `<button type="submit" class="govuk-link app-link-button" name="exit" value="hub">`
     with `copy.saveAndReturnToHub`.
  No "Cancel and return to overview" link while amending (AC1). Without `amend` the macro renders exactly what it renders
  today. Copy `name`/`value` with `primary.name if primary` (an inline-if with no else renders empty, which `govukButton`
  omits); there is no `assign` filter in these environments. Update the macro's header comment to state the amend rule.
- **D4 — Which pages get which ending.** Opt-in per template, by passing `amend`:
  - three controls (overview-linked, AC1/AC8): animals origin, commodity selection (search), commodity details,
    main reason for import, additional details, identification details, arrival details (port-of-entry), transit
    countries, transporter list, roles and addresses, upload documents; plants origin, commodity type, arrival status,
    arrival details, identification numbers.
  - two controls (AC5/AC8 — "party pickers, CPH"): animals CPH number (`showReturnControls = false` already), the five
    role pickers (`_address-picker.njk`, already `false`), and the contact address picker (`hubExitWhileAmending = false`;
    it keeps its three controls outside an amendment); plants consignor-select, place-of-destination,
    consignment-contact-select (`hubExitWhileAmending = false`; three controls outside an amendment, unchanged).
  - unchanged even while amending (no `amend` passed): animals transporter-add, transporters-select,
    commercial- and private-transporter-details (add-a-transporter detours; AC5 names a closed list and these return to
    the transporter list, which carries the amend ending); plants commodities list and commodity details (reached from
    commodity type, not overview-linked, not a picker); both review pages.
- **D5 — "The permanent address page" does not exist in animals or plants (defect in AC5/c-210).** Animals collects a
  horse's permanent address as fields on the identification page (`commodities/animal-identification/form/forms.js`),
  which is overview-linked and so gets the three controls. Plants has no permanent address. Nothing to build; recorded
  for the backlog owner.
- **D6 — "Outside an amendment they keep their single primary button" holds for CPH and the five role pickers only.**
  The animals contact page and the three plants pickers are overview-linked and end with three controls outside an
  amendment today (REQ-FLOW-004 / plants picker specs, ruled under DR1); this row does not change that. Recorded as a
  claim that does not hold for those four pages.
- **D7 — Back links (AC6).** The AC's examples ("origin back to the notification type page") are the prototype's; the real
  animals service has no notification-type page, and origin's Back is already the hub. The rule that holds is "never a
  Back link to the amend review": the one page that breaks it is animals roles-and-addresses under change context. While
  amending it goes to the hub (`addresses/controller.js`); on a draft it keeps going to the review. Plants needs no change.
  The party-edit spoke's return (`party-edit/edit-href.js`, reached from the review's role-error links) is not a question
  page and is left alone.
- **D8 — Redirects that must honour "Save and return".** CPH: `kit.exitTarget(request, hubEntryReturn(request)) ?? (await kit.nextTarget(...))`
  (hub exit, then the review on `change`, then the addresses return, then the flow) — draft never posts CPH with
  `change=1` from the UI, so draft behaviour is unchanged. Party pickers: new `kit.amendReviewTarget(request, journey)`
  (review path when `journey.status === AMEND` and the request carries change context, else `null`), used ahead of the
  existing addresses redirect in both the "keep the address already chosen" branch and `commitSelection`; a draft keeps
  going back to `addresses?change=1` (REQ-FLOW-010 behaviour).
- **D9 — Commodity selection keeps its detour.** "Save and return" on "What are you importing?" goes to commodity details
  (`?change=1`), whose own "Save and return" then reaches the review — a new commodity line has to get its count before
  the review can show it. Rejected: sending it straight to the review, which would leave a new line countless and the
  held Continue unexplained.
- **D10 — "Save and continue" goes where it goes outside an amendment.** `kit.nextTarget` without change context: the next
  page of the same task row, or Overview at the end of the row (REQ-FLOW-003 / REQ-PLANTS-FLOW-003). The prototype's
  "next page" is its linear order; the real service has no second navigation model for amendments and this row does not
  add one. In plants the arrival row shows it (arrival status → arrival details); in animals most task rows are one page,
  so it is Overview.
- **D11 — The held Continue (AC7, AC9, c-201).** While `journey.status === AMEND`, both review pages render with no error
  summary and no card/role/row error text, on open and after Continue, and a refused Continue redirects back to the review
  (post/redirect/get, 302) instead of re-rendering a 400. The refusal predicates themselves (`reviewRefusal`,
  `continueErrors`, `readyForCheckYourAnswers`) are unchanged, so the declaration still refuses an incomplete amendment.
  The "Missing" styling of blank rows (REQ-CYA-002) stays: it is not an error message. Rejected: suppressing on POST only
  (the summary would still stand on open, contradicting "shows no error, it simply stays put").
- **D12 — The AC7 example (arrival date more than 6 months ahead) cannot be saved in the real service:** the arrival page
  refuses it on either save control (`date.range`). The E2E proof makes the amendment incomplete the way the real service
  allows — clear the arrival date and "Save and return to overview" (inc-003's soft save) — which is the same held state.
- **D13 — Copy.** New shared key `saveActions.saveAndReturn`: en "Save and return", cy "Cadw a dychwelyd" (Welsh draft beside
  it, invariant 1). Added, not a rewording of existing shared copy (invariant 7).
