## 0. Decisions

1. **Origin reads "Ireland", not "Republic of Ireland".** The criterion quotes the prototype's label. The real service's origin list is whatever MDM serves through reference-data (programme invariant: "its entries are what MDM serves"), and the MDM stub (`trade-imports-stub/src/main/resources/responses/countriesResponse.json:362`, code `IE`, in `GBNAG_SPS_EX`) names it "Ireland"; the frontend labels origins by MDM `name` (`services/countries/index.js:45`). The tests repo already reads it as "Ireland" (`domain/animals/constants/country-codes.ts:18`, `countryCodes.eu.ireland`). The walk chooses `countryCodes.eu.ireland` and the review asserts "Ireland". Rejected: asserting "Republic of Ireland" (would need a reference-list edit the programme forbids).
2. **Port of exit and port of entry: Holyhead.** The prototype's exit port "Holyhead POE - GBHLY" is MDM's `GB HLY` "Holyhead Port" (`portsOfEntryResponse.json:31`). Port of exit is a native `<select>` (`import-reason/template.njk:66-73`, no autocomplete), so it is chosen **by value** `GB HLY` (`selectOption('GB HLY')`), which survives any change to how the list reads (the spec's SCN-IMPORT-REASON-004-B already describes a "name - code" shape the code does not yet render; a sibling theme may change it). Port of entry is the accessible autocomplete and is chosen with the existing `arrivalDetails.selectPort('Holyhead Port (GB HLY)')`, the same "{name} ({code})" shape the cattle walk uses for Heathrow today. On the review both ports are asserted with `toContainText('Holyhead Port')`, not the full label, for the same reason. Rejected: exact full-label assertions (brittle against the reference-lists theme).
3. **Arrival by sea = means of transport "Vessel"**, the real option label for `VESSEL` (`transport/copy/copy.en.js:26`). Transport identification `STENA ADVENTURER` (the prototype's value), transport document reference `BOL-2026-0001`. Vessel keeps transit countries out of scope (`obligations/sections/transport.js:96-111`, land modes only), so the run goes arrival details → transporter, and the overview has no "Transit countries" row (`flow/task-rows.js:75`, conditional).
4. **Transporter: `J & G Campbell LTD`.** The prototype's "Roadtrain Ltd" is not in the real list (`services/transporters/records.js`). The criterion asks only for "a transporter". J & G Campbell LTD is an approved commercial record of the same shape as García (whose "Name" row the cattle review already proves), so the review's Transport details "Name" row carries it; choosing it rather than García also exercises a second list entry. Rejected: a private record (Aberdeen Livestock Ltd) — different review shape, not needed by the criterion.
5. **Identification: one horse, all three identifiers, saved with Save and continue.** Horse calls for microchip, passport and horse name (`services/commodities/stub.js:128`). With one animal on the line the card shows no in-card "Save and add another/finish" button (`card/view-model.js:80-82`), and Save and continue appends the typed record (`animal-identification.controller.js:137`). Labels on a horse line: "Microchip number", "Passport", "Horse name" (`commodities/copy/copy.en.js:83-99`). Values: microchip `900123456789012`, passport `IE-EQ-2026-0001`, horse name `Dublin Bay`.
6. **Additional details: "Registered equine animal" only.** Horse is not an unweaned commodity (`stub.js` `UNWEANED_ANIMAL_COMMODITIES = ['Cow']`), so the unweaned question is not asked and is not answered. "Registered equine animal" is a real certification purpose (`services/certification-purposes/stub.js:6`).
7. **No CPH step.** Horse's code 0101 is CPH-exempt (`stub.js` `CPH_EXEMPT_COMMODITY_CODES`), so Roles and addresses is complete with the five parties and Continue goes straight to the contact page.
8. **One accompanying document is uploaded.** The criterion lists no document, but criterion 2 needs "Upload documents" to read "Complete"; with zero documents the hub draws either "Complete" or "To do" (`hub/copy/copy.en.js:16-19`) and nothing proven on the stack says which. Uploading one veterinary health certificate exactly as the cattle walk does removes that doubt. Rejected: walking with no document (an unproven status claim the walk would rest on).
9. **"Every task reads Complete" is asserted two ways:** each of the 11 named rows reads "Complete" (exemplar's loop), and the overview has exactly 11 status tags (new `overview.taskStatuses` getter, `toHaveCount(11)`), so no other row (Transit countries, a stray CPH) is on the page un-complete.
10. **Exit date** is `getRelativeAppDateText({ monthOffset: 2 })` — after the arrival date (`ARRIVAL_DATE`, month +1), in the unpadded d/m/yyyy the review renders (`rows/value-text.js:30`), so the review's "Exit date" row is asserted with `toHaveText` against the same string.
11. **`fillOriginOfImport` gains the country from `JourneyOptions.countryCode`.** `selectCountry(options.countryCode?.display ?? COUNTRY)`; every existing caller passes no `countryCode`, so they keep France. Rejected: a second, horse-only origin helper (duplicates the region/reference handling).
12. **Spec file name and tag:** `tests/animals/e2e/journeys/horse-temporary-admission.spec.ts` (the name the programme header's `touches` already reserves), `@integration` tag and `test.slow()`, as `opening-run.spec.ts`.
13. **The spec's "Temporary admission of horses" vs the page's "Temporary admission horses".** The real radio label (reason service) is "Temporary admission horses"; the review prints the same. The walk uses the real label. The drift in spec wording (SCN-OB-IMPORT-REASON-001-D, SCN-IMPORT-REASON-005-C) is pre-existing and left alone (§7).
