## 0. Decisions

1. **How the GOV.UK word reaches the title.** A new shared copy leaf `layout.govukSuffix: 'GOV.UK'` in
   `shared/copy.en.js` and `shared/copy.cy.js` of both frontends, as animals does. Rejected: hard-coding
   `GOV.UK` in `layout.njk` (copy belongs in copy modules; the copy convention and animals both say so).
2. **Welsh.** The Welsh value is `'GOV.UK'` too (the Welsh GOV.UK carries the same brand name), so the
   leaf is added to each repo's `copy-parity.test.js` `IDENTICAL_ALLOWLIST` as `'shared:layout.govukSuffix'`
   with the animals justification comment. The `errorTitlePrefix` (`'Error: '` / `'Gwall: '`) and
   `serviceName` leaves are untouched (programme invariant: shared wording is never reworded in place — this
   adds a leaf, it rewords nothing).
3. **The INS home's title.** No copy change. `features/dashboard/copy/copy.en.js` already has
   `title: 'Dashboard'` and `dashboard/controller.js:74` passes it to `kit.base`, so the layout change alone
   produces `Dashboard - Import notification service - GOV.UK` (req-953 / c-146). Verified against the tree.
4. **Error pages.** Both frontends' `common/helpers/errors.js` render `shared/error` through `kit.base(errorMessage)`,
   which extends the shared layout, so `Page not found - Import notification service - GOV.UK` follows from the
   layout change with no change to `errors.js`.
5. **Plants E2E page choice.** The plants proof uses the commodity-type page (`What are you importing?`), the
   journey's entry page and the one that can be put in an error state with a single click (Save and continue with
   nothing chosen). Rejected: the plants dashboard, whose page title is `Import notification service`
   (`dashboard/copy/copy.en.js:5`) and so reads `Import notification service - Import notification service - GOV.UK`
   under the pattern — true, but a poor witness, and the dashboard's own title is not this row's to change.
6. **Unit assertions use literal strings for the INS home** (`'Dashboard - Import notification service - GOV.UK'`),
   because that exact string is an acceptance criterion; the plants layout test uses the copy leaves as animals
   does.
7. **Test placement.** INS gets a new FIT file at the features root,
   `src/server/app/features/page-title.fit.spec.js` (the `features` Playwright project's `testDir`), mirroring the
   animals `page-title.fit.spec.js`. Plants gets the same at
   `src/server/app/sets/high-risk-plants/journeys/linear/features/page-title.fit.spec.js`. The tests repo gets one
   new spec per domain: `tests/ins/e2e/features/page-titles.spec.ts` and `tests/plants/e2e/features/page-titles.spec.ts`.
   Rejected: folding assertions into existing specs (address-book.spec.ts, start.spec.ts) — a title is a
   cross-cutting capability and gets its own spec, as it gets its own spec capability.
8. **Spec home.** Two new capabilities, `ins/page-titles` (area `INS-PAGE-TITLE`) and `plants/page-titles`
   (area `PLANTS-PAGE-TITLE`), mirroring `live-animals/page-titles`. Rejected: putting the INS home's title in
   `ins/notification-dashboard` — the title is produced by the shared pattern, and one subject, one capability;
   the home's literal title is a scenario of `ins/page-titles`.
9. **Plants in-repo digest left alone.** `src/server/app/sets/high-risk-plants/spec/journey-spec.json:169` (and the
   panel rulings) describe the old `| Import notification service` pattern. That file is the frozen DISTIL record
   of an earlier programme, not live documentation; it is not edited (new programmes never backport).

Claims checked against the tree: all hold. INS layout line 18 and plants layout line 24 carry
`{{ pageTitle }} | {{ sharedCopy.layout.serviceName }}`; no other template overrides `block pageTitle` in either
repo; the tests repo has no title assertion today (`grep toHaveTitle` finds none), so the E2E proof is new.
