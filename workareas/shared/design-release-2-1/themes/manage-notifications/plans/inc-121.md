Routing: this is `frontend-change`'s "change the frontend (anything else)" — wording, page
content and layout on an existing feature plus one guard target. It adds no field, page,
section or collection, changes no obligation, and changes no journey flow data (the
cancel-amendment address is an action slug the entry guard already skips, not a dispatch
page). Sets: `sets/live-animals` (spec namespace `live-animals/`) and
`sets/high-risk-plants` (spec namespace `plants/`).

Neither page is signed off: `cancel-amend/page.js` is `detailing` (animals) and
`exploring` (plants); `check-answers/page.js` is `detailing` and `exploring`. The two
`journey-pages/check-your-answers` specs this row also edits are `detailing` (animals)
and `exploring` (plants), so no signed-off hold applies anywhere in this row.

## 0. Decisions

1. **The confirmation stays a page at today's address, not a dialog.** The design source
   draws a modal (`prototype-specs/e2e/manage-notifications.fit.spec.js:133-137`,
   `#cancel-amend-modal`), and the programme invariant and the owner ruling both say
   confirmations stay pages carrying the dialog's wording as page content
   (`sources/ruling-sam-2026-10-09-pm.md:309-311`). So only the page's copy, its controls
   and its chrome change; the route, the method and the handlers' shape stay.
   Rejected: building the dialog — a separate `waiting-on-design` row owns it.

2. **The strip goes off from the feature, not from the shared kit.** `kit.base` already
   takes `showJourneyStrip` (animals `shared/kit.js:287`, `:314`; plants
   `shared/kit.js:248`, `:272`) and the kit serves every other page's strip, so the page
   turns its own strip off through that option and drops the Back link by passing none.
   Rejected: teaching the kit about this page, which would move a page decision into the
   shared layer the other theme owns.

3. **The `offerCancelAmend` option comes out of both render calls, and both kits keep the
   option.** With no strip at all the option is dead on this page. The option is not this
   row's to delete: plants still passes it from its own review
   (`high-risk-plants/.../check-answers/controller.js:124`), and each repo's
   `shared/kit.js` belongs to the journey-foundation theme, which this row does not edit
   (row note; section 7 of this plan). In animals the option then has no production
   caller at all — `grep -rn offerCancelAmend repos/trade-imports-animals-frontend/src`
   leaves only `shared/kit.js` itself and two tests (`shared/kit.test.js:160`,
   `features/journey-strip.test.js:107`) — which is recorded as a follow-up for the kit's
   owning theme rather than widened into this row.
   Rejected: deleting the animals kit option here, which would edit the shared layer and
   the two tests that exercise it, outside this row's footprint.

4. **The link back sits inside the existing `govuk-button-group`, beside the button.** The
   design source puts the two controls beside each other and GOV.UK's button group is the
   documented component for a link beside a button, so no new markup mechanism appears.
   Rejected: the `shared/save-actions.njk` shape (a `govuk-body` paragraph below the
   group) — that shape exists for a page's save controls, and it puts the control on its
   own line, which the design source does not show here.

5. **The confirm redirect keeps the cancellation marker on the address while the banner
   goes.** The acceptance criteria require both, and the marker still has a reader: the
   performance suite checks it (`trade-imports-performance-tests/src/k6/journeys.js:313-323`).
   Nothing in either frontend reads it after this change, so the plan deletes the view
   model flag, the banner helper and the banner's copy keys in both repos rather than
   leaving a flag no template reads. Each repo's shared `successBanner` slot stays: the
   dashboard, addresses, party-picker and transporters pages all fill it
   (animals `dashboard/controller.js:124`, `addresses/controller.js:214`,
   `transporters.controller.js:155`).
   Rejected: dropping the marker too (the criteria and the performance suite both name it);
   rejected: keeping the flag unused.

6. **The guard lands on the set's own notification list from every state, and logs through
   the mechanism each repo's architecture doc names for a refusal answered by a redirect —
   its own named line.** Today both repos send a SUBMITTED notification to its view page
   instead (animals `cancel-amend/controller.js:24-27`, plants `:27-30`); the criteria
   replace that with the list for every non-amending state, so the status-dependent helper
   is deleted in both. The branch is answered by a redirect, and both repos' architecture
   docs put that case on a hand-rolled named line, not on `kit.logRefusal`: "A refusal
   answered by a redirect logs its own named line with the journey id and the reason"
   (animals `src/server/app/docs/architecture.md:250-251`, plants `:251-252`), with
   `declaration/controller.js` named canonical (animals `architecture.md:253-266` over
   `declaration/controller.js:70-82`; plants over `declaration/controller.js:57-67`).
   `kit.logRefusal` is scoped to the other case — "Every other refusal **that shows the
   page again** ... calls `kit.logRefusal`" (animals `architecture.md:229-231`, plants
   `:230-232`) — and it hard-codes a message about the page being shown again
   (`REFUSAL_LOG_MESSAGE`, animals `shared/kit.js:139`, plants `:141`), which is untrue of
   a redirect. So animals' existing named line stays on its own mechanism, keeping the
   searchable reason name it carries today, and plants — which logs nothing on this branch
   — gains the same line with the same reason name and the same message shape, so the one
   rule reads the same in both twins.
   Rejected: moving both repos onto `kit.logRefusal` (the plan's earlier reading), which
   would log a message that says the page was shown again when the request was redirected,
   and would lose the named reason support searches by.

7. **Welsh: the criterion as written cannot be observed, so the plan builds the draft and
   nothing else.** Criterion 8 says "with the service in Welsh". There is no locale
   selector: `shared/copy.js:15` always resolves the default locale and its doc comment
   says locale selection "plugs in via the `locale` argument when it is" commissioned
   (`shared/copy.js:8-9`). What the programme invariant actually requires, and what every
   other row does, is a Welsh draft beside the English in the same change, with the same
   key tree — enforced by each repo's `copy-parity.test.js`. The plan lands that and specs
   no Welsh behaviour. Recorded as a claim that does not hold (section 3).

8. **The confirmation page's own behaviour is spec'd under each domain's
   `notification-lifecycle` capability, not a new page capability — and the banner's
   removal is also spec'd in each domain's `journey-pages/check-your-answers`, which
   states it.** `openspec/specs/live-animals/journey-pages/` and
   `openspec/specs/plants/journey-pages/` hold dispatch journey pages only, and both
   confirmation pages (cancel and delete) are already specified inside
   `REQ-LIFECYCLE-008` / `REQ-PLANTS-LIFECYCLE-007`, so extending those is the existing
   mechanism for the page. Separately, two check-your-answers scenarios state the restored
   view's cancelled message — `SCN-CYA-003-D` and `SCN-PLANTS-CYA-009-B` — so they become
   untrue too and are edited in the same change (section 8).
   Rejected: minting `journey-pages/cancel-amendment`, which would split one requirement
   across two capabilities and leave the delete page's twin behaviour behind; rejected:
   leaving the two check-your-answers scenarios alone, which would leave the spec stating
   a banner the code no longer renders.

9. **Plants' set specification: `journey-spec.json` and `decisions.json` are updated;
   `backlog-extras.json` and `panel/rulings.json` are not.** The programme invariant
   requires the set's journey specification, its decisions ledger entry and any guide that
   describes the behaviour. `journey-spec.json:1042` states the amendment-cancelled banner
   as live behaviour and becomes untrue. `backlog-extras.json:441`, `:525` and
   `panel/rulings.json:1620`, `:1635`, `:1655` are dated records of what was planned and
   what a panel ruled at the time, so they stay as written.

10. **Plants' `docs/copy-status.md` gets no row.** Its table lists the features whose copy
    is provisional and has never carried a `cancel-amend`, `delete-notification` or
    `notification-view` row, so the change makes nothing in it untrue. Its incompleteness
    is a follow-up (section 7), not this row's footprint.

11. **The guard's POST half is proved end to end in animals only.** `FrontendFormClient`
    mints its crumb on the animals set and runs on the animals seed context
    (`adapters/http/frontend-form-client.ts:13`, `fixtures/ui.ts:192`), and
    `flows/animals/seeded-journey.ts:127-129` already posts to this very address through
    it. Plants has no equivalent client, so plants' POST half stays proved by its
    controller unit test and only its GET half is proved end to end. Building a plants form
    client is a follow-up.
    Rejected: posting from a browser page in a plants FIT spec — the page the form lives on
    is exactly the page the guard refuses to render, so there is no form to post.

12. **The plants cancel-amendment page object gains no "Go back" locator.** Criterion 7's
    link half is proved where plants already drives that control from the feature's own
    copy module, in the plants FIT spec (section 4, entry 21); no plants test in the tests
    repo exercises the link, so a locator for it would be support nothing reaches
    (section 15). Only the page object's heading changes, and its one consumer is
    `tests/plants/e2e/features/review.spec.ts:482`.
    Rejected: adding the getter for symmetry with animals' (whose getter has three
    consumers in `cancel-amend-ui.spec.ts`) — symmetry is not reachability; rejected:
    adding a plants E2E test for the link, which would duplicate the FIT proof in the
    slower rung for no new coverage.

13. **The delete-notification page is untouched.** Its shorter wording and plain link back
    are inc-125's.
