## 0. Decisions

1. **Two placeholders, two keys.** `copy.country.placeholder` ('Select a country' / 'Dewiswch wlad') stays as it is: it is the text of the native select's blank first option, which is what users without JavaScript see (AC 2 and 4 keep it). The type-ahead's empty-box text is a NEW key `copy.country.searchPlaceholder`: 'Search for a country' / 'Chwiliwch am wlad'. Rejected: re-pointing `placeholder` at the new string — it would change the no-JS blank option, which the criteria keep.
2. **Welsh string is reused, not machine-drafted afresh.** 'Chwiliwch am wlad' is already the Welsh for 'Search for a country' in live-animals `features/transport/copy/copy.cy.js` (`transitCountries.country.placeholder`). Both frontends use it.
3. **How the placeholder reaches the component.** The shared component reads its config from the select's `data-*` attributes. Add one optional macro param, `autocomplete.placeholder`, rendered as `data-placeholder` (empty string when absent, like every sibling attribute), and one line in the client component: `if (dataset.placeholder) { config.placeholder = dataset.placeholder }`. `placeholder` is a native option of the vendored `accessible-autocomplete@3.0.2` (`src/autocomplete.js` default `placeholder: ''`, rendered on the input), and `enhanceSelectElement` passes config through unchanged — so this is the library's own behaviour, configured, not custom JavaScript. Every other consumer (port of entry, transit countries, import reason in animals; commodity details and arrival details in plants) passes no placeholder, gets `data-placeholder=""`, and is untouched. Rejected: setting the `placeholder` attribute from the template on the select (the library builds a new input and would not carry it over).
4. **The hint goes by deleting the key, not by blanking it.** Remove `country.hint` from `copy.en.js` and `copy.cy.js` in both frontends and remove the `hint:` line from both origin templates. The copy-parity and copy-convention tests then see identical key trees; a unit test pins the key as `undefined` in both locales, as import-reason does.
5. **Welsh criterion (AC 6) — claim checked against the tree and does not hold as written.** Neither frontend can show Welsh: `copyFor` (`src/server/app/shared/copy.js` in both repos) is always called with the default locale `en` — there is no language toggle or cookie yet ("Only `en` exists until a second language is commissioned"). So "with Welsh chosen, the placeholder shows its Welsh counterpart" cannot be observed on a page. Planned against reality: the Welsh copy modules carry `searchPlaceholder: 'Chwiliwch am wlad'` and no `country.hint`, pinned by each feature's `copy.test.js`. When a locale switch lands, the same `copy.country.searchPlaceholder` flows through `data-placeholder` with no further change. No spec scenario is written for Welsh (the spec records observable behaviour only).
6. **The origin page's full-page visual baseline is refreshed in this increment, not in inc-010.** The row's notes put the refresh in the region-code row, but the gate's e2e rung runs `test:docker-compose`, which includes `@visual` (it only excludes `@a11y|@active|@dynamics`), and `tests/animals/e2e/visual/origin-of-import.visual.spec.ts` screenshots this exact page on first load. Removing the hint and adding the placeholder changes that image, so leaving the baseline would fail this increment's gate. Both `origin-of-import-animals-darwin.png` (gate, local) and `origin-of-import-animals-linux.png` (CI) are regenerated. inc-010 will refresh them again for its own change. Rejected: tagging the visual test out, or loosening its threshold.
7. **Plants keeps its own list, guidance and errors.** Only `country.hint` is removed and `country.searchPlaceholder` added; `guidance`, `errors.*`, the narrowing and the SPS origin list are not touched.
8. **Plants `spec/journey-spec.json` is left alone.** Its origin entry still records `"hint": "Start typing to search for a country."`, but it is the set's historical digest (read by comments and panel files, not by any test or runtime path). Rewriting provenance artefacts is out of scope.
9. **No-JS proof in plants is new.** The plants origin FIT spec and plants E2E have no `javaScriptEnabled: false` test today (animals has one). This increment adds one in each, because AC 3, 4 and 5 are "with or without JavaScript".
10. **Hint absence is asserted two ways in FIT** — by the GOV.UK hint element (`#countryOfOrigin-hint`, the id govukSelect gives a hint) having count 0, and by the removed English sentence not being on the page. In E2E, through a page-object locator `countryHint` (the id) — assertions stay in the specs.
11. **GDS caution on placeholders noted, ruling wins.** GOV.UK generally avoids placeholder text; the 9 October afternoon ruling (claims p1-013, p3-031) asks for it on this type-ahead and keeps the label 'Country of origin', so the placeholder never replaces the label.

Add after REQ-ORIGIN-014:

```
### Requirement: The country question carries no hint, and its empty search box invites a search
**ID**: REQ-ORIGIN-015
The system MUST ask "Country of origin" with no hint text, with or without JavaScript. With JavaScript the empty search box MUST show the placeholder "Search for a country"; without JavaScript the country list MUST begin with its blank "Select a country" entry.

#### Scenario: With JavaScript, the empty search box shows "Search for a country" and no hint
**ID**: SCN-ORIGIN-015-A
- **GIVEN** the user has reached the origin of the import page with JavaScript available and no country chosen
- **WHEN** the page loads
- **THEN** the country field, labelled "Country of origin", shows the placeholder "Search for a country"
- **AND** no hint text is shown for the country question

#### Scenario: Without JavaScript, the country list begins with "Select a country" and no hint
**ID**: SCN-ORIGIN-015-B
- **GIVEN** the user has reached the origin of the import page without JavaScript
- **WHEN** the page loads
- **THEN** the country list, labelled "Country of origin", begins with its blank "Select a country" entry
```
