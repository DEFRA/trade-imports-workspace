## 0. Decisions

1. **Which hint is "the region of origin code question's hint".** It is the radios question's hint (`copy.regionRequirement.hint`), which today reads 'If a region of origin code is required it will be shown on your health certificate.' The DR2.1 prototype (`origin-of-the-import.html`, `#region-of-origin-hint` under the legend) puts the new sentence there, and keeps 'Enter up to 5 characters.' under the code box. So `regionRequirement.hint` changes and `regionCode.hint` ('Enter up to 5 characters.' / 'Rhowch hyd at 5 nod.') stays. Rejected: replacing the code box's hint.
2. **No clears the code — at the page, not in the obligation.** `validate.js` `toAnswers` saves `regionOfOriginCode: ''` whenever the requirement answer is not `yes`, whatever the hidden box still posts (a GOV.UK conditional reveal hides the box but the browser still submits it). Then the stored code is empty, the review page's always-in-scope region code row writes 'Not applicable' on the finished Import details card (`summary-row.js` → `notApplicableCell`), and choosing Yes again shows an empty box (`fromAnswers` splits an empty code). Rejected: changing the `regionCode` obligation's `applyTo` to put the code out of scope under No — that would also drop the review row the criterion wants to read 'Not applicable', and change the retain-value engine contract the obligation model documents.
3. **A code with no country is not saved.** `regionCodeFrom` returns `''` when there is no country prefix (today it saves the bare typed part, `'75'`). "Kept on the page" is met where the page shows the submission back: the server never blanks a submitted value (`pageValidation.onSubmit`), so when the same submission is refused for any other answer the typed code is still in the box. After a successful save nothing holds the typed part — the app stores only the joined code and there is no field for a loose suffix. Rejected: keeping the bare suffix in `regionOfOriginCode` (that is exactly the "saves a region of origin code" the criterion forbids); adding a frontend-only `regionOfOriginCodeSuffix` answer (it would need the animals backend's notification aggregate, outside this row's repos, and the 9 October afternoon ruling keeps the prefix server-side as DR1 shipped it). Recorded as a risk, not a defect: a trader who saves Yes + a code with no country and comes back sees Yes with an empty box.
4. **Completeness needs no model change — it is already the rule, and is pinned here.** `obligations/sections/origin.js` already makes `countryOfOrigin` and `regionOfOriginCodeRequirement` mandatory, and `regionOfOriginCode` mandatory under `yes`. So a country with the region question unanswered is In progress, a country with No is Complete, a country with Yes and a code is Complete, and a stored Yes with no code is never Complete (the row's note asked for that last rule to be added — it is already there). This increment adds the tests that pin it (unit, FIT, E2E) and the spec requirement that states it. Rejected: editing `origin.js` for a rule it already holds.
5. **Browser cap.** The code box gets `attributes: { maxlength: "5" }`, `autocomplete: "off"` and `spellcheck: false` — `govukInput`'s own params, as CPH does for maxlength. The server's existing 5-character rule (`requiredMaxText` / `maxText`) is unchanged and still the authority. Tests that need an over-long code to reach the server remove the `maxlength` attribute first (a page-object method in the tests repo, an `evaluate` in FIT), because Playwright's `fill` inserts text the way a user does and the browser's cap applies to it.
6. **Over-long code under No.** The existing rule rejecting a hidden over-long box under No ('Should reject a typed part over 5 characters even when the answer is No') is left as it is: the spec's REQ-ORIGIN-010 still says "on either save control", the cap now makes the case unreachable by typing, and changing it is not asked for. Rejected: dropping the rule under No.
7. **Internal reference hint.** `internalReference.hint` drops 'It can be up to 58 characters.' in English and 'Gall fod hyd at 58 nod.' in Welsh. The 58 limit stays in `validate.js` and in `errors.internalReferenceMaxLength`, which names it. The copy test 'Should state the internal reference length limit in the hint, not only in the error' is inverted (the old intent is retired by the design, not weakened by accident).
8. **Welsh.** New Welsh machine drafts, in the file's existing MACHINE-DRAFT style: region hint 'Gwiriwch y dystysgrif iechyd am god rhanbarth tarddiad. Gallwch ychwanegu’r cod yn nes ymlaen os nad yw’r dystysgrif gennych nawr.' (curly apostrophe U+2019, as the file uses); internal reference hint 'Rhowch unrhyw gyfeirnod mewnol yr hoffech ei ddefnyddio i adnabod y llwyth hwn, neu gadewch yn wag.' **The criterion "With Welsh chosen, … show their Welsh counterparts" does not hold as written**, as inc-009 Decision 5 found: `copyFor` is always called with the default `en` (`src/server/app/shared/copy.js`: "Only `en` exists until a second language is commissioned"), so Welsh cannot be chosen on the page. Planned against reality: the Welsh copy carries the new strings and none of the removed text, pinned by `copy.test.js` and by a `grep` check; no spec scenario for Welsh.
9. **Visual baseline.** Both `origin-of-import-animals-darwin.png` and `-linux.png` are regenerated in this increment (the gate's e2e rung runs `@visual`; the copy changes alter the first-load image). inc-009 already took them to the no-hint, placeholder page; this refresh adds the new region hint and the shorter internal reference hint. The subdivision-label row (req-030) has not landed, so it refreshes the baseline itself later.
10. **FIT test replaced, not edited.** 'the region of origin code is still held and shown after it is made optional' asserts the opposite of AC 3, so it is deleted and a new test with an honest name takes its place. Its two coverage links move (section 8).
11. **No-country E2E lands on the overview.** With no country chosen the opening run has no next page and Save and continue sets the user down on the overview (existing 'saves what the user has when submitted without a country'). The new E2E relies on that path.
