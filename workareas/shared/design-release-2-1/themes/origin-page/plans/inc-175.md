## How it works today (checked against the live tree)

- `src/server/app/services/countries/index.js` already has a private `subdivisionDisplayLabel(code)` that
  returns `"<subdivision> (<parent>)"`. It falls back to the bare name when the parent is unknown.
  `destinationCountryOptions()` uses it. `originCountryOptions()` does not: it lists subdivisions by their bare
  name (`{ value: 'ES-CN', text: 'Canary Islands' }`) and sorts by `text`. The two functions are otherwise
  identical. Both lists come from the same `GBNAG_SPS_EX` load (`ensureLoaded`), or from the
  `countries-origin.json` captured fixture in stub mode.
- The origin page (`features/origin/controller.js`) builds `countryItems` from `originCountryOptions()`.
  `validate.js` checks membership against the option *values*, so changing the labels cannot change what is
  accepted or stored.
- Stored code: `toAnswers` stores `countryOfOrigin: 'ES-CN'` and `countryOfOriginSubdivisionCode: 'ES-CN'`. On
  reopening, `fromAnswers` gives the select `ES-CN`. `prefixFor('ES-CN')` gives `parentCountryCode` = `ES`, so the
  prefix is already `ES` (AC3's code and prefix halves already hold). The box text comes from the selected
  option's text, so it becomes "Canary Islands (Spain)" when the option label changes.
- The type-ahead (`src/client/javascripts/components/accessible-autocomplete.js`) searches the option labels
  by case-insensitive substring. After the change, `fran` matches France and its six territories (7 options,
  not 1).
- The check-answers card (`import-details.js`) and the dashboard row already use `originDisplayLabel`, which
  already reads "Canary Islands (Spain)". Nothing changes there.
- Captured fixture (`countries-origin.json`, recaptured by inc-173, which is `done`): 31 countries plus 9
  subdivisions (FR ×6, PT ×2, ES ×1). The tests repo's `resources/reference-data/countries-origin.json` holds
  the same data.

## 0. Decisions

1. **One builder for both lists.** In `services/countries/index.js`, `originCountryOptions` and
   `destinationCountryOptions` both delegate to one private `countryAndSubdivisionOptions()`. That function
   holds the body `destinationCountryOptions` has today: countries by name, subdivisions by
   `subdivisionDisplayLabel`, one `localeCompare` sort by `text`. Both exports stay, because their call sites
   (origin and import-reason) and doc comments name the page they serve.
   Rejected: copying the subdivision label into `originCountryOptions`, which would leave two identical bodies;
   and moving the builder into another theme, since it already lives in the shared countries service.
2. **The test fixtures use the same shared builder.** In the frontend `_capture/fixtures.js`,
   `originPageCountryEntries` and `destinationPageCountryEntries` both return one private
   `countryAndTerritoryEntries()`, which holds today's destination body. In the tests repo,
   `originPageCountryNames` and `destinationCountryNames` (`domain/shared/fixtures/reference-data.ts`) both
   return one private `countryAndTerritoryNames()`. All four export names stay, so no other importer changes.
3. **The FIT filter test changes its query, not its name.** "filters the list as the user types,
   case-insensitively" now types `belg` and expects exactly one option, Belgium. The `IRELAND` half stays.
   `fran` now matches 7 labels. The test name stays the same, so its coverage link (SCN-ORIGIN-002-A) holds.
4. **No plants change.** The invariant says plants mirrors behaviour it shares. The plants frontend's origin
   list offers no subdivisions: there is no `subDivisions` handling under `src/server` in
   `repos/trade-imports-plants-frontend`, outside its captured fixtures. So plants has no counterpart behaviour
   to change.
5. **No germinal change.** No `sets/germinal-products` exists in the frontend at this HEAD. The backlog note
   ("the germinal set copies this when it copies the page") is for that future row.
6. **No Welsh drafts.** The labels are MDM data plus brackets. No copy string is added or changed.
7. **The dropped AC clause stays dropped.** The row drops "typing spain lists Canary Islands (Spain)". The
   substring filter will do it anyway, but no test is written for it (c-009, req-019 out of scope).
8. **E2E proof of the stored code uses a region code.** The existing E2E subdivision test only checked the
   select value and the box text. It is extended to answer Yes with region code `12`, so the reopened page proves
   the `ES` prefix (AC3). `12` is used because the region box takes the part after the prefix, and `12` is a
   short, valid suffix.
9. **Reuse the first attempt's patches; leave the unrelated flakes alone.** The patches match this plan, so the
   implementor applies them rather than retyping them (see "Second attempt"). The contact-address and
   cancel-amend flakes come from outside this slice and get no change here. Rejected: hardening
   `contact-address.spec.ts` in this row. That would make an origin-list increment change an unrelated page's
   test, and the 500 comes from starting a notification, not from anything this row changes.
