## 0. Decisions

1. **Region markup = plain HTML `<section>` with `aria-labelledby` (named by a visible heading) or `aria-label` (no visible heading).** This is what the DR2.1 trace shows (`<section ... aria-labelledby="notification-hub-tasklist-heading">`, `<section ... aria-label="Animals summary">`, trace p11-012, p11-013-m1). No new CSS class and no `app-dr2-*` class is copied (programme invariant); the task lists stay `govukTaskList` (c-129). Rejected: `role="region"` on `<div>`s — `<section>` with an accessible name is the native element and what the source uses.
2. **The two total cards keep their element class and children, only the element changes from `<div>` to `<section>`.** `.app-commodity-total` is a class-only selector (`src/client/stylesheets/components/_commodity-total.scss`), so styling is unchanged, and the FIT `expectTotalBoxes` (`locator('> *')` → value, label, caption) and the styling test keep passing. Rejected: wrapping the card in a new `<section>` — adds a needless DOM level.
3. **Heading ids**: `commodity-totals-heading` (Your commodities), `notification-tasklist-heading` (Notification tasklist), `{{ group.id }}-heading` (each numbered section, both frontends). `govukTaskList` stamps `{idPrefix}-{n}-hint|status` ids from the same `group.id`, so `-heading` never collides; the hub FIT's `groupTaskList` filter (`[id^="<group>-"]` inside `ul.govuk-task-list`) is unaffected because the heading sits outside the `ul`.
4. **New copy keys.** Animals `commodityTotals.animalsRegionLabel: 'Animals summary'` / cy `'Crynodeb anifeiliaid'`, `commodityTotals.packagesRegionLabel: 'Packages summary'` / cy `'Crynodeb pecynnau'` (machine-draft Welsh, the file's existing MACHINE-DRAFT banner covers them). Plants `taskListLabel: 'Notification tasklist'` / cy `'Rhestr dasgau’r hysbysiad'` — the exact Welsh the animals hub already uses for `taskListHeading`, so the two services read the same (ruling p3-044 "mirror wording patterns"). Strings live in each feature's own copy (invariant: never reword shared copy). Rejected: reusing the animals key name `taskListHeading` for plants — plants has no heading, so the key says what it is: a label.
5. **Welsh for 'Main import reason' is 'Prif reswm mewnforio'** — the Welsh the import-reason page title (`import-reason/copy/copy.cy.js:3`) and the review page (`check-answers/copy/copy.cy.js:47`, `mainImportReason`) already carry. Rejected: a fresh machine draft — three different Welsh renderings of one English phrase would be worse.
6. **Claim check — "With Welsh chosen" (AC5, AC7).** Neither frontend has a runtime language switch: `shared/copy.js` `copyFor` always resolves `en` (no cookie/toggle yet). So no browser test can choose Welsh. The Welsh criteria are proven where the repos already prove Welsh: the feature's `copy.test.js` pins the Welsh value (copy parity only checks it differs from English). This is not a defect in the row — it's the same as every other Welsh string in the service — but no E2E/FIT can cover it.
7. **Claim check — AC3 (status/hint read with the link).** Holds today: `govukTaskList` puts `aria-describedby="<hintId> <statusId>"` on each link (govuk-frontend `task-list/template.njk` line 12). Wrapping in sections doesn't change it. Pinned by a new FIT test with `toHaveAccessibleDescription` so the region change can't regress it.
8. **Claim check — AC8 (axe).** The two live-animals axe tests ("hub with nothing but the origin answered…", "hub showing commodity totals…") and the plants one ("has no serious or critical axe violations on the initial render") already exist and stay as they are; re-running them over the new markup proves AC8. No new axe test.
9. **Spec IDs**: new `REQ-OVERVIEW-010` (regions), `REQ-OVERVIEW-011` (row title), `REQ-PLANTS-OVERVIEW-005` (plants regions) — confirmed unused by `grep`. Welsh isn't recorded in any spec (no `Welsh` anywhere under `openspec/specs/live-animals` or `plants`), so the spec records English only.
10. **The rename touches the hub row only** (row notes). The import-reason page title and the review page already read 'Main import reason'. Two tests-repo assertions that check "Main reason for import" is ABSENT (`hub-groups-and-cya-rows.spec.ts` line 78 on the review page; `pages/import-reason.spec.ts` line 21) stay as they are — they're the guard, not a use of the old title.
11. **Integration proof placement**: the animals regions test goes in the existing `tests/animals/e2e/features/hub-groups-and-cya-rows.spec.ts` (which already pins this hub's headings and lists); the plants regions test goes in `tests/plants/e2e/features/start.spec.ts` beside "the Overview carries the journey strip…". Rejected: new spec files — the hub's structural assertions already live in these two.
