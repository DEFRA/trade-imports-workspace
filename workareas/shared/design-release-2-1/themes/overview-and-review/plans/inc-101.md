Both trees were clean at planning time, with no merge in progress. The set is `sets/live-animals`, and the spec namespace is `live-animals/`. The change goes through `frontend-change` as a routed "change the frontend" (L4: the set's own `check-answers` feature folder). No recipe covers retitling and restructuring review cards. The page changed is the review, "Review your notification" (`features/check-answers`). The browser title and the H1 stay the same.

## 0. Decisions

1. **The group layer is removed, not just left without headings.** Every section's view model becomes `{ anchor, heading, cards: [...] }` and the template loops sections then cards. With no subsection heading left anywhere, `groups` would be a layer that always holds one heading-less wrapper. Later review rows build their cards into this structure (the row's `gate`), so it should be the simple one.
   *Rejected:* keeping `groups` with `heading: null`. The template already supports that, but it leaves a dead layer, and a stray non-null group heading would bring the old structure back unseen.
2. **Card titles become h3 and inner headings become h4.** The template's `cardHeadingLevel` is fixed at 3 and `innerHeadingLevel` at 4 ("Animal details" above the identifier table, "Document N" in the documents card). That makes each card title one level below its h2 section heading (AC3).
3. **Copy keys, card `id`s, card anchors, section anchors and file names stay as they are. Only the values change.** For example, `cards.importDetails` now holds 'Origin of import', and `REVIEW_CARDS` ids and anchors (`import-details`, `reason-for-import`, `additional-animal-details`, `roles-and-addresses`, `contact-address`, `consignment-parties`, `documents-section` …) are untouched. Ids and anchors are not observable behaviour. The error summary hrefs, `cardStoredErrors(REVIEW_CARDS, …)`, `withCardErrors` and many tests key on them.
   *Rejected:* renaming keys, ids and anchors to match the new titles. That is wide churn with nothing observable, and it belongs in its own tidy-up.
4. **The `copy.groups` block is deleted from both `copy.en.js` and `copy.cy.js`.** Nothing reads it once the sections stop building groups. The hub has its own `copy.groups` in `features/hub/copy`, which is a different module and is left alone.
5. **The visually hidden Change-link text follows the new card titles:** "Change origin of import", "Change main import reason", "Change additional details", "Change addresses" and "Change contact address". The fit spec's `cardChangeLink` and the e2e `changeLink(...)` calls name cards this way, and a Change link should name what it changes.
   *Rejected:* keeping the old hidden text. A screen reader would then announce "Change import details" on a card titled "Origin of import".
6. **Unfinished-card messages change only where the AC says so:** 'Complete origin of import', 'Complete main import reason' and 'Complete additional details'. 'Complete roles and addresses' and 'Complete contact address for this consignment' stay. The DR2.1 prototype keeps those two old strings even though it retitles the cards (prototype-dr2-1-source-p11-053, p11-054), and the AC names only the three.
7. **The Addresses card keeps its per-row "Edit details" links.** AC7's "single header Change link" is about the card's one Change link in its header, which already goes to `addresses` (the roles and addresses page). The row-level "Edit details" links on copied addresses are a different action, owned by REQ-ADDR. They stay, as do the fit and unit tests that pin "one Change link per card, no row Change link".
8. **The Contact address card's Change link is already correct, so only a proof is added.** It goes to `consignment/contact/select?change=1`. The contact form posts to its own URL, query included, and `kit.nextTarget` → `exitTarget` sends a `change` save back to the review. Nothing changes in `contact/`. The proof is a new leg in the tests repo's `change-from-cya.spec.ts`.
9. **Transit countries stays its own card with its own Change link**, directly under "3. Transport and arrival" with no subsection heading above it (AC3). The prototype folds it into the Arrival details card (p11-099), but this row does not ask for that, and a later card-content row may.
10. **The Additional details card always stands.** The prototype shows it only when it has a row (p11-091), but no AC here asks for that, so it is out of scope.
11. **Welsh drafts** sit beside every changed English string (programme invariant). Where the service already has a Welsh form, it is reused: 'Tarddiad y mewnforyn' (origin page title), 'Prif reswm mewnforio', 'Manylion ychwanegol', 'Cyfeiriadau’r llwyth' (addresses page title) and 'Cyfeiriad cyswllt'.
12. **The tests-repo `summaryCard(name)` now matches a card by its exact title heading,** not by `hasText` substring. The new titles are shorter and more generic ('Addresses', 'Contact address', 'Additional details'). A substring match could hit another card that happens to contain the words, while an exact heading match pins the title and proves it is a heading. Every existing caller already passes a full card title.
13. **Claim checks against the live tree:**
    - The note "the germinal set copies the result" does not hold on this branch. There is no `sets/germinal-products` folder (`ls src/server/app/sets` shows only `live-animals`). Nothing is planned for germinal.
    - The note "the tests repo's view-state spec and page object find sections and cards by today's names" holds for the specs. The page object itself holds no card names. The specs do: `notification-view-states.spec.ts`, `hub-groups-and-cya-rows.spec.ts` and twelve others, listed in §4.
    - The hub's own section captions ("4. Documents", "5. Consignment parties" in `features/hub/copy`) are not the review's and are not changed. `hub-groups-and-cya-rows.spec.ts` lines 15–22 and 61–70 assert the hub and stay as they are.
14. **Plants is not in this row's repos.** The plants review keeps its own 'Import details' card (tests/plants specs assert it). The "plants mirrors" invariant would ask for a plants twin, but the row names only `frontend` and `tests`, so this is recorded under risks for a later plants row rather than widened here.
