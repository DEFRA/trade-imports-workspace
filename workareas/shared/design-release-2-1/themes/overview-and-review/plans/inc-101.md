## 0. Decisions

1. **The group layer is removed, not just left without headings.** Each review section's view model goes from section → groups → cards to section → cards. The template loops sections, then cards.
   - Why: with no subsection heading left, every group would be a heading-less wrapper holding cards. The row's gate says later review rows build their cards into this structure, so it should be the simple one.
   - Rejected: keeping groups with an empty heading. The template already handles that, but it leaves a dead layer, and a stray group heading would bring the old structure back unseen.
2. **Card titles are always level 3, and headings inside a card are always level 4.** That puts each card title one level below its level-2 section heading. The inner headings are "Animal details" above an identifier table and "Document N" in the documents card.
   - Source: the prototype renders every card title as `<h3>` under an `<h2>` section heading (`app/views/partials/design-release-2.1/review-summary-card.html` at `04a073b`, and `review-sections.html`).
3. **Only the copy values change. Copy keys, card ids, card anchors, section anchors and file names stay.**
   - For example, `cards.importDetails` now holds "Origin of import", and the error-summary anchors (`#import-details`, `#reason-for-import` and so on) are unchanged.
   - Why: ids and anchors are not observable. Error-summary hrefs, the review-card registry and many tests key on them.
   - Rejected: renaming keys and anchors to match the new titles. That is wide churn for nothing a user sees. It is a follow-up (section 7).
4. **The review's copy loses its whole subsection-heading block, in English and Welsh.** Once no section builds a group, nothing reads it.
   - The hub has its own `groups` captions in `features/hub/copy`. That is a different module and is left alone.
5. **The Change links' hidden text follows the new card titles.** A screen reader hears "Change origin of import", "Change main import reason", "Change additional details", "Change addresses" and "Change contact address".
   - Why: a Change link should name what it changes. The prototype has no hidden text to copy (its header link reads only "Change"), so the service keeps its pattern and fills it from the new titles.
   - Rejected: keeping the old hidden text, which would announce "Change import details" on a card titled "Origin of import".
6. **Unfinished-card messages change only for the three cards the criterion names.** They become "Complete origin of import", "Complete main import reason" and "Complete additional details".
   - "Complete roles and addresses" and "Complete contact address for this consignment" stay. The prototype builds each message from the card's original title (`app/routes.js` at `04a073b`, lines 4896–4905 and 5179, 5193, 5212, 5272, 5284). It renames the Addresses and Contact address cards only later, in its presentation layer (lines 5568–5575), so those two messages keep the old words.
7. **The Main import reason card's first row is keyed "Main import reason".** Today it is keyed "Reason for import", from the review copy's row label.
   - Source: the prototype (`routes.js:5035`, `:8379`) and the criterion.
8. **The Addresses card keeps its per-row "Edit details" links.** The criterion's "single header Change link" is the card's one Change link in its header, which already opens the roles and addresses page. The row "Edit details" links on copied addresses are a different action. A later row ("Addresses card: permanent addresses, CPH format, one header link and a single unfinished entry") owns the Addresses card's content.
9. **The Contact address card's Change link already opens the contact address page.** Only its title, row and hidden text change. Its round trip is already proven end to end (`change-from-cya.spec.ts`, the contact address test).
10. **Transit countries stays a card of its own,** standing directly under "3. Transport and arrival" with no subsection heading. The prototype folds it into Arrival details as a subsection (`routes.js:5580–5585`), but this row does not ask for that. "Arrival and transit task statuses on the overview, and transit countries on the review" owns that.
11. **The Additional details card still always stands.** The prototype shows it only when it has rows, but no criterion here asks for that. It is out of scope.
12. **Welsh drafts sit beside every changed English string** (programme invariant). Where the service already has a Welsh form of the same English words, the implementor reuses it, for example the review's own subsection Welsh for "Main import reason", "Additional details" and "Contact address". The file keeps its machine-draft header. The copy-parity test refuses a Welsh value identical to its English one.
13. **Browser tests find review cards by heading and accessible name, not by class.**
    - The fit spec counts cards by their level-3 title headings.
    - It proves "one Change link per card and none on a row" by asserting the whole, ordered list of Change links' accessible names against the card titles' hidden texts. A row Change link would add an extra name and fail the list.
    - The hidden "Missing" is found by its text inside the answer cell, which the spec reaches by its `definition` role. Its hidden look is still compared with GOV.UK's visually-hidden values read at run time, which the set's testing guide allows (`sets/live-animals/docs/testing.md:137–141`). Finding the element is the part that stops using structure or class.
    - Rejected: dropping the run-time comparison and relying only on a screenshot. A screenshot cannot prove that the text is still announced.
14. **The screenshot suite gains a review screenshot that ends on the last card.** It is a new visual spec in the tests repo, following `refused-review.visual.spec.ts`.
    - It shows a ready draft's review at desktop width, full page, from the first section to the Contact address card and the Continue button below it.
    - It masks the journey strip, as its neighbours do, and the arrival date value. The seeded arrival date moves with today's date (`journey-options.ts:30`).
    - The existing refused-review baselines change too, because their headings, titles and messages change. Both are regenerated (section 4).
15. **The tests-repo page object matches a summary card by its exact title heading.** Today it matches any card whose text contains the name, ignoring case (`notification-view-page.ts:35–37`).
    - Why: the new titles are short and generic ("Addresses", "Contact address", "Additional details"). A substring match can hit another card that happens to contain the words. An exact heading match pins the title and proves it is a heading.
    - Every caller already passes a full card title. The species card's title comes from the domain's own title function.
16. **The tests repo keeps the hub's and the review's numbered headings apart.** The hub still reads "4. Documents" and "5. Consignment parties", and the review now reads "4. Uploaded documents" and "5. Consignment addresses". `hub-groups-and-cya-rows.spec.ts` uses one constant for both today, so it needs one list for each page.
17. **Claim checks against the live tree:**
    - "The germinal set copies the result" does not hold. The frontend has only `sets/live-animals`. Nothing is planned for germinal.
    - "The tests repo's view-state spec and page object find sections and cards by today's names" holds. The page object names one card itself (`regionOfOriginCode`, "Import details"). The specs name the rest, listed in section 2.
    - The note's fit line numbers (`:43`, `:146`) have moved. The class uses are now at `check-answers.fit.spec.js:47–48` (visually-hidden reference), `:181` and `:372–384` (summary-card class). The last-card check at `:152–159` uses form siblings and the subsection heading.
    - The note that "no review screenshot exists yet" holds. Only the refused review has one.
18. **Plants is not in this row's repos.** The plants review keeps its own card titles. The "plants mirrors" invariant would ask for a plants twin, but the row names only `frontend` and `tests`, so it is a risk and a follow-up rather than widened scope.
19. **The fit Change-link test is retitled to state what it asserts.** It asserts one Change link per card, named for its card, in card order, and none on a row (the ordered list of link names equals the cards' hidden names). It no longer claims each link "sits in a card heading".
    - Why: proving placement in the card's title area without the GOV.UK summary-card classes needs a structural locator the set's testing guide steers away from. The ordered-name equality already proves the behaviour a user meets: one link per card, named for it, none on a row.
    - Rejected: keeping the old title over the new assertion. It would claim placement the test does not prove.
    - Follow-on: `add-a-section.md` §7 quotes the old title, so it changes in the same edit (sections 2.10a and 12).
20. **Behaviour-spec scenarios outside the review that name an old card or link:**
    - SCN-FLOW-013-B (`journey-flow/spec.md:317`) quotes the link text "Change import details". It changes to quote "Change origin of import". Not signed off.
    - SCN-FLOW-018-C (`journey-flow/spec.md:405`) says "the Change link for the reason for import". It changes to name the Change link for the main import reason. Why: it names the card the link sits on, and one concept keeps one name. Not signed off.
    - SCN-ORIGIN-013-H (`journey-pages/origin-of-import/spec.md:328`, signed off 2026-11-11) says "the Change link for the import details". It is **left unchanged**. Why: its behaviour (Back from the origin page opened by a Change link shows the review) does not change. Its words are a lower-case description of what the link changes, not a quoted label, and they still describe it truly. Editing a signed-off scenario for wording alone would hold the row for a person with no behaviour change. Rewording it belongs to a promotion review (follow-up, section 7).
21. **Visual baselines are regenerated only for this row's two screenshot specs**, the new review spec and `refused-review.visual.spec.ts`, never the whole visual folder. The macOS script already writes only changed images, and the Linux script passes its file arguments on to Playwright, so naming the two spec files limits both to their own images.
