## 0. Decisions

**What the live tree already does** (checked against the claims):

- C1 — **Means of transport already reads with the question's labels.** `CA/copy/copy.en.js` `means` maps `AIRPLANE → 'Air'`, `RAILWAY → 'Rail'`, `ROAD_VEHICLE → 'Road'`, `VESSEL → 'Sea'`, the same as `features/transport/copy/copy.en.js` `portOfEntry.means.options`. No code change. A unit test is added that checks every code the arrival page offers, so the two cannot drift (section 4).
- C2 — **Transit countries are already optional for submission.** `src/server/app/sets/live-animals/obligations/sections/transport.js` gives `transitedCountries` `status: 'optional'` when in scope. `statusOf` returns `OPTIONAL` for an empty optional part, and `rowReady(OPTIONAL)` is true. So an empty list neither blocks `readyForCheckYourAnswers` nor marks a card. **No obligation change.** The backlog note's "one line shared with the theme owning the arrival obligations" is not needed. What this row does change is that the separate Transit countries card, and its `'Complete transit countries'` message, go away (D3).
- C3 — **The region code row already always shows.** `regionOfOriginCode` is a retain-value obligation that is always in scope, so `regionCodeApplies` is always true. What changes is that the `'Region of origin code required'` row goes, and the value reads Not applicable when no code was needed (D2).
- C4 — **In live animals the Additional details card always has a row.** `animalsCertifiedFor` is `status: 'mandatory'` with no gate (`obligations/sections/misc.js`), so the additional details page is always in the journey and the card always shows with its Change link. The rule is still written into the card (D5) and checked by a unit test. Nothing a user sees changes in live animals.
- C5 — **The germinal set does not exist in this repo.** `src/server/app/sets/` holds `live-animals` only. Ruling `ruling-sam-2026-10-09-p1-020` (germinal certified-for, no Change link) has nothing to land on here. It is satisfied by the general rule in D5 once a germinal set copies this feature.
- C6 — **The transporter Country already comes from the stored address.** `transport-details.js` reads `transporter.address?.country`, which `transporter-record.js` copies from the register record (c-130). No change to where the value comes from. What changes is that every row always shows (D6).

**Choices settled:**

- D1 — **Exit rows for a Transit import.** When `answers.reasonForImport === 'transit'`, the Main import reason card shows `'Exit border control post'` (the `portOfExit` answer, labelled through `ports.label` as now), then `'Destination country'`, each still gated on its scope entry. Every other reason keeps today's rows and order. Temporary admission of horses keeps `'Exit date'` then `'Port of exit'`, and transhipment keeps `'Destination country'` alone. *Rejected:* renaming `portOfExit` to "Exit border control post" for every reason. The source (`prototype-dr2-1-source-p11-077`) names only Transit, and `horse-temporary-admission.spec.ts` asserts `'Port of exit'` for horses.
- D2 — **Region of origin code value.** Always one `'Region of origin code'` row. Its value is `answers.regionOfOriginCode` when `answers.regionOfOriginCodeRequirement === 'yes'`. Otherwise it is blank, which `row()` writes as Not applicable, or marks missing on an unfinished card. The `'Region of origin code required'` row is removed. *Rejected:* keep showing a stored code after the requirement flips to No. The AC says the row reads Not applicable when no code was needed, and the origin page already clears the code on No (`origin/controller.test.js`), so a code kept after No only exists in seeded or legacy data. The unit test "Should retain a stored region-of-origin code across a requirement flip to no" is rewritten to pin the new reading.
- D3 — **Transit countries move inside Arrival details.** The Arrival details card gets a `subsections` array. While `scope.has('transitedCountries')` it holds one subsection: `{ heading: 'Transit countries', rows: [transit row] }`. The transit row is keyed `'Countries that the consignment will travel through'`, reads the country labels comma-separated in stored order (as now), and carries its own row-level Change link to the transit countries page (`/transit-countries?change=1`). The link has visually hidden text `'countries that the consignment will travel through'` and is left off when the review is read-only. The separate Transit countries card is gone. In `REVIEW_CARDS`, the `transitCountries` entry is removed and its task row `'transitCountries'` joins the `arrivalDetails` entry (`rows: ['arrivalDetails', 'transitCountries']`), so every task row is still covered exactly once. Because the transit row is optional (C2), it never marks the Arrival details card unfinished on its own. *Rejected:* a second header link on the Arrival details card. The source (`p11-098`) puts the link on the transit row only.
- D4 — **Rendering the subsection.** `template.njk` sends a card with `card.subsections` down its existing custom `govuk-summary-card` branch, the same branch identifier tables and documents use. After the card's own summary list, each subsection renders an `h{{ innerHeadingLevel }}` `govuk-heading-s` heading, then `govukSummaryList({ rows: subsection.rows })`. This uses GOV.UK Frontend components only, with no new CSS. `blankEmptyValues` in `incomplete-cards.js` blanks subsection rows as it already blanks `documents[].rows`. A row's own `actions` survive blanking, because the row is spread before its value is replaced.
- D5 — **The Additional details card is shown only when it has a row.** `additionalAnimalDetailsCard(journeyId, answers, scope, readOnly)`:
  - the `'Certified for'` row appears only while `scope.has('animalsCertifiedFor')`;
  - the `'Includes unweaned animals'` row keeps its existing `unweanedApplies(answers)` gate;
  - with no rows the factory returns `null`, and `descriptionOfGoodsSection` leaves a `null` card out;
  - the Change link appears only while the additional details page is in the journey: `scope.has('animalsCertifiedFor') || scope.has('containsUnweanedAnimals')`.

  `descriptionOfGoodsSection` therefore takes `scope`. Its signature becomes `(journeyId, answers, scope, evaluation, readOnly)`, and the one call in `view-model/index.js` is updated to match.
- D6 — **Transport details rows.** The card always shows five rows in this order: `'Name'`, `'Address'`, `'Country'`, `'Approval number'`, `'Type'`. Each is built from the active transporter, which may be null. A blank value goes through `row()`, so it reads Not applicable on a finished card and is marked missing on an unfinished one. `approvalNumberRow`'s omit-when-blank behaviour is dropped. Name, Country and Approval number become `row(...)` calls on `transporter?.…`, and `transporterAddressRow(transporter)` already handles a null party. *Rejected:* keeping the rows off when no transporter is chosen. The AC says "always".
- D7 — **Arrival date label.** `copy.rows.arrivalDate` becomes `'Arrival date at destination'`. The port-of-entry page's own field label (`'Arrival date at port of entry'`, in `features/transport/copy`) is not changed. It belongs to the arrival-and-transit area, and the FIT driver `fit/live-animals-journey.js` `answerArrivalDetails` finds the field by that label.
- D8 — **Copy keys** (en and cy together, no shared copy touched):
  - removed: `rows.regionCodeRequired`, `cards.transitCountries`, `hidden.cards.transitCountries`, `errors.cards.transitCountries`;
  - added: `rows.exitBorderControlPost`, `subsections.transitCountries`, `hidden.rows.transitedCountries`;
  - changed: `rows.arrivalDate`.

- D9 — **Row-level Change helper.** The transit row reuses `cardAction(journeyId, slug, visuallyHiddenText)` from `rows/change-link.js` for its `actions`, because it already returns `{ items: [{ href, text, visuallyHiddenText }] }`, and wraps it in `editableActions(readOnly, …)`. Rename `cardAction` to `changeAction` throughout the CA folder, so its name no longer says "card" now that a row uses it too. The call sites are `import-details.js`, `reason-for-import.js`, `additional-animal-details.js`, `arrival-details.js`, `transit-countries.js`, `transport-details.js`, and every other card under `view-model/cards/` that imports it. Find them with `grep -rln "cardAction" <CA>`. Replace `cardAction`'s doc comment (which says rows carry no link and points at the transit card) with one or two lines saying it builds the one Change action a card heading, or the transit countries row, carries. Update `rows/summary-row.js`'s doc comment the same way: it currently says no row carries a Change link.
- D10 — **Plants untouched.** The plants review (`high-risk-plants/.../check-answers`) has no region-code row, no transit countries, no reason exit rows and no transporter card, so there is nothing to mirror. The row's own `repos` are frontend and tests.
- D11 — **No conflict with inc-103.** inc-103 (todo) wants the overview's Transit countries task to read To do until a country is listed, and a review row with a Change link. This row builds that review row (D3) and does not touch overview statuses. Optional-for-submission (C2, req-880) is pinned here by tests on the review and the declaration redirect, so inc-103 must keep transit countries optional for submission. That is recorded as a risk.
