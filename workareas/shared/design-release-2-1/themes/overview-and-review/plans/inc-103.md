## What the live tree already does

All four criteria already hold in the application at `59040f14`. They came in with the arrival-and-transit theme (inc-028) and the earlier overview-and-review commits (`93d8eec2`, `59040f14`). The checks:

- **AC1, a stale arrival date reads To do.** The hub runs `invalidRowIds` (`flow/stored-answers.js`) on every visit. It runs the port-of-entry page's `validation.onStored`, and `dateTextInRange` measures the stored date against `arrivalWindow()`, worked out again on each request (`DAYS_BEFORE = 7`). A date more than 7 days back fails with `arrivalDateNoLongerInWindow`. `statusTag(status, invalid)` in `features/hub/controller.js` then turns a FULFILLED row back to To do. Reopening the page shows the same message, because the GET runs `onStored` too. **No test anywhere pins the stale date.** The only stored-answer tests use a stale port (`GB ZZZ`).
- **AC2 and AC3, Transit countries reads To do, then Complete.** `transitedCountries` is optional, so `statusOf` gives OPTIONAL with no countries and FULFILLED with one or more. The hub shows FULFILLED as Complete and everything else as To do. `transit-means-scope.spec.ts` already proves Road (To do, then Complete) and Rail (row present, then Complete via Road). Rail's To do status is not asserted.
- **AC4, the review row.** `cards/movement/transit-countries.js` gives the row "Countries that the consignment will travel through", lists the country labels joined by ", " in the order added (the prototype does the same, `routes.js:5231`), and gives it a Change link to `transit-countries?change=1`. The FIT test clicks the link. The E2E test (`hub-groups-and-cya-rows.spec.ts`) asserts only its href.

So this slice is the proof the application lacks, plus the spec text for the stale-date rule. No source file changes.

## 0. Decisions

1. **No production code changes.** Every criterion already holds (see above). Rejected: re-implementing any rule, which would duplicate `invalidRowIds` and the optional-status rule. What the slice owes is the missing proof (AC1 has none; AC2 lacks Rail; AC4's E2E stops at the href) and the spec text for AC1.
2. **A time bomb in the existing hub controller test gets fixed now.** `features/hub/controller.test.js` seeds `arrivalDateAtPort: { day: '12', month: '12', year: '2026' }`. Once that date is more than 7 days in the past (from 20 Dec 2026), the stored-date rule this increment pins makes the test's "Complete" case read To do and fail. The seeded dates become relative to `arrivalWindow()`. Rejected: leaving it for later. It breaks for exactly the reason this increment documents.
3. **How the E2E set-up makes a stored date the page would refuse.**
   - **How:** seed a draft through the frontend's own form routes (`animalsSeededJourney.createDraftNotification('draft')`, the existing pattern). Then overwrite only the `arrivalDateAtPort` fulfilment through the backend's `PUT /notifications/{ref}`. The concurrency token comes from `GET /notifications/{ref}/fulfilments`; the backend's `NotificationFulfilmentsView` already returns `concurrencyToken`. This is the row note's "set up in the past through the backend": set-up for a one-page assertion, not a seeded journey.
   - **Rejected:** a direct Mongo write (the CDP runs have no database access), and a FIT test (the frontend's server clock cannot be moved from Playwright, and the stub store has no way to seed it).
   - **What the PUT sends:** the fulfilments alone, which clears the record's notification-shape fields until the frontend's next save rebuilds them. The frontend reads its answers only from the fulfilments (`records/real/lifecycle/read.js` → `getFulfilment`), so the overview and the arrival page see exactly the stored answers.
4. **The stale date is 8 days before today** (`getRelativeAppDateParts({ dayOffset: -8 })`, anchored on the Europe/London civil day like `arrivalWindow`). Exactly 7 days back is still inside the window, so the unit test pins that boundary as Complete.
5. **The new E2E spec goes in its own file**, `tests/animals/e2e/features/stale-arrival-date.spec.ts`. Its subject is the arrival task's status, not transit scope or the review rows. Rejected: adding it to `soft-save.spec.ts`, which is about the "Save and return" exit.
6. **AC2's Rail case** becomes one line in the existing `transit-means-scope.spec.ts` test that already saves Rail. AC4's "opens the transit countries page" is appended to the end of the existing review test in `hub-groups-and-cya-rows.spec.ts`. Test titles stay the same, because coverage links name them verbatim.
7. **Not routed through `frontend-change`.** The slice adds no field, page, section or collection, and changes no obligation or flow. It changes tests only. Section 8 still applies.
8. **The spec gets one new Overview requirement** (REQ-OVERVIEW-013) for the stale-date rule, and one new arrival-details scenario (SCN-ARRIVAL-007-F) for the message the reopened page shows. That message is the cited source `repo-frontend-p11-021`, and the spec has no record of it yet. REQ-OVERVIEW-012 and SCN-CYA-001-J already state AC2 to AC4 word for word, so they only gain coverage.

- Add a method after `saveNotification`:
  ```ts
  /**
   * Overwrites one stored answer on a draft, keeping the others: set-up for a page that reads an
   * answer it would itself refuse. Sends the fulfilments alone, so the notification-shape fields stay
   * empty until the frontend's next save rebuilds them; the frontend reads its answers from the
   * fulfilments only.
   */
  async overwriteStoredAnswer(id: string, obligationId: string, value: unknown): Promise<Notification> {
    const { concurrencyToken, fulfilments } = await this.getNotificationFulfilments(id);
    if (!fulfilments.some((entry) => entry.obligationId === obligationId)) {
      throw new Error(`Notification ${id} has no stored answer for obligation ${obligationId} to overwrite.`);
    }
    const overwritten = fulfilments.map((entry) => (entry.obligationId === obligationId ? { obligationId, value } : entry));
    return this.saveNotification(id, concurrencyToken, { fulfilments: overwritten });
  }
  ```

```ts
import { test, expect } from '@fixtures';
import { ARRIVAL_DATE_AT_PORT_OBLIGATION_ID } from '@domain/animals/constants/obligation-ids';
import { getRelativeAppDateParts } from '@utils/date-utils';

const ARRIVAL_DETAILS_TASK = 'Arrival details';
const NO_LONGER_IN_WINDOW = 'The saved arrival date is no longer a date you can choose. Enter a new arrival date.';

test.describe('Arrival details when the saved arrival date goes stale', { tag: ['@integration'] }, () => {
  test('overview: when the saved arrival date is now more than 7 days in the past, Arrival details reads To do and the page names the date', async ({
    animalsPages,
    animalsSeededJourney,
    notificationApi,
  }) => {
    // Arrange
    const reference = await animalsSeededJourney.createDraftNotification('draft');
    await animalsPages.overview.open(reference);
    await expect(animalsPages.overview.taskStatus(ARRIVAL_DETAILS_TASK)).toHaveText('Complete');
    await notificationApi.overwriteStoredAnswer(reference, ARRIVAL_DATE_AT_PORT_OBLIGATION_ID, getRelativeAppDateParts({ dayOffset: -8 }));

    // Act
    await animalsPages.overview.open(reference);

    // Assert
    await expect(animalsPages.overview.taskStatus(ARRIVAL_DETAILS_TASK)).toHaveText('To do');
    await animalsPages.overview.task(ARRIVAL_DETAILS_TASK).click();
    await expect(animalsPages.arrivalDetails.heading).toBeVisible();
    await expect(animalsPages.arrivalDetails.errorSummary).toBeVisible();
    await expect(animalsPages.arrivalDetails.errorSummary.getByRole('link', { name: NO_LONGER_IN_WINDOW })).toBeVisible();
  });
});
```

- **Why the 'draft' depth:** it posts origin, commodity, reason, additional details, the parties and a full in-window arrival step. That makes Arrival details Complete before the overwrite, so the baseline assertion proves the overwrite alone causes the demotion.
- **Path aliases:** if `@domain` or `@utils` are not yet mapped in `tsconfig.json`, use the alias the other specs use for the same folder. `hub-groups-and-cya-rows.spec.ts` uses `@flows/...`, and `seeded-journey.ts` uses `@domain/...` and `@utils/...`, so both already exist.
- **Error summary locator:** `errorSummary` is an existing getter on `AnimalsArrivalDetailsPage`. If it does not scope to the summary container, use `pages.page.getByRole('link', { name: NO_LONGER_IN_WINDOW })`. The message appears as a summary link and as field text, and only the summary carries a link.
