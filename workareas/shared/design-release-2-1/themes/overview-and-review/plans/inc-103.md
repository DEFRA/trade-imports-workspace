It moves the stored date in Mongo, so it runs on the compose stack only.
  - Transit countries To do / Complete (criteria 2 and 3). With rail or road and no country, the row's engine status is Optional (`flow/task-rows.test.js:375-391`). The hub shows every status except Fulfilled, and every invalid row, as To do (`hub/controller.js:43-44`). The E2E spec `tests/animals/e2e/features/transit-means-scope.spec.ts:31` and `:41` proves both states through the stack.
  - Review row (criterion 4). `check-answers/view-model/cards/movement/arrival-details.js:18-49` reads the row keyed "Countries that the consignment will travel through" (`check-answers/copy/copy.en.js:53`, Welsh at `copy.cy.js:54`), lists each country, comma-separated, and gives it a Change link to the transit countries page. The FIT test `check-answers.fit.spec.js:600-634` follows that link to the page's H1. The E2E test `hub-groups-and-cya-rows.spec.ts:155-159` reads the row and its link through the stack.
- **The salvage commits are not replayed.** Frontend `2d5a96b5` and tests `5924420` added tests that now exist in another form, or that only add coverage:
  - The tests-repo half (an API overwrite helper, an obligation-id constant, `getRelativeAppDateParts`, a new stale-date spec, a Change-link click) duplicates `arrival-date-out-of-window.spec.ts`. That spec already covers the overview and the arrival details page, and it was merged since.

From 20 December 2026 that date is more than 7 days in the past, so the arrival details row reads To do and the test goes red, with no code change. That is a flaky assertion in this row's own behaviour, and the house rules say to fix it. The seed's date becomes a date inside the window measured from today, through `arrivalWindow()`. Rejected: freezing the clock. `docs/best-practices/node/testing/frontend.md:57` keeps real time unless "the assertion depends on time moving".
