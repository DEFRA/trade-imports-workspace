## 0. Decisions

1. **Unfinished-card entries.** Today one `species` entry in `REVIEW_CARDS` covers the task rows `commodities`, `consignmentDetails` and `animalIdentification`. It splits in two:
   - `whatAreYouImporting` — rows `['commodities']`, anchor `what-are-you-importing`, message "Complete what are you importing?". It marks the new card like every other card (decorateCard).
   - `commodityDetails` — rows `['consignmentDetails', 'animalIdentification']`, anchor `commodity-details` (carried by the first commodity card only), fallback anchor `description-of-the-goods`, message "Complete commodity details". It marks no card: the commodity cards carry no `id`, so `decorateCard` never reaches them (AC 9, prototype p11-049 "always built with hasError false").
   Rejected: folding `animalIdentification` into `whatAreYouImporting`. The identification table lives inside the commodity cards, so its unfinished entry belongs with them. Every task row still maps to exactly one entry (the `#REVIEW_CARDS` suite).
2. **Where "Complete commodity details" links when there is no commodity card.** `statusIn('consignmentDetails', {})` is `NOT_STARTED` (`flow/task-rows.test.js:222`), so a brand-new draft names both new entries and has no commodity card to link to. The link falls back to the "2. Description of the goods" heading (`#description-of-the-goods`), which always stands. Mechanism: `cardAnchorHref(key, pageAnchors)` returns the card's `anchor` when the rendered page carries it, otherwise its `fallbackAnchor` when it has one, otherwise its `anchor`. Rejected: dropping the commodity-details entry while nothing is chosen (would break "every row once"); a static anchor that dangles.
3. **Commodity grouping key.** Lines group by their trimmed `commoditySelection`, in first-seen order. A line with no commodity groups under the blank key, titled "Not applicable" (today's `speciesCardTitle` behaviour). Cat and Dog share code 01061900 but are different commodities, so they stay separate cards.
4. **"Other live mammals".** Our catalogue has no commodity named "other live mammals"; the prototype's test is the code (`isOtherLiveMammalsCommodityCode`: `code === '01061900'`, routes.js:712). The live tree already has the same predicate: `commodities.speciesListedIndividually(name)` (`services/commodities/index.js:59`). Use it. Each such line adds its own code and `commodities.speciesCommonName(name, speciesSelection)` as its common name (what `animal-identification/summary/selected-commodities.js` already uses). Every other commodity adds its code and name once.
5. **Title case.** Mirror the prototype's `toTitleCaseLabel`: split on whitespace, first letter upper, rest lower, join with one space. "Bos taurus" → "Bos Taurus", "Canis lupus familiaris" → "Canis Lupus Familiaris", "Bos spp." → "Bos Spp.". Applies on the review only (Species row and block headings); the identification table's "Animal N" cells are untouched.
6. **Species block heading for a line with no species** (e.g. a Fish line saved without one): the commodity name; with no commodity either, "Not applicable". Rejected: an empty heading (empty h4 fails axe).
7. **Packages label.** `copy.rows.numberOfPackages` becomes "Number of packages (when required)", the label the consignment-details page uses (`commodities/copy/copy.en.js:47`) and the prototype trace shows (p13-143). Blank reads "Not applicable": commodity cards are never blanked (decision 1), so `row()`'s `notApplicableCell` stands even on an unfinished notification.
8. **Card header Change link hidden text** = the card title, verbatim ("Change Cow (0102)"). The old `hidden.commodity(n)` ("commodity 1") goes. **Block row Change link** hidden text = new `hidden.numberOfAnimalsFor(species)` → "number of animals for Bos Taurus"; Welsh "nifer yr anifeiliaid ar gyfer Bos Taurus". Both links go to the consignment-details page (`consignmentDetailsPage.slug`, `?change=1`).
9. **What are you importing? Change link** goes to the commodity selection page (`commoditiesPage.slug` = `commodities`), hidden text "what are you importing".
10. **Heading levels.** Card title h3 (unchanged), species block heading h4 (`govuk-heading-s`), the identification table heading ("Animal details", unchanged wording) drops to h5 (`govuk-heading-s`) because it now sits inside a block. Renaming it "Identification details" belongs to the later identification-details row (gate note), not here.
11. **Plants.** The header invariant asks for plants to change with any behaviour plants also has. Plants' review already has its own "What are you importing?" card (`cards.commodityType`) and no species blocks; the row's repos are `frontend` and `tests` only. No plants change; recorded as a risk.
12. **Welsh drafts** (machine-draft, as the file header already says): cards.whatAreYouImporting "Beth ydych chi’n ei fewnforio?", hidden.cards.whatAreYouImporting "beth ydych chi’n ei fewnforio", errors.cards.whatAreYouImporting "Cwblhewch beth ydych chi’n ei fewnforio", errors.cards.commodityDetails "Cwblhewch fanylion y nwyddau", rows.numberOfPackages "Nifer y pecynnau (pan fo angen)", hidden.numberOfAnimalsFor `(species) => \`nifer yr anifeiliaid ar gyfer ${species}\``. Use the file's curly apostrophe (’).

Claims checked against the live tree: every AC holds as a requirement on today's code (none is already true; none contradicts another). AC 9's "linking to the first commodity card" holds only when a commodity card exists — decision 2 covers the case with none.

## 3. New files

**`CYA/view-model/cards/consignment/what-are-you-importing.js`** — imitate `cards/consignment/import-details.js`. Exports sync `whatAreYouImportingCard(journeyId, answers, readOnly)`:
```
{
  id: 'whatAreYouImporting',
  title: copy.cards.whatAreYouImporting,
  ...editableActions(readOnly, changeAction(journeyId, commoditiesPage.slug, copy.hidden.cards.whatAreYouImporting)),
  rows: [
    row(copy.rows.commodityCode, commodityCodes(lines)),
    row(copy.rows.commonName, commonNames(lines)),
    row(copy.rows.species, speciesNames(lines))
  ]
}
```
`lines` = `toArray(answers.commodityLines).filter((line) => line?.commoditySelection)`. Small named helpers in the file:
- `readBackOnce(lines, perIndividual, perCommodity)` — walks lines in order; a line whose commodity `speciesListedIndividually` adds `perIndividual(line)`; any other adds `perCommodity(line)` the first time its commodity is seen. Filters blanks, joins with `', '`; `''` when nothing.
- `commodityCodes` = `readBackOnce(lines, codeOf, codeOf)`, `codeOf = (line) => commodities.commodityCodeFor(line.commoditySelection)`.
- `commonNames` = `readBackOnce(lines, (line) => commodities.speciesCommonName(line.commoditySelection, line.speciesSelection), (line) => line.commoditySelection)`.
- `speciesNames` = every line's `speciesName(line)`, blanks dropped, joined `', '`.
An empty string goes through `row()` as blank, so it reads "Not applicable" on a finished card and is marked missing on the unfinished one.

**`CYA/view-model/cards/consignment/species/species-name.js`** — imitate `species-text.js`. Exports `titleCase(text)` (decision 5) and `speciesName(entry) = titleCase(speciesText(entry))`. Used by the What are you importing? card's Species row and by each block heading.
