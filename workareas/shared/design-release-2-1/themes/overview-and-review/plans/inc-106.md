## 0. Decisions

1. **What "more than one species selected and identifiers required" means here.** The review names short species when, and only when, the notification's own submit rule asks for identifiers per species. That rule is `unitRecord.requires.floorAppliesToParent = moreThanOne(allowListed(commodityCode, identifiedCommodities))` (`obligations/sections/commodities/identifiers.js`): more than one commodity line whose commodity is in `identifiedCommodities()`. The review restates that test as `lines.filter(identified).length > 1`, with `identified = (entry) => identifiedCommodities().includes(entry.commoditySelection)`. That is the same predicate `flow/task-rows.js` `identifiesAnAnimal` uses.
   Rejected: the prototype's own test (`hasMultipleSpeciesSelected && hasAnimalIdentifiersRequired`, so Cat + Fish counts as multiple). Our model does not refuse that notification, so the review would name a species that submit does not actually need. The message must name only what the submit gate refuses.
2. **Which species are named, and with which words.** This mirrors the prototype's `getSpeciesMinimumIdentifierReviewErrorMessage` (routes.js:4861-4877). Only lines whose commodity is identified are considered. A line holding at least one animal with a non-blank identifier (any id in `scopedFields(commodity)`, so permanent address does not count) is not named. Otherwise the message depends on the count:
   - `numberOfAnimalsQuantity` blank (`isBlank`): "Enter the number of animals for <species>".
   - otherwise: "Enter at least 1 animal identifier for <species>".
   `<species>` is the block heading lower-cased (`speciesBlockHeading(entry).toLowerCase()`, so "bos taurus" or "felis catus"). The prototype does the same (`toTitleCaseLabel(label).toLowerCase()`). A species that has an identifier but no count is not named, as in the prototype; "Complete commodity details" already covers its missing count.
3. **Where the entries sit, and that "Complete commodity details" stays.** In the prototype the error list runs `commodityDetailsCard`, then `...speciesSections`, then additional details (routes.js:5304-5313). The species entries go straight after the commodity details entry, in line order. "Complete commodity details" stays as it is: the `#REVIEW_CARDS` "every task row exactly once" contract keeps a refusal and a named card in step. A short species always makes `consignmentDetails` or `animalIdentification` not ready, so the two always appear together.
   Rejected: dropping "Complete commodity details" when only identifiers are short. That would break the one-row-one-entry invariant, and readiness and naming would drift apart.
4. **Where a species entry links.** Each species block gets an anchor `species-<n>`, where `n` is the line's 1-based position in `commodityLines` (the `index` that `state.collectionView` already gives `commodityCards`). The anchor sits on the block's h4 heading, as `id` plus `tabindex="-1"`, the same pattern the section h2s use. The prototype's `review-species-<n>` names no element (claim p11-059, conflict c-134). Ours always resolves, because blocks are built from the same `collectionView` the entries are.
5. **The block is not marked.** No in-block error message and no error class. inc-104 decision 1 leaves commodity cards unmarked, and the DR2.1 commodity cards are "always built with hasError false" outside the action-required variant. Only the error summary names the species. Rejected: a `govuk-error-message` inside the block, which the prototype does not draw.
6. **Animal label.** `copy.identifierTable.animalNamed(species, n)` → "Bos taurus 1", using `speciesText(entry)`: the catalogue label in sentence case, not title case (trace p12-158: "Bos Taurus ... Bos taurus 1"). With no species text it falls back to `copy.identifierTable.animalN(n)` ("Animal 1"). This mirrors the identification page's `animalLabelOf` (`commodities/animal-identification/card/view-model.js:48`).
7. **Columns: one per identifier field.** AC 2 and the prototype's `buildSavedAnimalsTable` (routes.js:2186: `context.identifierFields.map(...)`) head the table with every identifier field the commodity declares. Today's `identifierColumns` keeps only fields some unit has filled, which is wrong against the AC. Change it to every `scopedFields(commodity)` field, in the commodity's order, with an unfilled cell reading "Not applicable" (`valueText`, as today). The Permanent address column keeps its current rule (shown when any animal carries one), because the service collects it and dropping it would hide an answer. For fullSeed's Cow (ear tag and passport both declared and filled) nothing changes. The E2E Cow, with only an ear tag, gains a Passport column reading "Not applicable".
8. **The Identification details Change link.** It goes to the identification page (`animalIdentificationPage.slug` = `commodities/identification`) with `?change=1` through `changeAction`. Its text is `copy.change` and its hidden text is `copy.hidden.identificationDetailsFor(heading)`, which reads "identification details for Bos Taurus" (block heading, title case, matching `numberOfAnimalsFor`). It is offered only on an editable review (`editableActions`), and only where the table stands (identifiers saved). The prototype offers it only with a table (claim p11-089).
   Rendering: a `<p class="govuk-body">` holding a `govuk-link` directly after the h5, before the table, built the way the template's `cardActions` macro builds its anchor. Rejected: a link cell in the table head row, as the prototype draws it. That breaks table semantics and needs custom CSS.
9. **Welsh drafts** (machine drafts, as the file already is):
   - `identifierTable.heading`: "Manylion adnabod"
   - `identifierTable.animalNamed`: `(species, n) => \`${species} ${n}\``
   - `hidden.identificationDetailsFor`: `(species) => \`manylion adnabod ar gyfer ${species}\``
   - `errors.species.numberOfAnimals`: `(species) => \`Rhowch nifer yr anifeiliaid ar gyfer ${species}\``
   - `errors.species.atLeastOneIdentifier`: `(species) => \`Rhowch o leiaf 1 dynodwr anifail ar gyfer ${species}\``
10. **Plants.** The header invariant asks for plants to change with any behaviour plants also has. The plants review has no species blocks and no identification table, and the row's repos are `frontend` and `tests`. No plants change is needed, so it is not raised as a risk.
11. **Germinal.** req-879 is the live-animals half (ruling claim 57). The germinal wording ("number of packages", req-1841) belongs to the germinal set's review row. No other set imports this feature (checked with `grep`).

Claims checked against the live tree:

- AC 4–5 hold. No per-species entry exists today; "Complete commodity details" is the only one.
- AC 5's source list cites ruling claim 57 (the set split). That is consistent.
- No AC contradicts another.
