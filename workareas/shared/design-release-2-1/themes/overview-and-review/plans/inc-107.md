## 0. Decisions

1. **One card per document, every card keeps the review-card id `documents`.** `REVIEW_CARDS` in
   `CA/view-model/incomplete-cards.js` is unchanged (one `documents` entry, anchor `documents`, task row
   `documents`), so the `#REVIEW_CARDS` "every task row exactly once" suite still holds.
   Rejected: giving each card its own id (`documents-1`…) — REVIEW_CARDS would then need entries per
   document and the task-row coverage pin breaks.
2. **When several cards share an id, only the first carries the anchor and the message; every one of them
   is blanked.** `withCardErrors` decorates the first card of each id with `anchor` and `error`; later
   cards with the same id get `error: null`, no `anchor`, but still have their empty rows turned into the
   missing marker when that id has an error. So the error summary's "Complete documents" / virus-scan
   entry links to `#documents` on "Document 1" (one element with that id, valid HTML), the message reads
   once, and a part-filled "Document 2" still shows its owed rows as missing rather than "Not applicable".
   This mirrors the commodity cards (first card carries the anchor). Rejected: repeating the message on
   every document card (noisy, and the summary can only link to one); rejected: blanking only the first
   card (a part-filled later document would read "Not applicable" on a card that is owed something).
3. **The empty state is one "Document 1" card with one row, "Document reference" = "Not applicable"**,
   exactly as the prototype draws it (routes.js 5514-5527). Built with `row(copy.rows.documentReference,
   null)`, so the cell is `notApplicableCell()` (marked `empty: true`) like every other blank. Rejected:
   four "Not applicable" rows — the prototype draws one.
4. **"Attachment" reads `entry.filename`.** A legacy entry stored before file names were kept has no
   `filename`; `row()` writes it as "Not applicable" on a settled card. Rejected: falling back to the
   attachment type — the design names the file, and a type in a "file name" row would mislead.
5. **Each card's Change link names its card for a screen reader: "Change document 1", "Change document 2".**
   New copy leaf `hidden.documentN: (n) => \`document ${n}\`` (Welsh `dogfen ${n}`), the way commodity cards
   pass their own title. Every card links to `accompanying-documents?change=1` (no per-document address —
   the documents page has none, and the row says "at the address it has today").
6. **Copy clean-up in the same change**: remove `cards.documents`, `hidden.cards.documents` and
   `documentsEmpty` (en + cy) — nothing reads them after this; rename `rows.attachmentType` →
   `rows.attachment` = "Attachment" / Welsh "Atodiad" (the Welsh the documents page already uses for its
   file label). `errors.cards.documents` stays ("Complete documents").
7. **The template loses its nested-documents and `emptyText` branches.** Document cards now carry plain
   `rows`, so they render through the same `govukSummaryList({ card: … })` branch as every other card (or
   the custom error branch, which already renders `card.rows`). Rejected: keeping dead branches.
8. **Not routed through `frontend-change`.** This changes what the review reads back, not a field, page,
   section, collection, obligation or journey flow, so no recipe applies. Section 8 still applies.
9. **Integration proof goes in `tests/animals/e2e/features/promoted-documents.spec.ts`** — the spec that
   already uploads through the real uploader (`@compose @integration`, which `test:docker-compose` runs).
   Uploading needs the real cdp-uploader, so a new file would only duplicate its set-up. Two documents are
   uploaded so the test proves "each document has its own card", not just one.
10. **The germinal-products set's review is not touched** — sibling set, own spec namespace, not named by
    this row.
11. Two E2E specs that assert "You have not added any documents yet." (`promoted-documents.spec.ts` lines
    34 and 45, `documents-reject.spec.ts` line 21) assert it on the **documents page**, whose own copy
    (`documents/copy/copy.en.js` `empty`) keeps that sentence. They stay as they are.
