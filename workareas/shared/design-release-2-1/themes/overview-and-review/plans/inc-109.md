## 0. Decisions

1. **Live-animals party read-back is already one part per line with GB as "United Kingdom".** Checked against the tree: `party-row.js:20-34` already draws the name, then each non-empty address part, then the country, joined by line breaks, and `frozen-parties.js:32` already resolves the country code to its name through `addressBookCountryName`. So the live-animals change is to drop the telephone and email lines (`party-row.js:40`) and to read the address parts from their one owner. The "name, lines, country, each on its own line" and "GB reads United Kingdom" criteria become tests of behaviour that already holds, pinned so the change cannot break them. Rejected: re-implementing the country lookup in the review.
2. **County stays in the read-back.** The criterion lists "address line, town or city and postcode"; the stored copy also has a county, which the review shows today and the address book holds. Kept, in its stored place between town or city and postcode, as one more address line. Rejected: dropping county, which no source asks for and which would lose a stored fact.
3. **Each part on its own line, not the prototype's "last line, country".** The prototype (`GB-notification-service@04a073b`, `app/routes.js:2397-2420`, `formatConsignmentAddressForDisplay`) appends the country to the last address line after a comma. The row's acceptance criteria, from the 9 October afternoon ruling, say the country is on its own line in both live animals and plants. The ruling-derived criteria win; this is recorded in risks as a possible `design` finding, not built as the prototype.
4. **Name stays bold in live animals.** Today the name is the first line, in bold (`party-row.js:25`). The criteria say "its name, then…" and say nothing about weight. Unchanged. Rejected: restyling, which no criterion asks for.
5. **One owner of the address-parts list per repo, and both twins draw the same line: the parts list excludes the country.** The row note says design snagging left `ADDRESS_PARTS` in the animals `address-lines.js`. The live tree differs: the animals file now holds `STREET_PARTS` and `LOCALITY_PARTS` (`addresses/party-picker/view-model/address-lines.js:1-2`). Animals: `address-lines.js` gains the "every non-empty part, one per entry, no country" export, and `party-row.js:10-18`'s own copy is deleted. Plants: `address-book-picker/address-lines.js` gains the same export over `ADDRESS_PARTS` (also no country), and its existing `addressText` (`:12-15`) and `detailLines` (`:19-28`) build on that export instead of each mapping `ADDRESS_PARTS` themselves. In both repos the country is added by the caller that needs it: the review's party row builder (animals `party-row.js`, plants `partyCard`) and plants `detailLines`. Rejected: a plants owner that includes the country while the animals one excludes it (the twins would draw the line differently), and leaving `detailLines` repeating the parts list.
6. **The transporter address row follows the owner.** `transport-details.js:5,24` imports `addressLines` from `party-row.js`. With that export gone, it imports the new owner from `address-lines.js` instead; what it shows does not change (each part on its own line, no country; country has its own row there).
7. **Permanent-address rows and party rows become one row builder.** With telephone and email gone, `partyLines` and `addressWithoutContactLines` (`party-row.js:36-40`) build the same lines, so `permanentAddressRow` (`party-row.js:60-63`) is `partyRow` with no error. Collapse to one row builder; `addresses.js:14-23` calls it for permanent addresses. Rejected: keeping two functions with identical output.
8. **Plants keeps its Name and Address rows; the Address row becomes multi-line.** The plants criteria remove the "Telephone number" and "Email address" rows and ask for the address one line per line then the country. The "Name" row stays (no criterion removes it). Rejected: merging Name into one address cell like live animals, which the ruling for plants does not ask for and the plants spec scenarios key by row.
9. **Plants errors for telephone or email move to the Name row.** Today a copy whose email or telephone breaks the address-book rules shows the message on its own row (`check-answers/view-model/index.js:137-146`, test `controller.test.js:732-764`). With those rows gone, a phone or email message lands on the Name row, the first row of the card, so the trader still sees what to fix; address-field messages stay on the Address row. Rejected: dropping the message, and putting it on the Address row (email is not an address part). The design source does not show this case: recorded in risks as a question for the designer.
10. **Plants keeps "Edit details" on its review party cards.** The row note asks to decide. Live animals has one Addresses card whose heading Change opens the Roles and addresses page. Plants has no such page: its review party cards are where the trader edits a copy the review flags as broken, and `REQ-PLANTS-CYA-012` states that action. Kept; raised as a follow-up for the designer.
11. **Each uploaded document gets its own card, titled "Document n".** The prototype builds one card per document (`app/routes.js:5505-5538`, `buildDesignRelease2DocumentCards`), each with the header Change action to the upload documents page and rows Document reference, Document type, Date of issue, Attachment (`app/routes.js:5149-5169`). With none uploaded it shows one "Document 1" card with a single "Document reference" row reading "Not applicable" (`app/routes.js:5514-5527`). Built as that. The "Uploaded documents" card title and the "You have not added any documents yet." sentence go; the section heading "4. Uploaded documents" stays.
12. **All four document-card row keys come from the check-answers copy bundles; Attachment reads the uploaded file's name.** The recipe (`add-a-section.md:280`, `add-a-field.md:161`) puts review row labels in both check-answers copy bundles, where Document reference, Document type and Date of issue already live (`copy.en.js:69-71`). The Attachment key joins them there: the check-answers `rows.attachmentType` key ("Attachment type" / "Math o atodiad") is renamed for the attachment and reads "Attachment" / "Atodiad" (the Welsh the documents page already uses, `documents/copy/copy.cy.js:57`). The rename covers the concept's vocabulary in the check-answers tests. The value is the stored entry's `filename` (`documents/handlers/claim-upload.js:28`; canned in `flow/fixtures/happy-path.json:36`). The documents feature's type labels stay read from its own copy (`cards/documents.js:30`), as the recipe says for value labels. Rejected: keying Attachment from the documents feature's `file.label` while the other three rows key from check-answers copy (two copy owners for one card's keys).
13. **Several document cards share one review card id; the first carries the HTML anchor, every one carries the error and hides its blanks.** The incomplete-card mechanism is keyed by card id (`incomplete-cards.js:48` `REVIEW_CARDS` entry `documents`; `decorateCard` at `:125-136` gives anchor and error and runs `blankEmptyValues` (`:112-123`) only on a card bearing a known id). Every document card carries the `documents` review card id, so while the documents task row is unfinished, or a scan error is set, every document card gets the error (red left border and its line) and every blank cell in it reads as the hidden "Missing", never "Not applicable". Only the first card bearing a given review card id in the page gets the HTML anchor, so the page keeps one HTML id per anchor and the error summary link lands on "Document 1". Owner: `withCardErrors` in `incomplete-cards.js:139-143`, through `decorateCard`; it is the one place that sees the page's cards in order. Why every card shows the error: the documents task row is one unit of "unfinished", the review cannot tell which document owes answers, and `page-design.md:115-120` makes the border and line the only visible marking of a card with hidden blanks. Rejected: id on the first card only (an unfinished Document 2 would read "Not applicable" with no marking while finished Document 1 is marked); a new per-document anchor (nothing links to it); a per-document unfinished rule (a second rule beside the task row's). The repeated line across document cards is recorded in risks as a question for the designer.
14. **Each document card's Change link names its card for screen readers.** The visually hidden suffix becomes the card title in lower case ("document 1"), as the set's page design says for every card (`page-design.md:140-141`). Rejected: one shared suffix, which gives duplicate link names.
15. **The template's empty-text branch goes.** `card.emptyText` has no producer once the documents card stops setting it (`template.njk:64,99-101`). Delete the branch and the condition term. Document cards then render through the plain summary-card path unless decorated with an error, like every other row card.
16. **Plants `errorRow` tells a multi-line value by the value's own shape.** A value that is a list of lines renders each line escaped, joined by line breaks, under any messages; a single value (string, number, blank) renders exactly as today, through `readOnlyRow` with no messages and through the escaped text with messages. No option or flag is passed. `partyCard` passes the Address lines as a list, and passes nothing (so "Not provided" as today) when there is no party. Its other caller, the Name row, passes a string and renders unchanged. Rejected: a positional boolean, a named option (the shape already says it), and a second row helper beside `errorRow`.
