## 0. Decisions

1. **What the live-animals change is.** `partyLines` in `check-answers/view-model/rows/party-row.js` already reads the name, then `addressLines` (line 1, 2, 3, town or city, county, postcode), then the country, one per line, joined with `<br>`. `toDisplayParty` (`addresses/frozen-parties.js`) already resolves `countryCode` GB to "United Kingdom" through `addressBookCountryName`. AC1, AC2 and AC4 already hold except for the telephone and email lines on the end. **The only behaviour change in animals is removing `telephoneNumber` and `emailAddress` from `partyLines`.** Both the Addresses card and the Contact address card build their rows with `partyRow`, so the one edit covers both. I checked the claims against the code and none is wrong. The AC1 "country of GB reads 'United Kingdom'" is already true, and is now pinned by tests.
2. **The name stays bold.** The row says "name, then address lines, then country, each on its own line". It does not say how the name is styled. The live tree, trace p8-004 and the unit tests all show `<strong>name</strong>`. The prototype's own custom class is not copied (programme invariant). Rejected: dropping the `<strong>`, which nothing asks for.
3. **The county stays in the read-back when it is present.** AC1 lists "address line, town or city and postcode". The county is a non-empty address field the address book holds. Trace p8-004 reads it back, and the prototype prints every address line. Dropping it would lose data that the trader is supposed to check. Rejected: removing the county.
4. **Telephone and email are hidden even on a copy refused for its contact details.** The current unit test "Should show the telephone and email of a copy refused only for its contact details" contradicts AC3 ("No party's telephone number or email address appears"). The ruling wins. The role's error message ("Correct the address details for the consignor") and its Edit details link still show, and the edit page shows the telephone and email fields. That test is rewritten (section 4). Rejected: making an exception for refused copies, which AC3 does not allow.
5. **The edit page keeps telephone and email.** Only the review read-back changes. The address-book record and the party-edit form still carry both (c-293: "The address-book record still carries both").
6. **Plants keeps its Name row and Address row, and drops the Telephone number and Email address rows.** The plants party card (`partyCard` in `view-model/index.js`) changes from 4 rows to 2:
   - "Name": the party name, as now.
   - "Address": each non-blank address part (line 1, line 2, town or city, county, postcode), then the country, each on its own line.

   It keeps its one card-level Change link (c-293 keeps it). The AC asks only that the telephone and email rows go and that the address reads line by line. Rejected: folding the name into the Address row as animals does. Plants keeps its own structure (invariant "plants mirrors … keeps its own questions").
7. **How plants renders the lines safely.** The Address value becomes `{ html: lines.map(escapeHtml).join('<br>') }`. Plants has no `escapeHtml`, so copy the animals one verbatim (`animals …/check-answers/view-model/rows/value-text.js` lines 33-40) into plants' `rows/value-text.js`. A party with no resolvable address, or no party at all, still reads `{ text: 'Not provided' }`. The "every row reads Not provided" tests then still hold, and now count 2 rows instead of 4. The new row helper `readOnlyLinesRow(key, lines)` goes in plants' `rows/summary-row.js`, beside `readOnlyRow`.
8. **Shared address-part order in plants.** Add an exported `addressLines(address)` in plants' `address-book-picker/address-lines.js` that returns the non-blank `ADDRESS_PARTS` values in order. Rewrite `addressText` as `addressLines(address).join(', ')` so the two cannot drift apart. `addressText` is then no longer imported by the check-answers view-model, but the picker still uses it.
9. **Plants copy keys.** `labels.telephoneNumber` and `labels.emailAddress` in plants' check-answers `copy.en.js` and `copy.cy.js` have no other reader once the rows go (checked with grep), so delete both in both locales. No new English string is added, so no Welsh draft is needed.
10. **E2E line-by-line proof.** Every review read-back assertion uses `toHaveJSProperty('innerText', '<line>\n<line>…')` on the row's value cell. This is a web-first assertion that retries, and it is the only one that proves both the order and the line breaks: `toHaveText` folds `\n` into spaces, and `textContent` drops `<br>`. The same form is used in both FIT suites.
11. **Contact address E2E (AC4).** Extend the existing full-journey review test `hub-groups-and-cya-rows.spec.ts`, whose contact is the seeded APHA record (it has a phone and an email). This is better than writing a new journey, because that test already reaches the review with every section done.
12. **No flake work in this increment.** The first attempt's red came from timeouts in specs this slice does not touch. The connect-bounded fetch commits now on both frontends are the fix for it. The implementor does not edit `cancel-amend-ui`, `contact-address`, `cph-number` or `arrival-details`, and does not raise timeouts. Rejected: lengthening `beforeEach` timeouts, which would hide the cause (memory: "Preserve assertion intent", "remove flake causes, never shrink tests").
13. **Plants party-card unit tests sit in their own `describe`.** The two new tests, plus the two existing "Not provided" tests that now cover the 2-row card, move into a new `describe('Check your answers party cards', …)` placed after the main `describe('Check your answers', …)`. They keep their test titles, so no coverage link changes for them. The first attempt did this and it passed lint. It keeps the main block's function length in check. Rejected: leaving them in the main block.
