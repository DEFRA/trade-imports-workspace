## 0. Decisions

1. **The backend already returns the submitted date. The note's claim is about a different endpoint.** The note says "the view data carries only the created date". That is true of `NotificationView`/`NotificationViewData`, the dashboard **list** projection (`GET /notifications?…`). The submitted view does not read that projection. It reads `GET /notifications/{ref}/fulfilments` (`NotificationFulfilmentsView`), which already has `getSubmittedAt()`. `NotificationControllerTest.findFulfilments_shouldReturn200WithProjection` already pins `$.submittedAt`. Both frontends' marshals already carry `submittedAt` on the journey (`real/marshal/document.js`: `submittedAt: status === SUBMITTED ? document.submittedAt : null`). The plants confirmation page already renders it.
   - Settled: the backend change is a test only. A `NotificationIT` round trip proves the stored submission instant comes back on the fulfilments read after a real submit. Nothing in that test path pins this through Mongo today: the existing IT checks only status and fulfilments.
   - Rejected: adding `submittedAt` to the list projection. No criterion reads it from there.
2. **How the page tells a submitted view from the journey review.** It uses the same route (`/notifications/{id}/notification-view`) and the stored status (`journey.status === SUBMITTED`, the existing `readOnly`). DRAFT and AMEND keep everything they have today: the "Review your notification" or "Review before re-submitting" H1 and title, the status strip, and Back to Overview. Dashboard draft rows still go to the hub, because `dashboard/view-model/row/actions.js` is untouched.
3. **The header markup is GOV.UK Frontend only. It sits in each set's own review template, and the shared layout does not change.** On the submitted view the controller passes `journeyStrip: null`, so the layout draws no strip. It also passes a `viewHeader` object. The template draws:
   ```njk
   <div class="govuk-!-margin-bottom-6">
     <h1 class="govuk-heading-l govuk-!-display-inline-block govuk-!-margin-right-2 govuk-!-margin-bottom-2">{{ viewHeader.reference }}</h1>
     {{ govukTag({ text: viewHeader.status.text, classes: viewHeader.status.classes }) }}
     {% if viewHeader.dateSubmitted %}<p class="govuk-body govuk-!-margin-bottom-0">{{ viewHeader.dateSubmitted }}</p>{% endif %}
   </div>
   ```
   The tag sits outside the `<h1>`, so the heading's accessible name is exactly the reference.
   - Rejected: the tag inside the `<h1>`. The heading would then read "GBN-AG-… Submitted".
   - Rejected: a custom `app-*` class. The invariant forbids it, and `govuk-!-display-inline-block` does the job.
4. **The tag reuses the strip's status mapping.** `viewHeader.status = journeyStrip(journey).status` gives the text from `sharedCopy.journeyStrip.submitted` ("Submitted") and the class `govuk-tag--green`. The dashboard rows already use this (`toRow`). A status that later rows add (Submitted action required, Completed) is then mapped in one place. Shared copy is not touched.
5. **The date reads `d MMMM yyyy` and is the UK day of the stored instant.**
   - Animals: add `formatMomentAsLongDay` to `lib/validate/calendar.js`. It is the long-month sibling of `formatMomentAsDay` and goes through `startOfDayInZone(date, SERVICE_TIME_ZONE)`, so `2026-07-21T23:30:00Z` reads "22 July 2026".
   - Plants: the controller copies plants' own `confirmation/controller.js` `dateText` (`toLocaleDateString('en-GB', { day: 'numeric', month: 'long', year: 'numeric', timeZone: 'Europe/London' })`). Feature folders stay independent, and plants has no `SERVICE_TIME_ZONE` module.
   - Month names stay English in Welsh. Every rendered date in both services does this today (dashboard, confirmation, declaration).
   - A SUBMITTED journey without `submittedAt` (legacy data) gets no date line rather than "Date submitted: Invalid Date".
6. **Wording.** Add to each review's own copy, never to shared copy: `viewHeader: { dateSubmitted: (date) => \`Date submitted: ${date}\` }`. The Welsh draft is `\`Dyddiad cyflwyno: ${date}\``. Both copy files are already marked MACHINE-DRAFT.
7. **Page title.** On the submitted view, `pageTitle` and the H1 are `journey.journeyId`. The layout gives "<reference> - Import notification service - GOV.UK". The draft and amendment reviews keep their titles. The plants view title starts with the reference in the same way.
8. **Back link.** On the submitted view it is `dashboardPath()`, the set root that `dashboard/controller.js` serves as the set's own notification list: `/<live-animals mount>` and `/<high-risk-plants mount>`. DRAFT and AMEND keep `hubPath(journeyId)`. No configured URL is involved.
9. **A notification that does not exist: the claim that it "stays caught in the review's controller" does not hold as the tree stands.** Each set's entry guard (`journeys/linear/flow/entry-guard.js`, run on `onPreHandler`) calls `engine/read.js get` for every guarded path, `notification-view` included. `currentJourney` throws `Boom.notFound()` there, so the request 404s before the controller runs.
   - Settled, in both frontends, three changes:
     - The guard admits a notification it cannot find (returns `null`). It is the page's business, not the guard's.
     - The review controller's GET catches the not-found and redirects to `dashboardPath()`.
     - Every other page still answers 404 from its own `state.get`, exactly as today.
   - The not-found test is a new engine helper, `isJourneyNotFound(error)`: `error?.isBoom === true && error.output?.statusCode === HTTP_STATUS_NOT_FOUND`. It lives in `engine/journey.js`, beside the throw, and is exported from `engine/index.js`.
   - Only GET is caught. The review's POST and every action route keep their behaviour.
   - Plants takes the same change under the plants-mirrors invariant, although the plants criteria do not list it.
   - Rejected: redirecting from inside the guard. That puts the review's behaviour in the guard, against ruling claim p2-063.
10. **A well-formed reference is what "does not exist" means.** The animals backend validates the path against `REFERENCE_NUMBER_PATTERN` and answers 400 to a malformed one, which the frontend surfaces as a 500. The tests use `GBN-AG-00-000000` (the backend tests' own `NONEXISTENT_REF`) and plants `GBN-HRP-00-000000`. A malformed reference is out of scope.
11. **Header actions stay where they are.** On the read-only view, the Copy as new and Delete button group stays exactly as it is, below the new header. Moving it is the header-actions row's work.
12. **Tests repo page objects.**
    - `AnimalsNotificationViewPage` and `PlantsNotificationViewPage` gain:
      - `viewHeading(reference)`: the level-1 heading named exactly the reference.
      - `dateSubmitted`: `getByText(/^Date submitted: /)`.
      - A `statusTag` override: `this.page.getByRole('main').locator('.govuk-tag')`. That is the strip's tag on a draft or amendment and the header's tag on the submitted view, so every existing `notificationView.statusTag` assertion works on both.
    - The animals `open()` waits for a level-1 heading matching `^(Review your notification|Review before re-submitting|<journeyId>)$`, so `toNotificationView` keeps working on submitted notifications.
    - The animals page object gains `visit(journeyId)`, which calls `super.open(journeyId)` without the heading wait, for the unknown-notification case. The plants base `open()` has no wait already.
