frontend-change routes this as a "change the frontend" (L4: the review page's header, template, copy and view model) plus one L2 engine addition (recognising a notification that does not exist) and one "change the journey flow" touch (the entry guard admits a notification it cannot find). No add-a-field, page, section or collection recipe applies. No obligation, page order or task row changes.

Design source read: `GB-notification-service` at `04a073b`, `app/views/design-release-2.1/review-notification.html` and `app/views/partials/design-release-2.1/review-page-header.html`. The header there is, in order: the reference as h1, the status tag beside it (outside the h1), the actions (Amend this notification, Copy as new, Delete), the date line. Under the header, after any error summary, the "Import reference numbers" section: warning text, then the Notification reference and Customs document code rows. The prototype's Copy buttons, its amend modal and its `app-dr2-*` blocks are not built (programme invariants, and the 13 November design ruling).

## 0. Decisions

1. **The backend changes nothing. The note's claim that "the view data carries only the created date" is about a different endpoint.**
   - True of the dashboard list projection (`NotificationView`, `NotificationViewData`). The review does not read that.
   - The review reads `GET /notifications/{ref}/fulfilments` (`NotificationFulfilmentsView.getSubmittedAt()`), which already returns the stored submission instant; `NotificationControllerTest` pins `$.submittedAt`.
   - Both frontends' real marshals already carry `submittedAt` onto the journey for a submitted notification (`services/persistence/records/real/marshal/document.js:11` in each), and the stub stores stamp it on submit.
   - Settled: no backend edit and no backend test. A new backend test could not fail without a change it covers. The gate's E2E rung proves the date end to end through the real backend.
   - Rejected: adding `submittedAt` to the list projection. No criterion reads it there.
2. **How the page tells a submitted view from the journey review.** Same route, `notification-view`, keyed on the stored status: a SUBMITTED journey (the controllers' existing `readOnly`) gets the header; DRAFT and AMEND keep everything they have today (their heading and title, the status strip, their end controls). Dashboard draft rows still go to the hub; nothing in the dashboard changes.
3. **The strip goes off through the mechanism each controller already uses.**
   - Animals `renderCya` builds `journeyStrip` itself: it passes none on a submitted view.
   - Plants `render` builds its chrome with `kit.base`: it passes the existing `showJourneyStrip` option, off on a submitted view.
   - The shared layout and shared kit do not change.
4. **The header's status tag reads the status mapping the strip and dashboard rows already use** (`journeyStrip(journey).status` in `shared/kit.js`, as `dashboard/view-model/row/index.js` does in both repos). "Submitted" and the green class come from there, so the action-required and completed rows map their statuses in one place.
5. **The tag sits beside the h1, outside it**, as the prototype draws it. The heading's accessible name is exactly the reference. GOV.UK Frontend only: `govukTag`, heading and spacing classes and `govuk-!-*` overrides; no `app-*` class is added.
6. **Page title.** On a submitted view the page title and the h1 are the notification reference, so the layout gives "<reference> - Import notification service - GOV.UK". The draft and amendment titles do not change (animals keeps its existing re-submitting title rule).
7. **The date line** reads "Date submitted: <d Month yyyy>", the Europe/London day of the stored instant.
   - Plants already owns this display rule in `features/review/notification-date.js` (`notificationDateText`, used by the confirmation and declaration pages). Plants' header reuses it.
   - Animals has no owner for it: `lib/validate/calendar.js` `formatMomentAsDay` gives the short month, and the declaration's local `dateText` has no time zone. Animals gains a module with the same contract at the mirrored path, `sets/live-animals/journeys/linear/features/review/notification-date.js`, and its test mirrors plants' `notification-date.test.js`. One rule, one owner per twin.
   - Rejected: a long-month sibling in animals' `calendar.js`. Plants' owner is not there, so the twins would disagree on where the rule lives.
   - Month names stay English in Welsh, as every rendered date in both services does today.
   - A submitted journey with no stored instant shows no date line rather than an invalid date.
8. **Header actions.**
   - **Amend this notification** (both sets, primary): no amend confirmation page exists yet (the manage-notifications row that builds it, inc-120, is todo), so the row note's "only leads to a confirmation" does not hold. Today Amend is the dashboard's crumb-checked POST to `notifications/{id}/amend` (`dashboard/controller.js` `amendPost` in each repo), which lands on the review being amended. The header's Amend is a form button posting there with the CSRF crumb, the dashboard card's own route. inc-120 later turns both into links to its confirmation.
   - **Copy as new** (animals only, secondary beside Amend): the existing read-only copy form (POST to `copy` with the crumb, concurrency token and the view as the copy's origin) moves into the header. Its wording stays the shared `notificationActions.copy` text.
   - **Delete** (animals: "Delete", shared `notificationActions.delete`; plants: its own "Delete notification"): a red warning link-button to the existing delete page, as everywhere today.
   - Amend and Copy as new sit in one form with one crumb, Amend taking its own form action. One button group holds all three, in the prototype's order.
   - Rejected: two forms using `app-form-inline`. That is a custom block the GOV.UK-only invariant forbids; this change removes the animals review template's last use of it. The SCSS rule stays, because the dashboard still uses it.
9. **"Copy as new is the primary button when Amend does not show" is not built.** Today only a SUBMITTED notification reaches the header, and Amend always shows there. The other states that will reach it (Submitted action required, Completed, a draft's header) arrive in inc-113, inc-116 and inc-187, which add that branch. Section 15.
10. **Plants' read-only Delete leaves the foot of the page** and stands in the header. The draft's Delete beside Continue is unchanged. Plants offers no Copy as new (parked by plants).
    - The delete-button rule (`deleteButtonFor`, plants `controller.js:99-103`) moves into the new plants header module, its one owner; the controller's draft foot (`buttonsAfterPrimaryFor`) imports it. Rejected: passing it into the header module as an argument, which leaves the rule's home in the controller and the header depending on a caller to supply it.
11. **Import reference numbers.**
    - A labelled section headed "Import reference numbers", a `govukWarningText` with the sentence the criteria quote, and a `govukSummaryList` of rows: "Notification reference" with the reference, and, in animals only, "Customs document code" reading "C640".
    - Each value is a summary-list value: server-rendered text the trader can select with JavaScript on or off. No Copy button and no script.
    - C640 is a fixed code, the same in Welsh, so it is not copy. It is a literal inside the one animals function that builds the import reference rows. Rejected: a copy leaf, which would need a copy-parity allowlist entry for a value that is not language.
    - Plants has no customs document code row (its own blocked row, req-2002).
12. **Header builder home.** In each repo a new `check-answers/view-model/` module owns the submitted view's header: reference, status tag, date line, actions and import reference rows. The controller calls it only for a submitted view. Exemplar: `view-model/incomplete-cards.js` and its test in each repo. Mirrored in both repos so the twins hold the rule in the same place.
13. **A notification that does not exist goes to the set's own list.**
    - As the tree stands, the claim that it "stays caught in the review's controller" cannot hold on its own: each set's entry guard (`journeys/linear/flow/entry-guard.js`, on `onPreHandler`) calls `engine/read.js` `get` for the review path, and `currentJourney` (`engine/journey.js:94-97`) throws a not-found Boom before the controller runs. So the request 404s today.
    - Settled, in both repos:
      - the engine gains one exported predicate, beside the throw in `engine/journey.js` and re-exported from `engine/index.js`, that recognises the not-found `currentJourney` raises;
      - the entry guard admits a request whose notification it cannot find, leaving the page to answer it;
      - the review's GET catches that not-found and redirects to the set's notification list (`dashboardPath()`), logging once;
      - every other page still answers 404 from its own read, as today. Only the review GET is caught; its POST and the action routes keep their behaviour.
    - A notification the backend refuses as another organisation's already reads as not found (`real/http/get-fulfilment.js`), so it lands on the list too.
    - Rejected: redirecting from inside the guard. That puts the review's behaviour in the guard, against the afternoon ruling's claim p2-063.
    - Plants takes the same change under the plants-mirrors invariant.
14. **Wording.** New strings go in each review's own copy, never shared copy, each with a Welsh machine draft beside it:
    - the date line, as a function of the formatted date: "Date submitted: …" / "Dyddiad cyflwyno: …";
    - "Amend this notification" / "Diwygio’r hysbysiad hwn";
    - "Import reference numbers" / "Cyfeirnodau mewnforio";
    - the warning sentence / "Rhaid i chi ddefnyddio’r cyfeirnod a’r cod cywir ar y datganiad tollau neu bydd oedi i’ch llwyth.";
    - the warning icon fallback "Warning" / "Rhybudd" (plants' copy already holds one under `late.icon`; the new section takes its own leaf, since it belongs to a different block);
    - "Notification reference" / "Cyfeirnod yr hysbysiad";
    - animals only, "Customs document code" / "Cod dogfen tollau".
15. **Back link: no change.** `backLinkFor` in both controllers already sends a submitted view's Back to the list (design snagging, on main). The salvage's Back link line is dropped.
16. **Tests repo page objects.** Each notification view page object gains the submitted header's locators: the reference heading, the header's status tag, the date line, the header actions, the Amend button and the import reference section with a row-value lookup. The base page's `statusTag` keeps meaning the strip's tag; one name, one element. Assertions on a submitted view that read the strip, or the review heading, move to the header locators. The animals view's `open()` wait accepts the submitted view's reference heading as well as the review headings, so `toNotificationView` keeps working on a submitted notification. A page-object method that opens the address without that wait serves the unknown-notification test.
17. **Germinal products.** The set does not exist in this tree. Nothing is built for it.
