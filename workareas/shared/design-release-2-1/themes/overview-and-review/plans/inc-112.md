## 0. Decisions

1. **"Amend this notification" submits a form for now. The note's claim that it "only leads to a confirmation" does not hold as the tree stands.**
   - No amend confirmation page exists in either frontend. Amend is today a POST to `notifications/{id}/amend` (`dashboard/controller.js` `amendPost` in both repos). It calls `amendJourney`, then redirects to Overview, or to the list when the amend is refused. The list card's Amend is a form button posting there with the CSRF crumb.
   - Settled: the header's "Amend this notification" is a primary `govukButton` that posts to that same route with the crumb. It lands where the card's Amend lands today (Overview, status Amend). This is the only working path, and it keeps the no-JS invariant (a state change is a form post).
   - inc-120 (manage-notifications) builds the confirmation page. It then turns this button and the card's Amend into links to that page (c-310). Leave that to inc-120.
   - Rejected: a link to `notifications/{id}/amend`. A GET there has no route, so it would 404.
2. **One form per header, with `formaction`. No `app-form-inline`.**
   - Animals header: `<form method="post" action="{{ viewHeader.actions.copyHref }}" novalidate>` holds the hidden `crumb`, `concurrencyToken` and `copyOrigin=notification-view` inputs, then one `govuk-button-group`:
     - Amend: `govukButton({ text: copy.viewHeader.amend, attributes: { formaction: viewHeader.actions.amendHref } })`;
     - Copy as new: `govukButton` with `sharedCopy.notificationActions.copy.text`. It submits to the form's own action (copy). Its class is `govuk-button--secondary` unless `copyIsPrimary`;
     - Delete: `govukButton({ text: sharedCopy.notificationActions.delete.text, href: viewHeader.actions.deleteHref, classes: "govuk-button--warning" })`. This is a link styled as a button, as Delete is everywhere today.
   - Plants header: the same shape, with `action="{{ viewHeader.actions.amendHref }}"`, the `crumb` input only, Amend (primary, no `formaction` needed) and `copy.delete` (warning link button).
   - The amend POST ignores the extra copy fields. `routeOptions` is `{ auth: 'session' }`, with no payload validation.
   - Rejected: two forms with `class="app-form-inline"`, as the current read-only group does. The plants journey-spec names `app-form-inline` as debt not to copy, and the GOV.UK-only invariant forbids new `app-*` blocks. The animals template loses its last use of the class here. The SCSS rule stays, because the dashboard still uses it.
3. **Copy as new is primary only when Amend is not offered.**
   - The view model decides it: `amendHref` is set only when `journey.status === SUBMITTED`, and `copyIsPrimary = amendHref === null`.
   - Today only a SUBMITTED notification reaches the view header (`readOnly`), so on the live page Copy as new is always the secondary button beside Amend.
   - The "otherwise primary" branch is for the Submission complete and action-required rows. It is built now and pinned by a unit test on the pure builder.
   - Rejected: hard-coding secondary. The rows that add statuses would then have to rework the template.
4. **Where things sit.** Inside the existing `{% if viewHeader %}` block, in this order:
   1. h1 with the tag;
   2. the date line;
   3. the action form;
   4. the "Import reference numbers" section.

   Then come, as today, plants' late banner and both sets' numbered sections. Animals' old read-only button group under the heading is removed. Plants' read-only `govukButton(copy.delete …)` at the foot of the page is removed: the template's `{% if readOnly %}…{% else %}…{% endif %}` becomes `{% if not readOnly %}…{% endif %}`.
5. **The import reference numbers markup.** It is GOV.UK components plus semantic HTML:
   ```njk
   <section class="govuk-!-margin-bottom-6" aria-labelledby="import-reference-numbers">
     <h2 class="govuk-heading-m" id="import-reference-numbers">{{ copy.importReferences.heading }}</h2>
     {{ govukWarningText({ text: copy.importReferences.warning, iconFallbackText: copy.importReferences.warningIcon }) }}
     {{ govukSummaryList({ rows: viewHeader.importReferences }) }}
   </section>
   ```
   - Each value is a summary-list `value.text`: plain text that can be selected with JavaScript on or off.
   - There is no Copy button and no script. The Copy buttons wait on design (req-1986, c-294).
   - The labelled `<section>` gives tests and screen readers a "region" named "Import reference numbers". The id is a plain id, not a class.
6. **C640 is data, not copy.** It is a fixed customs document code, the same in Welsh. It lives as `const CUSTOMS_DOCUMENT_CODE = 'C640'` in the animals view-header module, not in the copy files.
   - Rejected: a copy leaf. That would need a `copy-parity.test.js` IDENTICAL_ALLOWLIST entry for a value that is not language.
   - Plants has no customs document code row. That waits in its own blocked row (req-2002).
7. **Wording.**
   - "Copy as new" and "Delete" reuse `sharedCopy.notificationActions.*` unchanged (claims p2-067, p2-068).
   - Plants' Delete keeps its own `copy.delete` ("Delete notification").
   - New strings go into each review's own copy, never into shared copy:
     - `viewHeader.amend`: "Amend this notification" / "Diwygio’r hysbysiad hwn";
     - `importReferences.heading`: "Import reference numbers" / "Cyfeirnodau mewnforio";
     - `importReferences.warning`: "You must use the correct reference and code on the customs declaration or your consignment will be delayed." / "Rhaid i chi ddefnyddio’r cyfeirnod a’r cod cywir ar y datganiad tollau neu bydd oedi i’ch llwyth.";
     - `importReferences.warningIcon`: "Warning" / "Rhybudd";
     - `importReferences.notificationReference`: "Notification reference" / "Cyfeirnod yr hysbysiad";
     - animals only, `importReferences.customsDocumentCode`: "Customs document code" / "Cod dogfen tollau".
   - Plants keeps the warning's "reference and code" wording exactly as its criterion quotes it.
8. **The header builder becomes its own module in animals.** `submittedDateText` and `viewHeaderOf` move out of `check-answers/controller.js` into a new `check-answers/view-model/view-header.js`, which also builds `actions` and `importReferences`. The pure "Copy as new is primary" branch can then be unit-tested on a plain journey object. That matches the programme's `touches` entry `check-answers/view-model/header`, and imitates `view-model/invalid-parties.js` and its test.
   - Plants keeps `viewHeaderOf` in its controller, where inc-111 put it. It has no primary or secondary branch to pin.
9. **Plants' `deleteHref` context key is now a draft-only key.**
   - `endButtonHrefs` sets `deleteHref` only for DRAFT. It feeds the foot "Delete notification" beside Continue.
   - The submitted view's Delete comes from `viewHeader.actions.deleteHref`.
   - Animals keeps `deleteHref` for the draft and amendment foot form as it is. The read-only arm moves into `viewHeader.actions`, and the `copyAction` context key is removed.
10. **Draft's review shows none of it.** `viewHeader` is null on DRAFT and AMEND (inc-111), so neither the header actions nor the import reference section render there. c-246's draft header is a later row, which builds on this one.
