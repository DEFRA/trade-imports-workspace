## 0. Decisions

1. **Claims checked against the live tree. All of them hold.**
   - Both declaration templates render `govukCheckboxes` with no `fieldset`/legend and no `classes`, so the checkbox is standard size (animals `features/declaration/template.njk:40-50`, plants `:21-31`).
   - Both controllers spread `kit.base(copy.title, { journey, ... })`. That fills `journeyStrip` from `kit.journeyStrip(journey)`, which carries the status tag, the reference and Cancel amend while amending. The shared `layout.njk` (`{% if journeyStrip %}`, animals `:95-101`, plants `:96-101`) draws the strip above the heading for draft and amend alike.
   - The prototype source (`distil/extract/prototype-dr2-1-source.work/app/views/design-release-2.1/declaration.html:67-83`) uses `classes: "govuk-checkboxes--small"` and `fieldset.legend` `{ text: "Declaration confirmation", classes: "govuk-visually-hidden" }`. The plan copies that exactly.
2. **Where the strip is switched off: in each feature's own controller view model, as `journeyStrip: null` after the `...kit.base(...)` spread.** The template and the shared layout are not changed for this purpose. `kit.base`, `kit.journeyStrip` and `shared/layout.njk` are not touched. This is the same "set's own page, not the shared layout" placement the ruling asks for (claims p2-060 to p2-062). The exemplar is check-answers, whose controller already sets `journeyStrip: readOnly ? null : ...` (animals `check-answers/controller.js:154-156`, plants `check-answers/controller.js:127`).
   - *Rejected:* a top-level `{% set journeyStrip = null %}` in `template.njk`. It depends on Nunjucks letting a child template's top-level `set` leak into the parent layout's context. Neither repo has a precedent for it, and a unit test of the view context cannot see it.
   - *Rejected:* calling `kit.base` without `journey`. That would also drop `concurrencyToken`, `amending` and `hubHref`.
3. **Every render path goes strip-less.** The GET render, the 400 re-render and the 500 recoverable-error re-render all go through the one `render` helper, so the override sits there once.
4. **Legend wording lives in each feature's own copy as `declarationLegend`.** English is `'Declaration confirmation'`. The Welsh draft is `'Cadarnhad y datganiad'`, so `copy-parity` passes (cy ≠ en). Shared copy is not touched (programme invariant: shared wording is never reworded in place).
5. **The legend is a `govuk-visually-hidden` legend with no size modifier class,** exactly as the prototype has it. It is not `isPageHeading`, because the page already has its own `<h1>Declaration</h1>`.
6. **Amendment proof.** The unit tests cover the amendment state (`AMEND` → `journeyStrip` null) in both repos. The E2E proof covers both states in both sets:
   - animals: the draft in `declaration.spec.ts`, the amendment in `amend-resubmit.spec.ts`;
   - plants: one new test in `review.spec.ts` covering a first submission, then an amendment.
   FIT adds the draft state only. The FIT harness has no amend helper on either declaration spec, and adding one is out of proportion here.
7. **How the tests repo asserts "not shown on screen" and "small".** Playwright treats a `govuk-visually-hidden` element as visible (it has a 1×1 box), so the tests assert the legend's class (`/govuk-visually-hidden/`) and the checkbox container's class (`/govuk-checkboxes--small/`). They find the group by its accessible name (`getByRole('group', { name: 'Declaration confirmation' })`), which proves screen readers get the legend. Pixel or box-size checks are not used (house rule: no tolerance-based layout tests).

- **Add the requirement `REQ-DECLARATION-005`** — "The declaration is confirmed with a small checkbox in a group named for screen readers, and the page shows no status bar". The system MUST offer the confirmation as a small GOV.UK checkbox in a group whose legend "Declaration confirmation" is announced to screen-reader users but not shown on screen. It MUST NOT show a status bar above the heading — no "Draft" or "Amend" tag, no reference number and no "Cancel amend" — whether the notification is a draft being submitted for the first time or an amendment being re-submitted.
  - **`SCN-DECLARATION-005-A`** — "A draft's declaration offers a small confirmation in a hidden-legend group and no status bar".
    - GIVEN a draft notification ready to submit
    - WHEN the user opens the declaration
    - THEN the confirmation is a small checkbox in a group named "Declaration confirmation", whose name is not shown on screen
    - AND no status bar is shown above the heading
  - **`SCN-DECLARATION-005-B`** — "An amendment's declaration shows no status bar".
    - GIVEN a notification is being amended
    - WHEN the user continues from check your answers to the declaration
    - THEN no status bar, reference number or "Cancel amend" is shown above the heading
