## 0. Decisions

1. **What is left to build.** Live tree checked against each criterion:
   - Criterion 1 (animals guard): not met. `features/confirmation/controller.js:22-31` redirects a status that is not submitted to `hubPath` (the Overview). This row changes it to the declaration.
   - Criterion 2 (the ITAHC bullet): already met at HEAD. The row before this one in the theme (inc-113, commit `14b805e2`) made `outstanding.js:8-9` read the status recorded at submission, and that status is Submitted action required exactly when no uploaded document is an ITAHC (`services/persistence/records/stub/lifecycle/submitted-status.js:12-15`; backend `OutstandingItem.java:13-25`). This is the one test the submission record uses, as the row's note asks. No production change. The plan adds only the missing end-to-end proof that a submission with an ITAHC shows no outstanding section.
   - Criterion 3 (plants guard): not met. Plants `features/confirmation/controller.js:21-23` sends anything not Submitted to check answers (`kit.CYA_SLUG`). This row changes it to the declaration.
   - The 'view or change' copy and the new-tab HMRC links are already on the branch (`copy.en.js:25`, `template.njk:51-53`), as the row's notes say. Not changed.
2. **"ITAHC or health certificate" is one document.** The prototype at `04a073b` treats `itahc` and `health-certificate` as the same certificate (`app/routes.js:6650-6656`). `health-certificate` is the value the prototype's testing versions use for the ITAHC (`app/routes.js:292-294, 11303-11311`). In Design Release 2.1 the type is `itahc`, labelled 'Intra Trade Animal Health Certificate (ITAHC)'. The real service's `VETERINARY_HEALTH_CERTIFICATE` is a different document, and it does not settle the bullet. The existing unit and E2E tests already pin this ("only a veterinary health certificate" still lists the bullet). Rejected: counting `VETERINARY_HEALTH_CERTIFICATE`. That would make the confirmation disagree with the status the backend records and the dashboard and review show, and the salvaged `HEALTH_CERTIFICATE` type does not exist in either document-type list.
3. **Where an animals draft or amendment ends up.** The confirmation guard redirects to the declaration's address, as criterion 1 and the prototype (`app/routes.js:12716-12718`) say. The animals declaration's own GET is reached only by continuing from check your answers (spec REQ-DECLARATION-005; `declaration/controller.js:88-102`), so it sends the trader on to check your answers ('Review your notification'). The declaration's entry rule keeps its one owner. Rejected: redirecting the confirmation straight to the review. That would copy the declaration's rule into a second controller and depart from the criterion. Rejected: changing the declaration GET to render. That reverses a spec'd requirement this row does not own. Plants' declaration GET renders (`plants declaration/controller.js:69-75`), so a plants trader sees the Declaration page itself.
4. **Plants keeps its submitted-status check as is.** Plants has no Submitted action required status (no `isSubmittedStatus` in the plants engine). Its guard stays "status is not Submitted", and only the target changes.
5. **Plants' guard gets a log line.** It is a refusal branch the row alters, and today it logs nothing. It mirrors the animals confirmation's existing refusal log fields. Rejected: leaving it silent, which breaks the house logging rule on a line this row touches.
6. **The declaration's slug comes from its `page.js`.** Each controller takes the declaration's slug from its `page.js`, as the animals declaration takes the confirmation's slug from `confirmation/page.js` (`declaration/controller.js:15, 94`). Rejected: a literal `'declaration'` string.
7. **Where each new FIT and E2E case lives.** Each new case sits where its only set-up is its own draft or ITAHC submission (section 2). Rejected: the existing submitted describes in the animals FIT spec and the animals E2E spec, whose `beforeEach` already submits a notification without an ITAHC, and the plants `declaration of a draft` describe, whose `beforeEach` walks to the declaration.
8. **Animals unit test set-up held once.** The panel-and-reference test goes through the file's `submittedView`, which gives back the journey id with the view. Rejected: leaving its inline copy, which keeps one set-up in two places in a file this row edits.
9. **Provenance only:** criterion 1 is req-927/prototype p11-151; criterion 2 is req-928/req-929 and DR1 p8-059; criterion 3 is req-2008 under the afternoon ruling p3-055, which supersedes plants decision d-066. req-934 (dashboard link) and req-935 (create link) stay out, as the row says.
