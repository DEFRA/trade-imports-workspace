## 0. Decisions

1. **Where the guard sends an unsubmitted notification.** Both sets redirect to their own declaration page, built with `pagePath(journey.journeyId, declarationPage.slug)` and `declarationPage` imported from `../declaration/page.js`. Animals today goes to the hub; plants today goes to check your answers. Both change. Rejected: sending only a draft to the declaration and an amendment elsewhere — DR2.1 (p11-151) and the ruling redirect whenever the declaration is not confirmed, and an amendment's declaration is not confirmed until it is resubmitted. Plants' d-066 (hub) yields to the afternoon ruling (claim p3-055). No loop: neither declaration GET has its own redirect for a draft or amendment (only for submitted), and the review section's `gate` is not enforced on a GET (`flow/gates.js` is consulted by task rows and analysis only).
2. **Which statuses count as submitted.** Animals keeps `state.isSubmittedStatus` (Submitted and Submitted action required). Plants has no action-required status, so it keeps `journey.status !== state.SUBMITTED` as its test; only the redirect target changes.
3. **Which test decides the outstanding-documents bullet.** The bullet shows when the submission's recorded `journey.outstandingItems` includes `state.OUTSTANDING_HEALTH_CERTIFICATE` — the same test the submission record uses (the backend's `OutstandingItem.outstandingFor`, mirrored by the stub's `outstandingItemsOf`), as the row's notes ask (req-909). Rejected: re-deriving the test from the answers' document types in the confirmation feature. That would duplicate the rule and disagree with the backend, which also requires the ITAHC or health certificate to have passed its virus scan. Consequence, recorded in the spec: the bullet tracks "no ITAHC or health certificate on record", so a Veterinary health certificate alone still shows it.
4. **Bullet wording.** `upload the ITAHC and any other required documents` (DR2.1 p11-146, verbatim, lower-case start as a list item following "You still need to:"). Welsh draft: `uwchlwytho’r ITAHC ac unrhyw ddogfennau gofynnol eraill`.
5. **View-or-amend wording.** Body becomes `You can view or change this notification from your dashboard.` (p11-158). The heading "How to view or amend this notification" is unchanged — DR2.1 keeps it. Welsh draft: `Gallwch weld neu newid yr hysbysiad hwn o’ch dangosfwrdd.`
6. **New-tab links and their text.** "contact HMRC" and "Find out about call charges" get `target="_blank" rel="noreferrer noopener"`, as the repo's other new-tab links do (`features/documents/template.njk:50`, `features/transport/transporters/transporters.njk:27`). Their visible text stays exactly as DR2.1 gives it (it already matches; p11-164, p11-165). DR2.1 does not tell the user these links open a new tab (p11-166, marked inferred). This plan adds a `govuk-visually-hidden` suffix `(opens in a new tab)` inside each link. Screen-reader users then hear the warning that GOV.UK link guidance and this repo's other new-tab links give them, and the visible link text is still DR2.1's. Rejected: a visible suffix, as the documents and transport links use, because it would change the link text the criterion fixes. Also rejected: no warning at all, because it leaves screen-reader users with a context change they cannot anticipate. Flagged under risks. The suffix is a new copy key, `help.newTab`: English `(opens in a new tab)`, Welsh `(yn agor mewn tab newydd)`. The Welsh matches `commodities/copy/copy.cy.js` `lookupNewTab`.
7. **Unchanged.** 'Return to your dashboard' (req-934, already met) and 'Create a new notification' (req-935, kept as today's real POST form). The identifier bullet is another row's work.
8. **E2E document for "other documents uploaded".** A Commercial invoice (`COMMERCIAL_INVOICE`), which both the frontend's type list and the backend's `DocumentType` enum carry. It is unambiguously not a health certificate. The unit test keeps its near-miss `VETERINARY_HEALTH_CERTIFICATE`.
