## Claims checked against the tree

- "Today a draft's review, reached from the hub's 'Review and submit', has the journey heading and the status strip and no header." True in both sets:
  - animals `check-answers/controller.js` `renderCya`: `viewHeader: readOnly ? … : null`, `journeyStrip: readOnly ? null : journeyStrip(…)`;
  - plants `chromeOf`: the same gating.
- "Dashboard draft rows go to the hub" (AC9). Already true. Animals `dashboard/view-model/row/actions.js` gives a DRAFT row "Resume" → `hubPath(id)`. Nothing changes here. This increment adds the test that proves it.
- `journey.createdAt` exists on the journey object in both frontends: the real marshal maps `document.created`, the stub stamps it on create, and `resume-self-heal.test.js` lists it among the journey's keys. So "Date created" needs no backend change.
- Copying a draft is already supported. The `notification-actions` copy route is status-agnostic, and the dashboard offers Copy as new on draft rows. The draft header's Copy as new needs no new route.
- The prototype (p11-027) makes Copy as new the primary button when there is no Amend. inc-112 already builds that branch: `copyIsPrimary = amendHref === null`, unit-pinned with `status: DRAFT`. On a draft, Copy as new is the primary button.
- The prototype's draft variant ends with Continue alone (p11-115). Its red Delete beside Continue belongs to the header-less "journey" variant (p11-118). With Delete now in the header (p11-029), the draft's foot keeps Continue only.
- No claim was found that does not hold.

## 0. Decisions

1. **Which reviews get the header.** A review is "headed" when it is read-only (any submitted status) or its status is DRAFT. An amendment (AMEND) keeps its "Review your notification" / "Review before re-submitting" heading (animals), its "Check your answers" heading (plants), its status strip and its foot controls, as today.
   - Both controllers compute `const headed = readOnly || journey.status === DRAFT` once and gate the header, the strip and the title on it.
   - Rejected: heading the amendment as well. No criterion asks for it, and REQ-CYA-013/014 pin the amendment's heading and foot.
2. **The browser title follows the h1.** A draft's review is titled by its reference, as the submitted view is (GDS: the title echoes the h1). The shared layout still prefixes "Error: " while the error summary stands. So an unfinished draft's title is `Error: <reference> - Import notification service - GOV.UK`. This keeps the programme's error-title invariant.
   - Rejected: keeping "Review your notification" / "Check your answers" as the draft's title while its h1 is the reference. The title and heading would disagree.
3. **One Delete per page.** On a draft, Delete moves to the header, and the foot's Delete beside Continue is removed in both sets.
   - Animals: `deleteHref` in the context is set only while amending, and the template's foot Delete renders only `{% if deleteHref %}`.
   - Plants: the `deleteHref` key leaves `endButtonHrefs` entirely, and the template's `{% elif deleteHref %}` arm goes.
   - The amendment keeps Continue, Cancel amend and Delete at its foot (animals) and Continue with Cancel amend (plants), unchanged.
   - Rejected: two red Delete buttons on one page. The prototype's draft variant has only the header Delete.
4. **Copy as new on a draft is the primary header button.** This follows the prototype (p11-027) and inc-112's existing `copyIsPrimary` branch. Continue at the foot is the page's other primary button, as on the prototype. Plants offers no Copy as new (ruling p3-056).
5. **Back.**
   - Animals draft: Back goes to the live-animals notification list (`dashboardPath()`), per AC8 and c-143/c-246. The amendment's Back stays on Overview (`hubPath`).
   - Plants draft: Back stays on Overview. AC10 and ruling p3-056 list exactly what plants changes (header, Draft tag, Date created, header Delete, import reference numbers, no strip; Change links, errors and Continue stay) and leave Back out. AC8 is written for live animals only. Plants' foot also still offers "Save and return to overview" and "Cancel and return to overview", so REQ-PLANTS-CYA-010 holds unchanged.
   - Rejected for plants: moving Back to the list "to mirror". No plants criterion asks for it, and Back would then disagree with the two Overview controls beside it. Flagged as a risk for review.
6. **"Date created" reuses each set's own date formatting.**
   - Animals: `formatMomentAsLongDay(new Date(journey.createdAt))`, as `submittedDateText` does.
   - Plants: the same `toLocaleDateString('en-GB', { day: 'numeric', month: 'long', year: 'numeric', timeZone: 'Europe/London' })` that `submittedDateText` uses, lifted into a small `longDateText(iso)` helper that both date lines call.
   - The header carries `dateCreated` only on a DRAFT and `dateSubmitted` only off a DRAFT, so a draft never shows both. A missing `createdAt` gives no line (null). The prototype's "today's date" fallback (p11-024) is not built, because the real service always stamps `createdAt`.
7. **Plants' draft header has no form.** Plants' header form posts to `amendHref`, which is null on a draft, and an `action=""` form would post to the review itself (Continue). The template renders the form only `{% if viewHeader.actions.amendHref %}`. Otherwise it renders a bare `<div class="govuk-button-group govuk-!-margin-top-4">` holding only the Delete link-button. A local macro `headerDelete(text, href)` draws the Delete button once for both branches.
8. **Wording.** New strings go in each review's own copy, never shared copy:
   - `viewHeader.dateCreated: (date) => \`Date created: ${date}\`` / `(date) => \`Dyddiad creu: ${date}\`` in animals and plants.
   - The "Draft" tag text is the shared strip's existing `sharedCopy.journeyStrip.draft`, read and never edited.
9. **The import reference numbers on a draft are the same section as on the submitted view** (c-246, c-294): warning, "Notification reference", and for animals "Customs document code" C640, all as plain text with no Copy buttons. Plants' customs code stays blocked (inc-199).
10. **Tests-repo page objects.** Many specs wait on `notificationView.heading` while on a draft review.
    - Animals: `heading` becomes "the review's level-1 heading, whichever it is". A new `reviewTitleHeading` keeps the exact "Review your notification" for the assertions about that wording.
    - Plants: `heading` matches "Check your answers" or a plants reference.
    - Rejected: rewriting each of the roughly 25 page-load waits. They are waits, not wording assertions.
