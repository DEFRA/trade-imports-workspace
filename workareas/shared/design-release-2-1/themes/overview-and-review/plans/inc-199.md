## 0. Decisions

- **Where the code lives.** The plants view header's import references builder (`view-model/view-header.js:40-52`) gains a second row, mirroring the animals twin (`trade-imports-animals-frontend/.../check-answers/view-model/view-header.js:60-79`): key from the feature's copy, value the literal code held inside the builder function, as animals holds C640. Rejected: a shared constant or a set-level config key. Each code is used by one function in one repo, and the house rule keeps a literal used by one function inside that function.
- **The code value is C085.** From Sam's 16 November ruling (claim 1), which unblocked the row. The animals value stays C640 and its repo is not touched.
- **Copy.** The key label is a new `customsDocumentCode` entry in the plants check-answers feature copy (`copy/copy.en.js` and `copy/copy.cy.js`), the same key name and English wording as animals ("Customs document code"). The Welsh draft follows the animals Welsh draft ("Cod dogfen tollau"), as the programme invariant asks for a Welsh draft beside every new English string. Rejected: putting it in plants' shared copy. Only this feature uses it, and the programme says a set-specific string goes in the feature's own copy.
- **"Selectable text".** The row is a plain summary-list row with no action and no button, like the reference row and the animals row. The template (`template.njk:60-62`) already renders `importReferences.rows` through `govukSummaryList`, so it needs no change.
- **Spec requirement title.** REQ-PLANTS-CYA-017 is titled "shows its notification reference as text to copy". It now shows two values, so the title changes to name the import reference numbers, as the animals requirement does. Its ID stays.
- **Animals still reads C640 (second criterion).** No animals file changes. Its existing unit test (`view-header.test.js:103`) and the animals E2E (`notification-view-states.spec.ts:20`, `:265`) already prove C640. The gate's E2E rung scopes to `tests/plants/` for this row, so section 5 runs the animals unit test as the check for that criterion.
- **No signed-off hold.** The plants check-your-answers spec is at `**Maturity**: exploring` with no `**Signed off**` lines, so changing its scenarios is ordinary work.
- **Spec claim checked.** The row's detail says the plants section has no customs document code row. True on the live tree: `view-header.js:46-51` builds one row, and the spec (REQ-PLANTS-CYA-017) says "with no 'Customs document code' row".
