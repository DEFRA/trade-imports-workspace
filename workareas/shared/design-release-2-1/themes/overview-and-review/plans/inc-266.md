## 0. Decisions

1. **Submission is already right; only the confirmation page changes.** Checked against the live tree. The identifier floor (`obligations/sections/commodities/identifiers.js:94-97`, `floorAppliesToParent: moreThanOne(...)`) asks for a record only when more than one line carries an identified code, and then one record per line, never one per animal (`sets/live-animals/docs/services.md:44-47`). So a single-species consignment with none saved, and a multi-line one with one record per line but fewer than declared, both submit today. Nothing in submit, review refusal (`check-answers/refusal.js:106`) or the obligation model changes. Rejected: touching the obligation floor, which would change what submits.
2. **"Species asks for identifiers" is read from the commodity service, not restated.** A line asks when its commodity code is in `identifiedCommodityCodes()` (`services/commodities/index.js:40`, derived from `COMMODITY_IDENTIFIERS` in `rules.js:11-30`). `services.md` names `IDENTIFIED_CODES` as "whether a code is asked to identify at all". A line under a code outside that list (poultry `01051111`: identification details and description only) never raises the item. Rejected: a commodity list of our own, or `identifiersFor(code).length`, a second spelling of the same rule.
3. **"Identified" means one identifier filled.** A record counts once any one of the identifier fields that apply to its line is non-blank. Per the 9 October ruling (section f, claims 36-37), the every-identifier bar is closed. The DR1 hold and the open parity question are overruled and not re-raised.
   - **Existing statements of identification, and why neither is reused as is.**
     - The obligation model already states "one applicable identifier filled" per record: `unitRecord.requires.anyOfIds` (`obligations/sections/commodities/identifiers.js:84-97`), evaluated per record by `checkAnyOfIds` (`model/obligations/state-queries.js:108-136`). It is a refusal rule: it yields an error only for a record that exists. It cannot count identified records against a declared number, and it is not exposed per record outside the evaluator.
     - The engine exposes per-record completeness as `collectionView(...).complete`, through `bridge/collection-complete.js:37` `entryComplete`. That flag is "no unsatisfied mandatory concern beneath the record". It also fails a record that lacks its mandatory permanent address (`identifiers.js:184-190`, `status: 'mandatory'`), so a horse or cat with a microchip but no permanent address would count as unidentified. `complete` does not mean "identified", so the owner cannot read it.
   - **What the owner reads instead.** The fields that apply to a line come from the identification feature's existing `scopedFields(commodityCode, speciesLatinName)` (`commodities/animal-identification/identifier/fields.js:13-21`), and blank is `isBlank` (`lib/answered.js`), as `check-answers/.../identifier-columns.js:4-11` already reads them.
   - **Kept in step with anyOfIds.** `scopedFields` filters its candidates (`identifiersFor(code)` plus identification details and description) through `appliesForGateValue` (`bridge/applicability.js:16`), which reads each leaf's own `applyTo` gate from the manifest. Those candidates are exactly the `anyOfIds` leaves (microchip, passport, tattoo, ear tag, horse name, identification details, description), and the permanent address leaves are in neither. So the owner and the obligation model judge "identified" from the same leaves and the same gates; a new identifier leaf reaches both through `COMMODITY_IDENTIFIERS` and the manifest. The owner must not keep its own list of identifier field names.
   - Rejected: reading `complete` (folds in the permanent address); adding a per-record "identified" query to the evaluator beside `checkAnyOfIds` (a second evaluation path for one confirmation-page count, wider than this row).
4. **"Fewer than declared" compares identified records with the line's declared number of animals** (`numberOfAnimalsQuantity`, stored as a string; `commodities/lines.js:9` `hasAnimalCount`). A line with no declared count declares no animals and owes nothing. Submit requires a count, so after submit this case cannot occur. No branch or log is added for it.
5. **The rule gets one owner in the identification feature, and confirmation reads it.** It is an identification rule (what identified means, what a line owes). It sits beside the record and field code in `features/commodities/animal-identification/`, not in `confirmation/outstanding.js`, so the withdrawn action-required view can later read it without a second copy. `outstanding.js` stays the one owner of which items the confirmation page lists and in what order. Rejected: writing the rule inline in `outstanding.js`, which would mix an identification rule into the page's list.
6. **Order of the bullets follows the prototype:** certificate item first, identifier item second. Design source: `~/git/defra/defra-design/GB-notification-service` at `04a073b`, `app/routes.js:6400-6418` (`getConditionalSubmissionItems`), with the wording `'complete the animal identifier information in the notification'` at `:6414`. The heading and intro stay as they are (`notification-submitted.html:32`, "You still need to:").
7. **The prototype's extra condition (`hasMinimumAnimalIdentifiersForSubmit`, `routes.js:6412`) is not copied.** In the real service a notification below the minimum cannot submit at all, so on the confirmation page that condition is always true.
8. **The action-required half is out.** The 16 November ruling (claim 2) withdrew the header warnings and the inline "Enter a minimum of 1 identifier" error. inc-273 has removed the Submitted action required status (frontend `2d176be1`). Nothing here reads or adds a status.
9. **Plants twin: not applicable.** The plants journey has no animal identifiers. The programme invariant on mirroring plants does not apply because plants has no such behaviour. The animals frontend has no germinal-products set on this branch.
10. **E2E for the partly identified case needs the seeded journey to save an identified record on a line that declares more than one animal.** Today the seeded identification step posts the shared form with no action, and the identification page reads that form only for lines of one animal (`animal-identification/form/forms.js:59-67`), so such a line's identifier is silently dropped. The page's own add-another action (`action: add:<lineIndex>`, `forms.js:18-19`, `animal-identification.controller.js:148-188`) appends the record and redirects back, which the seed client already follows. Rejected: walking the whole notification through the UI only to reach this state.
