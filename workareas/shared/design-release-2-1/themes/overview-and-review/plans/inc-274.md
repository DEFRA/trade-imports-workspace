## 0. Decisions

1. **The transit row takes the existing "Port of exit" copy.** The check-answers copy's exit-border-control-post row key is deleted in both locales, and the transit path reads the same port-of-exit row label the temporary admission path already reads. The port rows helper in the main import reason card then no longer needs a label argument, since both callers pass the same label: the helper reads the label itself. Rejected: keeping two keys with one value (two names for one concept).
2. **Arrival date row** keeps its copy key (`arrivalDate` still predicts the value) and takes the transport page's wording in both locales. Rejected: sourcing the label from the transport feature's copy (a cross-feature import the check-answers copy does not use for any other row; the review owns its own row labels).
3. **The ruling's "section heading Addresses" covers the page caption too.** AC3 names the overview group, the review section and the addresses page heading; AC5 names the plants caption. The ruling text says the addresses page reads "section heading Addresses", and the addresses page's section heading is its caption. Plants mirrors live animals (programme invariant), so a plants caption of "Addresses" beside a live animals caption of "Consignment parties" would break the mirror. So the live animals caption changes too, with the party-picker caption that mirrors it. Rejected: leaving the live animals caption as "Consignment parties" (two names for one section across twins).
4. **The plants half of AC5 that names "its addresses heading, card title and unfinished message" does not hold.** Plants has no consignment addresses page, no addresses card on its review and no unfinished-addresses message: its parties section holds Consignor, Identification numbers and Contact cards, each with its own unfinished message (`check-answers/copy/copy.en.js:33-41`, plants). So plants changes only its overview group, its review section heading and its caption. Nothing else is invented.
5. **Internal section ids stay.** The flow section id `consignment-parties` (both twins' `flow/flow.js`, the hub group copy keys, the hub group's HTML id) and the caption section id `consignmentParties` (both twins' `flow/section-captions/index.js` and its copy key) are structural ids, never shown to a user. Renaming them touches flow, dispatch, gates and navigation tests across both twins, several of them linked to signed-off journey-flow and caption scenarios, for no visible behaviour. Recorded as a follow-up and as a departure (section 14). Rejected: renaming them in this row.
6. **The review section copy key is renamed.** Live animals `sections.consignmentAddresses` and plants `sections.parties` both now hold the Addresses heading; each is renamed to the addresses vocabulary, the same key in both twins. Rejected: keeping keys whose names no longer predict their value.
7. **The live animals review section builder keeps its name, file and anchor** (`view-model/sections/consignment-addresses.js`, anchor `consignment-addresses`). The section still holds the consignment addresses card, so the name predicts its content, and the anchor `addresses` is taken by the card itself (the error summary links to `#addresses`). Rejected: renaming the anchor to `addresses` (duplicate id on the page).
8. **The card's visually hidden Change text follows the card title** ("Change consignment addresses"), so the link and the card agree. Rejected: keeping "Change addresses" under a card titled "Consignment addresses".
9. **The contact address card's unfinished message is not touched** (the ruling does not cover it; the row's notes say so).
10. **Signed-off scenarios and their linked tests stay.** Three upload-documents scenarios (signed off 11 November) say "Roles and addresses is shown" and are linked to tests whose titles say the same (`tests/animals/e2e/features/documents-save-buttons.spec.ts`, the documents controller unit test, `upload.fit.spec.js`). Those tests assert the addresses page heading, which does not change, so they stay green. Rewording them is a change to a signed-off page and goes in a follow-up. Rejected: rewording them here (the change itself is cosmetic, and it would make the theme's signed-off check hold the theme).
11. **Test-title clean-up stays inside the footprint.** A test file the change already edits has every title naming "roles and addresses", "consignment parties", "exit border control post" or the "Addresses card" brought into the new vocabulary. A file whose only stale content is a title (`dispatch.test.js`, the documents tests, `addresses-picker.spec.ts`, `documents-save-buttons.spec.ts`) is left for the follow-up.
12. **The tests repo gets one home for the addresses wording.** The overview task title "Roles and addresses" is typed in about ten places in `flows/animals/journey.ts` and specs, and the review card title "Addresses" in about fifteen. AGENTS.md: "Import a value that has a home rather than retyping it." A new constants file holds the addresses task title, the review card title, its Change link name, the review section heading and the unfinished message. The animals notification view page object gains an addresses card getter beside `whatAreYouImportingCard`. Rejected: retyping the new literals in every spec.
13. **The plants journey-spec.json, backlog-extras.json, decisions.json and panel/rulings.json are left alone.** They are the set's distil records, with provenance, not docs stating current behaviour. Rejected: rewriting provenance records.
14. **The plants review section builder is renamed in step with its key.** `partiesSection` (plants `features/check-answers/view-model/index.js:287`) builds the section now headed "3. Addresses" and holds the Consignor, Identification numbers and Contact cards. Identification numbers is not a party, and the section is no longer called parties anywhere a user sees, so "parties" mispredicts it. It takes the same addresses word as the renamed section key (Decision 6). It is a module-private function with one call site in the same file (`index.js:330`), so the rename changes no signature across callers. `partyCard`, which builds the Consignor and Contact cards, keeps its name: each of those cards is a party. Rejected: keeping `partiesSection` beside an addresses key (two names for one section in one twin).
    - Twin vocabulary, stated once: in both twins the review section's copy key is the same addresses word, and that word names the section. The plants builder carries that word. The live animals builder keeps `consignmentAddressesSection` in `sections/consignment-addresses.js` (Decision 7): it is named for the consignment addresses card it builds, which is still the card's title, and its anchor must differ from the card's `addresses` anchor. Each twin's builder name therefore predicts what it builds, and the shared concept (the Addresses section) has one key name across both twins.
15. **The plants section-captions copy files lose their rationale.** Plants `flow/section-captions/copy/copy.en.js:4-8` explains why captions are journey chrome and where the page map lives (another module), and `copy.cy.js:2-9` records where each Welsh caption came from and how to add one. Both are rationale in code. The English doc comment keeps only its contract sentence (lines 1-3, the shape live animals' twin file already has). The Welsh file keeps only its line-1 MACHINE-DRAFT marker, which a test reads. The reasoning that the plants docs do not already hold moves there: `docs/journey-flow-and-gates.md:241-243` already says the caption map is data and never a string chosen page by page, so nothing moves for copy.en.js. The Welsh provenance (dashboard from the journey spec, About the consignment from live animals, Arrival and Destination from the spec's own Welsh nouns, Addresses from live animals) and "a new section brings its Welsh string" go into `docs/copy-status.md` as a section-captions row. Rejected: rewording the comments.
