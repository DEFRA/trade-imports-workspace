## 0. Decisions

1. **Task list heading text.** Both overviews read "Notification task list" (two words), in place of "Notification tasklist". The Welsh "Rhestr dasgau’r hysbysiad" already reads as two words and stays as the Welsh draft in both repos. Rejected: rewording the Welsh too (nothing in it is wrong).
2. **Plants copy key.** Plants' `taskListRegionLabel` becomes the same key animals uses for the same concept (`taskListHeading`), because it is now a visible heading and one concept takes one name across twin repos. The rename covers its copy test, its FIT helper and the hub template. Rejected: keeping the region-label name for a heading.
3. **Plants overview headings.** Plants mirrors animals' structure: a region named by a visible second-level "Notification task list" heading, holding one region per group whose heading drops to the third level. Class sizes follow animals' hub template (task list heading large, group heading medium). Rejected: keeping groups at level 2 under a level-2 heading.
4. **One form per header action, animals.** The view header's button group holds, in order: Amend's own form (crumb only, posting to the amend action), Copy as new's own form (crumb, concurrency token and copy origin, posting to the copy action), then the Delete link-button outside both. The formaction reroute goes. Each form uses the inline-form class the animals dashboard's post actions already use (dashboard `template.njk:85`), so the forms sit in the button group's row. Rejected: one form with formaction (the reviewed break); a new layout class.
5. **One form per header action, plants.** Plants' header button group holds Amend's own form (crumb only) and the Delete link-button outside it. Plants' dashboard post actions use a plain `<form>` inside the layout with no app class, and plants' journey-spec (`spec/journey-spec.json:361`) calls animals' inline-form class debt not to copy, so the plants form takes no app class. Rejected: copying `app-form-inline` into plants' markup.
6. **Identification details heading.** It becomes a level-5 heading styled `govuk-heading-s`, one level under the species block's level-4 heading, matching the pattern on main that headings inside cards use `govuk-heading-s`. Rejected: bold body text (the reviewed break); a larger heading class, which would outrank the species heading visually.
7. **Card accessible names, animals review.** Every review card is rendered by one hand-written summary card shape: a `<section class="govuk-summary-card">` named by `aria-labelledby` pointing at its own title heading's id, as `commodities/animal-identification/_identification-card.njk:6-8` does. `govukSummaryList`'s card option cannot give its title an id, so the template's two card branches (hand-written and macro card) become one card shape, with the rows still drawn by `govukSummaryList({ rows })`. The `govukAttributes` import, `role="group"` and `aria-label` go. A card with an error anchor keeps its id and tabindex on the section. The title id comes from the section's anchor and the card's position within it, in the template, because only some cards carry an anchor (commodity cards after the first carry none, `commodity-cards.js:14`). Rejected: naming cards through `govukAttributes` (the reviewed break); giving every card a view-model id (a second owner for something only the template needs).
8. **Review not found, both repos.** The review's own catch-and-redirect goes from both controllers, and so does the entry guard's catch, so the not-found the engine already throws (`engine/journey.js:93,97`) reaches the shared error page: status 404, H1 "404" and "Page not found", as every other journey page and as main does. `isJourneyNotFound` then has no caller in either repo, so it, its engine index export and its unit tests go too. Plants changes as well, because the programme invariant says plants mirrors a page behaviour it shares, and plants carries the same redirect (`check-answers/controller.js:159-180`, `flow/entry-guard.js:55-64`). Rejected: animals only.
9. **Contact address "Edit details" on the review.** It is a row action on the Contact address card's contact row, beside the card's heading Change link, exactly as main had it (`origin/main` c944e373 `cards/addresses/contact-address.js`, `rows/party-row.js` `editAction`): shown only when a contact address is chosen and the review is editable (draft and amend), linking to the contact edit page with the review as its return and the review's own trail. Only the contact address gets it. Main also gave each Consignment addresses party row an Edit details link, but this row's criteria name only the contact address and this branch's ruled spec says the Consignment addresses card offers only its Change link. Rejected: an extra card-level action (main put it on the row); restoring the party-row links (not asked for).
10. **Edit details copy.** The review's own copy gains "Edit details" (Welsh "Golygu manylion", as main had), not a reach into the addresses feature's copy: the invariant keeps set-specific strings in the feature's own copy. The link announces "contact address" to a screen reader through the card's existing hidden contact address copy.
11. **Trail to the edit link.** `buildSections` takes the review page's trail and passes it to the contact address section and card only, as main did. This is a signature change across `buildSections`' callers (the controller and its tests), needed so the link returns to the review with its trail.
12. **One review heading in the tests.** Each review page object (animals and plants) exposes one `heading`: the page's level-1 heading inside main, whichever state the page is in (the reference for a draft or submitted notification, the review title while amending). A test that cares which title shows asserts that heading's text. The amend-only, resubmitting and any-of headings go from the page objects. The resume and save-and-continue helpers lose their alternative-heading overloads and wait on `heading` only. Rejected: keeping several named headings (the reviewed break).
13. **Card lookup in the tests.** Animals review cards are found as plants finds them: the GOV.UK summary card element filtered by its exact title heading (`page-objects/plants/notification-view-page.ts:27-29`). Party rows use the summary list row class as plants' `row()` does. The commodity card titles list is the titles of the summary cards that hold species blocks. The card subsection lookup selects the summary list straight after its subsection heading with a CSS sibling combinator. No lookup uses XPath or a section caption. Rejected: role `region` by name (plants does not do it, and the criterion asks for plants' way).
14. **Restored contact-from-review tests.** Main's "editing the contact address from the review changes only this notification" e2e comes back. The cancel test covers both starts again: the consignor from the consignment addresses page and the contact address from the review, so its title states both. The "copied address offers Change and Edit details" test asserts the review's Consignment addresses card offers exactly its Change link and the Contact address card offers exactly Change then Edit details.
15. **Shared task list heading locator.** The animals overview page object's task list heading locator moves to the shared notification page beside the shared task list region, so the plants overview spec uses the same locator. The shared task list name constant reads "Notification task list".
16. **Claims checked.** Every note in the row holds against the live tree, except the line numbers in the tests note (the XPath lookups are at `notification-view-page.ts:51`, `:76`, `:113` (row by `dl > div`, not XPath) and `:122`). The resolutions file does not apply: this is not a merge row.
