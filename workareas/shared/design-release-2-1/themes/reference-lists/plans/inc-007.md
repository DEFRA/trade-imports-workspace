## 0. Decisions

1. **The order is reference data's, built once.** `GET /ports-of-entry` sorts by: type group (airport, then seaport,
   then rail, then any port whose MDM traffic is missing or unrecognised), then the name compared with every run of
   whitespace or non-breaking spaces collapsed to one space, trimmed, lower-cased with `Locale.ROOT`, compared by
   `String.compareTo`; then the code, as a tie-break, so two ports with the same name (MDM's two "Pembroke Port",
   two "Port of Sheerness") come out in a fixed order. The frontends add no sorting: they show the list as served,
   which is what the animals port of entry, both animals port of exit selects and the plants place of landing already
   do. Rejected: sorting in each frontend (three copies of one rule, and the detail says the order is reference
   data's).
2. **Type mapping.** MDM `traffic` `Airport` → `airport`, `Port` → `seaport`, `Rail` → `rail`, matched ignoring case.
   Anything else, or no traffic, gives `"type": null` and sorts after rail — the port is kept, never dropped (AC5).
   Rejected: dropping unknown ports (breaks "still holds every port"), or failing the request.
3. **Wire shape.** Each port is `{"code": ..., "name": ..., "type": ...}` in that field order, `type` a lower-case
   string from a `PortType` enum with `@JsonValue`. Names are served exactly as MDM has them: the double space in
   "Portsmouth  Port", the non-breaking space in "Port of Middlesbrough" and the capitals of "TILBURY" stay (detail:
   "List content stays what MDM serves"). Only the comparison normalises.
4. **The captured fixtures are regenerated with jq from the stub's fixture, not by running `capture:*`** — the same
   reasoning inc-173 recorded (Decision 6 there): the capture scripts read reference data's 60-minute MDM cache on the
   leased stack, and the planner must not depend on what that container is running. The planner ran the jq program
   below against `STUB_PORTS`; it puts the 18 airports first (Aberdeen Airport … Teesside International Airport),
   then the 59 seaports (Aberdeen Harbour … Teestort, TILBURY, Tilbury 2 Ro-Ro Terminal, Tilbury Port), then the one
   rail port (Folkestone). The tests repo's existing E2E "the port of entry list offers every captured port, in the
   order reference data serves them" then proves on the rebuilt stack that the jq order and the Java order agree.
   The jq output format (2-space indent, raw UTF-8, trailing newline) matches what `capture.js` writes.
5. **The port of exit label is built in the animals ports service.** A new `portOptions()` in
   `services/ports/index.js` (mirroring the plants ports service's `portOptions()`) returns
   `{ value: code, text: '<name> - <code>' }`; the import-reason controller's `portItems` uses it for both exit
   selects. The placeholder "Select port of exit" and the disabled divider stay first.
6. **Defect in the row: the port of entry does not take '<name> - <code>' on this branch.** AC7 says the exit label
   is "the same label the port of entry options take", and the detail says Design Release 2.1 labels exit "as the port
   of entry options are labelled". On this branch the port of entry options (animals) and place of landing options
   (plants) read `<name> (<code>)` (port-of-entry.controller.js:38; plants ports `displayName`). Changing the entry
   and landing labels is the parent backlog's inc-027 ("Port options read '<port name> - <port code>', in animals
   and plants", theme arrival-and-transit, status todo), which also owns the autocomplete's chosen-port text and the
   plants label. This plan builds the exit label as DR2.1 shows it ('<name> - <code>', the prototype's label for both
   lists) and leaves entry and landing labels to inc-027, so for now entry reads `(code)` and exit reads `- code`;
   when inc-027 lands it should point the entry select at the same `portOptions()`. Rejected: changing the entry and
   plants landing labels here (absorbs another theme's row, its spec and E2E rewrites, and collides with its branch).
7. **No Welsh string is added.** The label is a format of two MDM values, not copy; the placeholder and the label
   "Port of exit" are unchanged.
8. **AC10 (a port of exit saved before is still shown selected) needs no code**: the selects bind `value:` to the
   stored code, which this change does not touch. It is pinned by the existing unit test "Should offer a stored port
   of exit to both reveals that ask for it", the FIT "saves a reason and its reveal in one submit, and offers the
   answers back", and a new E2E (section 4).
9. **"Locally, in CDP dev and in CDP test" (AC2, AC8).** Locally is proved by the gate's E2E. CDP dev reads the same
   stub; CDP test reads real MDM, whose raw capture carries the same three traffic values. Both are post-merge
   observations once reference data redeploys; nothing in this plan can run against CDP.
10. **The reference data API shape is not given a new spec capability** (section 8): no prefix holds a reference data
    capability, and the `type` field is not shown to any user; the observable effect, the order, is specced on the
    three pages that show it.

in list order `AIRPORT("airport", "Airport")`, `SEAPORT("seaport", "Port")`, `RAIL("rail", "Rail")`; fields

**`RD src/main/java/uk/gov/defra/trade/imports/portsofentry/PortListOrder.java`** — `public final class PortListOrder`
with a private constructor, `private static final Pattern WHITESPACE = Pattern.compile("[\\s\\u00A0]+");` and

```java
public static final Comparator<PortOfEntry> AIRPORTS_THEN_SEAPORTS_THEN_RAIL =
    Comparator.comparing(PortOfEntry::getType, Comparator.nullsLast(Comparator.naturalOrder()))
        .thenComparing(port -> sortableName(port.getName()))
        .thenComparing(PortOfEntry::getCode, Comparator.nullsLast(Comparator.naturalOrder()));

private static String sortableName(String name) {
  return name == null ? "" : WHITESPACE.matcher(name).replaceAll(" ").trim().toLowerCase(Locale.ROOT);
}
```

Javadoc on the class and the constant: airports, then seaports, then rail ports, then ports of unknown type; each
group A to Z by name ignoring letter case, reading non-breaking and doubled spaces as one; then by code. Names are not
changed, only compared.
