## 0. Decisions

1. **How the stub fixtures are regenerated: two jq programs, run once, kept beside the raw captures.** The raw captures
   cannot be parsed as JSON, `node`/`python` are denied and the stub has no `package.json`. jq reads the raw text
   (`-Rs`), removes every masked token, and rebuilds each record. The planner ran both programs against the captures and
   verified the result (see 5). They go in the workspace repo at `MDM/regenerate/countries.jq` and
   `MDM/regenerate/ports.jq` (workarea output; the orchestrator commits the workspace), so the fixture can be
   regenerated from the same captures later. Rejected: hand-editing 250 records (error-prone), a Java generator in the
   stub (code that ships for a one-off), a Node script wrapped in a new stub `package.json` (a Node toolchain in a Java
   repo).
2. **Masked values are left out, never guessed, with three recoveries by code from a real capture** (the spec's own
   method):
   - countries `effectiveAlias` (reference-data's `name`) from `cdp-test--countries.json` by `alpha2.value` (249; GB's
     stays out because GB is masked and reference-data drops GB anyway);
   - countries `effectiveAlpha2`, only where its key was masked (Suriname: raw `"Suri******2":"SR"`): the value is
     visible in the raw and equals `alpha2.value` for all 250 records; reference-data needs it as the country code;
   - subdivision `name` from `cdp-test--countries.json` by subdivision code (FR 6, PT 2, ES 1); GB-NIR's name stays out;
   - ports `name` by code from `cdp-test--ports-of-entry.json`, which keeps GB MID's non-breaking spaces;
   - ports `townCity` for AYR, FRB and GRK, whose value is visible in the raw after a masked span (spec: restore it).
   Everything else masked is left out: `longName`, `name`, `statusName`, `systemLongName`, `effectiveLongName`, every
   `listName`/`listAgencyName`, subdivision `countryCategory.categoryName`, the port `building…` key and its value, the
   third `status` field, and the `independent` value of the 8 records whose key is masked (TD OM CU TG PE IQ ML FJ —
   nobody reads `independent`, so the visible `false` is not re-keyed). Block names: an entry whose masked token ends
   `_EX` becomes `GBNAG_SPS_EX` (31 with `includeCountry: true` plus GB's, spec); every other block keeps its
   `includeCountry` and `tags` with no `name`. "Western Sahara*" keeps its asterisk: that is MDM's own value.
3. **The stub serves both fixtures as `JsonNode`, passed through unchanged; the six model classes are deleted.** Spec
   "Pass-through" offers this or extending the models; pass-through is the only way to serve fields no model names
   (`countryUUID`, `ISONumeric`, `traffic`, `status` …). `MdmCountry`, `MdmBlock`, `MdmSubDivision`, `MdmCodedValue`,
   `MdmPortOfEntry`, `MdmPortsResponse` have no other user once the controllers stop using them.
4. **Each controller parses its fixture once, in its constructor**, not per request (today `FileUtils` re-reads per
   call; the countries file grows from 31 to 250 full records and the stub's latency is measured by the performance
   tests). The parsed tree is only read, never changed.
5. **The `blocks` filter keeps a record when any entry in its `blocks` array has `name` equal to the parameter,
   whatever `includeCountry` says, in fixture order** (spec: 32 for `GBNAG_SPS_EX`, GB included; the SPS raw capture's
   order equals the unfiltered order). A missing or blank `blocks` returns all 250. An unknown block returns `[]`
   (keeps the performance tests' forced-miss path `?blocks=PERF_TEST_NO_SUCH_BLOCK` empty, so it is still never cached).
   `system` stays accepted and ignored. The subscription-key header stays required with any value (missing → 400, as
   today).
6. **The frontend and tests fixtures are written from the CDP-test reference-data captures with jq, not by running the
   capture scripts against the leased stack.** The planner proved that the regenerated stub fixtures, put through
   reference-data's own mapping (`Country(MdmCountry)`: code = `effectiveAlpha2`, name = `effectiveAlias`, subdivisions
   by code/name; GB removed; SPS = `GBNAG_SPS_EX` with `includeCountry` true; sorted by name), give exactly
   `cdp-test--countries.json`, `cdp-test--countries-sps.json` and `cdp-test--ports-of-entry.json` (`==` true for all
   three). Running `capture:*` against the stack now would read reference-data's 60-minute MDM cache, which may still
   hold the old 31-country answer, and the run may not restart reference-data. `jq '.body'` output is byte-identical to
   what `capture.js` writes (`JSON.stringify(body, null, 2)` plus a newline). The tests repo's new E2E specs then prove,
   through the rebuilt stack, that the stub → reference-data → frontend chain serves exactly these fixtures.
7. **The INS frontend gets the same `_capture` shape as the other two frontends** (`services/_capture/fixtures.js` +
   `fixtures/countries.json`), and its capture script goes in `scripts/capture-reference-data.js` with npm script
   `capture:reference-data` — outside `src/` because INS's `sonar.sources=src/` would count an untested script against
   new-code coverage. Rejected: keeping the four hand-typed countries (AC), a fixture with no capture script (no way to
   recapture).
8. **The animals capture script drops its "expected — endpoint not built" optional tag** and fails on any target, exactly
   as the plants script already does (AC: no check marked as waiting on an endpoint that is not built).
9. **"The end-to-end specs take their country names from the recaptured fixture" is met through the tests repo's one
   country constant module.** `domain/animals/constants/country-codes.ts` builds `countryCodes.eu` from a copy of the
   recaptured `countries-origin.json` (names looked up by code; a missing code throws), and the 164-entry `row` list and
   its unused type aliases are deleted. Specs that type a country name literally ('France', 'Belgium' …) stay as they
   are: every one of those names is unchanged by the recapture (all 31 SPS names are identical before and after), and
   rewriting ~60 call sites is not what the ruling asks. Rejected: rewriting every spec.
10. **"Every spec that counts the unfiltered country list expects 249": no spec counts it today** (the only country
    count, 41 in `country-of-origin-type-ahead.spec.ts`, is the SPS origin list and is unchanged). The new INS spec is
    the one that does: it expects United Kingdom then the 249 captured names.
11. **The new list specs compare the whole rendered list with the copied fixture and run only on the compose stack**
    (`skipUnlessComposeEnvironment`): on CDP test the list is live MDM content that may move. They name no single port
    or country by hand, so no misspelt or duplicated port is pinned (ruling p1-171); the fixture carries whatever MDM
    serves.
12. **Claims that do not hold, planned against reality:**
    - "every plants check that pinned an old port name or the old count of 77": no plants check pins 77 or a port name
      that changes. The plants ports fixture already holds the same 78 ports; the only difference after recapture is
      `GB MID` "Port of Middlesbrough" gaining its non-breaking spaces, which moves it from position 62 to 66 in
      reference-data's name order. "77" appears only in the plants set's ruling/decision prose (`spec/journey-spec.json`,
      `spec/decisions.json`, `spec/panel/rulings.json`), which is a historical record and is left alone.
    - "today the stub's ports are 78 hand-kept GB ports": they were captured from MDM TST (stub `2489a1f`), not hand-kept;
      they are cut down to `id`, `code`, `name` and ordered A to Z. The change still applies.
    - The spec's "reference-data needs `traffic` mapped through for req-304" is a reference-data change not in this
      row's repos or criteria (req-304 belongs to inc-007). Not planned here.
13. **CDP dev** is proven by the same stub image once it is deployed; the gate cannot reach it. The stub's own tests and
    the local-stack E2E carry the proof.
14. **Workspace doc** `docs/repos/trade-imports-stub.md` states "No filtering … `blocks` … accepted and ignored" and
    "Shape only" fixtures; both become false. It is corrected in the same change (workspace repo, committed by the
    orchestrator, like the jq programs).
15. **Second attempt restores the first attempt's tree from its preserved patches rather than rebuilding it.** The
    first attempt's only red was the stale reference-data cache, a factory fault since fixed (`32b6ed90`); its slice
    passed review and every other rung. Rebuilding would re-decide settled choices and risk drift from a reviewed tree.
    Rejected: re-implementing from sections 1-3 (only the fallback if a patch fails), popping the stashes (indices move;
    the workspace stash also holds unrelated docs edits), and any change to the E2E specs (their expectations are
    right; the diffs show only the stale cache).
