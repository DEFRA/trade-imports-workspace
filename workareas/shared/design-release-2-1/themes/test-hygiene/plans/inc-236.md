## 0. Decisions

1. **The coverage claim is reworded, and no code moves.** The live tree shows the old reason is false. The guide says the type-ahead readers live in the spec "so the coverage report never counts them as source". The repo's Vitest coverage `include` is `src/**/*.js`, so `fit/` is never in scope. Sonar takes `src/` as sources and excludes `src/**/*.test.js` and `src/**/*.fit.spec.js`. Today's `coverage/lcov.info` (12 Nov) holds no `fit/`, `*.fit.spec.js` or `*.test.js` entry. So a reader in `fit/high-risk-plants-journey.js` costs no coverage either. The guide will state the true fact: the coverage report and the quality gate count only application source, never browser-test files or `fit/` helpers. Where a reader lives then depends only on how many specs use it. Rejected: moving readers to keep them in a spec file, which would act on a false premise.
2. **The type-ahead spec's reference-style reader and its style comparer move into the shared helper.** Once the arrival details label tests compare against a GOV.UK label read at run time, the reader has two specs (rule: set-up used by two tests goes in the shared helper). The promoted pair takes the animals twin's shape and names: `measureReferenceElement` and `expectStyle` in `repos/trade-imports-animals-frontend/fit/live-animals-journey.js:119-157`. That covers the parameter names, the single request object handed to the page under the same keys, and the try/finally removal. This follows the rule "one concept, one name … across twin repos". The type-ahead spec's local copies are deleted, and its call sites (`:224-229`, `:382-387`, `:397-400`, `:430-436`) pass the twin's argument names. This changes callers' arguments, but every caller is in a file this row already edits. Rejected: keeping the plants name `govukReferenceStyleOf` with its `element`/`classes` arguments, which leaves two names for one concept across the twins.
3. **`govukColourOf` reads its token through the promoted reader, as the animals twin does** (`live-animals-journey.js:165-172`). Otherwise the plants helper would hold two in-page "make a reference element, read its computed style, remove it" routines (rule: extend the mechanism that exists, one owner). Its exported signature and JSDoc contract (page, token → `rgb(…)`) stay the same, so no caller changes. Rejected: only renaming its in-page parameter from `name` to `token`, which keeps the duplicate.
4. **"Each plants browser reader that runs code in the page" means every `evaluate`/`evaluateAll` in plants FIT code that passes an argument.** The live tree has six. Each hands its value over under a different name from the one it takes:
   - `fit/high-risk-plants-journey.js:92-96` `computedStyle`: takes `property`, hands it over as `name`.
   - `fit/high-risk-plants-journey.js:105-113` `govukColourOf`: takes `token`, hands it over as `name`. Settled by decision 3.
   - `fit/high-risk-plants-journey.js:518-532` `overwriteRadioInputs`: takes `postedValue` and an inputs locator, hands them over as `value` and `elements`.
   - `fit/high-risk-plants-journey.js:947-963` `postUnknownAddressId`: takes `fieldName`, hands it over as `name`, and hands `NOT_IN_THE_BOOK` over as a bare `id` when it is an address id.
   - `type-ahead.fit.spec.js:444-469` `govukReferenceStyleOf`: takes `element`/`classes`/`focused`/`properties`, hands them over as `tagName`/`className`/`isFocused`/`names`. Settled by decision 2.
   - `arrival-details.fit.spec.js:106-112` `selectPortMissingFromTheList`: takes `code`, hands it over as `portCode`.

   `overwriteRadioInputs` writes rather than reads. It is included because it runs code in the page with a renamed argument, and the criterion's purpose (one name per value across the page boundary) covers it. The row notes leave it out; this departs from them on purpose. Every evaluate that passes no argument (`documentTop`, `documentBottom`, `contentWidthOf`, the edge reads at `:198-201`, `:486`, `type-ahead.fit.spec.js:250`, `:258`, `:366`, `:405`, `measureJoinedSearchButton`, `origin.fit.spec.js:105`, `arrival-status.fit.spec.js:124`, `commodity-type.fit.spec.js:134`) has nothing to hand over and stays as it is.
5. **The arrival details label tests keep their titles.** "…in the medium GOV.UK label size" still states what the new assertions prove: font size and weight equal a GOV.UK medium label read at run time. The coverage links for the medium-label scenarios therefore keep binding. Only their notes change (section 8).
6. **The label-size comparison reads font size and font weight**, as the type-ahead no-JavaScript label test already does (`type-ahead.fit.spec.js:224-229`). A medium label differs from the default label in both. Rejected: adding margin or line height, which depend on where the label sits rather than on its size.
7. **Place of landing accents go into the existing place-of-landing requirement; genus search gets a new requirement on commodity details.** The arrival details requirement on finding a port by name or code (REQ-PLANTS-ARRIVAL-DETAILS-003) already owns the search, so its statement takes the matching clause in the words origin uses (`origin/spec.md:24`). Rejected: one shared "type-ahead" capability, since each page spec owns its own questions and origin set the per-page pattern.
8. **The tests repo gets a plants visual script that mirrors the animals one**, `package.json:48`. It narrows the all-domain visual script to `tests/plants/`, sits in the plants block after `test:docker-compose:plants` (`:61`), and goes in the plants visual cell of the README's domain table (`README.md:104`). The visual run-command sentence at `README.md:433-434` names only the animals script for running one domain.
