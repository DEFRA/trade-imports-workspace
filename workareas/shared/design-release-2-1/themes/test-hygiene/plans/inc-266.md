- **Holds.** accessible-autocomplete 3.0.2 (both repos) styles
  `.autocomplete__input--focused` as `outline: 3px solid #fd0; outline-offset: 0;
  box-shadow: inset 0 0 0 2px;` (`node_modules/accessible-autocomplete/src/autocomplete.css:31-35`).
  The shadow has no colour, so it paints in `currentColor`.
- **Holds.** govuk-frontend 6.5.1 (installed in both repos) paints a focused
  `.govuk-input` through the mixin `govuk-focused-form-input`
  (`node_modules/govuk-frontend/dist/govuk/helpers/_focused.scss:84-95`):
  outline `$govuk-focus-width` (3px) in the focus colour, offset 0, and
  `box-shadow: inset 0 0 0 $govuk-border-width-form-element govuk-functional-colour(input-border)`.
- **Holds.** Neither repo's `accessible-autocomplete.scss` overrides the focused
  state (frontend and plantsfrontend files are identical, lines 1-38).
- **Holds.** The animals focus test pins the shadow to the input's own text
  colour (`type-ahead.fit.spec.js:416-438`, helper `shadowInColour` at :122).
  The plants twin compares only the shadow with its colour stripped
  (`type-ahead.fit.spec.js:391-418`, local `withoutColour` at :403), so it does
  not prove colour at all today.

## 0. Decisions

- **The override goes through GOV.UK's own mixin.** Each repo's
  `accessible-autocomplete.scss` gives the library's focused-input state GOV.UK's
  `govuk-focused-form-input` mixin, so GOV.UK owns the whole focused look
  (outline width, outline colour, offset, inset shadow width and colour).
  Rejected: setting only a `box-shadow` colour from the input-border token. That
  would be a second copy of GOV.UK's focus rule beside the mixin that owns it.
  The mixin's outline (3px, focus colour, offset 0) is the same as the library's,
  so the yellow outline and the shadow's width do not change.
- **The test compares the whole computed `box-shadow` with a focused plain
  GOV.UK input read at run time.** One equality proves the colour, offsets and
  width at once, and the reference shadow is read from the page, never typed.
  Rejected: reading the input-border token through `govukColourOf` and splicing
  it into the shadow. That keeps a string-surgery helper whose only job is to
  rebuild what the reference element already reports.
- **Both twins change in this increment** (programme invariant on plants
  mirroring). The plants test today does not prove colour; it now does.
- **Signed-off pages.** The origin, arrival, transit and import-reason pages are
  signed off. The focus style tests are not linked to any scenario in
  `openspec/coverage/**` (grep below), so no signed-off check trips. Sam ruled on
  12 November that the type-ahead follows GOV.UK (provenance: the increment's
  note, raised from inc-234's open question).
- **No tests-repo change.** The plants screenshot
  `tests/plants/e2e/visual/origin.visual.spec.ts` "shows the country suggestions
  listed under the type-ahead" captures the input focused, so its 2px shadow
  moves from rgb(0,0,0) to rgb(11,12,12). That is far inside Playwright's
  default per-pixel threshold (0.2; no override in the tests repo), so the
  baseline holds. The animals visual specs capture no focused state. Recorded as
  a risk rather than planned work; the row's repos are frontend and
  plantsfrontend.

- **Every FIT check names this machine's worker count.** The plan review asked
  for it: each FIT command in section 5, the removal probe included, ends with
  `--workers=3` after the spec file, for both frontends. Without it the script's
  default can start a browser per core. Rejected: leaving the count for whoever
  runs the check to add.
