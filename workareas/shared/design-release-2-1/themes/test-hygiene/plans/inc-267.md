## 0. Decisions

1. **Where the "not on screen" proof lives: the FIT layer, in the shared picker layout helper.** jsdom (the unit layer, `documentOf` in `src/server/common/test-helpers/document-of.js`) loads no stylesheet and computes no layout, so it cannot measure what is rendered. The browser test already has `expectPickerResultsLayout` (`fit/high-risk-plants-journey.js:1013`), which every single-address picker runs through `describeAddressPicker` (consignor, place of destination, consignment contact). It gains the check. Rejected: a fixed pixel box (`width <= 1px`) — `docs/testing.md:127-131` forbids fixed pixel sizes in a fit spec; a screenshot in the tests repo — heavier, and the row is plantsfrontend only.
2. **How "hidden" is measured.** The legend (found inside the group named by the results heading, by its text, not by tag class) must have the computed hiding styles of a GOV.UK visually-hidden reference element read at run time: position, width, height, overflow and clip-path, read through `measureReferenceElement` (`fit/high-risk-plants-journey.js:137`) and compared with `expectStyle` (`:123`). That is the comparison `testing.md:121-124` sanctions. Rejected: Playwright `toBeVisible`/`toBeHidden`, which call a 1×1 clipped box visible, so the assertion would prove nothing.
3. **Accessible name, unit layer.** jsdom has no accessible-name computation and the repo has no `dom-accessibility-api` or Testing Library. The unit test proves the HTML rule a fieldset's name comes from: its own first child is a `legend` whose text is the shared picker copy's results heading (read from `pickerCopy`, not a literal). The browser-computed name stays proved where it already is: `expectPickerResultsLayout`'s group lookup by role and name (`:1015-1019`). Rejected: adding a devDependency for one assertion.
4. **AC "no test of the picker asserts a class list" covers more than the legend line.** `results.test.js:80-95` prove the error and plain form groups by querying `.govuk-form-group--error` and `.govuk-form-group > fieldset`. Those are class-list assertions. They move to the browser, where what they protect (the GOV.UK error border round the radios when the picker is refused, none otherwise) can be measured. `results.test.js:110` finds the radio label by `.govuk-radios__label`; it changes to find the label through the radio it labels, so the file queries no class at all.
5. **The error-border proof joins `describeAddressPicker`'s refusal group** as one new shared test (all three pickers get it), not a per-page test: the markup comes from one macro (`results.njk:50`).
6. **Signed-off check.** The three picker pages are `maturity: 'exploring'` and `openspec/specs/plants/addresses/spec.md` has no signed-off scenario, so no trip is expected. The row's note says a trip here is already approved.
