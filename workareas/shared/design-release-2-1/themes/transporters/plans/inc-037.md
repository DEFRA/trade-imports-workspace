## 0. Decisions

1. **Two of the six acceptance criteria are already met on this branch, and the plan builds only
   the other four.** Read against the live tree: the secondary "Add a transporter" already sits in
   the right-hand half of a grid row above the fieldset and opens the type question
   (`transporters.njk:64-82`, proved by the three tests in the fit spec's "Add a transporter beside
   the search" group at `fit/transporters.fit.spec.js:687-734`), and the search already matches a
   transporter's type word and status word as well as its name, address and approval number
   (`transporters/rows.js:19-28`, proved at `transporters/rows.test.js:88-110` and
   `fit/transporters.fit.spec.js:508-515`). Both came from the design-snagging row this increment
   declares as an external dependency. Rejected: re-implementing or re-proving them, which would
   churn passing code. They still get a check in section 5, so a regression shows.

2. **The sub-heading and the legend are one copy string in two roles, not two strings.** The design
   source puts the same words in both (`app/views/design-release-2.1/transporter.html:73` for the
   `h2`, `:107-108` for the visually hidden legend; extracted as
   `prototype-dr2-1-source-p7-015` and `-p7-022`, and seen rendered in
   `trace-prototype-dr2-1-p8-076` and `-p8-083`). The repo already has this exact pattern in the
   party picker, which reads one copy key for a visible `govuk-heading-m` and for the fieldset
   legend it marks `govuk-visually-hidden`
   (`features/addresses/party-picker/_address-picker.njk:15` and `:38`). So: one key, two readers.
   Rejected: a second key holding the same words, which lets the heading and the announced group
   name drift apart.

3. **That one copy key is renamed, because after this change its present name mispredicts.** It is
   read today only as a fieldset legend (`copy/copy.en.js:99`, `copy/copy.cy.js:98`, used at
   `transporters.njk:89`); after this change it is also the page's visible sub-heading. The rename
   covers the template, both locale decks and the one fit assertion that reads it
   (`fit/transporters.fit.spec.js:287`); the feature's copy test asserts a key list only for the
   transporter-type deck (`copy/copy.test.js:291`), so it is untouched. Rejected: keeping the name,
   which the house names rule allows only while a name still predicts its use.

4. **"Not applicable" is a display label the list owns, never stored data.** The design source
   reaches the same rendered cell by storing the words as the record's approval number
   (`app/routes.js:3502-3511`, extracted as `prototype-dr2-1-source-p7-084`). Our records genuinely
   have no such field for a private transporter (`services/transporters/records.js:7-35`), and what
   a pick commits must stay the real answer, so the words live in the transport feature's copy deck
   and are applied where the row is built. Rejected: giving the shipped private records an approval
   number of "Not applicable", which would put display text into the notification's saved answer
   through `transporters/transporter-record.js:29-45`.

5. **The same label is what the row is searched on, so the rendered cell and the search text
   agree.** The design's rendered search text carries the words
   (`trace-prototype-dr2-1-p9-046`: a private row's search text ends "not applicable private new"),
   and the browser filter bolds matches in the cells it filters by
   (`src/client/javascripts/components/transporter-filter.js:8-35`), so a search text that omitted
   the words would bold a cell the term did not match. Rejected: keeping the approval number out of
   the search text when a record has none, which is what the code does today
   (`transporters/rows.js:27`) and what one unit test asserts
   (`transporters/rows.test.js:154-162`); that test changes with the rule.

6. **"Not applicable" goes in the transport feature's own copy deck, not in shared copy.** The
   review card already owns its own copy of this word
   (`features/check-answers/copy/copy.en.js:3`, `copy.cy.js:4`) and the repo's convention is that a
   feature owns the copy its own pages show (`.claude/rules/copy.md`,
   `sets/live-animals/docs/features.md` "Copy and templates"). Rejected: promoting the word to
   `shared/copy.en.js` / `shared/copy.cy.js` and repointing the review card at it — that edits a
   second feature for clean-up alone, which this row must not do. It is section 7's follow-up.
   The Welsh draft is the word the review card already uses for this concept
   (`features/check-answers/copy/copy.cy.js:4`), not a new translation: one concept, one name.

7. **A claim in the increment does not hold, and the accessibility check is planned against
   reality.** The fourth acceptance criterion says the list's error state is reached by saving
   "with nothing chosen". It is not: an empty pick is accepted and the page walks on, by design —
   `transporters/validate.js:52-57` reads the payload's pick as an empty string and
   `oneOf` passes it, asserted at `transporters/validate.test.js:38-44`, and the design source
   agrees ("transporter is optional to proceed",
   `prototype-specs/e2e/transport-and-arrival.fit.spec.js:149`). The list's only reachable answer
   error is a submitted pick that is not on the list, which the fit suite already drives twice
   (`fit/transporters.fit.spec.js:408-426` and `:533-550`). The new accessibility check uses that
   route. The criterion's substance — the list in its error state is held to the same axe bar as
   its other states — is unchanged and buildable, so this is a wrong parenthetical, not a blocker.

8. **The organisation's transporters stay where they are.** The ruling that unblocked this row
   makes the address book the home for per-organisation transporter records, but that move is
   another row's: this row's repos are the frontend and the tests repo, and the list keeps reading
   the in-process register beside the shipped fixtures
   (`services/transporters/index.js:27-34`, `services/transporters/register.js`). Everything planned
   here is about how the list reads, so it holds whichever store feeds it. Rejected: moving the
   store in this increment, which would need a repo this row does not name.

9. **One redundant test in the fit file is deleted rather than left beside the new one.** The
   file holds two tests with identical set-up and identical assertion for the list's plain state —
   one in its search-box group (`fit/transporters.fit.spec.js:445-451`) and one in its
   accessibility group (`:1090-1095`). No coverage link names either (a search of
   `openspec/coverage/live-animals/` for "axe violations" hits only the consignment-addresses
   capability), so the surviving one is the accessibility group's, beside the new error-state
   check. Rejected: leaving both, which keeps a test that proves nothing the other does not.

10. **Every FIT and E2E check below carries this machine's worker count, after the spec file.**
    `config/machine.json` sets `trade-imports-animals-frontend/fit` to 8 and
    `trade-imports-ins-tests/e2e` to 2, and its `$comment` says those counts "also govern a stage
    FIT run outside the gate" — which a plan check is. Left off, the frontend's `test:fit:ci`
    script runs at `--workers=100%`, a browser per logical core on a 12-core machine, and the tests
    repo's E2E suite its own default; both push this machine into swap and make the check's result
    about the machine rather than the code. Rejected: leaving the count to whoever runs the check,
    which is how the previous draft read and which the plan review refused.
