## 0. Decisions

1. **The rule's one owner is `kit.runBackLink()`, in each twin** (animals `src/server/app/shared/kit.js:264-285`, plants `src/server/app/shared/kit.js:188-201`). Today it consults the previous run step only while the opening run is active; the review completes the run (via `completeOpeningRun`), so on a Change-link page it always falls back to the overview. The helper gains one more state in which it consults the journey's existing `previousRunTarget` (through `journeyPreviousRunTarget`): a request carrying change context on a draft notification. No feature controller writes a Back-target rule of its own. Rejected: a per-controller branch on `kit.changeContext(request)` (the pattern animals Roles and addresses uses today) — that is a second rule beside the seam.
2. **"Previous page in the step order" is the opening run's own Back target** (`RUN_STEPS[].backCandidates`, `offersBackWhen`, gate-skipping), unchanged. A step with no `backCandidates` (animals: animal identification, arrival details, transporter, documents, Roles and addresses, contact address) keeps its fallback. No `RUN_STEPS` entry changes. Rejected: adding candidates to steps whose opening-run Back is Overview by spec.
3. **The Back href carries the request's change context** (the backlog's call 2; precedent: party pickers, transporter spokes and the commodity detour already wrap internal Back links in `kit.withChangeContext`). The previous page therefore opens with change context and its save follows that page's own change-context path, which the code already has and this row does not change:
   - pages whose save goes through `kit.exitTarget` / `kit.nextTarget` (animals import reason, commodity details, additional details, transit countries, origin; plants origin, arrival status, arrival details, identification numbers, the pickers) return straight to the review;
   - animals What are you importing? (commodity search) under change context goes on to Commodity details carrying change context (`commodities/search/actions/commit-selection.js:51-56`, pinned by `search.controller.test.js:516`), and Commodity details' save then returns to the review (`consignment-details.controller.js:151`, `kit.nextTarget` → `exitTarget`).
   The href is built with the existing `kit.withChangeContext` / `appendChangeContext`, not a new query builder. When the helper falls back (no earlier step applies), the fallback is returned exactly as today (overview, or plants' passed `fallback`), with no change marker. Rejected: a bare previous-step href, which would let Save and continue there run on through the task row instead of back to the review.
4. **The new state applies to draft notifications only.** It is gated on `journey.status === DRAFT` (`DRAFT` is already imported in both kits: animals `shared/kit.js:2`, plants `shared/kit.js:3`), so amended, submitted and deleted notifications answer exactly as today. The row's criteria and detail scope the rule to "a draft notification"; a status gate of "not amend" would also widen it to submitted and deleted, which nothing asks for. Animals' existing `returnsToReview` branch stays first, so upload documents still opens the review under change context or amend (REQ-DOCS-002). Rejected: `journey.status !== AMEND`. The amend unit tests (import-reason, identification-numbers) still pin that amend keeps the overview.
5. **Animals Roles and addresses stops hand-building its Back link.** `features/addresses/controller.js:75-78` (`backLinkOf`, review under draft change context) is replaced by a call to `kit.runBackLink(request, page.id, { journey, scope, answers })`. The addresses step has no `backCandidates`, so it answers the overview in every state, which is what the criterion asks ("no longer goes Back to the review"). Rejected: editing `backLinkOf` to return the hub — leaves a second owner.
6. **Origin (animals) and commodity type (plants) keep their Back links.** Neither calls `runBackLink` (both use `entryBackLink`), so their code is untouched; each gets a controller test that pins, on a draft opened with change context, the Back link it has without change context (section 4). Plants origin does call `runBackLink` with `fallback: entryBackLink(...)` and has `backCandidates: [commodities]`, so from a draft's Change link it now goes Back to the commodities list — plants' step order, as the second criterion asks.
7. **Animals' "Commodity details" is the consignment-details page; "What are you importing?" is the commodity search page.** Both already call `runBackLink`; the search page keeps its `commodityQuestionReturn` override first.
8. **Claims checked against the live tree.** All hold: the seam (`runBackLink`, `RUN_STEPS.backCandidates`, `previousRunTarget`) is on the branch in both repos; `exitTarget` already returns change-context saves to the review; animals addresses goes Back to the review under draft change context, pinned by `addresses/controller.test.js:279-285`; plants `spec/journey-spec.json:326` says "pages reached with ?change=1 (-> check your answers)", which neither the code nor this row makes true — it is corrected here. The criterion's `cph-scope.spec.ts:66-73` reference is stale (the file is 47 lines and holds no Roles-and-addresses Change-link check); the Roles-and-addresses e2e check is new, in `change-from-cya.spec.ts`. The first plan's claim that Save and continue on What are you importing? returns straight to the review was wrong (decision 3 states the real path).
9. **E2E placement.** Animals: `tests/animals/e2e/features/change-from-cya.spec.ts` (already the draft-review Change-link spec). Plants: `tests/plants/e2e/features/review.spec.ts` (holds the draft-review Change test and the amend Change test). Rejected: a new spec file — both homes exist.
10. **Plants kit's `runBackLink` gets the exported-API doc comment animals' twin has**, stating the same contract (states answered, the fallback), because the function's contract changes and the twins should read alike.
11. **Plants `runBackLink` callers each get a named test.** Seven pages call it: commodities list, origin, arrival status, arrival details, identification numbers, and the three address pickers through `address-book-picker/render.js:79` (place of destination, consignor, consignment contact). The pickers are proved together through the shared `describeAddressBookPickerController` support, which each picker's controller test already runs with its own `previousStep`. Every plants spec statement that gains the Change-link case is linked to the test that proves it (section 8).
