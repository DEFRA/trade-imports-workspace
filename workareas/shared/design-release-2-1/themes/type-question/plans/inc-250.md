## 0. Decisions

- **The compose claim is half wrong.** The row says the admin service in `docker/stack/frontend.compose.yml` still uses the old variable. It does not: the admin service (`frontend.compose.yml:26`) already sets `DEFRA_ID_BROWSER_FACING_HOSTNAME_REWRITE_ENABLED=true`. The file's one old-name line is the **plants frontend** service (`frontend.compose.yml:198`, `DEFRA_ID_SIGN_OUT_HOSTNAME_REWRITE_ENABLED=true`), and plants already reads the new name (`trade-imports-plants-frontend/src/config/config.js`). Acceptance criterion 1 says no file in `docker/stack` names the old variables, so that plants line changes to the new name. It is a workspace file, not a plants repo change, so the row stays inside its repos. Rejected: leaving it, which fails criterion 1 and leaves plants setting a variable it never reads.
- **Why sign-out works today and keeps working.** Admin reads the old variable, which nothing sets, so it falls back to its default, on whenever `NODE_ENV` is not `production` (`config.js:12`, `:217`). The stack runs admin with `NODE_ENV=development` (`frontend.compose.yml:17`). After the rename, the compose line already present supplies `true` explicitly. Plants is the same: default on in development, now set explicitly. No stack (local or CI) changes behaviour, whichever compose version it reads.
- **CDP needs nothing.** `cdp-app-config` sets no `HOSTNAME_REWRITE` variable for any service, and CDP runs `NODE_ENV=production`, so the rewrite stays off there under either name. No write-up for Sam.
- **`docker/stack/AGENTS.md` needs no edit.** Its prose (`:451`) and table row (`:465`) already say admin uses `browserFacingHostnameRewrite` and `DEFRA_ID_BROWSER_FACING_HOSTNAME_REWRITE_ENABLED`. Today that is untrue; this change makes it true. Rejected: rewording it for the sake of touching it.
- **Admin's sign-out URL shape stays.** Animals adds a `post_logout_redirect_uri` query; admin does not. The row says sign-out behaves as today, so only the config key path changes in `get-sign-out-url.js`.
- **The admin unit test is rewritten to the animals exemplar's shape.** It mocks admin's own config module and asserts a spy call (`toHaveBeenCalledWith('defraId.oidcDiscoveryUrl')`), both house-rule breaches in a file this row edits. It moves to the animals pattern: set real config values per test and restore them after (`trade-imports-animals-frontend/src/auth/get-sign-out-url.test.js`). Rejected: renaming the keys inside the mock and keeping the breaches.
- **Config `format: Boolean` stays.** Animals uses a stricter boolean format; aligning admin's is a separate change with its own behaviour (how `"yes"` or `"1"` parse) and is a follow-up.
- **The security half of criterion 2 is proved outside this run.** The admin auth security spec (`trade-imports-ins-tests/tests/animals-admin/security/admin-auth.spec.ts`) is tagged `@active` (`:7`): it follows the dashboard Sign out link (`:21`) and checks the Defra ID sign-out heading (`:22`). It runs only through `test:docker-compose:animals-admin:security:active`, which needs the stack's ZAP security profile, and the stack is leased to this run in its normal profile. So section 5 names that script as the check and leaves it to the human's milestone run or CI's security run. Rejected: dropping it from the proof, which leaves half of criterion 2 unproved; and running it here, which needs the stack restarted under another profile.
