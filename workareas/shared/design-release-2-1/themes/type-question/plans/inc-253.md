## 0. Decisions

1. **Today's value is `Strict`.** `getCookieOptions()` (`src/plugins/auth.js:101-108`, both repos) passes no `isSameSite`. `@hapi/cookie` passes its `cookie` options straight to `server.state`, and `@hapi/statehood`'s default is `isSameSite: 'Strict'` (`node_modules/@hapi/statehood/lib/index.js:52`). No server-wide `state` default overrides it (`src/server/server.js:64-65` sets only `strictHeader`). The explicit value is therefore `Strict`, keeping behaviour exactly as it is.
2. **The comment at `auth.js:17` is wrong, so it is deleted.** It says a Lax policy is required on the session cookie for the redirect after Defra ID sign-out, but the cookie has been Strict all along and sign-out works (the animals and plants `auth.spec.ts` E2E specs). The row asks to keep today's behaviour, so the value stays `Strict` and the false comment goes. Rejected: switching to `Lax` to match the comment — that changes behaviour the row says to keep.
3. **The explicit value is a literal inside `getCookieOptions()`, not a config entry.** Nothing needs to vary it per environment, and a literal used by one function lives in that function. Rejected: a new convict entry and env var — that builds an option nothing sets.
4. **The Bell state cookie's config entry is renamed, key and env var, and moves under `defraId`.** Today it is `session.cookie.sameSite` (env `AUTH_COOKIE_SAME_SITE`). Its key says "session cookie" and its env var says "auth cookie", and both read as the session cookie, which it does not set: its one reader is `getBellOptions().isSameSite` (`auth.js:69`). Bell's state cookie belongs to the Defra ID strategy, so the entry moves under the `defraId` block of `src/config/config.js`. Its key, env var and `doc` all name the Defra ID (Bell) sign-in state cookie. The implementor picks the names, and uses one name for the concept across key, env var, test keys and test titles.
   - Renaming is safe in every environment. Nothing sets `AUTH_COOKIE_SAME_SITE`:
     - the workspace stack (`docker/`, `scripts/`): no hit;
     - the tests repo and both repos' `.github/` (the CI docker stack): no hit;
     - the local `cdp-app-config` clones (`~/git/defra/cdp-app-config`, last commit 28 Sep 2026, and `~/git/cdp/cdp-app-config`): no hit.
   - So every environment runs on the default, `Lax`, and still does after the rename. Rejected: changing only the `doc` string — the row prefers the rename when it is safe, and it is.
5. **Every single-use module constant in `config.js` is inlined into the one entry that uses it, in both repos.** The file is edited by this change, so it meets the structure rule in full. The test is "used by one entry, and not module set-up or a value a test imports". Three constants meet it, at the same lines in both repos:
   - `authCookieSameSite` (`:19`), used only by the state-cookie entry's `default` (animals `:188`, plants `:185`). Its value becomes the renamed entry's `default`.
   - `oneWeekMs` (`:11`), used only by the static-cache entry's `default` (animals `:70`, plants `:67`).
   - `csrfEnabled` (`:20`), used only by the CSRF entry's `default` (animals `:342`, plants `:339`). Its expression is inlined there.
   
   The others stay at module scope because the module shares them or sets itself up with them: `env`, `dirname`, `fourHoursMs` (two entries), `isProduction`, `isTest`, `isDevelopment`, `isLocal`, the renamed `isPlatform` (two entries) and `STRICT_BOOLEAN`. Rejected: inlining only `authCookieSameSite`, which applies the rule to one case of three.
6. **The rationale comment above `isSameSite` in `getBellOptions` (`auth.js:66-68`) moves to the README.** It explains why the state cookie must be `Lax`, which is rationale. Its home is each repo's README "AUTHENTICATION" section (animals `:200`, plants `:218`), which is the only auth documentation either repo has: neither has a root `docs/`, and `src/server/app/docs/` documents the journey engine, not the auth plugin. That section gains a short statement of the two cookies' SameSite settings and why each has its setting. This is a departure from the rule's named homes, recorded in section 14.
7. **Every comment in `auth.js` goes, except the rationale moved by decision 6, in both repos.** The file is edited by this change, so it meets the comment rules in full. These are the comments in `register`, `getBellOptions` and `getCookieOptions`, which describe hapi, Bell, Defra ID, another module or callers: `:15-17`, `:20-21`, `:24-25`, `:32-34`, `:52-53`, `:71`, `:73`, `:87`, `:90`, `:117`, `:122`, `:125`, `:142-143`. The line numbers are the same in both repos.
   - `:73` describes `getSafeRedirect`'s job, another module's, and the call on the next line already names it. Deleted.
   - Where a comment carries something a name can say (the token-expiry tolerance at `:125`, say), the implementor extracts or renames rather than losing the meaning.
   - The stub-mode comment (`:24-25`) is deleted with no README addition. Its fact, that stub mode signs a session locally in place of the Defra ID exchange and still enforces auth, is already stated in both repos by the `stubMode` config entry's `doc` (animals `config.js:266`, plants `config.js:263`). Plants' README also states it (`README.md:236`); animals' README does not, and does not need to, because the config `doc` is the operator-facing description of every env var. Rejected: adding a stub-mode paragraph to the animals README, which widens the README edit beyond this row's cookie facts for a fact already written down.
8. **The unit test for the session cookie asserts the strategy's options, not the Set-Cookie header.** A header assertion through `server.inject` would also pass without the change, because the library default is already `Strict`. Asserting that `getCookieOptions().cookie` states `isSameSite: 'Strict'` fails without the change. The exemplar is the existing "configured auth cookie name" test (`auth.test.js:300-302`). Rejected: the header-only test, which breaks the "a test must fail without the change it covers" rule.
9. **`config.js`'s other comments in both repos.**
   - The inline comment at `config.js:17`, explaining `isPlatform`, is deleted. `isPlatform` is renamed within `config.js` to a name saying the service is deployed to CDP. All its uses (`:17`, `:348`, `:381` animals; the matching lines in plants) are in this file.
   - In animals, the rationale comment above the strict-boolean format (`config.js:26-28`) is deleted (plants already has none).
   - Both edits are breaches in a file this change edits.
10. **The module mocks in `auth.test.js` stay for now** (see section 14). The row adds and adjusts tests in that file. Rewriting the whole suite to mock only at the network boundary is one change for all four twin auth plugins (animals, plants, INS, admin), not two of them. That goes to section 7.

## 4. Tests

All are unit tests (vitest), the same in both repos.

1. **The session cookie strategy states SameSite `Strict`.** This test is in `src/plugins/auth.test.js`, inside the `getCookieOptions` describe block, and follows `:300-302`. It asserts that `getCookieOptions().cookie.isSameSite` is exactly `'Strict'`. It turns red when the explicit `isSameSite` added to `getCookieOptions()` (section 2) is removed, because the value is then `undefined`.
2. **The Bell strategy's state cookie SameSite comes from the renamed config entry.** This test is in `src/plugins/auth.test.js`, next to the other `getBellOptions` tests. The config mock gives the renamed key a value other than the default (`Strict`, say). The test asserts that `getBellOptions(oidcConfig).isSameSite` equals that value exactly. It turns red if `getBellOptions` still reads `session.cookie.sameSite`, or reads nothing.
3. **The renamed env var sets the state cookie's SameSite, and the default is `Lax`.** This test is in `src/config/config.test.js`, with fresh-import set-up like the `auth.cookieName` block. The test:
   - stubs the renamed env var to `Strict` and asserts the renamed key reads `Strict`;
   - with nothing stubbed, asserts the default is exactly `Lax`.

   It turns red if the env var or key is not renamed in `config.js`.

## 14. Departures from written rules

- **`.claude/rules/code-quality.md`: "Rationale goes in the repo's `docs/` or the behaviour spec, never in code."** The cookie SameSite rationale (decision 6) goes in each repo's `README.md` "AUTHENTICATION" section, not in `docs/` or the spec.
  - The reason: neither repo has a root `docs/`. Its only docs folder, `src/server/app/docs/`, covers the journey engine, not the auth plugin. A new docs file would widen the row's footprint for a home alone.
  - The behaviour spec does not record cookie attributes (`openspec/config.yaml`), so it is not a home either.
  - The README auth section is where both repos already document sign-in set-up and its env vars.

- **`docs/best-practices/node/hapi.md:374-381`.** Its session-cookie example sets `isSameSite: 'Lax'`. This change states `Strict`. Reason: the row's criterion is to keep today's value, which is `Strict` (decision 1).
- **`.claude/rules/code-quality.md`: "Mock only at the boundary the code does not own … Never mock your own modules. No spy assertions … unless the call is itself the external side effect."** `src/plugins/auth.test.js` already mocks the config, mode, safe-redirect, refresh-token and logger modules, and asserts internal calls. This change adds tests to that file and leaves the existing mocks.
  - The reason: the same suite exists in four twin frontends, and two of them (INS, admin) are outside this row's repos. Rewriting only two would split one test design across the twins.
  - The new tests assert returned values only, with no spy assertions.
  - The rewrite for all four is a section 7 follow-up.
- **`.claude/rules/code-quality.md`: "One concept, one name, from request header to repository and across twin repos."** Animals and plants name the Defra ID state cookie's SameSite setting `defraId.stateCookieSameSite` / `DEFRA_ID_STATE_COOKIE_SAME_SITE`, while the INS frontend and animals admin keep `session.cookie.sameSite` / `AUTH_COOKIE_SAME_SITE`.
  - The reason: those two repos are outside this row's repos.
  - The twin-fix open questions now recorded on the inc-253 row and the section 7 follow-ups carry the work of aligning them.
