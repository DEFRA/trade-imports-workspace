## 0. Decisions

- **hapi-pulse's joi goes through an npm override, not an upgrade or downgrade.** hapi-pulse 4.0.0 is its latest release and pins `joi ~18.2.1`, which cannot reach 18.3.1. npm audit suggests going down to hapi-pulse 3.0.1, but that pins `joi ~17.9.2`, which is also in the affected range. Rejected: the downgrade (still vulnerable, and a major step back) and an allowlist entry (a patched joi exists).
- **The override is nested under hapi-pulse, in the existing `overrides` block in `package.json`,** beside the blankie entry, pinned to an exact patched 18.x release (18.3.2, the latest). Rejected: a top-level `joi` override, because the tree holds two joi majors (17 for bell, catbox-redis and blankie; 18 for jwt and hapi-pulse), and one override would force one major onto both.
- **blankie's existing override moves from `npm:joi@17.13.8` to `npm:joi@17.13.9`,** the patched 17.x. It stays on 17.x: blankie 5.0.0 is the latest release and its schema was proven against 17.x when the override was added (1c8bd2f). Rejected: aliasing it to 18.x, an untested major change for no audit gain.
- **Every in-range path is fixed in the lockfile alone,** with no `package.json` change: top-level joi to 17.13.9, `@hapi/jwt`'s nested joi to the latest 18.3.x, and `@hapi/content` to 6.0.3. This is how 1c8bd2f fixed cheerio's undici. Rejected: adding overrides for packages whose parent's range already admits the fix (the npm-upgrade skill keeps only overrides it can prove it needs).
- **No allowlist entry.** Every advisory has a patched version, so `audit-ci.jsonc`'s `allowlist` stays `[]`.
- **Moderate and low findings stay out of this row.** They do not fail the audit and the row asks only for it to pass. Noted as a follow-up.
- **No source change.** `src/server/common/helpers/pulse.js` passes hapi-pulse only `logger` and `timeout`, which joi 18.3 validates as it did 18.2; blankie's CSP options (`content-security-policy.js`) use no schema feature that differs between 17.13.8 and 17.13.9. Neither advisory's vulnerable call (`string().email({ multiple: true })`, multipart Content-Disposition parsing) is something this repo calls directly.
- The row's claim holds against the live tree. It names `hapi-pulse > joi`; the tree also has `blankie > joi` on the same advisory, through our own override, so this plan fixes that path too.
