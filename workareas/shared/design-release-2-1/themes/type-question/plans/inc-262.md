## 0. Decisions

- **Claims checked against the live tree.** All hold.
  - Admin makes the same three Defra ID calls through the one shared `@hapi/wreck` instance: discovery (`src/auth/get-oidc-config.js:9`), signing keys (`src/auth/verify-token.js:9`) and token refresh (`src/auth/refresh-tokens.js:19`). Bell's token exchange goes through that same instance too (`node_modules/@hapi/bell/lib/oauth.js:301`). There is only one copy of `@hapi/wreck` in `node_modules`, so swapping `Wreck.agents.http` reaches Bell.
  - Wreck's own plain-HTTP agent is `new Http.Agent({ maxSockets: Infinity })`, which does not keep connections alive (`node_modules/@hapi/wreck/lib/index.js:39`).
  - On the local stack, admin reaches the Defra ID stub through `host.docker.internal:3007` (`docker/stack/frontend.compose.yml:23`), the same forwarder path the twins' flake went through.
  - Admin's `startServer` (`src/server/common/helpers/start-server.js:4-14`) installs no agent today.
- **Where the agent lives:** a new `src/auth/wreck-agent.js` in admin, mirroring the twins' path and exported surface (one factory for the agent, one function that installs it on Wreck for the process). Rejected: a shared package across four repos. There is no shared Node package in this workspace, and the twins each keep their own copy.
- **Where it is installed:** in admin's `startServer`, before `createServer`, only when `httpProxy` config is unset. This mirrors the animals frontend. Rejected: installing it in `setupProxy` (`src/server/common/helpers/proxy/setup-proxy.js`). That function owns proxy set-up, and the twins keep the two apart.
- **Not adding the one-second-per-address connect timeout** (`setDefaultAutoSelectFamilyAttemptTimeout`) that the three frontends' `startServer` also sets. The row asks only for the agent. The twins' own commit records that the IPv6 attempt fails at once, so the IPv4 attempt is the only one and the per-address timeout never limits it. Listed as a follow-up. Rejected: copying INS's combined change.
- **Admin's copy of the agent meets the house rules in full, even where the twins differ.** The set of "never opened" error codes is used by one function only, so it lives in that function, not at module scope (code-quality.md, Structure). The twins keep it at module scope; that is a follow-up, not something to copy.
- **Proving the proxy branch.** The twins do not test the branch where a proxy is configured and the agent is not installed. AC 2 makes it load-bearing for CDP, so admin gets a unit test for it. Adding that test to the twins is a follow-up.
- **The proxy case gets its own test file, beside `start-server.test.js`.** Reasons:
  - `httpProxy` is read from `HTTP_PROXY` when config loads, so the environment must be set before the first import of config. One file cannot load config both with and without it without `vi.resetModules`, and `resetModules` does not reload `@hapi/wreck` (an externalised CommonJS dependency).
  - Taking the proxy branch runs `setupProxy`, which sets undici's global dispatcher and bootstraps `global-agent` for the process. Neither can be undone, so they must not reach the no-proxy tests.
  - Vitest runs each test file with its own module graph (`vitest.config.js` keeps the default `isolate`), so the proxy file's config, `setupProxy` and Wreck are its own.
  - Rejected: a second describe in `start-server.test.js` relying on `resetModules` and describe order. Order-dependence is what `frontend.md:292` rules out, and the Wreck instance would be shared.
- **Every test that runs `startServer` restores Wreck's original plain-HTTP agent afterwards, and destroys the agent the run installed.** This is `frontend.md:292` ("Restore what you change … a module-level fake must put it back in `afterEach`"), done the way the twin's `wreck-agent.real.test.js:117-123` does it for the install function. Three test files need it (both start-server test files and admin's `wreck-agent.real.test.js`), so it is a shared test helper (section 11), not three local copies.
- **The auth-off config seam goes through the shared `mockAuthConfig`.** `start-server.test.js:6-14` hand-writes a copy of `mockAuthConfig`'s body with `auth.enabled` forced to `false`. `frontend.md:58` names `mockAuthConfig` as the config seam when a server starts, and `frontend.md:95` says to extend the helper with an option rather than write a local copy. So `mockAuthConfig` gains an option for the auth setting, defaulting to on so its two existing callers (`src/server/auth/controller.test.js:12-14`, `src/server/signout/controller.test.js:11-13`) are unchanged, and both start-server test files use it with auth off. The local copy is deleted.
- **The start-failure test drives a real failure: the configured port already in use.** `startServer` awaits `server.start()`, which rejects for real when a listener already holds the port. The test opens a real `node:http` listener on the port config reads, and asserts `startServer` rejects with the address-in-use error. No spy on `createServer`. This removes the earlier departure and its follow-up.
- **Bounded tidy-up applies to `start-server.test.js` in full**, because it is edited for the row's own behaviour: no spy assertions, no `@hapi/hapi` spy, test titles that state only what their assertions prove.
- **No new log lines for installing or skipping the agent.** The choice follows config at startup, and `setupProxy` already logs that it is setting up global proxies when the proxy branch is taken (`setup-proxy.js:18`). The one outcome-changing branch the row adds is the retry, and that is logged (section 13).
- **The CDP half of AC 2 needs no config change.** CDP sets `HTTP_PROXY`, which admin reads as `httpProxy` (`src/config/config.js:105-111`), so the agent stays out and calls keep going through `global-agent`. Nothing is written to cdp-app-config.

## 3. New files

### `src/auth/wreck-agent.js`

Owns the retrying keep-alive HTTP agent and its installation on Wreck.

- **Behaviour (from the twin):**
  - The agent keeps connections open for the next call.
  - When a connection times out (`ETIMEDOUT`) or is refused (`ECONNREFUSED`) before it opens, it logs a warning and tries once more.
  - A second failure, or any other error, is passed on to the caller.
  - Nothing is written to a connection before it opens, so a token exchange is never sent twice.
- **Exports:** one factory taking a pino logger, and one function that sets `Wreck.agents.http` to a new agent built by that factory.
  - JSDoc on both exports states their contract (doc-comments guide), as the twin does.
  - The internal class and the connect helper get no doc comment.
  - The error-code set lives inside the function that reads it (section 0).
- **Why a new file:** no existing admin module owns outbound HTTP transport. `setup-proxy.js` owns proxy set-up only, and `src/auth/` is where the twins put this.
- **Follow:** the animals frontend's `src/auth/wreck-agent.js` at `a9944ea6`.

### `src/auth/wreck-agent.real.test.js`

Real-connection unit tests: real `node:http` servers on 127.0.0.1 and real Wreck calls. Nothing is mocked; the only boundary is the network, which is real. Vitest's default include picks the file up (`vitest.config.js` sets no `include`).

- **Why a new file:** it tests the new module. The `.real.test.js` name matches the twins, and keeps the real-socket tests apart from the module-mocked auth tests beside it.
- **Follow:** the animals frontend's `src/auth/wreck-agent.real.test.js` at `a9944ea6`, except that the install test restores Wreck's agent through the shared helper (section 11) rather than a local `afterEach`.

### A second start-server test file, beside `src/server/common/helpers/start-server.test.js`, for the proxy case

Owns the proxy-configured branch of `startServer`.

- Sets `HTTP_PROXY` and `PORT` in the environment before its first import of the server modules, and unstubs them afterwards (`frontend.md:292`).
- Its `PORT` is one no other admin test file uses, since files run in parallel.
- Uses `mockAuthConfig` with auth off, and the shared Wreck restore (section 11).
- Stops the server it starts.
- **Why a new file:** section 0. The proxy branch needs config loaded with `HTTP_PROXY` set, and it changes process-wide dispatchers that cannot be put back.
- **Name:** follows `start-server.test.js`'s naming, so the implementor names it for the proxy case.
- **Follow:** `start-server.test.js` as edited above.

### A shared Wreck-restore helper in `src/server/common/test-helpers/`

Owns the set-up and clean-up that keep a test's Wreck agent change from reaching the next test: capture Wreck's original plain-HTTP agent, and after each test destroy whatever agent is installed and put the original back.

- **Why a new file:** three test files need it (both start-server files and `wreck-agent.real.test.js`), and `src/server/common/test-helpers/` is where admin's shared test set-up lives (`mock-auth-config.js` beside it). It is not part of `mock-auth-config.js`, which owns the config seam only.
- **Follow:** `mock-auth-config.js` for file shape, and the twin's `wreck-agent.real.test.js:117-123` for the restore.

## 13. Operability

**One branch added: the retry when a connection is refused or times out before it opens.**

- It logs once at warn, with `{ err }` and the target host and port.
- From that, support can find which upstream (the Defra ID stub, or Defra ID itself) failed to accept a connection, and why (the error code).
- There is no request id at that layer: the socket opens before any request is written.

**The final failure after the retry is not logged here.** The error passes to Wreck's caller, and the caller's existing handling logs it:

- Bell surfaces it on the sign-in error page.
- `getOidcConfigWithRetry` logs its own retries.

**Installing or skipping the agent is not a new log line.** The choice follows config at startup, and `setupProxy` already logs the proxy branch.
