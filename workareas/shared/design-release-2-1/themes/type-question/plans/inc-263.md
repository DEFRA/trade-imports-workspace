## 0. Decisions

1. **The claim holds.** `repos/trade-imports-animals-frontend/src/server/app/sets/` holds `live-animals` only, so `/germinal-products/start` has no page behind it. The INS frontend's one route to it is the `germinal-products` entry in `NOTIFICATION_TYPES` (`destinations.js:21-26`). Removing that entry removes the link. Nothing else in `src/` builds a germinal start URL.
2. **`NOTIFICATION_TYPES` stays the one owner of what the question offers.** The option goes from that list. The controller's items, its `requiredOneOf` rule and the copy test's key check all read it, so none of them changes. Rejected: hiding the option in the template or the view model. That would leave a second rule beside the list, and the POST would still accept and hand over `germinal-products`.
3. **A posted `germinal-products` is refused like any other value the question does not offer.** This follows from decision 2, because validation reads the same list. The unit test proves it with a positive assertion: a 400 and the error summary, not a redirect. This proves "no redirect to the germinal start" without testing by absence.
4. **`SET_BASES.GERMINAL_PRODUCTS` goes too, in both repos.** Once the option is gone, nothing reads `SET_BASES.GERMINAL_PRODUCTS` in the INS frontend (`journey-set-bases.js:3`) or `SET_BASES.germinalProducts` in the tests repo (`page-objects/shared/sets.ts:3`). They would be dead code ("Build only what this change makes reachable"). The INS test that pins "every set base the journey frontends mount under" would also become untrue, because the animals frontend mounts no germinal set. The germinal products theme's row adds both back with its start page. Rejected: keeping them for that row. The rule says build only what is reachable now.
5. **Spec wording.** `openspec/config.yaml:81-83` says a scenario "states what is shown now. Never quote removed copy… Prove a removal with what the page shows in its place." So the scenarios state the four options in order and quote no germinal label. The row asks that the spec "say the option is not offered". That goes in REQ-INS-NTYPE-001's requirement text, in the present tense: the question offers four options and no germinal products choice, because the animals service serves no germinal products journey. Rationale belongs in the spec under the house rules. Rejected: a scenario whose THEN says "Germinal products is not shown". That proves a removal by absence and quotes removed copy.
6. **Scenario IDs.** SCN-INS-NTYPE-002-B and SCN-INS-NTYPE-005-D are deleted, and the other letters are not renumbered. IDs are stable, and the file already skips a letter (001 runs A–D, then F).
7. **The tests repo's "chose another type for a live animals notification" table becomes one test.** With germinal gone, `landingCases` in `notification-type.spec.ts:230-277` holds one row, Plants for planting. A table and loop with a callback for a single case is indirection for nothing, so it becomes one plain test for Plants for planting. Its title must stay identical to the one the table generates today for the Plants for planting row, because the SCN-INS-NTYPE-005-C entry in `openspec/coverage/ins/notification-type/coverage.json` already names that title. Rejected: keeping a one-row table.
8. **The dashboard scenario that names the second option** (SCN-INS-DASH-004-A, `openspec/specs/ins/notification-dashboard/spec.md:61`) changes, because it states "the second option is Germinal products". The second option is now Plants for planting. The dashboard FIT test reaches it through the shared `expectUnselectedNotificationType` helper, which reads `LABELS_IN_ORDER`. So no dashboard code or test changes, only the spec line and its coverage note.
9. **Workspace docs.** The row names `docs/repos/trade-imports-animals-frontend.md` and `docs/repos/trade-imports-ins-frontend.md`. The workspace repo is not a backlog repo, but the orchestrator commits these with the spec sync. Both are planned here.
10. **Left alone:** the address-book `return` tests that use a `/germinal-products/notifications` URL (`ins-frontend …/address-book/return-to.test.js:29`, `ins-tests …/address-book-navigation.spec.ts:85`). They prove that a return to any page on the animals origin is honoured. They are not a link to the germinal start, and the ins/address-book spec's germinal scenario (`spec.md:462`) is about that return, not this question.
