h3. Background

Design Release 2.1 redesigned the address book in the Import notification service front door (INS): how an address is added, viewed, edited, deleted, listed and searched, and what an address can be used for. It also changed how a live animals notification reaches the address book: adding an address from a notification, and viewing one from the notification's address pickers. This ticket is the whole of that work, under EUDPA-646, for both domains it touched, in two sections: the INS address book first, then the live animals journey. High-risk plants is not part of it: its pickers are not wired to the INS address book and are unchanged.

The work was delivered as six tickets, EUDPA-707, EUDPA-708, EUDPA-709, EUDPA-710, EUDPA-706 and EUDPA-711, then EUDPA-721 for the live animals pickers. All of that is *merged to main* across the INS frontend, the address book API, the live animals frontend, the test suite and the workspace repository that holds the specification. Check it in a test environment that has deployed those services since 10 November.

One later change is made under this ticket and is *not yet merged*: every type of address can now be in any country. Before it, a Destination, Consignee or Importer address and a Branch address could only be in the United Kingdom, as the Design Release 2.1 prototype has it. It is on the branch feat/EUDPA-789-any-country in the address book API, the INS frontend, the test suite and the workspace repository.

Two pieces of the design are not in this ticket. Finding a real UK address by search waits on the address lookup becoming a real feature (its rows are blocked, below). Saving an edit made from a live animals notification's picker lands on the address book list, not back on the picker, as the Design Release 2.1 prototype does. The questions still open with the designer are kept in the address book snagging list, workareas/shared/design-release-2-1/address-book-snagging.md in the workspace repository.

h3. What changes for the user

h4. Adding an address starts with what it is

Adding an address from the address book starts with its address type: Origin or Consignor; Destination, Consignee or Importer; or Branch. The trader then ticks what the address can be used for, from the roles that type offers. The form asks for the address and contact details under 'Address' and 'Contact details', names each missing field in the form's own words, keeps a value that is too long, and offers every country for every type of address, opening on United Kingdom.

h4. The list is split by address type and can be filtered

The address book list has a tab per address type, with a Type column naming each address's roles. (A Transporter tab and address type were added afterwards by EUDPA-781 and are not part of this ticket.) A 'Filter addresses' disclosure holds a search that matches an address's name, any address line, town, county, postcode, country or role, and a Type filter for the tab. The list shows eight addresses a page, newest first, with each address line on its own line, and a page number out of range shows a real page.

h4. Viewing, editing and deleting match the design

An address's own page lists its details against their labels, leaving out empty optional fields, with Edit and Delete. Deleting asks for confirmation first, summarising the address. The success banner after an add, edit or delete stays until the trader leaves or reloads the page. A link to an address that is no longer in the book returns to the list rather than a 'Page not found' page.

h4. The address book returns the trader to where they came from

Opened from another page of the service, or from a live animals notification, an address's Back link and its delete confirmation return the trader to that page. Opened from a notification's picker, they return to the same picker, with its search, page and chosen address kept.

h4. Adding an address from a notification

A live animals notification's 'Add a new address' opens the INS add page in journey mode: it shows the notification's status, takes its role from the picker it was opened from, asks what else the address should be used for from that role's side, offers every country (opening on United Kingdom for a consignee, importer or place of destination, and on 'Select a country' otherwise), and returns to the notification. Save and select chooses the new address for the role. Save and return goes back to the picker with the new address listed first. Cancel saves nothing.

h4. The notification's address pickers show addresses as the design does

On the five live animals party pickers, the list fills the content column, each address shows its street lines on their own lines and then its town, county and postcode together, and each row ends with a 'View' link to that address in the address book instead of a 'View details' expander.
