<h3><a name="Whatchangesfortheuser"></a>What changes for the user</h3>

<h4><a name="Addinganaddressstartswithwhatitis"></a>Adding an address starts with what it is</h4>

<p>Adding an address from the address book starts with its address type: Origin or Consignor; Destination, Consignee or Importer; or Branch. The trader then ticks what the address can be used for, from the roles that type offers. The form asks for the address and contact details under 'Address' and 'Contact details', names each missing field in the form's own words, keeps a value that is too long, and offers only the United Kingdom as the country for a receiving or branch address.</p>

<h4><a name="Thelistissplitbyaddresstypeandcanbefiltered"></a>The list is split by address type and can be filtered</h4>

<p>The address book list has a tab per address type, with a Type column naming each address's roles. (A Transporter tab and address type were added afterwards by 
    <span class="jira-issue-macro resolved" data-jira-key="EUDPA-781" >

 and are not part of this ticket.) A 'Filter addresses' disclosure holds a search that matches an address's name, any address line, town, county, postcode, country or role, and a Type filter for the tab. The list shows eight addresses a page, newest first, with each address line on its own line, and a page number out of range shows a real page.</p>

<h4><a name="Viewing%2Ceditinganddeletingmatchthedesign"></a>Viewing, editing and deleting match the design</h4>

<p>An address's own page lists its details against their labels, leaving out empty optional fields, with Edit and Delete. Deleting asks for confirmation first, summarising the address. The success banner after an add, edit or delete stays until the trader leaves or reloads the page. A link to an address that is no longer in the book returns to the list rather than a 'Page not found' page.</p>

<h4><a name="Theaddressbookreturnsthetradertowheretheycamefrom"></a>The address book returns the trader to where they came from</h4>

<p>Opened from another page of the service, or from a live animals notification, an address's Back link and its delete confirmation return the trader to that page. Opened from a notification's picker, they return to the same picker, with its search, page and chosen address kept.</p>

<h4><a name="Addinganaddressfromanotification"></a>Adding an address from a notification</h4>

<p>A live animals notification's 'Add a new address' opens the INS add page in journey mode: it shows the notification's status, takes its role from the picker it was opened from, asks what else the address should be used for from that role's side, and returns to the notification. Save and select chooses the new address for the role. Save and return goes back to the picker with the new address listed first. Cancel saves nothing.</p>

<h4><a name="Thenotification%27saddresspickersshowaddressesasthedesigndoes"></a>The notification's address pickers show addresses as the design does</h4>

<p>On the five live animals party pickers, the list fills the content column, each address shows its street lines on their own lines and then its town, county and postcode together, and each row ends with a 'View' link to that address in the address book instead of a 'View details' expander.</p>
