h3. Background

This theme brings a live animals notification's overview, its review page (check your answers), its view header, the declaration and the notification submitted page up to Design Release 2.1. The review is regrouped into numbered sections of titled cards, and each commodity, document and address reads back the way the design shows it. A submitted notification and a draft each open under a header naming the notification by its reference, with its status, its date and the actions it allows. Submitting now checks more of the answers it needs before it accepts a notification.

This matters to a trader importing live animals into Great Britain, and to anyone who reads their notification afterwards. The review reads like the notification it describes, an unfinished card says what to complete in the card's own words, and the error summary takes the trader straight to it. A trader amending a notification is told whether they are re-submitting changed answers. A notification missing its main import reason, the answers that reason calls for, or what the animals are certified for, is refused at submission rather than sent incomplete.

High-risk plants gets part of this: the view header, the party cards' address read-back, the import reference numbers and the task list regions. It does not get the new review sections, the commodity and document cards, Cancel amend, Copy as new on a draft, the submission checks or the identifier item on the notification submitted page. Its customs document code is C085, where live animals' is C640. The sibling ticket is the high-risk plants one, EUDPA-828. The Import notification service front door's pull request changed only its tests, so it has no ticket.

Two things the theme built along the way are not in the result. A notification submitted without its health certificate was first given a new status, "Submitted action required"; a later row took it out, so such a notification is now plain "Submitted". And one row merged the identification details and permanent address work from {{main}} into this theme's branch: that behaviour is on its own ticket, EUDPA-796, and is not counted here.

This work is merged. It landed on {{main}} on 20 November 2026 in the live animals frontend, the animals backend, the high-risk plants frontend, the Import notification service front door, the end-to-end test suite and the behaviour specification, each through its own pull request. The acceptance criteria below are the behaviour specification as it stands on {{main}}.

h3. What changes for the user

h4. The overview

The task list is one region headed "Notification task list", holding the six numbered sections as regions. The commodity totals are regions named "Animals summary" and "Packages summary". A screen reader reads each task link's status with it. Consignment addresses is the only task with a hint.

h4. The review's sections and cards

Each card's title is a heading one level below its numbered section, and every card is a region named by its title. The reason, additional details and contact address each have a card of their own. Origin shows the region of origin code or "Not applicable". The port of exit reads as the option chosen, and transit countries sit inside the Arrival details card. A "What are you importing?" card reads the commodity back, then each commodity code has a card holding a block per species, with its counts and its identification table. The Consignment addresses card lists each animal's permanent address and reads a CPH number with slashes. Each uploaded document has its own card showing its file name.

h4. Ending the review, and the amendment's heading

An amendment's review ends with Continue, Cancel amend and a red Delete. It is headed "Review your notification" until an answer changes, then "Review before re-submitting". Adding only a document, or putting a changed answer back, keeps the first heading.

h4. The view header

A submitted notification is headed by its reference with a green "Submitted" tag, the UK date submitted, and Amend this notification, Copy as new and Delete. A draft has a blue "Draft" tag, its date created, Copy as new and Delete, and keeps its Change links, errors and Continue. Both show the import reference numbers, with customs document code C640, as text to copy; a Copy button waits on design. Every action works without JavaScript.

h4. Submitting

A notification is not ready to submit without its main import reason, any follow-up answer that reason calls for, what the animals are certified for, or, for cattle, the unweaned answer. Each can be left blank while working and is named when the trader continues. A confirmed declaration on an unfinished notification goes back to check your answers naming every unfinished card, and one the service cannot save shows the declaration again with a message. The notification submitted page lists the animal identifier item when the animals are not all identified, and shows the declaration instead when asked for too early.

h4. What a submission records

A submission is recorded as "Submitted" with its date, with or without the health certificate (ITAHC). Cancelling an amendment returns it to "Submitted" with its original date. Whether an amendment changed any answers is always yes or no, and a change to the documents alone is a no.

h4. Where the journey goes next

The CPH number page and the upload documents page go on to Consignment addresses, which goes on to Contact address.

h3. Acceptance criteria

These are copied from the behaviour specification, which is where they are maintained. This theme added 120 scenarios across 10 specification files for live animals. 30 are written out below, and the other 90 are named by their headings beneath their group: each is a mirror, pair, boundary or neighbour of one that is written out, so nothing is hidden, and Jira's size limit is what decides the number. Every file is linked in full at the foot of this ticket.

h4. The overview's regions and hints

h5. The task list is a region headed Notification task list holding the six numbered sections as named regions

* *GIVEN* a fresh notification
* *WHEN* the user views Overview
* *THEN* a region named Notification task list, by its visible heading, holds six regions named 1. About the consignment, 2. Description of the goods, 3. Transport and arrival, 4. Documents, 5. Addresses and 6. Contact address
* *AND* the 1. About the consignment region holds the Main import reason task

_Also specified in this group:_ "Consignment addresses is the only row with a hint"; "The two commodity totals are named regions inside the Your commodities region"; "A task link is described by its status".

h4. The review's sections and card titles

h5. Every card is titled one heading level below its numbered section, with no subsection heading between

* *GIVEN* the user is viewing the review for a notification with commodities entered
* *WHEN* they read down the page
* *THEN* every card's title is a heading one level below its numbered section heading
* *AND* no subsection heading stands above a card, none of "Where is this consignment coming from?", "Commodity details", "Upload documents", "Consignment addresses" or "Contact address for this consignment"
* *AND* "1. About the consignment" holds the cards "Origin of import", "What are you importing?" and "Main import reason", in that order

_Also specified in this group:_ "The reason, additional details and contact address answers stand on their own titled cards"; "A new notification's unfinished messages name the origin, reason and additional details cards in their titles' words"; "Every card is a region a screen reader announces by the card's own title".

h4. Origin, import reason and transport rows

h5. A given region of origin code reads on its row

* *GIVEN* a notification whose origin needs a region of origin code and has one saved
* *WHEN* the user views the review
* *THEN* the Origin of import card's rows are keyed "Country of origin", "Region of origin code" and "Internal reference number", in that order
* *AND* the "Region of origin code" row reads the saved code

h5. The port of exit row reads the option the user chose

* *GIVEN* a transit notification whose port of exit is Port of Dover
* *WHEN* the user views the review
* *THEN* the "Port of exit" row reads "Port of Dover - GB DVR", the same text as the option they chose

h5. A road notification reads its transit countries inside the Arrival details card

* *GIVEN* a notification arriving by road, with France and Belgium added as transit countries
* *WHEN* the user views the review
* *THEN* the Arrival details card holds a "Transit countries" subsection
* *AND* its "Countries that the consignment will travel through" row reads "France, Belgium"
* *AND* that row's Change link opens the transit countries page
* *AND* no card titled "Transit countries" is shown

_Also specified in this group:_ "A transit notification shows its port of exit then its destination country, and no exit date"; "A region of origin code that is not needed reads Not applicable"; "The arrival date row is keyed at the port of entry"; "An air notification has no transit countries subsection"; "A submitted notification's transit countries row has no Change link"; "A commercial transporter's five rows read its saved values"; "A transporter with no approval number reads Not applicable".

h4. What are you importing? and the commodity cards

h5. The card reads the selection back in three rows with a Change link

* *GIVEN* a notification with Bos taurus selected under commodity code 0102
* *WHEN* the user views the review
* *THEN* the "What are you importing?" card has rows "Commodity code", "Common name" and "Species", reading "0102", "Domestic Cattle" and "Bos taurus"
* *AND* its Change link opens the commodity selection page

h5. Species under two commodity codes stand as two cards, each holding only its own species' blocks

* *GIVEN* a notification with Bison bison and Bos taurus selected under commodity code 0102, and Felis catus under commodity code 01061900, each with a number of animals entered
* *WHEN* the user views the review
* *THEN* "2. Description of the goods" holds a card titled "0102" and then a card titled "01061900"
* *AND* the "0102" card holds a "Bison bison" block and a "Bos taurus" block, and the "01061900" card holds a "Felis catus" block alone
* *AND* each block's "Number of animals" reads the number entered for its species

h5. Each animal's row is labelled with its species name and number

* *GIVEN* a cat line of two saved animals
* *WHEN* the user views the cat's block on the review
* *THEN* the first cells of the table's rows read "Felis catus 1" and "Felis catus 2"

h5. A species with a count and no identifier is named and linked to its block

* *GIVEN* a notification with two species selected under identified commodities, each with a count and no animal identified
* *WHEN* the user views the review
* *THEN* the error summary reads "Enter at least 1 animal identifier for <species>" for each, the species name in lower case
* *AND* each entry links to that species' block
* *AND* following the entry for bos taurus moves focus to that species' block, whose heading reads "Bos taurus"

_Also specified in this group:_ "A block shows its counts and no commodity or species rows"; "Identification details has its own Change link on an editable review"; "Two species of one commodity share one code"; "Each species under other live mammals adds its own code and common name"; "A submitted notification's card has no Change link"; "Two species of one commodity stand as two blocks in one card"; "A blank package count reads Not applicable and a species with no packaging shows no package row"; "The card and the first row of each block carry their own Change links to consignment details"; "A submitted notification's commodity cards and blocks have no Change links"; "Identification details is a heading one level below its species heading"; "With no commodity selected the What are you importing? card is marked unfinished"; "Incomplete consignment details name commodity details and link to the first commodity card"; "A species with no count is named and linked to its block"; "A single identified species with no identifier is not named".

h4. The Addresses and Contact address cards

h5. A role never answered gives one error summary entry for the Consignment addresses card and none for the role

* *GIVEN* a draft notification complete except that one role was never answered

* *THEN* the error summary holds the single entry "Complete consignment addresses", linking to the Consignment addresses card

* *THEN* the review opens showing the edited details
* *WHEN* the user chooses "Edit details" again and cancels
* *THEN* the review opens with the address as it was

_Also specified in this group:_ "The Permanent address subsection lists an entry for each animal that has a saved permanent address"; "A stored county parish holding number reads with slashes"; "An animal that still owes a permanent address has no entry, while commodity details and consignment addresses are both still reported outstanding"; "A line needing a permanent address with no animal counted gives no Permanent address subsection"; "A stored CPH number that is not nine digits reads exactly as stored"; "A role whose copied address breaks the address-book rules is named in the error summary"; "The address cards carry only the links they offer"; "The review reads the filled party back as name, address lines and country".

h4. Uploaded documents

h5. Each uploaded document stands on its own card showing its file name

* *GIVEN* a notification with two documents uploaded
* *WHEN* the user views the review
* *THEN* "4. Uploaded documents" holds a card titled "Document 1" and a card titled "Document 2", in upload order

h4. What a submission records

* *GIVEN* a notification with no uploaded documents, or only a veterinary certificate

* *AND* once every changed answer is put back, the answers are reported as not differing
