h3. Background

This theme brings a high-risk plants notification's check answers page and its overview up to Design Release 2.1. A submitted notification and a draft now each open under a header that names the notification by its reference, shows its status and date, and offers the actions that notification allows. The header shows the import reference numbers a trader quotes to customs, with high-risk plants' own customs document code, C085. Each party card reads its copied address back as a name and an address, and the overview's task list is announced to screen readers by name.

This matters to a trader bringing high-risk plants into Great Britain. They can tell at a glance which notification they are looking at, whether it is a draft or submitted, and when it was created or submitted. A submitted notification is clearly read-only, with one way to change it: Amend this notification. A draft keeps its Change links and its errors, and can be deleted from its header. A trader who asks for the notification submitted page of a notification they have not yet submitted is taken to its declaration instead, so they cannot think it has been sent when it has not.

Live animals gets more from this theme than high-risk plants does. Its review was regrouped into new numbered sections with cards for each commodity, document and address. An amendment's review offers Cancel amend and says when the trader is re-submitting. A draft's header also offers Copy as new. Submitting checks the import reason and additional details answers, and the notification submitted page lists the animal identifier item. None of that is part of high-risk plants. A high-risk plants draft's header offers Delete notification only, and its customs document code is C085 where live animals' is C640. The sibling ticket is the live animals one, EUDPA-696, raised under this theme. The Import notification service front door's pull request changed only its tests, so it has no ticket.

This work is merged. It landed on {{main}} on 20 November 2026 in the high-risk plants frontend, the live animals frontend, the animals backend, the Import notification service front door, the end-to-end test suite and the behaviour specification, each through its own pull request. The acceptance criteria below are the behaviour specification as it stands on {{main}}.

h3. What changes for the user

h4. The overview's task list is a named region

The overview's four groups of tasks sit inside one region headed "Notification task list", each group a region named by its own heading, so a screen reader user can move between them. The heading has a Welsh name. The section once called "Consignment parties" is now "Addresses", on the overview and in the caption above the pages it holds.

h4. A submitted notification opens under its own header

The page is headed by the notification's reference, with a green "Submitted" tag beside it and the UK date it was submitted. It is read-only: no Change links and no continue button. The header offers "Amend this notification", which opens the amendment, and a red "Delete notification". Both work without JavaScript.

h4. A draft opens under the same header, and stays editable

A draft's check answers is headed by its reference, with a blue "Draft" tag and the UK date it was created. Its cards keep their Change links, its error summary lists every unfinished section, and it ends with the continue action, then "Save and return to overview", then "Cancel and return to overview". Its header offers only "Delete notification", which opens the delete confirmation.

h4. The import reference numbers

Both a submitted notification and a draft show an "Import reference numbers" section with its warning, the notification reference, and the customs document code C085, as text a trader can select and copy. There is no Copy button yet: that waits on design.

h4. Each party card reads its address as an address

The place of destination, consignor and consignment contact cards each read back a name and an address. The address shows each line that has a value on its own line, then the country, with no telephone number or email address. A copied party whose email breaks the address book's rules shows that message on its Name row.

h4. The notification submitted page, and a notification that does not exist

Asking for the notification submitted page of a notification that has not been submitted, or of an amendment not yet re-submitted, shows its declaration instead. Opening the view of a notification that does not exist shows "Page not found".

h3. Acceptance criteria

These are copied from the behaviour specification, which is where they are maintained. This theme added 23 scenarios across 4 specification files for high-risk plants, and every one of them is written out below. Every file is linked in full at the foot of this ticket.

h4. The overview's task list is a named region

h5. The four groups are named regions inside the region headed Notification task list

* *GIVEN* the user has started a notification and saved the commodity type
* *WHEN* they view Overview
* *THEN* a region named "Notification task list", by its visible second-level heading, holds four regions named by the four group headings
* *AND* each group heading is a third-level heading
* *AND* the only second-level heading on the page is "Notification task list"

h5. The task list heading and region have a Welsh name

* *GIVEN* Welsh is chosen
* *WHEN* the user views Overview
* *THEN* the task list heading reads "Rhestr dasgau’r hysbysiad" and names the task list region

h4. A submitted notification opens under its own header

h5. The submitted view is headed by its reference with a Submitted tag and no status bar

* *GIVEN* a submitted notification
* *WHEN* the user views it
* *THEN* the level-1 heading is the notification's reference number
* *AND* a green "Submitted" tag stands beside the heading
* *AND* no status bar is shown above it

h5. The date submitted is the UK day of the submission

* *GIVEN* a notification submitted at 23:30 UTC on 21 July 2026
* *WHEN* the user views it
* *THEN* the header reads "Date submitted: 22 July 2026"

h5. The submitted view is read-only and offers Amend this notification and Delete notification

* *GIVEN* a submitted notification is open on check-your-answers
* *WHEN* the user views it
* *THEN* the status tag in the header reads "Submitted"
* *AND* no Change or Edit details links and no continue action are offered
* *AND* the header offers "Amend this notification", posting from a form of its own, and a red "Delete notification" link outside it
* *AND* no "Copy as new" or cancel-amendment action is shown
* *AND* Delete notification is offered only in the header, and not at the foot of the view

h5. Amend this notification starts an amendment

* *GIVEN* a submitted notification is open on check-your-answers
* *WHEN* the user presses "Amend this notification"
* *THEN* the notification is opened for amendment and its status bar reads "Amend"

h5. The header actions work without JavaScript

* *GIVEN* a submitted notification's view, with JavaScript off
* *WHEN* the user presses "Amend this notification"
* *THEN* the amendment opens
* *WHEN* the user uses "Delete notification"
* *THEN* the delete confirmation page opens

h5. The submitted view and a draft's check answers are titled by their references, and an amendment keeps its title

* *GIVEN* a submitted notification, a draft notification and an amendment
* *WHEN* the user views each
* *THEN* the submitted view's browser title reads "<reference> - Import notification service - GOV.UK"
* *AND* the draft's check answers is titled by its reference in the same way
* *AND* the amendment's review is headed "Check your answers" with an "Amend" status bar

h4. A draft opens under the same header, and stays editable

h5. A draft's check answers is headed by its reference with a Draft tag and no status bar

* *GIVEN* a draft notification
* *WHEN* the user views its check answers
* *THEN* the level-1 heading is the notification's reference number
* *AND* a blue "Draft" tag stands beside the heading
* *AND* no status bar is shown above it

h5. The date created is the UK day the notification was created

* *GIVEN* a draft notification created at 23:30 UTC on 21 July 2026
* *WHEN* the user views its check answers
* *THEN* the header reads "Date created: 22 July 2026"

h5. The header offers only Delete notification

* *GIVEN* a draft notification
* *WHEN* the user views its check answers
* *THEN* the header offers a red "Delete notification" button
* *AND* the header offers no "Copy as new" and no "Amend this notification"

h5. The draft view invites submission, and its header offers Delete notification

* *GIVEN* a draft notification is open on check-your-answers
* *WHEN* the user views it
* *THEN* it invites them to continue to the declaration to submit
* *AND* the continue action is followed by "Save and return to overview"
* *AND* the "Cancel and return to overview" link stays below the buttons
* *AND* a red "Delete notification" button is offered in the header, not beside the continue action
* *AND* no cancel-amendment action is offered

h5. Change links, errors and Continue stay

* *GIVEN* a draft notification with incomplete sections
* *WHEN* the user views its check answers
* *THEN* its cards keep their Change links
* *AND* the error summary lists each incomplete section
* *AND* the page ends with a continue action

h5. Delete notification on a draft opens the delete page

* *GIVEN* a draft notification is open on check-your-answers
* *WHEN* the user presses "Delete notification" in the header
* *THEN* the notification's delete page opens

h5. A draft's check answers opens the delete confirmation

* *GIVEN* a draft notification is open on check-your-answers
* *WHEN* the user chooses "Delete notification"
* *THEN* the delete confirmation opens

h4. The import reference numbers

h5. The section shows the warning, the reference row and the customs document code row

* *GIVEN* a submitted notification
* *WHEN* the user views it
* *THEN* an "Import reference numbers" section shows the warning
* *AND* its rows are "Notification reference", reading the notification's reference number, and "Customs document code", reading "C085"

h5. The values read as text and no button shows without JavaScript

* *GIVEN* a submitted notification and a browser with JavaScript off
* *WHEN* the user views it
* *THEN* the section shows the warning, the reference and "C085" as text
* *AND* the section shows no button

h5. A draft shows the warning, the notification reference and the customs document code

* *GIVEN* a draft notification
* *WHEN* the user opens its check answers
* *THEN* the "Import reference numbers" section shows its warning, a "Notification reference" row and a "Customs document code" row reading "C085" as text
* *AND* the section has no Copy button

h4. Each party card reads its address as an address

h5. Party details appear on the party cards

* *GIVEN* a notification has a place of destination, a consignor and a consignment contact selected
* *WHEN* the user views check-your-answers
* *THEN* each of those cards has a "Name" row and an "Address" row, and no "Telephone number" or "Email address" row
* *AND* each card's "Address" row reads each non-empty address line on its own line, followed by the country on its own line

h5. A copy whose email breaks the address book's rules shows that message on the Name row

* *GIVEN* a notification whose copied party has an email address that breaks the address book's rules
* *WHEN* the user views check-your-answers
* *THEN* that party's card shows the email message above the name, on its "Name" row

h4. The notification submitted page, and a notification that does not exist

h5. Requesting confirmation for an unsubmitted notification redirects to its declaration

* *GIVEN* a notification has been started but not submitted
* *WHEN* its confirmation page is requested directly
* *THEN* the declaration, headed "Declaration", is shown instead

h5. Requesting confirmation for an amendment not yet re-submitted redirects to its declaration

* *GIVEN* a submitted notification has an amendment open that has not been re-submitted
* *WHEN* its confirmation page is requested directly
* *THEN* the declaration is shown instead

h5. An unknown notification shows page not found

* *GIVEN* a signed-in user
* *WHEN* they open the view of a notification that does not exist
* *THEN* the page not found status is returned
* *AND* the page is headed "404" and reads "Page not found"
