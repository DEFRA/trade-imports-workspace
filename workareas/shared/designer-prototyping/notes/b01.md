## Cross-commit patterns in this batch

1. **One big "updates" commit then same-day fix-ups.** 10:57 large restructure →
   11:00 SCSS fix → 11:10 layout fix → 15:43 content + bug fix. The designer
   commits when the browser looks right, not per-feature; commit messages are
   generic ("updates to v1", "more updates", "content changes") and carry no
   information about scope. Any tooling that wants to understand what changed
   has to diff, not read messages.
2. **Copy lives in three places at once.** The same label change needs edits in
   the view (`pageName` + `<h1>`), in `routes.js` (hub task-list `text`, review
   card `title`, `reviewCardErrorState` label) and sometimes in a data file.
   "Notification hub → Overview" was changed in the view but not in the route
   path or the "return to hub" button copy — partial renames are normal.
3. **routes.js is the model, the view-model and the controller.** New behaviour
   = new helper function in routes.js + edit to the redirect chain + edit to the
   guard chain. Flow changes are made by editing string literals in
   `res.redirect()` and `backLink:`; there is no route table or flow definition
   to change in one place, which is why the guard order had to be re-sequenced
   on eight handlers.
4. **Guards and validators are switched off rather than fixed** when they get in
   the way (`redirectIfNoArrivalDetails`, `validatePermanentAddressAnimalsForm`,
   `validateArrivalDetails`, `validateConsignmentAddressesComplete`,
   `validateContactAddress`, packages validation). The functions are left in
   place returning empty results or never called. Expect the codebase to
   accumulate dead validators.
5. **Conditional reveals via nested `res.app.render` callbacks.** Each new
   reveal adds one level of nesting (now three deep) and a partial under
   `views/partials/`. This is the designer's go-to for a radio option that
   reveals a select.
6. **Hand-rolled BEM tables instead of govuk components.** The "summary table"
   pattern (header row, fixed-width key column, value column, action column
   with a link-styled `<button>`) is rebuilt per page with a new class prefix
   each time and pixel widths tuned in follow-up commits (a5cc430). The
   `govukTable` import was removed to make room for it. `govukSummaryList` is
   not used anywhere for these.
7. **Per-page "shell" wrappers replace a shared layout.** `layouts/journey.html`
   existed to give a two-thirds column; four pages left it in one commit for a
   960px full-width shell, each with its own duplicated SCSS block. Layout
   decisions are made per page, not per layout.
8. **Query-param context (`?from=hub`) for back-links**, then a hidden field to
   carry it across POST once the bug is noticed (same day).
9. **Session-persistence side effects are worked around, not designed around.**
   Prototype Kit auto-stores every posted field, so `resetUploadDocumentFormState`
   deletes keys by name to stop stale form values reappearing.
10. **Reference data is typed in by hand as JS arrays** (`exit-border-control-posts.js`
    with 11 GB BCPs, Crown Dependencies added to `countries.js`, hint copy for
    eleven purposes). A stub reference-data service would replace these lists
    directly.
11. **No versioned view folders yet.** On 2 Jul the prototype is one linear
    "v1"; the copy-a-folder-per-release pattern (`design-release-2`,
    `design-release-2.1`, `testing`) starts on 15–22 Jul (2191e30 "testing
    version", 6d3dd1e "dashboard changes to design release 2").
12. **Buttons to not-yet-built pages are `href="#"`** (Add a transporter,
    Address book, Manage account, Log out) and get wired up in later commits
    (c93fe37 "add a transporter" on 7 Jul, dc8dcc6 "new address book" on 23 Jul).
