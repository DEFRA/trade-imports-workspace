## Cross-commit patterns

1. **One page pattern, cloned per entity.** The transporter add pages (c93fe37) are near-copies of the address-book
   add pages; `buildContactAddressResults` (649f527) is a copy of `buildConsignmentAddressResults`;
   the contact-address page (649f527) is the consignment-address-select markup with names changed. Field partials are
   duplicated four times (ef0b828 edits all four to add County). Nothing is extracted into a shared macro or helper —
   copy-adapt is the reuse mechanism.
2. **Session-array "database" + flash message, every time.** Each new "add" flow follows the same recipe:
   `sessionData.<thing>AddedX.unshift(item)` with `id: <prefix>-<Date.now()>`, `status: 'New'`, merge with the static
   `app/data/*.js` list in a `getAll*(sessionData)` helper, stash `<thing>SuccessMessage`, read-and-delete on the next
   GET, render `govukNotificationBanner type=success`. The same shape appears for transporters (c93fe37), address-book
   entries (pre-existing), and contact addresses (ebf9f4c).
3. **"Return-to" via query string -> session marker.** `?from=<section>` / `?return=<path>` set a session object that
   the shared address-book pages consult for back link, cancel href, guard and post-save redirect. Extended twice in
   this batch (bb69dff for view pages, ebf9f4c for contact address).
4. **Per-page session guards.** New multi-step flows guard each step on a session key
   (`redirectIfTransporterAddTypeNot`, `redirectIfNoAddressBookAddressType`) rather than on URL params.
5. **Same-day iterate / fix cadence.** 3832376 opens the filter details at 11:01, ee90b5f closes them at 16:33.
   ef0b828 (17:09) adds county to four partials; ebf9f4c (17:18, nine minutes later) finishes the plumbing that was
   missed. 649f527 next morning undoes part of `setAddressBookContactReturn` and fixes a JS scoping bug introduced by
   putting the search module on a second page. Commit messages are terse or placeholder ("6786", "new", "updates",
   "address changes", GitHub-default "Update dashboard.html").
6. **Content/label sweeps span every copy.** "Name or organisation" -> "Name or organisation name" is applied across
   partials, validation messages and summary-list keys in two commits (ef0b828, ebf9f4c) — a designer making a
   content decision then chasing every occurrence by hand.
7. **Pixel-parity SCSS over govuk defaults.** Each new page gets its own `.app-<page>-*` BEM block with hard-coded
   Figma values (630/420/315px input widths, 191x40px selects with an inline SVG chevron, weight-300 19px labels,
   30px flex gaps). The custom select recipe is pasted into the SCSS at least three times in this batch
   (dashboard filters, dashboard sort, transporter forms). `application.scss` is one ~5,800-line file.
8. **Monolithic routes.js.** All handlers and helpers live in one ~6,200-line `app/routes.js`; each new flow adds
   100-450 lines of parse/validate/build/render helpers plus routes, hand-written, with no tests.
9. **Data files for option lists; rest is static fixtures.** `app/data/transporter-types.js` is the only new data file;
   option lists get a module, but records (transporters, addresses) stay as hard-coded fixtures that session arrays
   are layered on top of.
10. **Reset entry point for testing sessions.** `/create-notification` (bb69dff) wipes the journey but keeps the
    address book — a deliberate "persistent account data vs per-notification data" distinction for usability sessions.
11. **No version folders in this batch.** Unlike later `design-release-*` / `testing` copies, this week's work edits
    the live top-level views directly — the versioning-by-folder habit had not started (or was not in use) yet.
12. **Visual-only controls are acceptable.** The dashboard filter panel (3832376) has no handler; controls exist to be
    seen and clicked, not to filter. Fidelity of appearance is prioritised over behaviour where behaviour is not the
    research question.
