## Cross-commit patterns

1. **Whole-journey fork as a folder copy.** The designer's way to try something without breaking what stakeholders are looking at is to copy *every* journey view into a new folder (`app/views/testing/`) and serve it under a URL prefix. 24 files copied in one commit, each differing by only the phase-banner removal and `/x` → `/testing/x` href rewrites. At HEAD the same pattern has produced `design-release-2/` and `design-release-2.1/` too, and `testing/` was never deleted. This is the single most important pattern for the plants-prototype work: designers want cheap, isolated "versions".

2. **The fork is smarter than a plain copy — but only in this instance.** `app/lib/testing-version.js` avoids duplicating `routes.js` by cloning the router stack and monkey-patching `res.render`/`res.redirect`; session state is namespaced under `_testing` with a shared allow-list. That is a lot of infrastructure a designer had to write (with AI help, judging by style) to get an isolated variant — a real prototype platform should give this for free.

3. **Shared partials, duplicated pages → double edits.** Because partials stay shared but pages are copied, every page-level change in this batch was made twice (88f469b `roles-and-addresses.html` ×2; cb13efb `animal-identification-details.html` ×2, `contact-address-for-consignment.html` ×2, `notification-submitted.html` ×2, `transporter-add-private.html` ×2). Partial-level changes (`cph-number-input.html`, `review-summary-row.html`, the County labels) needed one edit. Drift has already begun: `testing/animal-identification-details.html` still links `?resetSearch=1` after the route stopped honouring it.

4. **Global change, then split by flag the next night.** 2191e30 changed the reference format and ITAHC wording *everywhere*; cb13efb then introduced `_isTestingVersion` and re-derived DR1 behaviour (`toDesignReleaseDashboardReference`, `designReleaseDocumentTypeOptions`, reverting root views). Variant-specific behaviour lives as `if (isTestingSessionData(...))` branches inside the shared `routes.js`, not in the copied views.

5. **Validation is switched on late and all at once.** The prototype was built with stub validators (`return { errors: {}, errorList: [] }`) and the demo README notes "only /declaration blocks progress". In cb13efb ten validators became real in one commit, using one consistent shape (`errors[field] = {text}` + `errorList.push({text, href})`, POST re-renders the page, templates read `data.errors`/`data.errorList`). The kit gives no scaffolding for this; each is hand-written.

6. **Commit messages carry no information on the designer's side.** "testing version", "fixes", "fixes" for +5000 lines. Intent has to be recovered from the diff (and from the `index.html` release-card copy, which is the closest thing to a changelog). The developer's commits, by contrast, are long-form and AI-co-authored.

7. **Same-day iterate → fix → reverse.** Sam: parallel → serial (6143f36, "kit races state") → parallel again (59c3153, "it's per-session after all") within 80 minutes; Pages (bd3d591) → artefact (be9f42a, no admin) → artefact + delete-old (691ca71) in one day. Designer: sandbox at 14:19 → button-pattern fix at 16:25 → 1,100-line validation/UX commit at 01:30.

8. **Realistic seed data is part of design iteration.** Romanian and Irish farms, real-looking approval numbers (`RO/BUCHAREST/T1/00092010`), a CHEDA-style reference, "Republic of Ireland" not "Ireland" — the designer edits `app/data/*.js` fixture arrays as a normal design activity, and the notification reference format is treated as a design decision.

9. **Custom JS widgets accumulate.** `cph-number-input.js` joins `country-search.js`, `transit-country-search.js`, `address-book*.js`, `permanent-address-animals.js` etc. in `application.js`, bound by `data-module` attributes. The autocompletes are bespoke (`button.app-country-search__option`) not the GOV.UK accessible-autocomplete, which is what made the Playwright helpers fiddly.

10. **"Keep out of the designer's way" is an explicit constraint for tooling.** The developer stream deliberately confines everything to `journey-demo/` with two root npm scripts, writes a README aimed at non-technical viewers, and embeds a paste-ready agent prompt for keeping the demo current — a template for how designer-facing skills should be packaged.

11. **Kit-specific gotchas worth carrying into any tooling:** `serve`/production mode breaks http + yar sessions; the usage-data stdin prompt hangs headless runs; TCP-port readiness beats HTTP probe; `autoStoreData` writes request input onto `req.session.data` before your middleware runs.
