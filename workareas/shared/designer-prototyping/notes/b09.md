## Cross-commit patterns

1. **Commit messages are near-useless as a record.** "content", "update", "content changes" (twice), "validation". f622600 ("content") is actually four features plus a copy sweep. The real unit of work is the *working session* (3 Sep, 10 Sep, 16 Sep), each committed as one big commit + one small follow-up 9–25 minutes later (077c2f0 after f622600; 903344e/8283340 after 50afa9e; 91507cb after 268f070). Any tooling for designers should expect "one big blob then a quick fix" and help them describe what they did.

2. **Everything routes through one 13k-line `routes.js`.** View models, validation, journey ordering, hub rows, review cards, template seeding, dashboard filters and seed-data enrichment are all in it. A change like "move temperature from page B to page A" touches ~10 functions in that file plus templates. Removing the package-type field left `app/data/package-types.js` orphaned and `packageType: {}` still written to session.

3. **Versioning = copied view folders + predicates.** `design-release-2.1/` is the live folder; `design-release-2/`, `testing/` and the root views are older versions kept alive. Behavioural differences are `isDesignRelease21SessionData()` / `isDesignRelease21TemplateCreate()` / `usesGerminalImportOptions()` gates in routes.js; visual differences are a `--dr21` BEM modifier on the version's template wrapper with SCSS scoped under it. Version-specific *copy* for shared data goes in as a sibling field (`textDesignRelease21`).

4. **Version gates get promoted, then removed.** The `Main import reason` label was DR2.1-only (f622600, 3 Sep) and universal a week later (903344e, 10 Sep) with the `isDr21` ternary deleted. Once a copy change is accepted the designer back-ports it to all four review pages by hand (903344e, 8283340 each touch `design-release-2.1/`, `design-release-2/`, root and `testing/` copies of `review-notification.html`).

5. **Reverts are done by hand, not `git revert`.** 50afa9e re-edits two templates and the render function to undo a0e46bd's progress-tracker experiment; the now-unused `--started`/`--submitted` SCSS modifiers remain. Experiments are cheap to add and only partially removed.

6. **Reuse of an existing helper for a new purpose.** `parseArrivalDisplayDate()` (an arrival-date parser) is used to validate identifier dates; the `Temperature` review row is bolted onto the first species block of the first commodity card rather than given its own place. Speed over structure.

7. **Data files carry feature flags read by routes.js.** `forGerminalProducts: true`, `maxLength`, `type: 'date'`, `textDesignRelease21` — the designer's preferred way to vary behaviour per option is to annotate the option record and filter/branch in the route.

8. **Content review sweeps are a recurring, cross-cutting task.** f622600 + 077c2f0 change ~30 strings across ~15 templates, 3 data files and 1 embedded map ("&" → "and", shorter buttons, ITAHC wording, active voice, `View details` → `View`). The same label often exists in 3+ places (template h3, routes.js card title, template review title, seed data).

9. **Session-driven journey shaping is the core mechanic.** `getJourneySteps(sessionData)` decides page order; per-page `has*Complete()` predicates drive hub statuses, review error cards and route guards; `getNextJourneyPath()` handles redirects. Adding or removing a page means editing all of: steps list, hub rows, review card builder, route GET/POST guards, template `buildTemplateFromSession`/`seedNotificationSessionFromTemplate`/`applyCarriedOverNotificationFields` field lists.

10. **No tests, no JS, no images touched in this batch.** All work is Nunjucks + routes.js + SCSS + `app/data/*.js`. The Playwright journey-demo added by samfarrington in July is not updated to reflect any of these changes.
