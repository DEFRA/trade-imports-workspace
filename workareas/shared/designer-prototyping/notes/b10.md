2. **Big feature then same-afternoon fix-up.** 7467690 (15:39) introduces the notification-type gate; b9795ab (15:59) patches the template-creation flow it broke and adds the type-specific hint. Two-commit-per-sitting cadence; the second commit's message undersells it.

3. **Commit messages are labels, not summaries.** "text update" contained a flow change; "content updates" contained a delete-confirmation pattern, a review-partial extraction and a vocabulary rename with alias layer. Git log alone cannot tell you what moved — you have to read the diff.

4. **Placeholder data lives in route handlers.** Overall-dashboard counts (`actionNeeded: 4`, `messageCount: 12`) and `#` hrefs for plants are hard-coded in `renderOverallDashboardPage`, not in `app/data/`. Fine for a screenshot, but it means "real" list dashboards and the landing tiles disagree.

5. **Hand-rolled SCSS with hard-coded GOV.UK hex values**, appended to the end of a ~9.7k-line `application.scss`, using `app-dr2-*` / `app-overall-*` BEM prefixes. No govuk-frontend Sass mixins/variables (`govuk-colour()`, `govuk-spacing()`), 3-column CSS grid rather than `govuk-grid-*`. The 64px count typography and red pill are bespoke.

6. **Backwards-compat alias layers when renaming vocabulary.** The Air/Rail/Road/Sea rename added `MEANS_OF_TRANSPORT_ALIASES` + `normaliseMeansOfTransport()` used at every touchpoint so stale session data / seeds / templates keep working — the designer is conscious that Heroku sessions and seeded snapshots outlive a deploy.

## Implications for designer skills on the plants prototype

- A "new dashboard/landing page" recipe should own **counts and links from data**, not in the handler — the designer wanted static illustrative numbers quickly; a seeded fixture gives that without the drift.
- A "rename a vocabulary" recipe (options list + seed data + fixtures + alias for stale sessions) is a recurring designer task; here it touched 7 files and a Playwright fixture.
- A "delete-confirmation" recipe: GET confirm page with summary list → POST perform → success banner. The designer built this three times over; a govuk-toolbox pattern with a partial should be a one-line recipe.
- "Add a question page that scopes the rest of the journey" (notification-type gating the commodity search) is the shape the `frontend-change` add-page/change-journey-flow recipes already cover; the prototype version needed ~150 lines of hand-written normalisation.
- Commit-message hygiene: a skill that writes the commit message from the diff (what moved, which version, which entities) would make the history legible without reading `routes.js`.
