## Majors

- **retire deleted a never-saved release, then said it was in git history** (t1 major, t7 minor). `retire.js` now refuses a release that was never saved: "was never saved, so it is not in git history: retiring it throws it and every change in it away for good", with the save route and the exact `--discard` command. With `--discard` it removes the release and prints "It was never saved, so it is gone for good and there is nothing to save." A saved release still says "still in git history". The rule for a saved release with unsaved changes is unchanged. Tests: refuse-and-keep-every-file, discard-leaves-a-clean-tree, and the CLI message for each kind. `design-release` F.2 and `docs/designers/design-releases.md` say the same.
- **Undo of an unsaved change stashed; the skill said undo always adds a commit** (t7). One behaviour now: every undo ends in a revert commit. "Undo that" straight after an unsaved change saves the change (share steps 2, 3 and 5; no extra `--full` run) and then reverts it. Both go through `designer:save` (`git revert --no-commit`, then `designer:save -m 'Revert "…"'`), which also answers t7's note that `git revert --no-edit` skipped `designer:save`. The stash stays only as a stated fallback for edits that cannot be saved (a real-service file, or failing checks the designer does not want fixed), and the designer is told. "Bring back the change I undid" is a named-change undo of the Revert commit. Updated `share-my-change` (Unsaved edits, last saved change, named change, Verify), `change-the-journey` (after step 8) and `docs/designers/sharing-and-handing-off.md`. `settings-proposal.json` already allows `git revert:*`.
- **Plan T7 row named match-the-design** (t7). `plan.md` §8 now says `change-the-journey (confirmation-variant)`. The T7 undo criterion now says the unsaved change is saved and then reverted, with no stash.
