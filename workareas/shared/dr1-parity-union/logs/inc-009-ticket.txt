h2. Context

The permanent address block on the live-animals identification page labels two fields differently from signed-off Design release 1, and drops the phone field's hint entirely.

Frontend labels them "Postal or zip code" and "Telephone number", and the telephone input carries no hint and no {{aria-describedby}}. Design release 1 labels the same two fields "Postcode or Zip code" and "Phone number", and hints the phone field "For international numbers include the country code".

The other six labels the two sides share — name or organisation name, address line 1, address line 2 (optional), town or city, county (optional) and email address — already match word for word.

The same two labels are authored a second time on the private transporter form, and the validation messages on both forms repeat the same words, so wherever the service asks a trader to type an address it should ask in the same words.

h2. Acceptance criteria

* The permanent address postcode field is labelled "Postcode or Zip code" in the rendered frontend, not "Postal or zip code".
* The permanent address phone field is labelled "Phone number" in the rendered frontend, not "Telephone number".
* The permanent address phone field carries the hint "For international numbers include the country code", wired to the input through {{aria-describedby}}.
* The English strings are changed in {{src/server/app/sets/live-animals/journeys/linear/features/commodities/copy/copy.en.js}} lines 96-107, and the Welsh sibling copy file is updated to match.
* The private transporter form's copy of the same two labels in {{src/server/app/sets/live-animals/journeys/linear/features/transport/copy/copy.en.js}} lines 108 and 110 is brought into line in the same pass, with its Welsh sibling.
* The validation messages that name these two fields on both forms use the new wording, so no message contradicts the label above it.
* Existing unit tests and the E2E suite pass, with any test text or visual baseline that asserts the old wording updated.
