h2. Increment

{{inc-096}} from the {{shared/dr1-parity-union}} backlog.

Frontend tells a user whose animal count is not a whole number "Number of animals must be a whole number, like 25". Design release 1 says "Enter a whole number greater than 0". The one Frontend string is passed for both failure modes the rule has — a value that is not digits, and a value below one — so a user who types 0 is told to enter a whole number, which 0 already is.

h2. Acceptance criteria

* The animal-count validation message in {{src/server/app/sets/live-animals/journeys/linear/features/commodities/copy/copy.en.js}} reads "Enter a whole number greater than 0" in place of "Number of animals must be a whole number, like 25".
* The Welsh copy file beside it carries the matching translated wording, so the two copy files stay in step.
* The new message is shown for both failure modes the rule covers — a value that is not digits, and a value below one — since one string is passed for both in {{src/server/app/sets/live-animals/journeys/linear/features/commodities/consignment-details/fields.js}} lines 20 to 23.
* The message appears in both the error summary and beside the count box on the consignment details page, and the summary entry still links to the count box.
* Unit tests and end-to-end specs that assert the old wording are updated to the new wording, and the E2E visual baselines for the consignment details error state are refreshed.
