h2. Increment

{{inc-099}} from the {{shared/dr1-parity-union}} backlog.

Two of the animal identifier entry fields carry a longer label than the signed-off Design release 1 uses. Frontend labels them *Passport number* and *Ear tag number*; Design release 1 labels them *Passport* and *Ear tag*. Frontend's own summary of a saved animal already uses the short forms, so a trader is shown one name while entering a value and a different name after saving it.

h2. Acceptance criteria

* The animal identification entry field labelled *Passport number* is labelled *Passport*, changed in {{src/server/app/sets/live-animals/journeys/linear/features/commodities/copy/copy.en.js}} lines 58-72.
* The animal identification entry field labelled *Ear tag number* is labelled *Ear tag*, changed in the same file.
* The Welsh sibling copy file is changed to match, so the two locales stay in step.
* The *Tattoo* and *Horse name* labels are left as they are — they already match Design release 1.
* The worked-example hints ("For example, UK123456789" and "For example, UK123456789012") are left in place. Design release 1 neither states nor contradicts them, and this increment does not ask for their removal.
* The entry labels now agree with the summary labels already at {{copy.en.js}} lines 48-55, which the entered-records list and the check-answers identifier card both read via {{src/server/app/sets/live-animals/journeys/linear/features/check-answers/view-model/cards/consignment/species/identifier-columns.js}}.
* Existing unit tests and E2E specs pass, with any snapshot or visual baseline that carries the old label updated.
