Frontend shows the four means of transport as radios, all visible at once; Design release 1 hides them inside a "Select one" dropdown.

Frontend: "Means of transport to the port of entry" is a fieldset legend over four radios — Airplane, Railway, Road Vehicle, Vessel — all four visible on the page without interacting with anything, and none of them preselected ({{src/server/app/sets/live-animals/journeys/linear/features/transport/port-of-entry/port-of-entry.njk:29-39}}).

Design release 1: the same question is a label over a dropdown. The closed control shows "Select one" and the four options — the same four, in the same order, with the same words — appear only when it is opened ({{app/views/arrival-details.html:110-119}}).

Note for the reviewer: this is the one finding in the transport slice where the frontend is closer to the GOV.UK Design System's advice than Design release 1 is — the Design System steers a four-option question towards radios. Expect this row to look backwards, and read it as written: Design release 1 shows a dropdown here and the frontend does not.

h2. Acceptance criteria

* The means-of-transport control on the port-of-entry page is a select, not a radio group.
* The select's first option is selected by default and reads "Select one".
* The four options — Airplane, Railway, Road Vehicle, Vessel — keep the same wording and the same order.
* The label above the control keeps its existing wording, "Means of transport to the port of entry".
* The form field name stays {{meansOfTransport}}, so validation and the answer stored against the notification are unchanged.
* Existing unit and E2E tests that select a means of transport are updated to drive the select, and the visual baselines are refreshed.
