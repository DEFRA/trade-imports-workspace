  "detail": "The page offers two ways to submit the document form and only one of them keeps anything. \"Save and add another\" posts action=add and saves the document. \"Continue\" posts action=continue from inside the same form, so the reference, the date of issue and the chosen file all travel to the server in that request — and the server never looks at them. The post handler branches on the action and reads the payload only for add and remove; every other action loads the page state fresh, checks whether any already-saved document is still being scanned, and redirects to the next page (src/server/app/sets/live-animals/journeys/linear/features/documents/controller.js:255-279). Nothing is saved, no error is shown, and the next screen gives no sign that anything was dropped. A trader who fills the three fields, chooses their health certificate and presses the primary green button — the one the whole rest of the journey has taught them to press — arrives at the next page having attached nothing. \"Save and return to hub\" behaves the same way.\n\n\"Save and continue\" completes the document. Design release 1 treats a part-filled form as an intention to attach: if the trader has chosen a document type, it validates the whole form, and either adds the document to the notification and moves on, or stays on the page and shows the same four messages the add path would have shown — \"Enter a document reference\", \"Select a document type\", \"Enter a date of issue\" and \"Upload a document\" — so the trader is told what is missing rather than losing the file (app/routes.js:10173-10193). The captured Save and continue refusal is that state, showing the three messages that remain once the type has been chosen. The chosen type is the whole of the signal: the branch is entered only when the posted document type is one of the valid options, so a trader who fills in the reference, the date and the attachment but leaves the select on \"Select one\" is carried forward with the row dropped exactly as the frontend drops it. Uploading remains optional — an untouched form continues without complaint. \"Save and return to overview\" is the one action that deliberately discards a part-filled form.\n\nMake Continue finish the document rather than throw it away. On a Continue post, look at the add-a-document fields: if the trader has entered anything at all, run the same validation the Add path runs and either save the document and move on, or re-render the page with the field errors. The branch is in the post dispatcher at src/server/app/sets/live-animals/journeys/linear/features/documents/controller.js:255-279, which today falls through to the redirect for every action that is not add or remove; the saving path it needs already exists as postAdd at :92-129 and needs no new validation, no new copy and no service change. Two decisions belong to whoever picks this up. First, what counts as \"the trader meant to attach something\": Design release 1 keys it on the document type being chosen, and the frontend has no document type until documents--document-type-not-asked lands, so until then key it on any of the three fields being non-empty — an interim rule that is stricter than Design release 1, which would carry a trader on when only a reference has been typed, and it should be recorded as an extrapolation rather than as Design release 1's requirement.
