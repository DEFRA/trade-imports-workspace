h2. Context

The upload page is a single unbroken column: heading, Document reference, Date of issue, the file field, "Save and add another", the saved-documents table, then "Continue", "Save and return to hub" and "Cancel and return to hub". No heading, border or container separates them, so "Save and add another" and "Continue" read as two buttons in the same list. A user cannot see which button acts on the document in front of them and which leaves the page.

Design release 1 puts the fields, the "Save and add another" button and the saved-documents table inside a bordered group headed "File upload", with the page-level actions outside and below it.

h2. Acceptance criteria

* The reference, type, date and attachment fields, the "Save and add another" button and the saved-documents table are wrapped in a single bordered group on the documents upload page.
* The group carries an {{h2}} of "File upload", and the group references that heading so the grouping is announced as well as drawn.
* The page-level actions — "Continue", "Save and return to hub" and "Cancel and return to hub" — sit outside the group, below it.
* The border comes from the govuk-frontend toolbox — the summary-card border is the closest match already available — not from a bespoke card and not from the prototype-only classes Design release 1 uses.
* The new "File upload" heading is added to {{src/server/app/sets/live-animals/journeys/linear/features/documents/copy/copy.en.js}} as user-facing copy, not hard-coded in the template.
* The reading order is unchanged: fields, then the add button, then the table.
* The grouping holds on both states of the page — empty and with a saved document row inside the same border.
* No behaviour changes. This is layout and one heading.

h2. Falsified by

Finding any heading, border or container on the frontend's upload page that separates the fields and "Save and add another" from the page-level Continue.
