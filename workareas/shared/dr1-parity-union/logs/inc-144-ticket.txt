h2. Increment

{{inc-144}} from the {{shared/dr1-parity-union}} backlog.

Design release 1 tells a trader that ZIP files are not allowed and why. The frontend refuses them silently and gives a message that never mentions ZIP.

The file-requirements hint on the documents upload page is headed "Your file must be:" and has two bullets, a size and a list of accepted types. The word ZIP appears nowhere on the page. A ZIP file is refused, because the accepted types are an allow-list of eight extensions in {{src/server/app/sets/live-animals/journeys/linear/features/documents/upload-config.js}} lines 3 to 18, applied both as the file input's accept attribute and as a server-side check. The trader is told only "The selected file must be a PDF, DOC, DOCX, JPEG, PNG, XLS or XLSX", and only after they have chosen the file.

Design release 1 states the rule and the reason before the trader chooses a file, as the fourth bullet of the same hint in {{app/views/upload-documents.html}} line 169, and shows it on the page in every error state.

h2. Acceptance criteria

* The file-requirements hint under "Your file must be:" on the documents upload page shows a bullet reading "ZIP files are not allowed for security reasons", in Design release 1's words.
* The new copy string is added beside the existing file hint keys in {{src/server/app/sets/live-animals/journeys/linear/features/documents/copy/copy.en.js}} lines 11 to 16, and is rendered from the hint list in {{src/server/app/sets/live-animals/journeys/linear/features/documents/template.njk}} lines 43 to 48.
* The bullet is on the page in its initial state and in every error state of the page.
* Copy only. The allow-list in {{upload-config.js}} is unchanged, because it already excludes ZIP, and no upload behaviour changes.
* The string "ZIP" appears in the rendered DOM of the documents upload page. Its absence today is what falsifies this increment.
