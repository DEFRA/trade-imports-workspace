## 0. Decisions

1. **Plants FIT: exact is the default again, with one matcher for "this page, no trail or query" and one for "this page with
   exactly this trail".** `P:fit/set-base.js` `setUrl` always anchors the whole URL (origin, mount, path, any query the caller
   writes, end); it no longer rewrites a trailing `$` into an optional trail. `pageUrlWithTrail` (already built on the
   application's own `withTrail`, so it encodes the trail exactly as the app does) is the one way to expect a trail.
   `pageUrlAllowingTrail` has no callers and is deleted. Every inline copy of the optional-trail regex in plants FIT
   (`fit/high-risk-plants-journey.js:706, 737, 739, 750, 811`, `fit/journey-smoke.fit.spec.js:116`, `dashboard.fit.spec.js:21, 53,
   107`, `consignment-contact-select.fit.spec.js:30`, `place-of-destination.fit.spec.js:90`, `consignor-select.fit.spec.js:72, 157`,
   `identification-numbers.fit.spec.js:101, 205, 226`, `party-edit.fit.spec.js:23`) and every "any trail prefix" form
   (`check-answers.fit.spec.js:44, 56, 106, 130`, `fit/high-risk-plants-journey.js:1269, 1273`) is replaced by one of the two set-base matchers with the exact trail the page
   carries at that point. Unanchored raw URL regexes in the plants FIT files this row edits (for example
   `consignment-contact-select.fit.spec.js:28-29`) go through `setUrl` too. Rejected: keeping an "allowing trail" matcher for
   pages whose trail is awkward to predict — that is the loosening the house rule forbids.
2. **Where an exact trail is expected, the test states it from what the test did** (the start place and each page saved or each
   Change link followed, newest last), never read back from the page. The implementor reads each trail off the application's
   rule (`P:src/server/app/shared/trail.js` `trailPlus`/`pushTrail`/`carryTrail`, `docs/flow-and-gates.md` "Where Back goes")
   and the controller that builds the link, then writes it into the assertion. A page reached by `page.goto` with no trail is
   asserted with `setUrl` (no query).
3. **journey-smoke's `onPage` (path only) is deleted.** Its three uses and the forward walk's per-step path check assert each step's
   exact address through set-base, the forward walk with the trail accumulated from the steps it has saved (newest last),
   the Back checks with the trail the Back link's target carries. One owner: set-base.
4. **The address picker "nothing chosen" check fails on any alert again.** `describeAddressPicker`
   (`P:fit/high-risk-plants-journey.js:971`) asserts the whole list of alerts on the page Save and continue lands on, which is
   none by default. The consignment contact picker lands on the review page, which on a draft shows its own error summary (an
   alert) for every answer still missing (`plin/features/check-answers/controller.js:82-88`). For that picker only, the caller
   gives the exact alert the landing page shows — chosen so that list is one short, exact list: either the review's error summary
   for exactly the answers the set-up leaves missing, or a set-up that leaves only the contact missing
   (`startPotatoNotificationAtContact` exists). The not-in-book link check stays beside it and goes through the file's own
   `notInBookLink` helper (`:982-983`); the inline copy of that locator at `:1181-1183` is deleted. The test's title
   (`:1173`, "continuing with nothing chosen moves on without an error and leaves the overview row not yet started") is
   restated so it is true for all three pickers once the option exists: it must no longer claim "without an error", since the
   consignment contact picker's landing page shows the review's error summary; it states that the picker refuses nothing and
   the landing page shows exactly the expected alerts (decision 8). Rejected: keeping the narrowed
   not-in-book-only check (any other alert would pass), and asserting zero alerts on the review page (false: the review shows its
   errors on a draft by design).
5. **Live animals walk helpers check the landing page before any `page.goto`.** In `A:fit/live-animals-journey.js`, every helper
