## 0. Decisions

1. **The pattern is the union, exactly as resolutions.json records it.** The branch's feature-folder tree has
   both shapes of Playwright file under `src/`:
   - suffix leg: `src/server/app/features/dashboard/dashboard.fit.spec.js` (not in a `fit/` folder);
   - directory leg: `src/server/app/features/address-book/fit/{add,delete,edit,list,view}.fit.spec.js` plus the
     helpers `axe.js`, `seed-address.js`, `address-form.js` (no spec suffix).
   Main's pattern (`src/**/fit/**` only) would drop the dashboard spec back into production source; the branch's
   (`*.fit.spec.js` only) misses the three helpers. Union covers all ten files. Rejected: either single leg.
   The root `fit/` folder (`fit/sign-in.js`) is outside `sonar.sources=src/` and needs nothing.
2. **`sonar.coverage.exclusions=src/client/**` and `**/config.js` in `sonar.cpd.exclusions` come from main**, as the
   resolution records, matching animals (AC2). The ins `src/client/` folder exists (common, javascripts,
   stylesheets). Rejected: animals' extra entries (documents client, `fit/axe.js`) — ins has no such paths beyond
   `fit/axe.js`, which the test classification already removes from coverage and duplication.
3. **Comments in `sonar-project.properties`**: carry main's explanatory comment for the fit classification, reworded
   so it describes the union (both legs), and main's one-line comment on the coverage exclusion. Plants and animals
   both carry comments of this kind in their sonar files; the comment explains a why (why two legs), which the
   code-style guide permits. Rejected: dropping them (the pattern is non-obvious and the next editor would shrink it).
4. **`.sonarcloud.properties` header comment is factually wrong on the branch and is corrected.** It says the scanner
   steps in `.github/workflows/` are still commented out. They are not: `check-pull-request.yml` (line 44) and
   `publish.yml` (line 46) both run `SonarSource/sonarqube-scan-action` live. The resolution notes the "Automatic
   Analysis runs beside CI" premise is probably false, and the row's open question defaults to "assume Automatic
   Analysis is off; update for parity only". So the header is rewritten to say: CI runs the scanner from
   sonar-project.properties; this file is only read if Automatic Analysis is ever switched on, and is kept in step
   with sonar-project.properties for parity with plants. Rejected: leaving a comment that asserts something the
   repo contradicts; deleting the file (resolution says mirror, and main has no such file so git keeps the branch's).
5. **`.sonarcloud.properties` mirrors four keys only**: `sonar.exclusions`, `sonar.tests`, `sonar.test.inclusions`,
   `sonar.cpd.exclusions` (the last is new to this file). `sonar.sources=src/` unchanged. No coverage key: the
   resolution lists these four and Automatic Analysis computes no coverage. Rejected: mirroring coverage too.
6. **`get-safe-redirect.js` takes main's body verbatim**, including main's four-line comment, so the file becomes
   byte-identical to `origin/main:src/auth/get-safe-redirect.js`. That removes this path from the merge's conflict
   list. Zero behaviour change: the same literal is used, just named once.
7. **Claim that does not fully hold — "removes two ins conflicts from the merge".** Only `get-safe-redirect.js`
   stops conflicting. `sonar-project.properties` will still conflict at inc-007's merge (both sides edit the same
   lines differently, and the union is deliberately not main's text); its resolution there is already recorded as

8. **AC3's "the PR body says this is parity with plants, not a gate fix" is outside what any loop stage may do.**
   The guard rails forbid editing a pull request's body; the ins PR (#27) belongs to Sam. The implementor edits no

### 2.1 `sonar-project.properties`

Keep the header comment, projectKey, organization, the four `sonar.links.*` lines and
`sonar.javascript.lcov.reportPaths` exactly as they are. Replace the scope block and the cpd line so the file's
body from `sonar.sources` down reads:

```properties
# The Playwright suite is test code: `npm test` is vitest and never runs it
# (`npm run test:fit` does, and produces no lcov), so without this it is scanned
# as production source no test covers. Two legs, because the suite has two
# shapes under src/: specs beside a feature (*.fit.spec.js) and fit/ folders
# whose helpers (axe.js, seed-address.js, address-form.js) carry no spec suffix.
sonar.sources=src/
sonar.exclusions=src/**/*.test.js,src/**/*.fit.spec.js,src/**/fit/**
sonar.tests=src/
sonar.test.inclusions=src/**/*.test.js,src/**/*.fit.spec.js,src/**/fit/**

sonar.javascript.lcov.reportPaths=./coverage/lcov.info

# The browser bundle is exercised by the Playwright suite, not by vitest.
sonar.coverage.exclusions=src/client/**

sonar.cpd.exclusions=**/config.js,src/**/*.test.js,src/**/*.fit.spec.js,src/**/fit/**
```

Exemplar: `origin/main:sonar-project.properties` (`git -C ... show origin/main:sonar-project.properties`) for
layout and comment voice; values are the resolutions.json union. File ends with a single trailing newline.

### 2.3 `src/auth/get-safe-redirect.js`

Replace the `try` block's hard-coded literal with main's named sentinel. The result must be byte-identical to
`origin/main:src/auth/get-safe-redirect.js`. Between the second `if` block's closing `}` and `try {`, insert
(one blank line either side):

```js
  // A parse-only sentinel: it gives the relative path an origin to resolve
  // against, so anything that escapes that origin can be rejected. It is never
  // fetched, and the scheme is arbitrary — https only so it doesn't read as an
  // insecure outbound URL.
  const parseBase = 'https://placeholder'
```

and change `new URL(redirect, 'https://placeholder')` to `new URL(redirect, parseBase)` and
`resolved.origin !== 'https://placeholder'` to `resolved.origin !== parseBase`. Nothing else changes; the export and
every guard stay. Simplest faithful route: write the file's content as `origin/main`'s blob shows it.
