## 0. Decisions

1. **The increment's cause is partly wrong, and the resolution still applies.** The detail and the resolution both say the test "reads real reference data with nothing stubbed". On the live tree (HEAD a551000, and on plants `origin/main`) the test *does* stub the network: it sets `stubMode` to false and replaces `global.fetch` with `vi.fn().mockRejectedValue(...)` for that one request. Because the countries reader calls `fetch` directly (`services/countries/client.js:13`), a local reference-data service answering on :8086 is never reached. So on today's tree the test does not show the flake described. It is still fragile: it reassigns `global.fetch` and `config` directly rather than with `vi.stubGlobal`/`vi.spyOn`, which `docs/best-practices/node/testing/frontend.md` ("`vi.spyOn` over reassigning", "Restore mutated globals") advises against. It also depends on the module-level `loaded` flag in `countries/index.js` being false, so it breaks if anything earlier in the same module instance loads countries. And it is the only difference between plants' test file and the shared D7 text. **Decision:** carry out the resolution as written (remove the test). Record the wrong cause here, and do not rewrite the test into something else. *Rejected:* keeping the test because it is not flaky today. That would re-decide a resolution, which the programme invariants forbid, and it would leave plants off the D7 text.
2. **Countries and ports readers are already covered at the service boundary, so nothing is added.** The resolution says to add a boundary test only if one is missing. Both are present in `src/server/app/services/run-mode.test.js`:
   - `countries service — real mode` › `Should reject with a serverUnavailable Boom error on load failure` (lines 147–156): fetch is stubbed to `{ ok: false, status: 503 }`, and `originLabel` rejects with `{ isBoom: true, output: { statusCode: 503 } }`.
   - `ports service — real mode` › `Should reject with a serverUnavailable Boom error on load failure` (lines 210–219): fetch is stubbed to `{ ok: false, status: 500 }`, and `list()` rejects with `{ isBoom: true, output: { statusCode: 503 } }`.
   Both use `vi.stubGlobal('fetch', ...)` plus `vi.resetModules()`, so they are deterministic whether or not a reference-data service is running. *Rejected:* adding duplicate tests, which the memory rule on coverage padding forbids.
3. **Target text.** Make plants' `errors.test.js` **byte-identical to ins' `src/server/common/helpers/errors.test.js` at ins HEAD**. Ins already carries the shared D7 text, and plants' page-title format (`<title> | Import notification service`) is the same as ins'. Animals differs only in its title strings (` - Import notification service - GOV.UK`), so animals is not the source. This also removes the `somethingWentWrongTitle` constant that only plants has, which converges the file fully. *Rejected:* a minimal delete that keeps `somethingWentWrongTitle`. It would pass, but plants would stay one text apart from ins for no reason.
4. **No E2E.** `gatePhases` is `[unit, fit]`. This is a unit-test-only change with no user-visible behaviour, so no integration proof in the tests repo is owed. The cross-repo end-to-end row carries the E2E rung for the programme.
