## 0. Decisions

1. **AC3 gets a new integration proof in the tests repo.** Add one `@compose @integration` spec in the e2e project. It signs in to animals, then ins, then plants in one cold browser context. It then reopens each service's landing page *without* attempting sign-in and asserts each lands on its own page, not the stub's sign-in form. Finally it asserts the context holds all three session cookies under their own names. *Rejected:* relying on the auth-state fixture. That fixture mints each project's session in a separate context, so it never proves that the sessions coexist in one browser.
2. **AC4's handshake return and the ins dashboard return are tightened, not duplicated.** The two `toHaveURL(/consignors\/select/)` assertions in `addresses-add-handshake.spec.ts` become exact pathname checks against `pages.consignorSelection.expectedUrl(journeyId)`, which is `/live-animals/notifications/<id>/consignors/select`. The last assertion in `address-book-navigation.spec.ts` also requires the pathname to start with `SET_BASES.liveAnimals`. Tightening keeps each assertion's intent and adds the set base (memory: preserve assertion intent). *Rejected:* new specs that repeat the same journeys.
3. **AC4's "Start a new notification" is proved below E2E, and this is recorded rather than worked around.** The button exists only when the whole aggregated store is empty. On a stack every spec writes to, an E2E for it would be non-deterministic unless it seeded or purged the store, and seeding a journey test is ruled out. The proof is:
   - the ins unit test that pins the href to `<animals>/live-animals`;
   - the existing `auth.spec.ts` case "redirects the service root to the default set's dashboard", which shows that `/live-animals` is the live animals dashboard.

   *Rejected:* purging the ins-backend store or adding an organisation-scoped empty state. That is a product change outside this row. The unscoped listing is a separate, already-known concern.
4. **AC5's CI is made green by rerunning the stale E2E runs, not by changing code.**
   - The tests commit from this row triggers a fresh `Publish Branch Image` → `E2E Tests` run on tests #227 by itself.
   - animals #339 gets no commit, so its red check must be rerun: `gh run rerun 36076383854 --repo DEFRA/trade-imports-animals-frontend`. The CI stage does this *after* the tests repo's new branch image has published, so the rerun picks up the new and tightened specs.
   - The rerun keeps the original `workflow_run` payload, so it reports on head 8bafd5ee, which is still animals' HEAD.

   *Rejected:* an empty commit on animals to retrigger. It adds noise to history.
5. **"Including the SonarCloud checks" applies to the three frontends.** The tests repo has no SonarCloud check: it is not one of the eight sonar-integrated repos. Recorded here, not treated as a failure.
6. **No ins, animals or plants source change is planned.** If the gate's E2E rung fails, the fix belongs in the repo that owns the failing behaviour. Where `resolutions.json` covers that file, the fix follows it. A new decision is recorded in this file before it is made (row note).

## 3. New files

### tests: `tests/e2e/features/cross-service-sessions.spec.ts`

- **Project:** `e2e`. It is under `tests/e2e/features/` and outside `ins/`, `plants/` and `admin/`, so the e2e project's `testIgnore` does not exclude it.
- **Exemplars:**
  - `address-book-navigation.spec.ts`: tag pair `['@compose', '@integration']`, `requireBaseUrl`, and URL predicates built from the origin.
  - `auth.spec.ts`: `test.use({ storageState: COLD_START })` and `SET_BASES`.
  - `fixtures/auth-state.ts`: `authCookieNameFor`.
- **Imports:**
  - `test`, `expect` from `@fixtures`
  - `COLD_START`, `authCookieNameFor` from `@fixtures/auth-state`
  - `requireBaseUrl` from `@page-objects/base/base-page`
  - `SET_BASES` from `@page-objects/base/sets`
- **Shape:** flat, AAA, one test, no loops or conditionals.

```
test.use({ storageState: COLD_START });   // one-line comment: this test is the three sign-ins

test.describe('Sessions across services', { tag: ['@compose', '@integration'] }, () => {
  test('signing in to animals, then ins, then plants in one browser keeps all three sessions', async ({ pages }) => {
    test.slow();
    const animalsBaseUrl = requireBaseUrl('TRADE_IMPORTS_ANIMALS_FRONTEND_BASE_URL');
    const insBaseUrl     = requireBaseUrl('TRADE_IMPORTS_INS_FRONTEND_BASE_URL');
    const plantsBaseUrl  = requireBaseUrl('TRADE_IMPORTS_PLANTS_FRONTEND_BASE_URL');

    // Given — the trader signs in to each service in turn, in one browser
    await pages.notificationDashboard.open();
    await expect(pages.notificationDashboard.heading).toBeVisible();
    await pages.insDashboard.open();
    await expect(pages.insDashboard.heading).toBeVisible();
    await pages.plantsDashboard.open();
    await expect(pages.plantsDashboard.heading).toBeVisible();

    // When / Then — each service opens again without asking them to sign in
    await pages.notificationDashboard.open(false);
    await expect(pages.page).toHaveURL((url) => url.origin === new URL(animalsBaseUrl).origin && url.pathname === SET_BASES.liveAnimals);
    await expect(pages.notificationDashboard.heading).toBeVisible();

    await pages.insDashboard.open(false);
    await expect(pages.page).toHaveURL((url) => url.origin === new URL(insBaseUrl).origin && url.pathname === pages.insDashboard.expectedUrl);
    await expect(pages.insDashboard.heading).toBeVisible();

    await pages.plantsDashboard.open(false);
    await expect(pages.page).toHaveURL((url) => url.origin === new URL(plantsBaseUrl).origin && url.pathname === SET_BASES.highRiskPlants);
    await expect(pages.plantsDashboard.heading).toBeVisible();

    // And — each service holds its own session cookie
    const cookieNames = (await pages.page.context().cookies()).map(({ name }) => name);
    expect(cookieNames).toEqual(expect.arrayContaining([
      authCookieNameFor('e2e', animalsBaseUrl),
      authCookieNameFor('ins', insBaseUrl),
      authCookieNameFor('plants', plantsBaseUrl),
    ]));
  });
});
```

Notes for the implementor:

- The `open()` methods with no argument sign in when asked, through `signInWhenRequested`. `open(false)` never signs in. The stub has no single sign-on, so a lost session leaves the page on `…/oauth2/authresp` and the URL assertion fails. That is the behaviour under test.
- `NotificationDashboardPage.open(true)` already waits for its heading. The `expect(...).toBeVisible()` lines after the sign-ins keep the spec readable, and they are cheap.
- If `pages.insDashboard.open(false)` lands on a path other than `'/'`, for example a trailing query, compare with `url.pathname === '/'`. That is what `expectedUrl` is. Do not loosen it any further.
- On the local stack the three names resolve to `sid`, `ins-sid` and `plants-sid`. Take them from `authCookieNameFor` and never hard-code them, so `AUTH_SESSION_COOKIE_NAME` still overrides.
- Follow the repo's Prettier/ESLint style, which the gate checks: single quotes, semicolons, width as in its neighbours. Do not add any comment beyond the Given/When/Then lines and the one-line `test.use` comment.
