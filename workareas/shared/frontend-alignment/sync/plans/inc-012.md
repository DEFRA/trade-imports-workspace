## 0. Decisions

D1. **Question 29 is a ruling, not an open question.** AC4 asks for question 29 "as blocked on Sam,
with its default". That no longer holds: inc-014's notes record *"Sam, 24 Sep 2026: ins keeps its
narrower countries reader, its full MDM list and its trace header. The two countries services stay
different files. Question 29 closed; the report records it as a ruling."* and the row is `dropped`.
The later ruling wins. The report records question 29 as a ruling in "Rulings applied" (the default
was what Sam chose), and the "Still yours to decide" section carries one line pointing at it so a
reader looking for question 29 finds it. Rejected: listing it as blocked, which would misstate
Sam's own decision back to him.

D2. **Sign-out changes in all three frontends, not only ins.** AC2's first item says "ins no longer
answers /signout". It holds for ins, but `origin/main` of animals and plants also registers
`src/server/signout/` at `/signout` (plants' `router.js` registers it server-wide behind
`auth.enabled`), and on the branch no frontend has that route; only the Defra ID provider's own
`/signout` in `src/auth/get-sign-out-url.js` remains. The report says: all three frontends stop
answering `/signout`; `/auth/sign-out` is the one sign-out URL in all three. AC2 says "at least", so
this is a correction of scope, not a contradiction.

D3. **"Rather than at boot" is wrong for ins; say what ins did.** On ins `origin/main` nothing loads
countries at boot: `routes/home/controller.js`, `address-book/address-countries.js` and the
address-book controllers call `countriesClient.getCountries(traceId)` on every request. The branch
(ruling 13, `c44e554`) makes ins fetch once per process on first read and keep the list until
restart. The report states "ins now loads countries once, on first read, and keeps them until the
service restarts, where on main it fetched them on every request", and "animals and plants already
did this on main" (c-021). Rejected: copying the AC's "rather than at boot", which is false for ins.

D4. **Cookie names: plants is the change, ins was already there.** ins `origin/main` already sets
`auth.cookieName` to `isDevelopment ? 'ins-sid' : 'sid'` and `session.cookie.name` to
`ins-session` in development (EUDPA-333 handshake). plants `origin/main` uses Hapi's default `sid`.
The report says: in development plants now mints `plants-sid`; ins keeps the `ins-sid` it already
had on main; animals keeps `sid`; every deployed environment keeps `sid`. It also names the shared
`auth.cookieName` key and `AUTH_SESSION_COOKIE_NAME` override, new in animals and plants.

D5. **The journey root and every set page 404 with sign-in off.** AC2 says "with sign-in disabled
the root answers 404". The live `src/server/router.js` in both journeys registers *both* the set's
prefixed routes and the `/` redirect inside `if (config.get('auth.enabled'))`, and animals'
`router.test.js` pins `/` and `DEFAULT_SET_BASE` both at 404 with only `/health` at 200. On main
both are registered unconditionally. The report states it whole: with `AUTH_ENABLED=false` a journey
serves only `/health` and static assets; `auth.enabled` defaults to `true`, so an environment that
does not set it sees no change. The per-set prefixes themselves (`/live-animals`,
`/high-risk-plants`) are main's EUDPA-619 and the report says so; they are not a change the merge
makes.

D6. **Changes main already made are marked as carried, not new.** Two AC2 items are already on
main: ins's add-address `Cache-Control: no-store` (ins `origin/main`
`src/server/address-book/add/controller.js` has `NO_STORE`) and the per-set prefixes. ins's links
into `/live-animals` are also main's (EUDPA-619 `fd1d21f`). The behaviour-changes table has a
column "Against main" with values **new** or **carried from main, moved into the new structure**, so
a reviewer can tell what merging changes from what it merely keeps.

workspace `main` as `0a601a77`. The proposal names ins #27, animals #339, plants #69 and tests #227.

"Where everything is" says the report lives on workspace `main`.

four agree on URLs, cookie names and sign-out only once all have landed. The report proposes merging
