    * fix(EUDPA-304): remove @Transactional from saveNotification
    
    @Transactional enrolled ShedLock's MongoDB writes in the Spring
    transaction, making the lock acquisition invisible to concurrent
    sessions until the transaction committed. Two concurrent page-save
    requests for the same notification would both see no lock, both try
    to upsert the shedLock document, and one would fail with DuplicateKey
    → OutboxWriteException → 500 → frontend timeout (cph-scope e2e failure).
    
    Submit and amend are unaffected because those lifecycle transitions are
    never concurrent for the same notification. Page saves can be, so the
    ShedLock alone is used here for version ordering without a wrapping
    transaction.
