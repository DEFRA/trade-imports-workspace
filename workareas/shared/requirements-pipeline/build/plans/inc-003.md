**D3. The shared helper is three small functions between marker comments, byte-identical in every script.**
The exact block, which the implementer pastes verbatim into both scripts:

```js
// >>> args-contract: byte-identical in every .claude/workflows/*.js, checked by tim/src/backlog/workflow-contract.test.js
const parseArgs = (workflowName, rawArgs) => {
  if (typeof rawArgs !== 'string') return rawArgs
  try {
    return JSON.parse(rawArgs)
  } catch (error) {
    throw new Error(`${workflowName}: args arrived as a string that is not JSON (${error.message})`)
  }
}

const missingKeys = (config, keys) =>
  keys.filter((key) => config === null || typeof config !== 'object' || Array.isArray(config) || config[key] === undefined)

const requireKeys = (workflowName, config, keys) => {
  const missing = missingKeys(config, keys)
  if (missing.length === 0) return
  const noun = missing.length === 1 ? 'key' : 'keys'
  throw new Error(`${workflowName}: args is missing required ${noun} ${missing.join(', ')}. Pass every one in args: this workflow has no defaults`)
}

const logResolvedConfig = (workflowName, config) => log(`${workflowName}: resolved configuration ${JSON.stringify(config)}`)
// <<< args-contract
```

The call sequence in every script is `parseArgs` → `requireKeys` → `logResolvedConfig`, before any other `log()` and before the first `agent()`.
- A required key is **missing** when it is absent or `undefined`. An explicit `null` counts as given, because the design's args carry meaningful nulls (`from`, `firstStep`, `pin`, DESIGN 7.3). Checking what a value means stays with each script.
- `requireKeys` names **every** missing key in one error, so a person fixes all of them in one relaunch.
- Args that are absent, `null`, an array, or a JSON string of a non-object report every required key as missing.

Rejected:
- One `resolveArgs(name, args, keysOrFn)` taking a function for conditional keys. It does three things and breaks code-style rules 1 and 9.
- A lib child workflow loaded with `workflow()`. It uses up the only nesting level, and gap-4 §2.2 marks it untested.
- A `.claude/agents` persona. That shares prompt text, not code.

**D7. The e2e witness runs the real script files under a fake runtime, loaded with acorn as DESIGN 4.6 and C-069 say. A live launch is owed to the launching session.**
- **One loader, in `tim/src/test-support/workflow-runtime.js`.** It is the only place in tim that turns a workflow script's source into something runnable. A sibling module keeps the loader tested on its own (tim rails), and later contract items reuse it.
- **Parse.** `parseWorkflowScript(source)` calls acorn's `parse` with exactly `WORKFLOW_PARSE_OPTIONS = { ecmaVersion: 'latest', sourceType: 'module', allowReturnOutsideFunction: true }`: the C-069 options, plus `ecmaVersion`, which acorn requires. In module mode acorn accepts top-level `await`. A syntax error throws acorn's `SyntaxError` with a line and column.
- **Turn the module into a body, from the AST (never from regex).** `toScriptBody(source)` walks the top-level statements of `program.body`:
  - an `ImportDeclaration` throws `workflow script imports a module: a Workflow script cannot import (line N)`;
  - an `ExportNamedDeclaration` whose `declaration` is a `VariableDeclaration` with exactly one declarator named `meta` is kept by cutting the source range `[node.start, node.declaration.start)`, which removes only the `export ` keyword;
  - any other `Export*` node throws `workflow script exports something other than meta (line N)`.
  Cuts are applied last to first, so offsets stay valid. Top-level `return` and `await` need no rewriting, because the body runs inside an `AsyncFunction`.
- **Run.** `runWorkflowSource(source, { args, answers })` builds `new AsyncFunction('args', 'agent', 'log', 'phase', 'parallel', 'workflow', body)` and runs it with fakes: `agent` records `{prompt, options}` and returns the next scripted answer, then `null`; `log` records lines; `phase` does nothing; `parallel` is `Promise.all` over thunks; `workflow` throws `child workflows are not supported by the test runtime`. `runWorkflowScript(path, opts)` reads the file and delegates.
- **Why acorn on merit:** fidelity (acorn with the C-069 options accepts exactly the module-with-top-level-return grammar the runtime runs); robustness (a regex anchored at `^export const meta` with the `m` flag also matches inside a multi-line template literal, and `increment-build-loop.js` is mostly long template-literal prompts; the loader test proves the AST path leaves string contents alone); errors (acorn reports a located `SyntaxError` for the file as written).
- **inc-019's item 6 sits alongside this.** It adds `extractMarkedBlock(source, marker)` (acorn `onComment`) to this module and runs the extracted helper through `runWorkflowSource`. One parse, one runtime.
- **The dependency.** `acorn` is added to tim `devDependencies` as `^8.16.0`, the version the lockfile already resolves.
- **This is each script's real entry point with only the runtime replaced**: DESIGN's C-033 proof for a tooling `fix`.
- **The live launch.** No agent can run it. It is listed in section 4 as a launching-session check (L1 to L4). DESIGN 11 row 15 calls it "inc-003's first acceptance run".

Rejected:
- A regex text substitution (`/^export const meta\b/m` → `const meta`). Less faithful, less robust, and against DESIGN 4.6 and C-069 for no gain.
- `node:vm` `SourceTextModule`. It sits behind `--experimental-vm-modules` and rejects a top-level `return` in a module.
- acorn for the syntax check only, with the body built by regex. Two readings of one file.
- `ok=false`. The behaviour is fully buildable and provable here. Only the live observation needs the main session.

## 1 Criteria map

**req-007 ac-1:** "Given args passed as a JSON string, when a workflow starts, then it runs with those values."

How it is met:
- `parseArgs` JSON-parses a string argument.
- The loop and the canary take every configuration value from the parsed object. No `FALLBACK` and no `??` default remain on a configuration key.

How it is proved:
- `workflow-contract.test.js` "args-canary runs with the values of a JSON-string args": returns `resolved` equal to the parsed object, `argsType: 'string'`, and the first log is the resolved-configuration line.
- "increment-build-loop runs with the values of a JSON-string args":
  - log 0 is `increment-build-loop: resolved configuration <JSON>` for a `local` configuration whose `workarea` is `shared/args-fixture`, not the old fallback's workarea;
  - agent 0 carries `options.model === 'fixture-light'`, from args `models.light`;
  - agent 1's prompt contains `~/ws/workareas/shared/args-fixture/backlog.json`;
  - the run throws `no readable backlog at /ws/workareas/shared/args-fixture/backlog.json` when the preflight answer is `null`.
- The object-args twin of each case shows both forms resolve to the same values.
- Live launches L1 and L2 prove it on the current runtime.

**req-007 ac-2:** "Given args missing a required key, when a workflow starts, then it stops before any agent runs and names the key."

How it is met: `requireKeys` throws, naming every missing key, before `logResolvedConfig` and before the first `agent()`.

How it is proved:
- A generic test runs every `.claude/workflows/*.js` with `args: {}` and with no args. Each run throws an error matching `/: args is missing required keys? /`, with `agents` and `logs` both empty.
- Named cases:
  - the loop given the reproduced failure's shape (a JSON string with every `local` key but `increments`) throws `… missing required key increments …`, with 0 agents;
  - the loop with `lifecycle: 'full'` and no Jira keys names all nine full-only keys in one message;
  - the canary missing `n` throws `args-canary: args is missing required key n. …`.
- Live launches L3 and L4 prove it on the current runtime.

**Statement clause "log its resolved configuration first":** in every run that gets past the key check, `logs[0]` is the resolved-configuration line (tests above).

**Statement clause "with no fallback defaults" (the falsifier):** the contract test asserts no `.claude/workflows/*.js` matches `/\bFALLBACK\b/` or `/\bCFG\.[A-Za-z]+\s*\?\?/`; invariants 4 and 5 check the same with `git grep`; "refuses a scope it would once have derived" proves a formerly defaulted key now stops the run.

**Statement clause "accept args given as a string":** as ac-1, plus a test that a string which is not JSON throws `<name>: args arrived as a string that is not JSON (…)` with 0 agents.
