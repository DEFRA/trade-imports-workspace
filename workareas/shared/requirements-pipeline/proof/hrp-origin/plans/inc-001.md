## What the live tree already does, and what this slice changes

The increment reads as though the page were new. It is not. The plants frontend already has an `origin` feature
(`src/server/app/sets/high-risk-plants/journeys/linear/features/origin/`). It collects the mandatory
`countryOfOrigin` obligation from an accessible-autocomplete list, saves it, shows it again on return, and blocks
Check and submit until it is answered. Check your answers shows it by name (`countries.originLabel`). It also has
a per-category narrowing (ware potatoes, conifer wood without bark, the EU member States) that is checked when the
page is submitted and again on Check your answers.

Where the live tree differs from the acceptance criteria:

| AC | Live tree today | This slice |
|---|---|---|
| 1. Page comes straight after the import type; caption "About the consignment"; heading "Origin of the plants, plant product or other objects"; tab title matches the heading | Origin comes **after** the commodity lines (flow `commodity` → `commodityDetails` → `origin`; run `commodity-type` → `commodities` → `origin`). The caption is already "About the consignment". Heading and title are "Origin of the import". | Move origin to straight after commodity-type in the flow and the opening run. Change the title copy, which also sets the tab title, because `kit.base(copy.title)` feeds both. |
| 2. One question, no hint, no body copy, one button "Save and continue" | Hint "Start typing to search for a country."; three controls (Save and continue, Save and return to overview, Cancel and return to overview) | Remove the hint. Render the primary button only (`showReturnControls = false`). |
| 3. Choose exactly one country from a list | Already true (single select plus type-ahead) | No change. Proved again in tests. |
| 4. Saved, and shown again on return | Already true | No change. Proved again in tests. |
| 5. Missing country → "Select the country of origin of plants, plant product or other objects" in the summary and beside the field; stays on the page | Message is "Select the country where the consignment originates from" | Change the copy. The mechanism stays. |
| 6. No country → cannot be completed | Already true in the frontend: the mandatory obligation holds the `origin` task row open, so `readyForCheckYourAnswers` is false and Check and submit cannot start | No change. Add an explicit test. |
| 7. Shown by name wherever answers are shown back | True on Check your answers and on the stub-mode dashboard. **False on the real stack's dashboard**: the plants backend list projection (`NotificationView`) carries no origin, so the dashboard card's "Origin" row is blank for every notification. | Give the plants backend its first typed content field, `origin.countryCode`. The frontend's dual-write mapper sends it. The list projection returns it. The frontend's list marshaller already reads `notification.origin?.countryCode`, and the dashboard already turns the code into a name. |

Programme invariant 2 ("the country of origin is asked before any commodity question") is what drives the move.
This increment is its first application.

## 0. Decisions

1. **Where origin sits in the flow.** It joins the `commodity` flow section between commodity-type and the
   commodities list: `{ id: 'commodity', pages: [commodityTypePage, originPage, commoditiesPage] }`. The separate
   `origin` flow section is deleted. Because origin now comes earlier in the flow, `countryOfOrigin` (already in
   `ENFORCED_AT_CONTINUE`) becomes a derived prerequisite of the commodities list and the commodity-details page.
   That is the rule "asked before any commodity question" in the engine's own terms.
   *Rejected:* keeping `origin` as its own section placed between `commodity` and `commodityDetails`. That would
   have to split commodity-type from the list. Outside the opening run, commodity-type's Continue
   (`nextInSection`) would then go to the Overview instead of carrying on, and a bounced deep link would lose its
   onward step.
2. **Opening-run order.** `RUN_STEPS` becomes commodity-type → origin → commodities → arrival-status →
   arrival-details → place-of-destination → consignor → identification-numbers → contact. The list page still
   sends a trader with no lines to the entry sub-page. So, inside the run, origin's Continue lands on
   `/commodities/details` after a redirect through `/commodities`, and the list's Continue goes on to
   arrival-status (plants and wood) or arrival-details (potatoes).
3. **Outside the run**, origin's Continue now goes to the commodities list (`nextInSection`). Before, it went to
   the Overview. This is accepted: it is the natural next page in the section. From Check your answers
   (`?change=1`), the change context still returns to Check your answers.
4. **Hub task rows and groups do not change.** The `commodities` row (commodity-type, list, details) and the
   `origin` row stay as two rows in group 1, in that order. The hub is a task list, not the page order, and
   commodity-type (which leads the commodities row) is still asked first. *Rejected:* merging origin into the
   commodities row. That would change the hub's visible rows and the submit-readiness units, which is beyond this
   slice.
5. **One button (AC2).** The origin template calls `saveActions(hubHref, copy = sharedCopy.saveActions,
   showReturnControls = false)`, so the only control is the "Save and continue" button. This departs, for this page
   only, from the repo rule in `shared/save-actions.njk` and `spec/journey-spec.json` (line 60) that a hub-linked
   page ends with three controls. The row is the newer requirement and it is explicit. IPAFFS itself renders
   exactly one button here (trace `secondaryActionsNote`). The Back link still returns to the Overview once
   anything is saved (`backLinkFor`), so a trader can still leave without saving. *Rejected:* keeping the
   three-control rule, because AC2 would then fail. Also rejected: adding a macro variant that keeps only the Cancel
   link, which is new surface nobody asked for. The server-side `exit=hub` handling in `kit.exitTarget` is left
   alone: it is shared kit behaviour.
6. **No hint (AC2).** Delete `copy.country.hint` in both locales and the `hint` parameter in the template.
   The label stays "Country of origin" at `govuk-label--m`, the trace's field label. The select's placeholder
   option "Select a country" stays: it is a list item, not a hint.
7. **"No body copy" and the narrowing guidance inset.** The existing ware-potato guidance inset renders only when
   the consignment already holds a ware-potato line. With origin now asked before any line exists, the page as
   first reached has no inset, so AC2 holds. The inset, the narrowing rules and their error sentences are existing
   behaviour that this row does not mention. They are kept exactly as they are (see Out of scope).
8. **Narrowing now bites later.** A country chosen before any line cannot be narrowed at that moment. It is still
   refused when the origin page is submitted again once lines exist, and on Check your answers, which already
   re-validates it (`originErrors` in `check-answers/controller.js`, with a Change link to `origin?change=1`) and
   refuses Continue. So a notification can never be submitted with a country its lines forbid. No new check is
   added to the commodity-details page: that would be new routing policy (req-013 and req-017 are out of scope).
9. **Error copy (AC5, open question c-006).** Build to the row's default, "Select the country of origin of plants,
   plant product or other objects". The key stays `errors.countryRequired`.
10. **Welsh.** Machine-draft Welsh for the two changed strings, marked as machine draft like the rest of the file:
    title `Tarddiad y planhigion, y cynnyrch planhigion neu’r gwrthrychau eraill`, error
    `Dewiswch wlad tarddiad y planhigion, y cynnyrch planhigion neu’r gwrthrychau eraill`.
11. **Backend typed origin (AC7).** Add a record `Origin(String countryCode)` to the plants backend, carried at
    `notification.origin` on the aggregate, accepted as a flat `origin` field on `NotificationDto`, and returned on
    the dashboard list projection as `origin`. The shape is `origin.countryCode`, because that is what the
    frontend's real list marshaller already reads (`real/marshal/list-item.js`: `notification.origin?.countryCode`)
    and what the animals mapper emits. The backend Javadoc already says "add fields as they are agreed", and this
    datum is now agreed (policy "All other goods" item 6). *Rejected:* reading the country out of the opaque
    `fulfilments` in the projection by obligation UUID. That would couple the backend to frontend obligation ids.
12. **Every write replaces origin.** `setNotificationDetails` sets `notification.origin` from the DTO on every
    create and replace, including `null`, just as it replaces `fulfilments`. The frontend sends the whole state on
    every write.
13. **Copy-as-new carries origin**, as it carries the fulfilments that already hold the country. So
    `NotificationCopyMapper` copies it.
14. **No backend submit validation for origin.** The frontend's readiness gate already blocks submission (AC6).
    Plants backend content validation is not agreed, and a draft saved before this change would not carry the
    typed field until its next write. *Rejected:* rejecting `POST /submit` without `origin`.
15. **`Origin` null guard.** A compact constructor with `Objects.requireNonNull(countryCode, ...)`, following
    the workspace rule "lock down Java records with null guards". An absent origin is represented by a `null`
    `origin`, never by `Origin(null)`.
16. **Frontend mapper reads through the set-agnostic manifest.** Follow the animals exemplar
    (`animals .../notification-mapper/mapper-a/sections/origin.js`): take
    `obligationSet().countryOfOrigin` and read it through `readFulfilment(...).scalar`. The unit suites run
    against a synthetic obligation set that has no `countryOfOrigin`, so the mapper omits `origin` when the
    configured set has no such obligation or the fulfilment holds no value. The existing expectation of exactly
    `{ referenceNumber }` for synthetic snapshots then still holds.
17. **Spec artefacts are not rewritten.** `sets/high-risk-plants/spec/journey-spec.json`, `decisions.json`,
    `conflicts.json` and `panel/*` are historical distillation records, and no code reads their page order. They
    are left as they are. The living docs (`docs/journey-flow-and-gates.md`) are updated.
18. **E2E helper reshape.** In the tests repo, `PlantsJourney.toOrigin()` is deleted. A new
    `chooseCountryOfOrigin(country)` follows `chooseCommodityType`. `toArrivalStatus()` and `toArrivalDetails()`
    lose their `country` parameter and now leave from the commodities list. *Rejected:* keeping `toOrigin` as a
    no-op or alias, which would leave a helper whose name no longer matches the journey.
