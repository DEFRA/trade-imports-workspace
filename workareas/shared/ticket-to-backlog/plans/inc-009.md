# inc-009 plan: one launch turns a fetched ticket into a checked, combined backlog, a readiness verdict and its questions

| Repo | Path | Branch | HEAD |
|---|---|---|---|
| workspace | `.` (`~/git/defra/trade-imports-workspace`) | `feat/EUDPA-838-one-launch-turns-a-fetched-ticket-into-a` | `2390f7ae` |

Two pieces, one slice, all in the workspace repo:

- **The backlog check learns ticket backlogs.** The envelope gains the ticket key (and may carry the branch). A new intake record schema sits beside the backlog schema. `tim backlog check` holds a ticket backlog to its intake record.
- **A new intake workflow**, `ticket-intake.js`, launched by `scriptPath`: one reader writes the investigation, the intake record and the rows; a different agent refutes them; the reader fixes once; tim checks the shape before and after.

Neither can be observed without the other: the workflow is the record's only writer, and the check is its gate.

## 0. Decisions

1. **The provenance and source prefix is `ticket:`, not `jira:`.** inc-008 shipped the source kind `ticket` and the source id `ticket:<KEY>` (`tim/src/backlog/from-ticket.js:183-193`, `extract-ticket.md`). The design plan's `(jira:EUDPA-832 AC1)` bracket becomes `(ticket:EUDPA-832 AC1)`. Rejected: a second prefix for the same source.
2. **Where the files live.** The intake record is `workareas/<workarea>/intake.json`; the investigation is `workareas/<workarea>/investigation.md`, both beside `backlog.json`, as EUDPA-718's investigation sits beside its backlog. The record's schema is `.claude/skills/requirements-pipeline/references/intake.schema.json`. The workflow is `.claude/skills/requirements-pipeline/workflow/ticket-intake.js`; its briefs are `workflow/intake/briefs/read.md` and `refute.md` (design plan §2, §8).
3. **What the intake record holds** (design plan §2, "Ticket backlogs in the one shape"), each field described in the schema:
   - the ticket key and Jira's `updated` time, copied from the fetch record `sources/ticket-<key>.json`;
   - the readiness verdict, one of the refinement check's three verdicts, with its reasons. The schema's verdict list is held equal to the list `tim refine finalize` accepts (`tim/src/commands/refine/finalize.js:7`) by a test, so the two never drift;
   - the statements, each with an id, a kind (acceptance criterion, scope, out of scope, background), the ticket's own words, and either the row ids that cover it or a reason it is not built. Statement ids are short upper-case letters then digits, keeping the ticket's own numbering (such as AC1) where it has one;
   - why each repo is in the backlog;
   - the questions, each with an id, the question, the readings it leaves, a default, whether it holds the launch and, when it does, which of five causes: security, access, data integrity, a signed-off scenario, a rulings-ledger entry (design plan §4);
   - an escalation: none, or the signals that tripped (spike, too many questions, too many rows, another requirement source, needs people outside the session, an open blocking link) with a plain-words reason.
4. **The ticket-backlog rules, all in one new module, run only when the envelope names a ticket.** A backlog without `ticket` is checked exactly as today, and its check result keeps exactly today's fields. On a ticket backlog:
   - with no intake record beside it: refused, saying the intake writes it;
   - the record against its schema, each problem in plain words;
   - the record's ticket key must equal the envelope's;
   - **coverage:** an acceptance-criterion statement passes when at least one row its cover list names is `todo`, `blocked` or `done`, or when it carries a reason it is not built. Otherwise it is refused, naming the statement's id and its words. A cover list naming a row the backlog does not have is always refused (a dangling id is never right), naming both. A statement covered only by `deferred`, `dropped`, `rejected` or `merged-into` rows is refused, naming each such row and its status. Rejected: refusing any withheld id even beside a covering row, because a merged-away row's statement legitimately names its old row too until the reader tidies it; the criterion says "covered only by";
   - **citations:** every acceptance criterion of a `todo` or `blocked` row ends with a provenance bracket naming at least one of: this ticket with one statement id, a `repo:` source, or a `ruling:` source (a rerun after a ruling cites it). A `ticket:` citation naming another key, no statement id, or a statement id the record does not have is refused, naming the row and the cited id. Rows `done` or withheld are left as built;
   - **questions:** a question that holds the launch names one of the five causes; one that does not names none. Refused otherwise. (Done by hand because tim's schema reporter drops `if`/`then` errors as "explained elsewhere", `tim/src/distil/problems.js:93-96`.)
   - **escalation:** with no escalation recorded, the backlog is refused when the verdict is SPIKE REQUIRED, the record holds more than 3 questions, or more than 4 rows are still to build (`todo` or `blocked`), each naming the signal. With an escalation recorded, a row still to build is refused, naming it: an escalated ticket hands over no buildable row, so BUILD's preflight (which runs this check) can never build past it;
   - **no themes:** `themes` and `theme` on a ticket backlog are refused, each saying a ticket builds on one branch. `splitOff` and `movedOut` are already refused on a backlog with neither `themes` nor `theme`, by `unthemedBacklogProblems` (`tim/src/backlog/themes.js:363-372`), and a ticket backlog never has either once the new rule holds. The new rule adds no second line for them; section 4 proves both are refused on a ticket backlog through `checkBacklog`.
5. **The check result for a ticket backlog gains a summary of the record:** the ticket key, the readiness verdict, the statement ids and their count, the not-built statement ids, the questions as the record states them, the escalation, and the ids of the rows still to build with their count. The workflow's relays copy it and are checked list against count. Left out entirely for a backlog without `ticket`.
6. **How the record reaches `checkBacklog`.** `checkBacklog` gains one option carrying the parsed record (or nothing, when the file is absent) and the intake schema. The `check` command reads `intake.json` and the schema only when the envelope names a ticket. Left out, the record rules do not run, as `externalDependsOn` is not followed without its reader (`shape.js:272-276`); the envelope rules (no themes) always run. `add-row.js` and `split.js` call sites stay unchanged: split refuses a ticket backlog through the no-themes rule anyway.
7. **The intake schema is loaded beside the backlog schema**, in `tim/src/backlog/backlog-schema.js`, through one shared "read a reference schema or refuse NOT_FOUND" helper both loaders call. Rejected: `loadDistilSchemas`, because the record is not a DISTIL file and `tim distil` never reads it.
8. **The branch reaches the envelope through the fetch record.** `tim backlog from-ticket` already works out the branch (`from-ticket.js:296-304`) but records only key, `updated` and fetch time (`:340-348`). The record gains the branch; the read brief copies key and branch from it into the envelope. Without this nothing could write the widened envelope `branch`. The branch rule keeps its one owner in `from-ticket.js`.
9. **The workflow's stages** (phases Status, Read, Check, Refute, Fix, Check again):
   1. **Status**, one light agent: the workspace root's absolute form; `tim distil status` for the sources and their kinds; `tim distil backlog-snapshot --save` under its own tag. A NOT_FOUND from the snapshot means no backlog yet (first run); any other failure stops the run.
   2. **Before any think agent:** sources.json must hold exactly one `ticket` source, else the run stops naming what it found. A source of any kind other than `ticket`, `repo` or `ruling` returns an escalation (another requirement source) with no rows and no further agent.
   3. **Read**, one think agent following `read.md`: reads the ticket file in full, attachments included, any existing refinement verdict, the rulings among the sources, and the code; writes `investigation.md`, `intake.json` and `backlog.json`; runs `tim backlog combine-candidates` and `tim backlog check` itself until they pass. On a rerun it reads the existing backlog and record and rewrites only rows still to build, keeping every id.
   4. **Check**, one light agent: `tim backlog check` (relaying the record summary), `tim backlog combine-candidates` (rows still to build), on a rerun `tim distil backlog-snapshot --compare-to` the status tag, and a listing of `investigation.md`. Problems from any of them, a removed row, a changed built row, or a missing investigation carry into Refute and Fix; they do not stop the run here.
   5. **If the check passed and the record names an escalation**, the run returns it with no rows. No refute runs. Rejected: refuting an escalation, which spends an Opus agent challenging a ticket that DISTIL will take over anyway.
   6. **Refute**, one think agent following `refute.md`, a separate agent call from the reader: a verdict (holds, wrong, missed) on every row still to build, on every split when more than one row is still to build (one split verdict per such row: why it cannot join another), on every statement, and a challenge on every question (stands, settled by the ticket or a ruling, or drop). It writes nothing. The workflow checks its verdicts name exactly the row, statement and question ids the check relayed; a mismatch asks it again once, then stops the run.
   7. **Fix**, one think agent following `read.md`'s fixing section (the reader's method; a workflow agent cannot be resumed, so "the reader fixes" means the reader's brief and its own decisions, given to a new call): applies or answers every verdict that is not "holds" and every check problem, once. The workflow checks every such verdict has an answer; any left unanswered stops the run naming them. When every verdict holds and the check had no problem, no fix runs and the log says so.
   8. **Check again**, the same relay. Still out of shape stops the run, naming every problem line. An escalation the fix recorded is returned as in step 5.
   - It returns the ticket, the rows still to build, the readiness verdict, the questions (each with its default and whether it holds the launch), the escalation, the refute's verdict counts and every answer, the reader's and fixer's decisions, and the paths of the three files.
10. **Combining is the reader's default, and the refute challenges every split** (ruling, 25 November). The read brief starts from one row; a further row stands only with a note giving one of the combine-review reasons (`combine-review.md:18-28`) and the reader runs `combine-candidates` before handing on. tim does not check the note's words: a note's reason is judgement, and the refute's split verdicts are its check. Rejected: a tim rule that a second row carries "a note", which any note passes.
11. **Models:** two tiers, think (read, refute, fix; default opus) and light (status and checks; default haiku), `inherit` allowed, as distil's `models` arg works. Args: `workspace`, `workarea`, `tim`, `models`, every one required, no defaults.
12. **The guard rails and the model-tier resolution are one text in both workflows.** The intake's agents must have distil's rails (no subagents or forks; finish your own task if a user message arrives). Workflow scripts cannot import, so the shared text goes in marker blocks in both `distil.js` and `ticket-intake.js`, held byte-identical by the contract test, exactly as the args-contract block is (`distil.js:46-67`, `workflow-contract.test.js:474-490`). Two blocks: one holding the agent guard rails, the envelope rule, the relay retry note and the relay label; one holding the tier validation and resolution over a tier table each script defines above it. distil's resolved-models log line must stay word for word as it is. This is the one reason `distil.js` is edited (the house rule on extracting a mirrored path); its touched lines meet the house rules.
13. **README documents the new workflow in this row.** The contract test holds each workflow's required args to its README table (`workflow-contract.test.js:597-623`), so the new script's section (args, stages, result, stops) lands with it. The wider docs (TICKET.md, routing, the "no lighter path" wording, BUILD.md's branch from the envelope, the worker-reference catalogue) stay with inc-010, which names them in its criteria.
14. **Rerun after a ruling** rewrites only rows still to build: `tim distil backlog-snapshot` already refuses a removed row and a changed row that is built or set aside (`backlog-snapshot.js`), so the intake uses it with its own tag rather than a new comparison.
15. **Test workspaces for the spawned check go through `makeTicketWorkspace`** (`tim/src/backlog/__fixtures__/ticket-workareas.js:30-54`), the shared builder that already writes files and backlogs under `workareas/` by workarea and already has a schema-copy option (`distilSchemas`). It gains an option that copies the backlog and intake schemas, and an option that writes an intake record beside a workarea's backlog, mirroring its `backlogs` option. `backlog-file.js` gains nothing. `rows.test.js` (edited for this row) builds every workspace through the helper and loses its local schema copy (`rows.test.js:25`, `:50-55`). Rejected: a second writer in `backlog-file.js`, and a schema copy local to `rows.test.js` (code-quality.md, Structure: "Extend the mechanism that exists"; Tests: "Set-up used by two tests goes in the shared test helper"). The same local copy in `edit.test.js`, `split.test.js` and `rigour.test.js` is outside this row's footprint (section 7 follow-up).
16. **The contract test's generic agent helpers become shared** (plan review). The distil describe's `byLabel`, `labelsOf` and `optionsOf` (`workflow-contract.test.js:11839-11849`) are not distil-specific; they move to module scope beside `stageLabels`, `modelOf` and `promptOf` (`:355-364`) and the distil describe's local copies are deleted. Each describe keeps only its own answer table and its run helper (which carries its own script's args). Rejected: a second copy of their bodies in the intake describe.

## 4. Tests

## 13. Operability

tim is a CLI and the intake is a workflow, so an outcome branch is logged through the result envelope or the workflow's `log` line, which the caller reads.

| Branch | What support must find |
|---|---|
| A ticket backlog refused | Exit 1, each problem naming the workarea's backlog and the statement id and words, the row id, the citation, the question id or the escalation signal it is about |
| No record beside a ticket backlog | The workarea and that the intake writes the record |
| Intake: sources hold no ticket, or more than one | The stop names the workarea and the source ids found |
| Intake: another kind of source | The escalation names the source id and kind |
| Intake: escalation from the record | A log line with the workarea, the ticket key and the signals; the result carries the reason |
| Intake: relay mismatch asked again | A log line naming the relay and the counts that disagreed |
| Intake: refute or fix incomplete | The stop names each missing id or unanswered verdict |
| Intake: no fix needed | A log line with the workarea and the verdict count |
| Intake: still out of shape | The stop carries every problem line exactly |
| Intake: snapshot failed | The stop carries tim's problem lines |

## 15. Reachability

Everything built is reachable when this lands:

- The intake workflow is launched by `scriptPath` on a workarea `tim backlog from-ticket` wrote.
- The envelope's `ticket` and `branch` are written by the reader, from the fetch record, which now carries the branch.
- The ticket-backlog rules run on every `tim backlog check` of such a backlog, the workflow's and BUILD's preflight's.
- Each escalation signal is recordable by the reader; the sources escalation is reached by any non-ticket, non-repo, non-ruling source in `sources.json`.
- The rerun path is reached by adding a ruling to `sources.json` and launching again.
- Both new `makeTicketWorkspace` options are passed by `rows.test.js`.

Reading the branch from the envelope in BUILD is inc-010's.
